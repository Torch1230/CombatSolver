# CombatSolver 架构边界重构

## 适用边界

本 skill 处理结构和所有权：拆分大类、迁移 run/session state、建立策略对象、隔离 renderer、整理测试编排、为工具提供稳定元数据。

如果任务改变卡牌/怪物结算，叠加 `combat-semantic-change`；改变 Beam 权重或候选政策，叠加 `search-performance-optimization`。纯重构不能借机改变这些行为。

开始前读取 `docs/ARCHITECTURE.md`，并读取 `tools/verify-refactor-boundaries.ps1` 与 `tools/verify-refactor-boundaries.sh` 中对应边界，只读取本次涉及的源码分片。两套门禁分别服务 Windows 和 Linux，规则必须保持等价。

`CombatBeamSolver.RoundLifecycle.cs` 统一回合推进；普通重放与后续检查点必须共用 `AdvancePlayerTurnStart`，不得复制玩家回合开始结算。提取阶段不改变选择事务、回调顺序、RNG 或逻辑预算。 直接 EndTurn 前缀由该次枚举独占；仅已完成阶段的空游标可临时分离，其他 Fork 禁止条件原样执行。所有恢复进入同一玩家开始方法，嵌套/逐实例选择维持原额度与顺序，枚举退出释放冻结图；不得把上下文搬到发布快照或共享 worker 缓存。

## 1. 先定义迁移前后的所有权

写清楚：

- 当前谁创建、持有、修改和销毁该状态；
- 目标类型的单一职责；
- 哪些调用顺序、集合顺序、比较器、日志事件和协议字段必须保持；
- 目标边界允许依赖什么，禁止依赖什么；
- 哪个代表场景能穿过这条边界。

优先迁移所有权，再考虑复用、池化或算法优化。不要在同一批同时移动代码、改变策略和优化分配。

## 2. 当前结构约束

- Search 只接收快照、policy、diagnostics、frame signal 和 cancellation；不引用 Runtime 全局、UI 或 Testing。
- 玩家回合末第二阶段由 `PlayerTurnEndLifecycle.RunPhaseTwo` 统一安排常规 Power、遗物及晚期 Power；Search、风险预估和无人差分调用同一入口，阶段内的挂起选择立即返回。
- `src/Api/PreCombat*` 拥有公开 API v5 的战前请求、状态/设置令牌与独立游戏 worker。主线程捕获，worker 通过无人协议恢复并复核完整跑局；Mod 使用独立副本、当前账号设置映射到 worker，求解设置变化使缓存及 worker 失效。跨请求停止/期限不能只等待繁忙锁；此边界不把 headless 等同操作系统沙箱。
- `CombatBeamSolver.cs` 只负责构造和接线；阶段循环、展开、评估、中间保路、终局排序和终局回放各在现有分片。
- 单次搜索可变状态属于 `SearchRunContext`；中间候选属于 `BeamRetentionPolicy`；终局政策属于 `FinalPlanOrdering`。
- `AdmittedExpansion` 只调度已预约父节点内的作业，固定 lane 排空并归并后才复用；提交仍按父节点和动作原序。`PrimaryChoiceReplayFrontier` 独占必经首层回放的暂存快照，所有生产作业结束后才移交一个续接消费者；动态预算和 occurrence collector 不跨 lane 共享修改。异常先排空，再释放 probe、frontier、batch 与根。
- `StandPatJobs` 只预计算原保路规则必经的未缓存探针，复用当前固定 lane；worker 释放完整回放的临时快照后只回传标量，缓存按首个原代表和原序由 coordinator 写入。Prune 根在全部作业排空前保持所有权，批内没有新准入或内存检查点；executor Dispose 清除 `SearchRunContext` 的活动引用。
- `RetentionJobs` 只在展开已排空后复用相同 lane 计算本次保路只读输入，索引结果和组内摘要独占；coordinator 统一应用观察请求、更新共享计数并计入包括失败作业在内的后台分配。不得把这个入口用于模拟、准入或与 Prune 重叠的推测展开。
- `RoutingChoiceNodes` 只持有本次 RankBest 的有序组和派生统计；分组完成后冻结排名摘要，在本次排名赋值前消费完毕，不把可变父排名放入跨调用缓存。监听分段属于 `SimulatedCombatState` 的分支派生视图；前段/后段均以不可变形式发布，完整路径保留无锚点与不透明 CardModifier 语义。 有效/活动前段与 Power 投影的保留只适用于卡牌/球失效，完整失效清空全部派生段；前段独立存活时仍由同一 Fork 上下文重映射。
- controller 状态属于 combat/search/deployment session，不回退为并列静态字段。
- 跨 SL 路线记录由 Runtime 的 `SolvedRouteCache` 持有磁盘协议；在普通根捕获和回合开始选择根捕获后按状态与策略匹配。结果中的 Forecast 从新根重新绑定，磁盘和跨会话所有者均不得保留旧 Creature/MoveState。Search 不读取路线文件。
- UI renderer 只消费 `SolverOverlay*Snapshot`；结果到 snapshot 的复制发生在主线程边界。
- 改动 UI 文案及投影时读取 `../ui-localization/SKILL.md`：保留中英模板和胶囊/tooltip 的统一来源；名称与语言在主线程捕获，worker 使用冻结显示表。不要把日志 Describe 重新接回玩家界面或把本地化带入 Search。
- 设置页自身驱动的后台任务使用控件所有者的完成邮箱收口；问题包上传的成功、失败和取消由 `SolverSettingsPanel._Process` 消费，不借用搜索生命周期的 `SolverDispatcher`。
- 问题包 `CombatBugReportMetadata` 在主线程冻结战斗/角色/怪物与比较标量；Uploader 读取归档中的同一份 report.json，发送前核对身份和玩家描述。新包按 report.json、diagnostics/、replay/ 组织，CheckpointArchive 兼容旧包路径，禁止后台重新采样 live 元数据。
- unattended 的协议、建局、执行、断言和结果写入分别属于 ProtocolHost、ScenarioBuilder、Executor、Assertions、Writer。
- `src/Replay` 只依赖标准库：包校验、顺序事件临时文件；Runtime 冻结原生输入，Testing 重放和对账，CheckpointTool 负责批量调度与结果口径。跨平台脚本只承担本平台启动与进程所有权。
- headless 实例目录、完整游戏/Mod 内容快照和主机资源预约属于 `tools/headless-runtime.ps1/.sh`；启动器保留请求协议、精确 PID/出生身份终止、结果与静稳 ACK。不得把测试协调放入游戏 Search/Runtime，或只删全局进程检查而继续共享 DLL/协议。并行只作正确性/吞吐验证，性能对照使用独占模式。
- CoverageCatalog 只消费 `IMethodMirrorRegistryDescriptorProvider`，不反射 registry 私有字段。

## 3. 实现方式

- 沿用仓库现有 concrete type、partial 和窄接口，不引入 DI 容器、事件总线或多程序集拆分。
- 纯移动批次保持方法体、可见性、集合类型、迭代顺序和调用顺序。
- 需要新抽象时，让它拥有真实状态或消除实际重复；不要只建 facade 转发旧单体。
- snapshot 在所有权边界一次性复制，不让下游重新追溯 mutable 对象图。
- 工具元数据由被描述对象自己提供，避免工具依赖私有字段名。
- fail-fast 行为、stage 名、结构化日志和请求/result schema 在纯重构中保持不变。

## 4. 滚动批次

一次提交完成一个可解释边界：

1. 记录迁移对象和不变量；
2. 移动或接入具体所有者；
3. 删除旧所有权和双写路径；
4. 同步扩充 `verify-refactor-boundaries.ps1` 与 `verify-refactor-boundaries.sh`，阻止旧结构回流；
5. 运行结构门禁和一个代表场景；
6. 更新架构地图、必要的核验记录并直接提交。

不要等所有目录都看完才写。按职责块读取、修改、验证、记录和提交。

## 5. 验证

纯职责移动的最低验证：

- Release 编译；
- `pwsh -NoProfile -File tools\verify-refactor-boundaries.ps1`（Windows）或 `./tools/verify-refactor-boundaries.sh`（Linux）；
- 一个穿过新边界的代表 headless 场景；
- 若移动 Beam 比较器，比较动作序列、expanded/transitions/choice branches 和各剪枝计数；
- 若移动 UI 边界，验证 renderer 签名与 ready/deploying/complete 事件，人工视觉项不冒充 headless 通过；
- 若移动 registry 元数据，比较 CoverageCatalog 前后分类与生成文件；
- 若移动 unattended，覆盖 Passed、Failed、Held 和同进程恢复中受影响的协议分支。

文档或 skill 本身的维护只需路径、链接、frontmatter 和职责一致性检查，不自动跑实机。

## 6. 记录

`Simulation/Compact/` 保持纯值执行和不可变候选，`Prediction/Compact/CompactDiscardProjection.cs` 独占实验准入与旧评估投影；Runtime 在主线程整根准入后选择紧凑后端，未迁移域使用模型后端。扩展这条边界必须同时维护双端所有权规则并提供完整支持闭包证据，不能只删除门禁或把可变 Simulator 藏入冻结句柄。类型分发诊断通过 registry 自己的 `DescribeDispatch` 获取，不反射私有注册表。

原型阶段计量由 Testing 的 `CompactPhaseProbe` / `CompactKernelProfile` 持有。直接调用旧 Snapshot 时必须保持正式通知隔离上下文；其线程静态作用域在 await 与原生部署前释放。新读视图只借用当前同步评估所需的权威状态，不能逃入保留候选或通过读接口重新构造每叶旧对象图；共享完整公式与原状态键编码，避免新增独立评分权威。

紧凑冻结状态由候选独占页表并共享不可变值页；工作区的页缓存只是派生数据，写入和 rollback 均须失效。恢复必须在写前拒绝外根与活动 checkpoint，页表不能指回 worker 或祖先候选。槽位追加和逻辑长度须由检查点撤销；删除后缀后清零，冻结只保留有效范围，恢复支持同根不同长度且不能暴露旧容量中的值。只有目标容量足够时复用恢复才保证无分配，增长容量属于 lane。页共享与零分配恢复不等于生产 Beam 存活量或 GC 暂停改善；长历史仍需核对页表、恢复扫描和所有实际语义消费者。

- `docs/ARCHITECTURE.md` 保存当前事实；
- `docs/refactoring/verified-audit-*.md` 保存阶段证据，不作为永久入口；
- `docs/refactoring/refactor-roadmap.md` 保存批次状态；
- `docs/TEST_MATRIX.md` 保存可重跑场景。

普通架构重构直接提交，不自行提升版本、不计算文件哈希。版本和打包时机以 `AGENTS.md` 的活动发布批次和发布口令为准，再转 `release-gate`。

完成状态读视图阶段：旧／新入口必须共用完整 SnapshotCore、合法性、原键和排序；Prediction/Compact 负责能力闭包，Search 只认识读取合同。未迁移字段须证明在闭包内不变，不能从 live 或一份过期旧分支补读。历史 getter 的惰性零项与缺席可能影响原键，根级准备须隔离；技能次数与技能集合等并存语义不能遗漏。风险摘要可在固定来源闭包内准备，但保留每次风险事件的历史计数。读取器不逃入候选，完成快照释放借用 Simulator；每批初始化成本纳入对照。真实原生前后字段净变化只是观测，packed 字段、重复字段和瞬态写入须注明，不能据此宣称实际 dirty page 或紧凑复杂效果已验证。

洗牌／Power 选牌扩展阶段：Shuffle 的 counter 与四个 64 位状态、原排序关系和抽牌剩余位置必须一并保存、冻结、恢复及撤销；从 Power 选择恢复后不能重复抽牌或遗物触发。直接原键与投影洗牌都读取分支 RNG，其他八流只有在能力闭包证明不变时才能借用根。估值缓存仅复用闭包内不变的敌人／AI、Power、存活牌集合和元数据，根级创建成本计入测量，换根即重建；共用原计算公式并逐属性比较缓存开关。原生两回合测试若由旧引擎推进回合，必须明确标明，不能冒充紧凑跨回合执行或 Power 数量迁移。

生物值读取扩展：基础 HP／格挡／治疗算术由 `CreatureVitals` 统一，命令仍独占修正、伤害历史、Hook、死亡与终局安全点；值槽中的零 HP 不等于 roster 移除。完整读取合同同时提供数值、有序活动敌人和可空 TerminalStamp；原键的 AI／沙漏部分使用同一 roster，敌人变化时旁路根敌人／焦点缓存。未迁移的 Hook、宠物和领域公式不能依赖已变化值；Power 数量不变不足以证明这一点。逐属性／原键／排序测试须包含部分离场、全部离场和终局，标量原生差分不能冒充紧凑死亡程序已经实现。

普通攻击读取扩展：攻击目标、三个伤害结果标志、来源与命中历史、上一张攻击、死亡阶段和终局均须属于分支或已提交值事件。最后一击进入 IsEnding 后，结果牌堆移动可能被拒绝，不能在末击后强行送入弃牌堆。原公式的 Simulator scratch 不是只读元数据；并行读取器各自拥有初始化根副本，初始化成本计入测量，禁止每叶投影或让候选保留读取器。扩展到 Power 死亡时同时迁移数量、有序列表与生命周期，不凭简单击杀域通过放行复杂效果。

完成读取中的 Power 模型属于每 lane 的单向派生评估上下文。仅初始化克隆，显式恢复 Power 克隆后的 owner；每叶导入值、获得序列、根槽退休和当前阵容，并使 owner-anchor 监听器缓存失效。模型不执行命令、不发送 Hook、不回写紧凑程序、不进入候选。`EvaluationContext` 与权威状态的职责须明确，双端门禁禁止提前接入生产。

有序指令扩展：`CardEffectProgram` 只保存私有复制的不可变效果序列，模型准入和编译由 Prediction/Compact 负责。每帧指令索引、抽牌进度、选择和子牌位置写入同一撤销状态；子牌完成后恢复父牌剩余指令。覆盖同牌多次选择、部分抽牌后的洗牌、空选择与八工作区恢复；合成指令合同不能冒充原生效果闭包，两个原完整输入及动态生成仍须分别验证。

卡牌生命周期扩展：付款 X、结果位置、消耗和移除须在同一值状态与事件中恢复；移除保留历史身份，不进入战斗牌堆。旧读取器只单向导入 X 与移除标志，普通牌不得访问 X 专属属性；消耗历史进入原键，卡牌集合／元数据变化时禁用相关不变摘要。风险来源区分原 registry 分类，按实际组合缓存，不用容量上限或默认无风险掩盖未支持效果。能量 X 合法性使用完成读取提供的当前资源，原生逐实例字段与完整估值均须对账。

群体与条件指令扩展：精确卡牌编译由 Prediction/Compact 的 `CompactCardProgramCompiler` 独占，不在值执行器或旧投影中识别卡名。群体操作保留当前指令的目标顺序，不能改成每个目标完整执行所有效果；抽牌返回值按帧保存在撤销槽，区分实际抽牌、洗牌检索与满手牌的空返回。虚无标记仍进入正常出牌完成历史。原生测试覆盖类别分支、洗牌恢复、施加者、离场目标与原键；中毒数量迁移不表示中毒触发或回合推进已完成。

间接伤害与整手弃抽扩展：中毒事件保存原伤害属性、空攻击者／卡牌来源，不增加攻击完成或 powered hit；存活递减、归零退休、重获与末击终局均须对账。整手弃抽保存原实例列表与抽牌数，洗牌恢复返回抽牌阶段，Sly 在全部抽牌后执行，即便该实例已重新抽回手牌。未镜像效果的补偿来源位于原 OnPlay 作用域之外；不能为对账而修改旧历史。抽牌通用方法改变后，应保留普通抽牌返回值的原生哨兵。

Power 根实例重获的读取不能只修改数量：读取器初始化时为原实例和规范新实例准备独立模型，由根槽退休值选择；额外目标、回合初始值、持续计时标记及动态变量跟随对应实例。不得逐叶克隆或将选择过的模型回写执行状态；原生非默认字段与逆序根恢复必须对账，额外初始化成本单列。

Power 条件／计算指令直接读取当前分支的目标数量或存活敌人总量，不能预计算根倍率；条件跳转沿用帧指令位置，基础值与额外倍率只作为不可变标量编译。格挡在求和后统一经过原敏捷／脆弱与取整规则；覆盖归零、重获、离场、升级消耗与原键。

下回合计数 Power 的施加与跨回合执行分开验收；读取绑定须导入当前计数及获得顺序。格挡返回值先保留修正后的 decimal，再按原生 Power 规则转整数，不能使用封顶后的净增量。零层实例尚未表示时，按根及后续可达敏捷区间拒绝可能产生正小数零层 Power 的整个根，不在执行后忽略。

临时力量的首次施加先执行 Strength，再加入临时计数；叠加及首次封顶后的回调按修正后的请求偏移与当前 Amount 比较，不能用计数净变化替代。Power 准备（修正、Artifact）与写入共用一个入口，各做一次；覆盖力量归零重获、正负偏移、首次／叠加封顶、双方回合末恢复及普通 Power 哨兵。

紧凑临时力量指令只接受已表示的敌方计数类型；每个目标完整执行首次 Strength／计数／数量回调，再推进下一个目标。Power 的顺序、施加者、退休及死亡清理从值槽读取；只扩大准入的精确回调，回合末仍需单独迁移和验收。

增长的领域状态与事件必须允许交错分配。索引缓冲区的树根、层级、长度、尾指针和数据都属于可撤销值，布局只保存不可变偏移；冻结恢复不能依赖 lane 外部的追加游标。事件保留完整实例编号，不以字节截断生成卡；新增索引和事件宽度的成本纳入含准入链路测量。

生成卡的定义在根闭包捕获，实例编号与有序牌堆在可撤销值中增长；不得只按卡名对账或截断编号。验证满手溢出、生成后消耗／洗牌、来源历史、卡牌特有计数和新 Hook 准入。读取模型池由单个 lane 持有，按实例／定义复用并在恢复时重绑；根不变模型旁路导入，池和模板初始化成本计入测量。

将生成后修改折叠为最终模板前，证明中间 Hook 没有观察者、修改无额外战斗历史／效果且排序不变。混合模板须覆盖同实例编号在兄弟分支中的不同定义、完整卡牌指纹和逆序恢复；准入其他附魔时重新证明，不能从普通生成测试外推。

随机费用须同时保存完整本地修饰列表和独立 RNG 五字段，重复相同结果也保留追加与取随机数次数。付款和原键消费当前分支，读取器只导入修饰对象；验证重复抽取、满手无抽牌、长列表恢复、两流独立、根在原生继续抽牌后不变。

施加修改必须先于 BeforeApplied 内部效果；已准备的外层 Power 直接提交，避免再次消费人工制品。状态域不创建某类 Power 时可只捕获根实例，但仍保存其消耗、退休和死亡清理，并验证首次／已有计数、零值与正增益。

牌组与战斗 Hook 必须按原版派发作用域分别审计；不能因战斗实例已迁移就放行牌组副本的同名覆盖。首回合已完成起手后的遗物不变性不能外推到回合推进，完整样例验证保留全部牌组、附魔、遗物及原生牌序，并明确夹具的实际边界。

通用伤害入口通过效果接收接口通知玩家死亡清理，Power 退休及死亡阶段仍由领域状态拥有；不要从 Engine 反向引用 Search，也不要将玩家塞入敌人清扫来复用调用。施伤者身份和分支存活值必须分开。

手牌末尾阶段须独立准入，并在冻结候选中保留准入配置；原生并行入场与串行效果不能合并推断。入场顺序从根合同显式传入，worker 不读取动画设置；比较原生真实阶段及出牌区，不能仅逐牌调用方法冒充原生调度。玩家死亡保留阵容，累计失血进入原评分，状态牌抽取进入原键；虚无消耗、伤害来源和待失败／终局一并恢复。

怪物指令扩展须从冻结静态参数编译，不在 worker 读取实机难度／意图；攻击者、无卡牌来源、空创建者及生物攻击计数分别表示。值执行、事件投影和原键共用伤害／历史合同；验证交错玩家生成、溢出抽取、致死结束门和冻结后实机继续推进。指令体原生差分不等于 AI 选择、状态机日志、怪物阶段或完整回合已经迁移。

将旧影子补偿迁入原生 Power 字段时，对已迁类型只保留一个写入权威；未迁类型的补偿边界单列。原键与续用共用语义字段分类，并检查持久路线键是否已隔离二进制版本，不能只修编码而遗漏应用入口或缓存所有权。

Power 阶段需独立整根准入，冻结配置随候选保存；回合初始量及跳过递减标志由同一撤销状态持有，读取器每次导入。清除格挡后的延期格挡不吃敏捷／脆弱，持续递减不走施加修正；临时力量先移除计数再由自身恢复。阶段体通过不等于回合身份、历史归零、AI 和起手已经迁移，新增监听器须同时审计普通与 Late 阶段。

确定性怪物 AI 的根准入先验证整个图并复制整数后继、当前索引和有序日志；不得从 worker 重读原生当前状态或日志。日志增长、当前招式与其他领域值共同撤销／冻结。每读取器一次准备各招式的旧 AI 记录，逐叶只导入值日志和意图，不调用 RollMove 或旧 AI 推进，也不让读取记录逃入保留候选。原生 PerformMove／RollMove 与旧驱动选择边界分开核对；日志条目的无语义投影须以实际消费者证明，不能为凑历史数量改变原评分。完整回合仍需阶段、时间与历史窗口的独立迁移。

完整回合驱动将回合、玩家回合、阵营、首次终局回合和清理标志纳入撤销状态。回合末 flush 不触发弃牌历史或 Sly；保留与临时 Sly 分别捕获，下一回合抽牌和 Tools 选择共用可暂停指令帧。完成读取器按提交的阶段标记恢复历史映射的根形状，再导入时钟与重置；只复用无 Hook 的历史记账方法，不执行旧效果，不逐叶 Fork。验证须覆盖非首回合、嵌套选择、历史归零、原键、首次终局及原生完整回合；准入必须拒绝未表示的玩家中毒和待抽牌，不能从阶段体通过外推所有回合闭包。中毒和持续时间递减共用直接数量写入，不消耗人工制品。

历史缓存的窗口须与原版相同，包含回合、阵营和玩家回合。不能只重置新阵营的参与者；续用文本必读字段在窗口切换时稳定建立零项，避免完成快照改变原键。根历史条目的匹配读取分支回合号，并以 live 继续推进后的冷缓存查询验证，不能因已预热缓存未变就断言后台不读 live。

完整计划桥接必须匹配正式卡牌状态键／出现序号及选牌 token 顺序；不能只按卡名或合法张数替代。完整根对照保留原牌组、附魔、遗物及起手顺序，并标明已核对的是所选路线和各前缀的已准入替代分支，不能冒充全搜索树验证。回合末最后攻击牌的本回合／上回合映射分别参与原键，提交点在手牌末尾后、终局检查前；原生状态或续用文本相等不足以证明原键相等。测试直接调用 coordinator／原生部署时，不将 NoGC 配置断言写成 Runtime GC 或全自动续用验收。

准入与模型适配现统一位于 `src/Prediction/Compact/`；纯值执行仍属于 Engine，估值／政策仍属于 Search，原生差分与计量仍属于 Testing。双端门禁只允许 Runtime/SearchBackendPolicy 选择已准入根、Search/CompactReplay 执行值状态；Testing 保留阶段探针。

紧凑候选接入阶段：只有主线程捕获的 `CompactCombatRoot` 可以通过 policy 注入；Runtime 每次扩大准入均需要完整闭包验收。每固定 lane 独占执行与读取状态，冻结候选只持有不可变值和根，不得持有读取器／祖先链。快照按需拥有的兼容图必须与权威值分开并一同释放；种子校验精确父候选。缺选择时冻结执行位置并按原挂起边界提交逻辑计数；请求与选项预览须由快照独占。比较完整路线、全部最终评分字段、展开／转移／选牌／剪枝计数；物理前缀恢复和兼容图数量另计。完整机甲搜索逻辑一致及 headless 加速只证明该已准入域，仍须验证原始亡灵完整输入与最终跨域 Runtime 验收。

同步政策读取使用独立 lane，不能将手牌／模型视图跨 iterator yield、子回放或后续恢复保留。当前能量、生命和阵容传给原合法性公式；其余字段只有闭包证明不变时才借用根上下文。完整搜索还须比较跨回合 `Continuations`。线程栈采样含等待，不能当 CPU 归因；优化后的兼容物化次数和相对旧后端成本必须重新记录。

挂起选择接入须共用原计划游标及业务无效分支异常，比较每个省略选择边界的完整评分、四种原键、请求与有序选项。选项预览不能引用可复用 lane；保留旧快照后逆序恢复验证所有权。回合开始选择完成前，AI 已推进而公开意图尚未发布，根当前值与根日志必须分开捕获。挂起出牌与挂起回合的洗牌计量提交点不同，维持旧逻辑；完成读取的稳定边界不能因新增挂起读取而放宽。

串行与并行须共享动作准备的完整顺序、去重、实例键与合法性；准备结果只持有独占动作元数据，不能携带可复用读视图。续用文本共享原编码，显式供应当前生物／牌堆／历史计数／RNG；其余字段的闭包不变性不能省略。验证完成搜索全部 Continuations 与每步完整文本；进程分配／CPU 增量包含游戏后台工作，结束 RSS 不是峰值，不能代替 Runtime GC 或可见性能。

Runtime/SearchBackendPolicy 独占主线程后端选择；初始准备、增量诊断和未迁移完整根明确使用模型后端。仅准入构造的 NotSupportedException 可作为后端不适用结果，执行／读取错误不得回退。完整原输入的取消／异常排空、DOP1/DOP2、原生整场部署和精确续用均须验证。区分普通 GC 下的 headless A/B 与真实 Runtime NoGC；当前机械骑士首次 NoGC 搜索耗时基本相当、分配减半，不能把普通 GC 的约两倍加速外推。最终预热交错 A/B 与亡灵完整域仍未完成。

资源／死亡扩展须核对选择中间态的原生顺序，不只比较动作结束值。阵营开始的一次性执行位置进入撤销状态，跨选择恢复不得重复施加；毁灭的双方相位与直接死亡历史分别验证。玩家新建负面能力的原生元数据按实际类型捕获，纯计数标记不等于持续语义。施加者窗口从值事件导入原键，旧镜像／规格只能保留一个权威效果入口；新增封闭类型不表示原始亡灵完整输入已准入。

宠物缺席也是根值：不能在分支未生成宠物时回落实时 Player.Osty。验证实机首次召唤后空根不变，以及从该空根独立生成身份。宠物不经过敌人死亡清扫，须在原生 AfterDeath 后清理普通能力并保留代伤能力；复活后的 Power／最大生命、完整续用和双方根隔离分别核对，不把宠物套入敌人复活 AI 阶段。

宠物在紧凑生物表中保留独立末尾身份，敌人循环通过明确上界排除宠物。派生宠物读取器只导入值并恢复根最大生命映射的缺席形状，不重放召唤／伤害／能力，不进入冻结候选。代伤 Hook 由精确状态感知 registry 独占，旧怪物路径不得以修改能力实例做补偿；未登记覆盖显式拒绝。

回合召唤量从根捕获为不可变配置，使用与卡牌相同的值命令。原生初始遗物在 AfterEnergyResetLate、抽牌及选择之前执行；暂停只冻结后续执行帧，不得恢复时重复召唤。验证每个省略选择边界的完整读取，并用原生选择前观察证明时点；战前首次创建和未迁移观察者不能因已支持回合召唤而自动准入。


抽牌堆选择的效果与来源须独立于牌堆位置：洗牌检索属于 Stratagem，卡牌消耗属于该牌的手动／自动来源。召唤指令完成后再挂起选择，恢复不能重复召唤；空牌堆不创建选择，单张隐式原生选择仍按正式计划核对。选中牌的消耗复用值牌堆事件及原历史计数，但不得借此执行 Sly／弃牌 Hook；可达消耗必须使存活牌集合估值缓存失效。原生两回合测试同时跟踪根身份和生成历史身份，不以卡名或 -1 合并怪物新生成牌。


随机生成牌的目标牌堆和插入位置由值执行器决定；逐张消耗捕获的 Shuffle RNG，空堆插入仍消耗一次，但不增加洗牌事件数。事件只保存目标／位置，模板从不可变实例定义解析，兼容投影不得再次抽取 RNG。X 次召唤保留逐次命令，不能折叠成一次倍数召唤；升级模板折叠须证明生成／升级观察者缺席。共享原生路线夹具核对根与生成身份、升级指纹、完整历史／续用及后续两回合，固定搜索仍比较旧新与串并行的完整结果。


终局前的生成历史与入堆必须分别建模：原生 AddGeneratedCards 在 IsInProgress 期间仍记录生成，而牌堆 Add 的 IsEnding 门禁拒绝插入；未入堆身份进入独立 Unplaced 值集合，不标记为已移除，不消费插入 RNG。怪物 AddToCombatAndPreview 另有存活接收者门禁，不能把两种生成入口合并推断。原生弃牌堆回收在结束后不请求选择，旧规格不得生成无法部署的伪选牌；直接生命损失保留原生伤害属性／来源，不计作攻击或受力量、格挡修正。
