# 在线服务维护入口

| 服务 | 权威源码 | 发布分支 |
| --- | --- | --- |
| 在线监控、跑局战绩、客户端版本提醒 | 本仓库 `tools/OnlinePresence/` | `main` |
| 在线问题日志、ZIP、筛选与归档 | 独立 `combatsolver-bugreport-service` 仓库 | `master` |

监控开发分支中的界面、筛选和启动恢复修复已经整合进主仓库。后续从权威分支维护；旧审查 worktree 只作历史对照。工作目录名或文件修改时间不能用来判断部署来源。

两个服务的部署目录均维护 `deployed-source.json`，记录仓库、分支、源码提交、子目录及同步时间。它描述源码部署，与监控数据库里的“最新已发布客户端版本”含义不同：服务文档或工具更新不代表 Mod 发布新版本。

监控运行与协议见[在线统计](ONLINE_STATISTICS.md)，界面见[监控工作台](ONLINE_WORKBENCH.md)。实际主机、目录与凭据位置统一放在维护者本机的 `combatsolver-online-services` skill 及私有定位配置；公开文档不复制连接配置或秘密。

线上同步只覆盖明确的源码文件，保留私有环境、数据库、问题包和运行环境。业务源码一致时，补齐测试/文档无需重启；依赖或业务代码变化才运行相关检查并重启对应服务。

每次下载渠道发布成功后，按 release-gate 的必做步骤维护监控系统最新已发布版本。版本维护失败须单独报告，不能把渠道成功等同于全部发布步骤成功。
