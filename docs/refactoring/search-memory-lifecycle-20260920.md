## 目标与边界

减少维持NoGC所需的恢复状态、异步等待和跨搜索所有权。成功标准是删减实际机制及依赖，不以拆分文件或改名充当完成。

当前三个相互影响的层次：

1. Search拥有候选、快照、缓存和在途作业；负责确定性提交与所有权释放。
2. Runtime提供内存准入信号，同时拥有进程级GC模式、后台收集与搜索外清理。
3. CLR与游戏/其他Mod共享进程。搜索的累计分配不是搜索独占存活堆，也不是物理内存占用。

重构先固定战斗语义与搜索策略。不能清除语义表、缩小候选或放大预算来制造性能收益；不能通过强制收集后的末尾快照声称降低峰值内存。对象池与写时复制只有在所有权和测量都支持时才考虑。

## 实施顺序

1. **诊断消融**：同一生产DLL，Windows静默弃牌和花园，分别启用当前NoGC策略、关闭NoGC使用常规CLR，ABBA独立进程；只改变开关。该消融不是交付候选。比较完整工作量、路线、完整等待、GC和内存，以判断当前策略的必要性。
2. **选择架构切口**：消融拒绝直接关闭NoGC。本轮先收口恢复与回收操作的所有权，删除重复状态和Search中的GC模式控制，并修复实际复现的失败完成链；没有将未经验证的对象池/COW或数值调参混入重构。主要模拟图分配仍是独立的后续问题。
3. **分阶段实现**：所有权迁移和策略变化分别验证。取消、失败、手动请求和旧搜索排空仍须正确终结，不能遗留等待链或可变分支引用。
4. **整体验收**：最终组合相对冻结基线做配对验证，既覆盖普通场景也覆盖高分支、长搜索和恢复边界；需要改变决策时另做广泛质量采样。所有失败、超时和退化都进入报告。

## 测量规则

- 同机器、运行时、完整Mod环境、原生开局与搜索配置；性能组独占执行，采样器与正式计时分开。
- 完整请求等待含准入、回调与必要同步；搜索后异步清理另列，不能转移到计时外后隐藏成本。
- 区分累计分配、搜索期间托管堆采样峰值、进程工作集/私有内存峰值及稳定存活集。比较必须处于同一生命周期阶段；采样不能冒充连续精确峰值。
- GC计数、累计/最大观测暂停与严格线程暂停分开。区域准入可能暂停但不计入累计GC暂停。
- 保留全部单样本与首尾基线；差异小于同版本漂移时记为未建立收益/退化，必要时有针对性追加样本。不能以统计不确定性证明绝对零退化。
- 质量包括战损、药水、成长、动作路线及完整非时序工作量。仅预计战损一致不等于整场原生部署验证。

## 实施结果

实现与本轮验收已完成，生产代码提交为 `1ed69101`。保留现有NoGC数值政策、恢复上限、后台收集方式、候选/评分/排序和搜索预算；未引入对象池或写时复制，也未声称解决主要模拟分配。

- `ExclusiveGcSearchScope` 拥有恢复退避与预算上限，以活跃scope身份拒绝过期回调；删除进程级恢复代号和预算状态。
- `ReclaimState` 值类型以Idle/Pending/Running统一持有完成源、运行任务、手动检查点加入任务与收集元数据；删除对应平行布尔/任务字段。手动与延后请求由可空完成源直接表达，不再双写请求布尔和任务副本。
- `SearchMemoryPressureSignal` 统一提交前恢复/准入、提交后回收与层预测的GC模式判定。Search只在排空并释放可重建图后执行信号返回的决定；`SmartLayerMemoryForecast` 保留纯数值预测。
- 回收启动与结束的诊断位于受保护操作内；完成源在最外层finally终结。诊断或恢复异常向等待者传播，不能留下永不完成的链；多个失败用AggregateException保留，不伪装成功。
