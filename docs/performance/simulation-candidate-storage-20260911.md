# 紧凑候选冻结、恢复与剩余瓶颈评估（2026-09-11）

[方案决策账本](simulation-strategy-ledger-20260911.md) · [原始样本与结果](simulation-candidate-storage-20260911.json) · [性能目录](README.md)

## 决定与范围

完成五项剩余评估的进入决策，并实现、验证第一批候选存储改动。保留不可变值页和同根工作区恢复：它显著减少封闭原型的候选分配，并避免反复复制未变化的长历史。**这不是生产搜索提速。** 新建工作区和密集写入存在退化，完整读取/估值仍使用旧模型投影，生产 Search/Runtime 未启用紧凑后端。

此前方案、失败实验、测量更正以及下一阶段进入条件统一记录在[决策账本](simulation-strategy-ledger-20260911.md)。本轮“评估完成”指逐项形成决策；未来完整 Power/RNG/死亡闭包、新后端 Beam 存活图和完整并行搜索仍需接入后验证，不能把结构探针称为这些验收通过。

## 已实现的所有权边界

- 工作区仍独占连续 `long[]`，撤销日志、暂停执行帧、选择实例和完整事件游标保持原语义。写入和 rollback 都失效对应 64 槽页。
- 冻结候选复制私有页表，共享已发布的不可变页。页中只有占用位图和完整非零 `long` 值；满页批量复制，空页共享，精确相等的缓存页可以复用。没有祖先差量链或 mutable worker 引用。
- `Restore` 在写前拒绝外根和活动 checkpoint；恢复时清除目标旧值，只重写失效或不同页。暂停指令属于可恢复槽，旧 checkpoint 令牌不会跨工作区续用。`Candidate.RestoreInto` 使后续消费者复用 lane。
- 页表和恢复扫描仍随容量增长。没有宣称 O(1) 长历史恢复，也没有截断游戏语义历史、修改原状态键或改变搜索额度。

## 长历史、写入密度和保留量

结构负载固定 1,024 个核心槽及 64 个尾槽；每条分支修改指定数量的核心槽，再追加一个历史值，并同时保留 128 个冻结候选。它不实现游戏 Power、RNG 或死亡结算；实际复杂效果仍由原引擎负责。

| 既有历史值 / 核心写入槽 | A → B 分配/128 候选 | CPU 变化 |
| --- | ---: | ---: |
| 0 / 8 | 1,121,280 → 106,496 B | −45.24% |
| 0 / 512 | 1,121,280 → 615,424 B | +51.80% |
| 0 / 1,024 | 1,121,280 → 1,197,056 B | +49.17% |
| 1,024 / 8 | 约 2,169,984 → 122,880 B | −83.05% |
| 1,024 / 512 | 2,169,856 → 631,808 B | +4.62% |
| 1,024 / 1,024 | 2,169,856 → 1,213,440 B | +24.74% |
| 8,192 / 8 | 约 9,510,143 → 237,568 B | −97.34% |
| 8,192 / 512 | 约 9,509,952 → 746,496 B | −69.21% |
| 8,192 / 1,024 | 9,509,888 → 1,328,128 B | −48.24% |

密集浅状态是明确反例：页表示不能一律优于完整数组拷贝。历史较长时，共享未变化前缀抵消更多成本；这仍不是对真实复杂战斗写入分布的估计。今后扩大后端支持面前，需要在实际效果入口测 dirty page 和真正首次写入比例，再决定密集表示/切换条件，不从借用次数推算。

8,192 历史值、8 槽修改的 128 候选共持有 **399 个不同非空页**，去重数据 payload **142,968 B**、各自页表 **148,480 B**；原稠密候选数据合计 **9,502,720 B**。页表已经占明显比例，不能忽略。统计不含对象头、对齐、根独占页、工作区和运行时堆余量，不能称为实测托管堆或 RSS。

真实生产保留图/GC 继续采用[P5 当前行为基线](simulation-refactor-p5-20260910.md)的直接证据：分配下降时 RSS 均值仍增加约 15%/19%，最坏 GC 暂停没有改善，B 最坏为 1,938.05 ms。本轮未测新后端的生产 Beam 图；没有增加 NoGC 预算来隐藏这项问题。

## 当前生产版本的 DOP 基线

复用 `2d7a837` 的已构建原生产后端，独占 headless 实例先预热一次，再 DOP8→1→2→4→8。沿用版本管理中的完整亡灵根输入，使用现有 Short 的固定工作量；无额外 Beam/节点/选择覆盖，每请求上限 120 秒。此处不与 09-08 的旧曲线直接比较收益，旧曲线早于后续调度改动。

| 1 | 13.8203 s | 1.00× | 0.99 |

五次均 Passed，比较的 **34 项逻辑/质量指标完全相同**：10,000 展开、147,282 转移、103,516 选择、评分 −4,268,054、投影战损 16、1 药；实际最大并发 DOP2/4/8 为 2/4/8。此次没有独立比较全部动作及逐状态等价，不能扩大这个断言。

平均用核来自每 50 ms 的 `schedstat`，包含 `.NET TP Worker` 和 Linux 截断名 `CombatSolver ex` 的 lane，按首结果断言阶段截取；包含边界误差，可能漏掉已退出线程尾段。DOP8 首尾漂移 −7.22%；相关线程 CPU 从 DOP1 约 13.74 s 增至 DOP8 约 22.64–24.35 s，调度队列等待约 0.19–0.22 线程秒，测量期间 GC 为零。DOP8 较快但累计线程 CPU 时间增加，仍有扩展空间；这不能未经新的 PMU 证据归因为内存带宽、缓存或伪共享。当前选择维持 DOP 与固定 lane 规则，下一读取迁移后再定位实际长尾。

## 正确性与整体原型的实际限制

最终 Release 构建 0 警告/错误。存储工具的七组容量合同与全部保留槽对照通过；原生 `COMPACT-KERNEL-NATIVE` 请求 **`ed3c059cd1a643b0aed19a65ab53597a` Passed**：34 叶完整状态/ContinuationStamp、原状态键、Snapshot 全属性、顺序历史及保留排序一致；同一 lane 依次恢复所有候选，8 worker 各自四次恢复同一暂停候选，嵌套撤销、下一动作续接、拒绝边界及原生嵌套链通过。

原生 fixture 保持正式通知隔离，并在 await/原生动作前释放；.NET 9.0.7，关闭分层编译，分段迭代 256。本次未附加 perf，原始阶段/模式计量一并归档。当前同进程参考：旧引擎约 **55.70 μs / 25,167.74 B 每叶**，含完整旧估值的紧凑模式约 **35.16 μs / 19,477.37 B**，纯内核约 **0.97 μs / 1,060.43 B**。完整参考约 **1.58×、分配 −22.61%**，仍远未达到 3×/分配 ≤20% 的进入目标；不同于上轮附加 perf 的上下文，不将二者时间差作为本次速度 A/B。

保留本批的理由是减少后续读取迁移必须承担的固定分配：当前同口径预热诊断中，Freeze 约 **917 B/叶**；若假设 RootFork 和 ProjectEvents 分配全部消失，其余仍约 **4,195 B/叶**，小于旧引擎 20% 对应的约 **5,034 B**。这只是扣除已测项的算术空间，还要计入新读取实现的实际成本，不能记作目标已达；完整 Snapshot 的 CPU 仍需优化。

剩余最大工作是完整估值直接读紧凑状态、保留唯一公式和原键编码，随后扩展真实效果闭包。本次没有把旧投影删除，没有新后端完整战斗、可见 Steam、Windows 或 10× 性能结论。两次 headless 实例均已按所有权停止。
