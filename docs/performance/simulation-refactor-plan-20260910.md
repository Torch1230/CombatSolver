# 完整搜索的模拟性能重构计划（2026-09-10）

[性能目录](README.md) · [采样基线](simulation-profile-20260910.md) · [基线数据与命令](simulation-profile-20260910.json)

## 目标与执行方式

用户要求先制定计划，后续开发由本任务负责完成。当前分支 `perf/simulation-profile-20260910`，行为基线为上游 `a6bc386` / `0.34.6`，采样证据提交为 `6f6d012`。本文件持续记录实施状态；诊断与方案取舍不表示优化已经落地。

目标是在正常极高配置下，减少完整战斗路线搜索的耗时、分配和长暂停，同时保持原有战斗语义与搜索质量。由执行者负责补证据、选择方案、实现、验证、撤回失败原型、更新记录与逐批提交。阶段转换按下文证据决定，常规实施不逐项等待用户确认。

每个实验结束都记录实际结果，不能为了完成阶段名而保留无收益实现。工作量是熟悉仓库的单人研发规模估计，包含验证，不是代理运行时间或交付日期承诺；条件阶段不预先相加为固定总工期。版本与发布仍按仓库现有发布规则及用户后续口令处理。

用户随后明确授权：局部优化有限时可以进行大幅重构，希望争取包括 10× 以上在内的大幅加速。因此后续不因所有权 API 或执行协议改造规模大而直接结束。10× 作为挑战方向，不冒充可实现性结论；真正的目标是显著减少正常完整请求耗时，仍须保持原搜索范围与战斗语义。模拟与 Fork 合计约 60% 的成本本身不足以支撑 10×，因此允许联动改造快照构造、状态表示与可恢复执行，但各因素仍分批验证、失败实现仍撤回。

## 固定约束

- 正式性能比较采用 VeryHigh、DOP8、NoGC 配置 16 GB，搜索完整战斗路线。沿用基线的完整牌组、附魔、遗物、药水、种子及政策，不覆盖搜索时间、节点、Beam 或选择预算，不以短搜结果替代正常搜索。
- 保持候选枚举、准入、保路、剪枝、评分、最终排序和逻辑预算。优化物理执行方式时保留原逻辑工作记账；新增复用计数与物理执行量另列。
- 保持牌序、RNG 状态与消费顺序、Hook 顺序、逐实例身份、死亡/召唤、能力移除与重新获得、选择事务和父子分支隔离。
- 单个可解释因素一批；纯所有权迁移与行为优化分开提交。沿用现有内嵌引擎，不并行维护两套权威战斗语义，不重新引入外部后端依赖。
- 已有卡牌预览 COW、历史前缀共享、监听分段、固定 worker lane 继续保留；无新证据不重复已撤回的缓存、容器和索引实验。
- 最小语义差分用于发现错误；完整正常搜索用于性能。增量验证如因边界改动而必要，只作为独立正确性检查，不在 headless 请求中开启。

### P1：补齐决策数据

优先复用已有 trace；缺少的数据只通过有明确问题的临时诊断补采。诊断请求仍使用完整正常配置，计数版耗时不当作无诊断基线。

1. 快照：沿 [StateEvaluation](../../src/Search/CombatBeamSolver.StateEvaluation.cs) 核对投影洗牌和其他纯派生组件的所有输入。记录计算次数、相同依赖再次出现的次数、失效原因，以及查询/维护成本。分别统计同一状态重复读取、父子分支和兄弟分支，不能用跨全请求无界缓存命中率代替实际可实施范围。
2. 归一化：沿 [PowerLifecycle](../../src/Search/SimulatedCombatState.PowerLifecycle.cs) 统计每个机制族的全扫描、实际写入、生成牌首次入场和能力变化。选择有明确写入入口、重复扫描明显的一个族。
3. 克隆：沿 [ForkPower](../../src/Search/SimulatedCombatState.Fork.cs) 按实际模型类型统计深克隆、映射命中、动态变量及其后续读写，区分调用次数、分配权重和 CPU 成本。记录最值得迁移的类型及依赖的原生/第三方克隆行为。
4. 选择：需要进入 P5 时，再测量不同选项之间的共同前缀长度及 CPU 成本；现有“完整状态 + 完整动作”约 2.52% 的历史重复率不能回答这个问题。

输出候选排序和否决理由。不能把快照 24%–28%、回合推进 20%–34% 或 Fork 14% 的整个占比都当成一个小改动的收益空间。

### P2：先实现一个快照组件

- 初始候选为投影洗牌相关派生结果，最终选择由 P1 决定。完整输入可能包括卡牌实例和顺序、当前状态/估值输入、Shuffle RNG，不能只按卡牌 ID 或一条粗版本判断相等。
- 缓存由真实状态所有者或单次搜索/worker 持有，容量有界，只保存冻结输入或不可变结果。分支变更必须可靠失效；无法观察的既有第三方可变输入使用原计算路径。
- 保持现有状态键值、字段追加顺序及稳定排序行为。不要以重构名义改变指纹组合算法，也不把计算移动到串行保路时才执行。
- 快照释放模拟器后仍可被父链读取，因此返回结果不持有用于延迟求值的可变模拟器。若只迁移职责，先独立验证该迁移；再加入复用。
- 正确性覆盖 RNG 不前进、牌序/牌值/升级/附着效果变化、父子和兄弟隔离、结果在源状态释放后的有效性。候选收益小于同期漂移则撤回复杂度。

### P3：按变化维护一个机制族

- 在现有结算调用点内检查该机制的变化标记，必要时处理有序待处理卡集合；不直接删除调用点。
- 首次根处理、生成牌首次入场、能力数量变化和移除后的清理各有独立责任。先证明这些事件如何到达维护入口，再缩小扫描范围。
- 修改观察器及 Fork 时，新增状态随分支正确复制；派生失效标记不加入战斗等价性键。
- 覆盖第一次处理前移除、从零获得、移除再获得、生成/变形、嵌套选择、跨回合及父子隔离。归一化总 CPU 约 4%–5%，若完整实现复杂而净收益很小，记录后停止扩大机制族。

### P4：减少 Power 模型复制

- 先选择 P1 显示成本高且状态边界能完整描述的类型，列出不可变定义、分支数值、内部计数、模型引用、获得顺序和派生显示数据。
- 先收口读写所有权，再引入小状态块或有写入屏障的共享结构。当前 [PredictionStateStore](../../src/Engine/Common/PredictionStateStore.cs) 的 `GetReadOnly` 仍会返回可变对象，不能在原 API 外面直接套通用 COW。
- 未迁移类型保持原有深克隆路径。类型相同不表示实例可共享；同类型多实例、移除重获和 applier/target 引用都必须保持身份语义。
- 原版克隆链包括 `DeepCloneFields`、`AfterCloned` 及 BaseLib 的窄并发保护。除非对应行为已被完整迁移和验证，否则继续调用并保留保护，不单独删除锁求速度。
- 迁移类型逐一收口到一个权威状态来源，不双写原 Model 字段和新状态。先以最小生命周期与 Fork 合同验证，再做完整搜索和必要的整场原生部署。
- 首批若没有明确 CPU 或分配/暂停收益，停止扩展到所有 Power、卡牌包装及全局对象表示；不能因为已投入较多工作就继续扩大。

### P5：有证据后才引入执行检查点

- 当前 [AdvanceRound / 动作回放](../../src/Search/CombatBeamSolver.Expansion.cs) 在 PendingChoice 后退出同步调用栈；选择补齐后从稳定父节点重放。[PrimaryChoiceReplay](../../src/Search/CombatBeamSolver.PrimaryChoiceReplay.cs) 负责并行暂存必经回放，不保存可继续执行的原调用栈。
- 只有共同前缀 CPU 足以覆盖检查点保存、Fork 和恢复开销时进入原型。先迁移一个明确的选择路径，记录阶段、监听器游标、局部上下文、历史边界、RNG 和待处理事务；不能把当前未完成事务强行视为普通可 Fork 状态。
- 新检查点必须拥有自己的完整复制合同。嵌套自动牌、付款、死亡处理及 AfterCardPlayed 的每个环节只执行一次，恢复后仍按原始选项顺序提交并消费相同逻辑额度。
- 同一效果的旧执行路径在迁移成功后收口，不保留两套结算逻辑。尚未迁移的路径维持当前稳定父节点重放行为。
- 无法形成窄而完整的检查点，或原型净收益不成立时，停止该阶段并保存原因，不自动扩展为全引擎重写。

## 验证与保留标准

正式场景沿用 P0：亡灵契约师 / AEONGLASS 的完整 38 牌、19 遗物、两药 RequireAtLeastOne 高分支场景，以及静默猎手 / 机甲骑士完整 30 牌含附魔的 Smart 场景。P0 的 CPU/分配请求带 profiler，作为热点与输入证据，不能作为新候选的无 profiler 速度基线。

每个有希望的候选先完成受影响边界的最小正确性验证，再冻结 A/B 构建。正式测量默认每版相同预热、独占实例，提前固定 `A–B–B–A–A–B–B–A` 顺序，分别完整运行两场；A 为进入该批之前保留的版本，B 为候选。最终集成与项目起始行为基线另作必要对照。没有新源码、输入变化或未解决问题，不追加同场景安心重跑。

- 记录完整请求及所有药水审计的耗时、搜索工作、worker 分配、每转移分配、峰值 RSS、GC 总暂停和最大暂停，以及完整动作、战损、药水、终局和重算。
- 同工作量时比较全部相关非时序指标及完整动作；计时、调度顺序指标和耗时派生 phase 分开报告。共享时间预算导致工作量不同的，显式报告差异及单位工作成本，不能只靠相同 HP 宣称等价，也不改变预算追求相同数字。
- 战斗语义必须通过对应严格差分。涉及 Fork/并行所有权时覆盖 DOP1/DOP2、取消/异常排空和后续复用；涉及跨回合与部署时补必要完整部署，使用 Instant / 0 秒并断言非预期重算。
- 判断收益时同时看交错配对结果、分布、首尾基线漂移与 GC。收益未超过波动且增加复杂度的候选撤回；显著分配下降可独立报告，不能直接称为提速或暂停改善。两场收益不能简单相加。
- Release 构建、受影响结构门禁及必要的覆盖检查随行为改动执行。职责变更同时更新架构地图、相关 skill 和双端结构规则；文档-only 阶段只做 L0。
- P6 在正常可见 Steam 会话验证最终候选，记录真实帧间隔与 Mod 栈。环境不具备可见会话时，继续完成其余工作并把这一项明确保留为未验证，不能用 headless 替代最终可见性能结论。

## 完成定义与当前交接点

完成条件是：P1–P5 的候选均有直接证据支持的保留/撤回/不进入结论；所有保留改动完成对应正确性与集成验证；最终报告给出实际收益、没有达到的目标及未验证项；任务改动分批提交，原型、profiler、游戏副本和完整日志不进入源码提交。没有预先承诺翻倍，也不以减少搜索范围换取时间。

P0、P1 已完成；[P1 直接证据](simulation-refactor-p1-20260910.md)否定本轮投影洗牌缓存的投入理由，P2 不进入该缓存。P3 的一个失效标记原型已通过最小验证，但无稳定提速证据且分配增加；交错序列遇环境变化及冷预热超时，完整记录后撤回，见 [P3 报告](simulation-refactor-p3-20260910.md)。[P5 测量](simulation-refactor-p5-20260910.md)支持进入回合检查点，纯职责迁移已提交 `1358179`，复制合同、原版差分、并行排空与完整 ABBAABBA 已通过，机甲获得重复配对提速及约 14.62% 分配下降，亡灵收益较小且 RSS 均值增加；P4 已确认可变 Model 借用、监听引用和 StateStore alias 必须一并处理，依用户追加授权继续做边界设计。可见桌面和 Steam 已由用户启动，最终保留改动仍需可见验证。每阶段结束更新实际证据，不把诊断、设计或单次快样本记作优化通过。
