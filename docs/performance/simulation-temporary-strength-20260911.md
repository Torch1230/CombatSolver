# 临时力量的施加顺序与封顶回调

基于 `2bded4a`。准备迁移尖啸时，原生对照确认现有生产实现有两处偏差：首次施加先加入临时计数、再改变力量，与原版顺序相反；计数封顶后使用计数净增量，漏掉原版仍会执行的力量变化。

`SimulatedCombatState.Apply<T>` 现在共用两个内部阶段：`PreparePowerApplication` 保留现有修正与 Artifact 拦截，`ApplyPreparedPower` 保留模型获得、数量／顺序及变更记录。临时力量在首次加入计数前执行 Strength；随后按原版「修正后的请求偏移不等于当前 Amount」条件再次处理力量变化。这既覆盖普通叠加，也覆盖首次创建就封顶时两个回调都执行的情况。两阶段不重复准备或消费 Artifact，普通 Power 沿用同一准备与写入。

临时力量增减入口只接受 `TemporaryStrengthPower` 类型族。计数与 Strength 的施加者、根实例退休／重获、监听顺序及回合末恢复仍由现有领域状态和 Fork 管理，没有引入新的并行状态副本。此项尚未把尖啸编译到紧凑指令。

## 失败基线与验证范围

- `fef5d0ebf0644f57b5609130953e5e0e`：原生尖啸首步严格差分失败，预测的 Power 序列先是临时计数，原版先是 Strength。
- `dda5db4530944fc4931c8fe1c26e6aae`：已有临时计数 `999999999` 时再施加 6，原版获得 Strength 6，预测缺失该 Power。

顺序请求包含两种原生根：尖啸普通版与升级版，覆盖已有力量归零后重获、无初始力量、Artifact 拦截；另以 `FlexPotionPower` 直接命令覆盖 +5、−2、−3 的增减与移除。比较每步所有固定敌人的完整快照、原续接文本与完整 Power 顺序／附加字段，子分支回合末恢复不修改父分支或根。

封顶请求包含两个根：已有计数封顶仍传递 +6 偏移；初始力量 −999999999、首次请求 1500000000，验证 `BeforeApplied` 与数量回调都执行。回合末直接调用原生 `TemporaryStrengthPower.AfterSideTurnEnd` 并与领域恢复对照。这是定向生命周期检查，不是完整药水使用或整场搜索结论。
