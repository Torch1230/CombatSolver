`PREPARED` 的37454次均有 `Adroit`，其中24365次唯一阻挡项就是附魔。`ACROBATICS` 的28981次有相同附魔，其中13514次仅被附魔挡住。所有观测负面附着均为 `Bound`。这说明“全部装饰一律排除”是保守初筛，不能据此断言这些路径不能续接，也不能反过来未经验证放行。

原版及当前镜像中，`Adroit.OnPlay` 在自身选择后获得格挡，可能触发后续行为；`Bound` 本体没有主要行为，逻辑位于 `ChainsOfBindingPower` 及出牌钩子，其Before阶段已可能写入 `BoundCardPlayed`。它们需要明确尾部与状态合同，不能靠名称视为无害。活动 `CardPlayPairPredictionState`、重复出牌也确实出现，仍应回放后备。

## 暂停点之前与之后

权威入口为 `CombatBeamSolver.Expansion.Replay` → 动作选择游标/卡牌执行死亡作用域 → `CombatPredictionSimulator.ManualPlay` → `OnPlayWrapper` → `ResolveManualCardChoice`。

暂停前已执行：合法性与资源花费（包括X值、能量/星能通知）、推入出牌trace、移入Play牌堆、计算结果位置及钩子、计算打出次数、BeforeCardPlayed、Power状态同步、写CardPlayStarted历史、RecordCardPlayStarted、卡牌OnPlay及领域效果补偿。卡牌Power应用作用域在自身选择前已结束。抽牌发生的洗牌、RNG推进、历史和间接效果都已属于前缀，不能续接时重做。

暂停后必须仍沿同一个权威实现依序执行：消费选择并应用弃牌效果；死亡检查；附魔；负面附着；CardPlayFinished；普通和晚期AfterCardPlayed；领域完成/生命周期通知；本次block归属清理；剩余重复打出；最终牌堆迁移/消耗；目标清理；CompleteCardExecution；搜索层死亡/Power边界结算、关闭选择事务、洗牌记账、胜负及强制结束回合、快照。不能只把弃牌之后的一段复制为第二套卡牌实现。

## 为什么不能直接Fork挂起结果

1. 当前未选择路径会执行AbortCardPlayed清理成对事务后退出。退出后的pending快照不是暂停前的事务状态。必须在Abort前建立显式暂停协议，且正常完成、挂起、取消、异常有明确不同的清理路径。
2. CardPlayStarted已写入历史。当前历史Fork封存并共享前缀，没有对活动出牌引用重映射。HasCardPlayStartedSince按trace引用相等查询，自动出牌和完成逻辑也有通过CardPlay.Card引用识别本次出牌的消费者。仅创建新trace或新CardPlay会把开始/完成拆开；共享旧CardPlay则会保留父分支可变Preview。
3. CardPlayPair、MusicBox、Imitation、PenNib等状态要求当前事务为空才可Fork。它们可能持有CardPlay、牌实例或成对金额，不能删除断言，也不能清空后假装恢复。
4. 当前自身选择点样本未观测到活动抽牌、延迟历史占位及待处理Power更改，这使窄原型有研究价值；不能外推到任意嵌套选择/第三方Hook。仍活动的trace、选择游标和外层执行作用域需要显式表示。

## 首个原型的具体合同

选择无附魔/负面附着、单次手动 `DAGGER_THROW` 自身弃牌点作为首个来源。它比无装饰 `ACROBATICS` 的初筛前缀分配更大，未观测到重复打出；预期节省仍很小（全部初筛前缀约整次分配1.12%）。首个原型用于验证机制是否值得继续，不能承诺10秒。

拟定暂停载体字段如下，尚未写入生产代码：

| 字段组 | 保存内容 | 恢复要求 |
| --- | --- | --- |
| 阶段 | AwaitOwnDiscard，成功后进入现有尾部 | 不再次SpendResources/Before/OnPlay |
| 本次打出 | 卡牌、目标、owner、resources、resultLocation、playIndex/count | 用同一PredictionForkContext得到分支引用，CardPlay重新建一次 |
| 因果与历史 | 本次trace、动作/打出/完成历史起点、活动出牌历史段 | 保存已完成共享前缀，复制活动段并重映射所有活动trace/CardPlay引用；索引及枚举顺序不变 |
| 选择与结算 | 来源/上下文/序号、选项身份、执行深度、已处理死亡集合、边界标记 | 分支独占；每项选择只消费一次，最后仍走现有settle |
| 生命周期 | 暂停状态所有者及待分支数量 | 兄弟可独立写入，取消/异常先排空再释放 |

原型应先把原OnPlay尾部提取成共享权威函数，再在选择前返回显式暂停结果；不要复制效果代码。新增暂停Fork API只能接受已验证载体，不放宽普通Fork。历史活动段中所有引用型字段必须先完成审计，不能仅重写CardPlayStarted一项就假定足够。

第一道验证是同根各合法选择的完整回放对照及兄弟/父/live隔离，随后验证弃牌间接触发新选择时的明确后备与清理。没有这些合同前，不接入并行生产搜索。若维护活动历史身份需要显著扩大改造，或无插桩净收益落入噪声，应停止这条窄原型并把时间投入外围Fork/快照等已测大项。

## 当前结论

调用链与最小载体设计已有具体依据；测量工具和可重跑对照已建立。尚无生产续接原型、分支隔离合同、DOP合同或正式性能A/B。#90最终合入与0.38输入兼容仍是接入前置条件。原估算2–4人日只可视为原先粗估，活动历史重映射审计完成前不能当成工期承诺。
