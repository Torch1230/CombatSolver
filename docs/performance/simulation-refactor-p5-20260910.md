## 进入原型的依据

此前完整动作缓存约 2.52% 的命中率不能回答“不同选择是否重复执行相同前缀”。本轮在原行为版本单独测量选择消费之前的线程 CPU，再实现可在已完成阶段恢复的回合原型。以下诊断数字是可考察的重复工作量，不是净节省或加速倍率。

诊断使用 Linux `CLOCK_THREAD_CPUTIME_ID`，每线程、每动作类型每 64 次采样，记录动作入口、Fork 完成、实际提供的选择被消费，以及进入下一玩家回合前的边界。自动固定策略选择不计入。各动作类型按 `calls / samples` 加权，避免稀有类型和最后不足 64 次的块按统一 64 倍放大。初步统一权重约 12% / 22% 的结论不变，正式数据采用类型内权重。

## 所有权与单一结算入口

`1358179` 先将回合推进迁至 [RoundLifecycle](../../src/Search/CombatBeamSolver.RoundLifecycle.cs)，玩家回合开始统一调用 `AdvancePlayerTurnStart`。纯提取保持原方法体、选择事务及回调顺序，Release 与结构门禁通过。正常完整机甲请求 `03bc4c371cb04593abef0f4098af2bb6` Passed，88 项逻辑字段及完整动作、回合结果、预测相同。这是结构验证，不是检查点收益证据。

检查点原型由一次 `BuildEndTurnBranches` 枚举独占，覆盖该动作的嵌套与逐实例选择；不进入 SearchNode、发布快照或 worker 全局缓存。只在前面阶段完成、游标为空且没有回调时，暂时分离该空游标，再调用正常严格 Fork。任何卡牌、Power、历史、伤害或待选择事务仍遵守原 Fork 禁止条件。复制后恢复同一游标，即使 Fork 失败也恢复。

冻结状态包括模拟器、同上下文重映射的领域对象、已处理死亡集合、洗牌数、回合索引及额外回合标记。每个后续选择从检查点正常 Fork，调用唯一玩家开始阶段，再进入原结算和 Snapshot；候选顺序与逻辑 Fork、转移和选择额度保持不变。额外的物理捕获、恢复以 `ROUND_PREFIX_REPLAY` 单独统计，不当作新逻辑转移。第一次完成阶段没有 `ToolsOfTheTradePower`、`TyrannyPower` 或 `MayhemPower` 时不建立检查点；这些是选择机制的资格判断，不是遭遇或质量政策特例。
