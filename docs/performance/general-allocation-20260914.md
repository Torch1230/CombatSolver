# 极高配置下的通用分配与重复工作优化（2026-09-14）

[返回性能索引](README.md)

本批从上游 `b1674f8`（0.38.2）继续开发，目标为极高配置中搜索超过20秒或进程峰值RSS超过20GB的场景，同时检查轻场景是否退化。不调整搜索预算、动作/选择枚举、评分、保路及药水政策；不改GC默认值，不重写模拟器。所有性能数字限本机Linux无头环境，不能外推Windows、可见帧时间或完整自动部署。

## 采用的改动及所有权

| 改动 | 省去的工作 | 保持的边界 |
| --- | --- | --- |
| 抽牌后选择前缀学习 | 实际观察到稳定点后选牌的lane，后续同父兄弟复用回合前缀 | 原ToolsOfTheTrade立即预留；其他来源第一次完整初探；不跨父/lane/搜索共享，原序消费全部预算 |
| 九条战斗RNG惰性物化 | 未消费流不创建原生Rng/内部随机对象；指纹/续用/投影只读状态 | 完整计数器及四段状态；已借出的可变流在Fork时立即捕获；真正随机操作仍为分支独占原生算法 |
| 卡牌首次进场检查位 | 每次Fork不再复制生成卡身份集；已检查的根牌省去重复HashSet查询 | 按wrapper标记，Fork继承、Clone重查；污染清除/层数更新仍每次归一化 |
| 冻结根集合与跑局监听前缀共享 | 根身份集不再Fork包装；精确根前缀不再逐项尝试无效重映射 | 根集合只捕获一次；仅精确根牌组CardModel/Enchantment前缀；Power及其他前/后缀继续重映射 |
| 均匀资源池省去祖先排名暂存 | 全池资源值相同且原本不产生独立资源路线时，不创建祖先字典或遍历父链 | 非均匀池保持原最高值群组、排名与恢复顺序；不修改GC预估和安全系数 |

前两项来自未合入上游的研究提交 `9307c39`、`f4cb0f4`；进场检查采用 `ed30d14` 的独立存储思路，并增加根牌也只查一次和根集合共享。未移植该研究提交的4GB GC窗口。适配当前上游时保留新增OnPlay配置的续用字段。所有源代码仅有局部所有权/重复工作变化，没有移动搜索策略职责。

根共享候选的独立计数探针，在亡灵契约师女王10000节点/每Solve内环记录：归一化访问69,902,521张牌，其中69,695,794次（99.704%）已经检查，197,091次为生成牌首次入场；404,985次根监听前缀复用省去16,604,385项无效映射查询。这是具体子路径工作量，不能把99.704%称为整搜提速或把探针耗时作为基准。

## 测量方法

固定生成器解析后的十个开局，涵盖五角色、女王多角色及不同精英/Boss。基线为 `b1674f8` 加相同的测试专用完整预算/NoGC回退支持；候选叠加上述生产改动。Writer仅在计时冻结后导出全部动作、路线与政策，测量期间无详细诊断、增量回放、采样器或并行构建/测试。

每次独立新进程，DOP16、原NoGC预算设置16（内部为16,000,000,000字节）。峰值为结果相同PID的Linux内核VmHWM，每250毫秒读取并保存Swap；包含建局。`totalElapsedMilliseconds` 是请求内各求解层总耗时，不含建局与求解器外准备；另保留请求内结果捕获时点，不能称为玩家点击延迟。禁止将累计分配或结束时WorkingSet写成峰值。

短内环为极高Beam135、分支72/42/54，显式Custom、每Solve10000节点、固定预算、90秒搜索软时限/120秒请求上限。先A1-B1-B2-A2比较前缀/RNG/生成卡检查，再追加C1-C2评估根共享两项；完整保留原单次样本和GC波动。

最终层在运行前保存十场A1-B1-B2-A2顺序，使用真实VeryHigh（Beam135、100000节点、分支72/42/54），`fixedSearchBudget:false`、原300秒搜索预算、独立420秒请求上限。设置文件中的旧Custom字段不决定VeryHigh预算，以导出的实际政策为准。这不是延长失败的120秒内环；所有TimeLimit和不等工作量必须保留，不能计算成等量提速。

比较器核对原输入、解析配置、配装、完整开局、实际政策、全部动作和逐回合路线，文本结果与结构化指标的所有未知字段默认参与比较。只排除明确列出的耗时/分配/GC/调度量，保留并发上限、质量和工作量字段；验证物理 `forks - round_prefix_captures == transitions`。源码/输入/GC环境与工具使用方式见[研究工具](../../tools/PerformanceBenchmarks/README.md)。

## 峰值反例后的局部修正

四项候选的完整交错对照中，蟹战耗时平均减少15.00%、累计分配减少20.68%，但峰值均值增加0.44%：B1为23.038GB，B2为28.633GB，基线两次为25.635/25.811GB。因此该阶段没有按“总优化逐场不退化”通过。

B2在最后一次大池剪枝前记录常规GC回退。此前一个单输入池的资源保路元数据分配48,616字节，成为整个搜索每输入高水位；按原1.5倍安全系数外推124,371个输入，预留约9.070GB，超过当时有效NoGC容量约8.593GB。代码核对发现，所有资源值相同的池本来直接返回空资源路线，但调用者仍先建立祖先字典、遍历父链和暂存/恢复排名。

独立短蟹战探针记录337次调用全部为均匀池，209,466个输入，297,433次祖先访问，暂存至恢复区间共6,992,848字节，单次最大102,976字节。该区域还含必要的资源最大值扫描及空结果分配，不能把全部字节都称为可消除成本。修正将同一最大值扫描移到暂存之前，仅省去无消费者的排名操作；不缩小GC预估或安全系数。

新增D1-E1-E2-D2短对照保持30000展开/310709转移及全部动作/路线。旧四项候选平均16.697秒、14.303GB分配、12.356GB峰值；新候选16.137秒、14.276GB分配、12.383GB峰值。耗时下降3.35%，峰值均值上浮0.22%但仍在旧样本12.300–12.412GB范围内，此内环不单独证明内存收益。BYRDONIS哨兵7.105秒、6.528GB峰值，完整oracle相同；完整极高结果用于最终取舍。

最终F1/F2蟹战的该进程日志均没有出现上述GC预留失败回退，但峰值仍有22.028/26.600GB波动。F2结束时托管堆24.870GB、碎片16.242GB、托管live9.260GB，F1托管堆9.335GB、碎片0.273GB、live10.572GB。这说明不能把较高RSS直接等同于保存了更多分支，也不能仅凭结束时碎片量确定是哪次GC/NoGC建立造成峰值；本批不据此削减内存安全余量。

原矩阵BYRDONIS均值耗时+1.79%的疑点另按预定B3-A3-A4-B4顺序复核。四次/版本合并为基线7.312秒、四项候选7.272秒，差异未形成稳定退化；全部原样本均保留。

## 正确性与失败记录

- 九条RNG：原生整数/浮点序列、完整内部状态、保留父引用继续推进、兄弟/多代Fork、冷读取不物化及live不变。
- 前缀：首次发现与原立即预留、全状态/历史/续用/洗牌、父子兄弟隔离；DOP1/DOP2完整动作/工作/非时序字段一致，真实并发、取消与错误排空。
- 根共享：根牌与生成牌的Clone/再次入场/污染层数；精确根监听前缀顺序和身份、可变Power remap、卡牌变异与多代Fork。具体runId与复跑输入见[测试矩阵](../TEST_MATRIX.md)。
- 资源保路：空池、均匀零/非零池及非均匀最高值并列，独立旧实现逐项核对选中身份/顺序与全图排名，覆盖共享祖先和全局重叠；live不变。夹具先修正旧反射参数数量及零资源初始化，失败记录均保留。
- 原完整亡灵契约师女王在120秒内环超时，缺失结果，内核峰值21.796GB；不计算提速。两个最小夹具先行失败分别由于敌人过早死亡和缺少技能牌，修正输入后覆盖对应断言，原失败仍保留。

最终正常Release构建0警告/0错误，比较器10项单元测试通过，Bash/PowerShell启动器语法检查及最终双端结构门禁通过（`search_files=90`）。没有为测试/发布替换正式游戏安装中的DLL；本批为普通开发提交。
