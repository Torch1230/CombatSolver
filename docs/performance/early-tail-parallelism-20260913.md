# 回合尾部提前计算（2026-09-13）

本轮在普通Power克隆优化 `461f528` 上单独比较提前EndTurn的收益。生产只改变已准入父节点内的派发时机与结果所有权，不增加搜索预算或父节点窗口。

## 理论空间与实现范围

修改前的[理论估算](power-clone-parallelism-20260913.md#任务调度与回合尾部)使用冻结作业时长、忽略依赖、16个lane满载的条件模型：整个展开调度窗口最多省4.5069秒，占该诊断总耗时17.90%。它不是这次Tail改动可保证的收益，也不能与Power的17.51%模型相加。Power落地后锁等待和作业耗时已经变化。

初始卡牌/药水全部派发后，EndTurn可与尚未完成的兄弟动作或选择链同时计算。worker沿用同父Fork gate取得独占分支，结果和待命基线暂存在独立批次中。coordinator等同父全部工作完成后，才按原序移交尾部快照并发布基线；所有权移交失败显式抛错，取消和异常先排空lane，再释放未消费批次。父节点和候选的最终接受顺序保持原规则。

这没有拆开一次EndTurn内部的依赖，因此不能消除所有长尾。原序提交、内存预约和选择预算仍会限制并行利用率。
