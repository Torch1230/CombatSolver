# 紧凑完整回合与历史窗口

单个机械骑士的完整回合现在可在紧凑值状态中执行：手牌末尾、保留与 flush、卡牌清理、双方 Power 阶段、敌方中毒、当前招式、AI 后继，以及下一回合能量、抽牌和选牌。仍仅由 Testing 准入；生产搜索尚未切换后端。

`CompactRoundLayout` 将回合、玩家回合、阵营、首次终局回合、已开始阶段与卡牌清理标志保存在同一撤销工作区。冻结候选保留不可变布局，不保留旧模型或读取器。玩家回合号与全局回合分别捕获，终局在安全检查点锁定，敌方开始的中毒末击不会多算一个玩家回合。

flush 只移动未保留的牌，不产生弃牌历史或触发 Sly。永久 Sly 与单回合标记分别捕获；清理后单回合标记失效，回滚后恢复。下一回合使用无卡牌身份的执行帧，复用抽牌、洗牌检索、Tools 弃牌与嵌套自动牌的暂停位置；起手抽牌事件单独标记，嵌套 Prepared 的抽牌仍属于普通抽牌。

每个完成读取器准备自己的历史映射存储；依据阶段事件恢复根形状、导入时钟与重置，再由事件得到当前计数。这里只复用无 Hook 的历史记账，不调用旧卡牌、Power、AI 或回合效果，也不逐叶 Fork。Power、AI 和卡牌读取绑定继续单向导入值，原 Snapshot、状态键和评分公式共用。

## 原生对照发现的两个语义问题

1. **中毒递减与人工制品**：紧凑触发原先将中毒减一送入施加减益的修正入口，会错误消费已有人工制品。原版 `PoisonPower.Trigger` 使用 `PowerCmd.Decrement`。改为直接提交数量递减；原生完整回合覆盖中毒和人工制品同时存在，数量与生命周期逐步对账。
2. **历史窗口跨阵营**：旧引擎与紧凑投影最初在中毒终局上相等，但原生续用字段 `Y` 为 `0/0/0`，两种模拟均为 `3/0/0`。原生 `HappenedThisTurn` 的窗口包含回合、阵营及玩家回合；旧缓存仅按参与者清零，保留了上一玩家阶段的状态牌抽取。生产 `SimulatedCombatState` 现统一在窗口改变时清理派生历史缓存，续用必读的三个计数显式归零，避免读取续用文本再改变已计算的键。根历史匹配改读分支玩家回合号，避免原生方法读取推进后的 live `PlayerCombatState`。

Power 自身的回合字段、技能触发标记、累计失血和上一张攻击仍遵循各自生命周期，没有把所有状态一律清空。原生历史方法的源码用于界定窗口；最终结论来自原生结果，而非仅旧／新模拟相等。
