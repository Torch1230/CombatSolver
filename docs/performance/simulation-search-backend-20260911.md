# 紧凑状态接入搜索候选：2026-09-11

本阶段把已通过原始 30 牌完整原生路线对照的值状态接入现有搜索。`SearchPolicySnapshot.CompactRoot` 默认空，仅 `COMPACT-SEARCH-BACKEND` fixture 在主线程捕获并注入；Runtime 尚未选择它。原始亡灵契约师输入及完整支持闭包仍未完成。

## 所有权与执行

- `Prediction/Compact/CompactCombatRoot` 捕获模型闭包、初始冻结值和共享根；旧根 Fork 的 COW 发布用窄锁保护，不锁事件解码、完整回放或搜索。
- 每个固定搜索 lane 独占值工作区、计划解析与完整评分读取器。完成动作直接冻结值，调用同一个 `SnapshotCore` 和原状态键编码；候选不持有 lane、读取器、模型池或祖先链。
- `SimulationSnapshot` 拥有冻结候选；旧政策确实读取模型时才创建并缓存派生兼容图。该图不回写权威值，`ReleaseSimulator` 同时释放两个引用。`HasSimulator` 此时表示快照仍拥有可用状态，不能拿它统计物理旧图数量。
- 并行 `ReplayForkSeed` 可以移交不可变候选和私有死亡集合；成功紧凑回放不创建旧 Fork。挂起候选也直接消费 seed 并保留精确选择请求。
- 缺少计划选择是明确挂起边界，现直接冻结选择帧、资源／牌堆及事件；专门的 `ReadPending` 共享完整评分，快照拥有请求和当前来源牌的私有预览。计划消费共用原 `TurnStartChoiceCursor` 和业务无效分支异常。完整回合的紧凑分支不实际恢复旧回合前缀，因此物理前缀计量不伪装成逻辑预算。
- 完成快照没有选牌请求时，两处 primary-choice 检查不再读取旧图。候选纯效果判定读取事件派生的最后非纯历史索引，保持旧四种纯历史类型的定义。

## 后续：同步政策读取脱离兼容图

15 秒 .NET 线程栈采样窗口覆盖紧凑搜索后段，样本中的搜索线程时间约 58% 位于兼容物化调用链；其中无进展检查约占全部搜索样本 29.4%，动作准备约占 26.5%。这是包含等待的 sampled-thread-time，不能写成 CPU 占比。采集首次使用了只适用于 collect-linux 的 profile 名，工具拒绝后，在同一次仍运行的搜索中改用 dotnet-sampled-thread-time；原始 trace 留在本地。

新增独立的每 lane 政策读取器，只有同步动作准备、药水槽读取、跨回合抽牌数判断、父节点遗物与目标判定借用；不让读视图跨 iterator yield 或子回放存活。手牌／费用／当前阵容来自冻结值，仍调用原 `CanPlayCardAtResources`、抽牌修正和 `IsHittable` 公式。旧目标公式只提取生命／存在性输入，其他领域合法性保持同一实现。该闭包没有 Enthralled、宠物、未准入的生成类型或未表示的可出牌 Hook，不能从这些模型的读取外推到新闭包。

构建 12.32 秒，零警告／错误；`427def306b9748988a4088c10646bb4c` 通过。同一原完整输入的 44 步路线、全部最终快照、全部续用状态及主要逻辑计数一致；111,401 次完成回放、22,654 次挂起回退保持不变，兼容物化降至 22,385 次。headless 搜索 13.897 秒对旧后端 12.804 秒，根准备 52.9 ms。初始接入的性能回退已大幅收回，但尚未得到相对旧后端的加速；后续迁移挂起选择，Runtime 默认仍不启用。

## 后续：挂起选择也保留紧凑状态

缺少选择不再重放旧引擎；冻结帧保留挂起点，选项只复制当前来源实例的预览，避免搜索政策保留 spec 时被后续 lane 恢复覆盖。完成读取仍要求 Complete，新增 ReadPending 只接受同根 NeedsChoice。回合开始选牌时 AI 已前进，但公开意图要到准备结束才发布；读取分别导入，空根日志或日志末项不等于根当前招式时也保留准确前值。挂起出牌不提交洗牌计数，挂起回合按原正常抽牌提交，主要逻辑计数保持原时点。

`72142ef230eb491788246c5ec6e22fca`（8 worker）和 `56b4397ddc4c44e7bcdd09365e20db88`（单线程）均通过原始完整 30 牌 A/B；各自旧／新全部路线、评分、SolverSnapshot、Continuations 和既定逻辑计数一致，实机保持不变。每条选牌前缀另有 9 个省略选择边界的完整评分／原键／请求／有序选项差分和冻结逆序恢复；单线程最终产物还断言每个有选择动作的错误来源由两后端抛出相同业务异常。
