# 性能优化正式 PR：当前上游验收（2026-09-15）

本批完成通用分配优化、生成池与抽牌前缀复用，以及41张原版单人卡、9种手动选牌药水、回合来源和嵌套执行的三阶段续接。当前整合基线为上游 `cd66b1d`（0.38.6）；这份报告单独记录合并后的验证与整批对照，历史分阶段收益不相加。

## 最终实现与评审入口

- RNG 未访问流共享不可变状态，已访问流在Fork时捕获；卡牌首次入场检查按wrapper保存，冻结跑局监听前段精确共享，均匀资源池跳过无消费者的排名暂存。
- 原生角色生成池按已核对的过滤规则冻结有序候选；回合抽牌前后稳定前缀复用保留原RNG、来源顺序和预算。
- 41张卡牌与9种药水的自身选择共用唯一结算入口；已适配的回合、抽牌、自动及重复子出牌保存纯数据帧，可以继续遇到选择并再次挂起。
- 同一Fork context重映射卡牌、CardPlay、历史、trace、Power来源和死亡集合；选择层/frontier持有检查点并在工作排空后释放。未知派发、历史或不透明事务继续原完整回放。没有保存CLR栈、Task或闭包。

原生逐字段、父子与兄弟隔离、DOP、取消/异常和全部来源合同见[三阶段实施记录](choice-continuation-expansion-implementation-20260914.md)。早期通用优化见[首批报告](general-allocation-20260914.md)，生成池与抽牌前缀见[后续报告](crab-latency-20260914.md)，三牌独立原型见[原型报告](choice-continuation-prototype-20260914.md)。这些是各自源码与输入的历史证据，不能当作当前上游的重复验证或累计百分比。

## 后续追加：派生计算与路线界面复用

用户随后授权继续完成成本较低、有实际收益的复用，并更新同一PR。此轮从PR已有的 `3d067f0` 出发，最终保留路线行复用和相关语言通知修复；投影洗牌缓存完成实验后撤回。追加提交没有Search、Engine或Runtime行为差异。

- **UI行复用**：同语言、完整动作显示值和本地化身份一致时，保留该行胶囊。新捕获的数组仍按值比较，选牌、目标、重放、遗物、击杀、tooltip和未来语言刷新身份均参与判断；变化行完整重建。每次Populate仍重置部署高亮，回合指标和Runtime最新采用路线照常更新。状态页清空上一快照，主题沿原整层重建。
- **已撤回的投影洗牌实验**：16个有界槽位属于当前run/lane，键核对牌数、RNG计数器和四段状态。缓存仅含整数交换位置，不保存卡牌、排序结果、估值或可变RNG；仍逐次执行原Sort、完整牌状态指纹和价值计算。超过4096张旁路，内存检查点清空，worker交回时只排空计数。最终源码不包含该缓存、计数或接线。

UI合同还发现并修正同帧语言往返的通知遗漏：中途新建的控件可能显示中间语言，而合并通知因最终语言等于上次语言被跳过。现在仍每帧合并一次通知，但无条件刷新届时存活的已登记控件，退出树照常解除登记。

### 界面局部测量

同一无头游戏、16个纯文字动作（无卡牌本地化身份）加1个回合开始选牌的合成单行，连续64次不变刷新。原实现两份样本为1522.846/1498.795毫秒，托管分配3,048,336/2,455,600字节；交付源码为0.208/0.139毫秒，各48字节。候选使用预先捕获的64份同值新数组，原基线重复同一快照引用。计时不含初次构建、输入快照生成与下一帧的延迟释放；实际Godot控件身份合同另含完整卡牌本地化身份，证明同值行不重建且变化时失效。这是局部工作消除，不能换算为FPS或整搜提速。

洗牌微基准中，热命中每20000次投影消除1,600,000字节的RNG构造分配。12张牌耗时未建立稳定改善，64/128张局部投影更快；排序、指纹和估值仍存在，不用这份微基准外推整搜收益。
