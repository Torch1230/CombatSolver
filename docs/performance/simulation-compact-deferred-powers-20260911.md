# 紧凑下回合计数 Power

基于 `ef1b96f`，在已修正的生产格挡返回值规则上，紧凑执行新增闪躲翻滚与必备工具计数。当前编译器准入 25 种精确卡牌，生产搜索仍使用原后端；本阶段没有整场性能结论。

## 值与执行

`BasicPowerLayout` 增加 `BlockNextTurn`、`ToolsOfTheTrade` 两类计数；适配器只为玩家增加这两槽，不为每个敌人增加空槽。数量、施加者、获得顺序与根槽退休沿用既有值布局，读取模型仍在每 lane 初始化时准备。

`GainBlockAndApplyPower` 指令先计算并增加格挡，再把同一次命令的修正后返回值按原生 Power 规则转整数施加。它使用完整返回值，不使用封顶后的净增量；当前已准入 Hook 不会在两条命令之间挂起。ToolsOfTheTrade 施加或叠加自身计数，完成后作为能力牌移除。完整 Snapshot 与原键从当前值读取计数与移除集合。

当前 Power 布局以零表示不存在。原版 `PowerCmd.Apply` / `PowerModel.ApplyInternal` 在正小数小于 1 时可能创建零层实例，因此整根准入检查玩家脆弱及当前／后续可达敏捷区间：有一次格挡返回可能为 `0.75` 时，执行前明确拒绝。区间是保守包络，可能拒绝部分实际上无法组合达到该点的合成输入；没有跳过候选或把零层实例当作不存在。原始机甲非负敏捷输入不受该限制影响。该边界的依据是原版源码和纯值拒绝合同，未把它算作零层实例的原生成功覆盖。

- `COMPACT-DEFERRED-POWERS-NATIVE`：三个原生根分别覆盖上限、已有下回合格挡、零返回；每根添加普通／升级必备工具，合计 16 分支和十次原生出牌。逐前缀比较完整 Snapshot、原键、Power 元数据／顺序、来源历史、九条 RNG、缓存开关、逐槽撤销及八工作区独立重算。
