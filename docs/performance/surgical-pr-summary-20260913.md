# 精简性能 PR 累计记录（2026-09-13）

大量选牌与跨回合搜索会反复构建分支、查询历史、排序和等待已准入父节点；小内存区域还可能被整段剪枝预约及过大的父节点冷下限限制。本 PR 在既有模拟器中削减重复工作、分配和并行等待，并纳入独立预测修复。保持搜索预算、评分、候选规则、RNG、完整路线语义与原序提交，版本保持 0.36.4 开发中。

本文是 **整个 PR 的累计记录**：覆盖从上游 `eff8cf4` 起的所有已采用优化、已测但撤回的方案、中间候选、性能研究与失败验证。后续更新在对应条目补充，不用最新实验覆盖前面结果。

## 阅读口径

- 下表时间变化统一指**耗时**，负数为减少，正数为增加；不是吞吐百分比。每轮有自己的基线，**不同轮次、不同场景和不同环境的百分比不能相加**。没有上游对最终组合的一组统一测速。
- 游戏性能证据均为 Linux 无头。机甲通常为 normal VeryHigh / DOP8，早期亡灵为 Low + FixedBudget / DOP8；瀑布巨兽为正常 VeryHigh / DOP16，盛碗虫群为诊断固定工作量 / DOP16。具体输入、预热、预算和原始值见每行报告与 JSON。
- **早期无头环境没有加载 BaseLib**，包括父节点预约约 27% 的结果；卡牌/Power克隆及提前尾部的最终对照才实际加载 BaseLib 3.4.7 / Ritsu 0.5.20。不能借旧环境证明完整 Mod 栈中的克隆提速。
- 累计 worker 分配、进程累计分配、GC 后保留堆、端点工作集、采样峰值 RSS、GC 累计暂停、最大暂停是不同指标。原始 JSON 保留已取得的单样本耗时、分配、各代 GC、暂停、内存端点/峰值、并行调度字段、runId、工作量和完整参考路线；缺失或不可比较的指标不补造。
- 多数正式 A-B-B-A 每实现只有两个样本。基线漂移、配对反向、回退和失败均保留。没有可见 FPS、帧时间、Windows 长驻进程整体收益或全牌组结论。

### 先于实现给出的条件估算

Power模型假设每次锁成本相同、候选均通过，候选锁内工作约4.794秒；再假设全部位于串行关键路径且理想16并行，可省4.494秒，约总耗时17.51%。关键路径比例假定25%/50%时分别为4.38%/8.75%；**不是收益下限、置信区间或严格上界**，实际落地独立对照为2.04%。

调度模型保持原作业耗时不变并忽略依赖：179.813/16=11.2383秒，较15.7452秒窗口最多省4.5069秒，即该诊断总耗时17.90%；它覆盖整个展开调度空间，不能全归给提前Tail，实际Tail单独为1.42%。同父Fork等待除16得到0.8071秒仅是线程容量当量；原序提交1.1298秒约占4.49%，也不能删除。以上相互重叠，不能相加。[推导及假设](power-clone-parallelism-20260913.md)

仅研究、没有实施或完整测速的候选：小类型内联计数、字典ref更新、分组统计进一步复用、deferred top-k、通用增量指纹/全局共享、牌堆位置缓存、整牌归一化短路、额外关键词路径、完整角色生成池迁移、JIT/PGO调整、批量内联、窄布局/SIMD/手写汇编、GPU与NativeAOT。现有缓存已覆盖的路径不重复算收益；top-k同分顺序、分支失效、值域和动态运行时边界未解决，不能把“研究过”写为“已优化”。

旧大分支的Compact、第二执行器、回合阶段迁移及其历史加速数据**不属于本PR新增成果**；已有上游优化随基线保留，不重复移植或累计收益。[范围审计](surgical-fixes-20260912.md)
