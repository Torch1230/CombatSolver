# 紧凑卡牌生命周期与 X 费用（2026-09-11）

[性能目录](README.md) · [有序指令阶段](simulation-effect-program-20260911.md) · [结构化证据](simulation-card-lifecycle-20260911.json)

有序指令扩展到能力牌移除、X 费用与消耗。新增 `FOOTWORK`、`MALAISE`、`SUPPRESS`、`ULTIMATE_DEFEND`、`FINESSE`、`STRIKE_NECROBINDER` 和 `DEFEND_NECROBINDER` 的准入，原有七种卡牌继续共用相同执行器。12 个组合分支、八工作区和九步原生出牌通过；完整原输入及生产搜索接线仍未完成。

## 权威状态与读取

每张卡牌定义明确费用形式与结果位置。付款时的 X 值写入卡牌值槽，并保存在执行帧资源中；后续指令使用该值计算正负 Power 数量，不能读取已花光的能量。卡牌退出时提交结果移动事件，分别进入弃牌、消耗或移除集合。移除集合不属于战斗牌堆，仍保留根实例句柄供历史和撤销使用。普通移动与消耗遵守结束门；原生 `RemoveFromCombat` 没有同样的结束门，按对应命令处理。

Power 指令现在明确归属和数量表达式，支持当前域的力量、敏捷和敌方虚弱；只允许常量及付款 X 的正／负倍数。新建玩家虚弱、易伤和脆弱仍未准入，避免未经迁移的乘区顺序进入执行。`FOOTWORK` 施加敏捷后移除自身，`MALAISE` 依次减少目标力量、施加虚弱并进入消耗堆；升级修正及零 X 按原版执行。

`CompactCardMetadataReadBinding` 在读取器初始化时取得独占卡牌预览，完成读取时仅导入 X 值与移除标志、失效相关缓存。它不执行命令或 Hook，不逐叶克隆、不回写程序、不进入冻结候选。普通牌不会读取或设置仅限 X 牌的属性。原生逐实例额外对账覆盖这两个字段；卡牌从活动牌堆离开并不等于删除历史身份。

消耗次数通过 `CardHistoryReadValues.Exhausts` 进入既有状态键编码，保留根历史缺席和显式零值的区别。卡牌集合或元数据可能变化时，完整 Snapshot 旁路卡牌／策略摘要缓存；相同原公式继续用于所有评分属性。`CanPlayAtResources` 的 X 费用改为使用调用方提供的资源池：旧完整模拟传入自身当前资源时行为一致，完成读取可使用新分支资源而不修改评估上下文。此次原生覆盖的是能量 X；星能 X 未另设原生场景。

风险记录保留旧 registry 的 `MethodNotMirrored` 与 `MethodMirrorIncomplete` 区别及补偿分类。读取器按实际遇到的组合缓存规范化结果，替代预建全部子集和四种来源的上限；本次根含六种来源。每个读取器独占缓存，不改变风险条目数量、原排序或状态键。这个容量扩展不构成未知效果准入，卡牌类型与 Hook 仍必须通过根审计。
