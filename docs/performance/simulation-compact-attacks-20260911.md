# 普通攻击与紧凑死亡状态（2026-09-11）

[性能目录](README.md) · [生物值读取基础](simulation-creature-values-20260911.md) · [原始证据](simulation-compact-attacks-20260911.json)

紧凑程序已实际执行单目标「打击」、消耗格挡、生命损失、主要敌人离场与永久死亡记录，并能连续打出最后一击。18 个分支、完整评分／原键／历史、八个独立执行与读取工作区，以及原生五步击杀链通过。生产搜索仍使用原后端；这批结果不代表完整原输入已经迁移，也没有新的整场加速结论。

## 状态与读取

`CreatureAttackLayout` 仅保存不可变槽位布局。玩家和敌人的生命／格挡／在场状态、死亡完成标记及终局标记都属于 `ReversibleValueState`；候选共享布局和不可变值页，不持有模型或模拟器。执行帧保存目标，事件记录保存目标、格挡／未格挡／过量伤害及三个结果标志。原基础算术仍由 `CreatureVitals` 提供。

`CompactDiscardProjection` 通过显式 `includeAttacks` 准入。当前攻击域要求存活的主要敌人、没有敌方 Power 或宠物、没有未迁移的攻击／伤害／死亡 Hook。既有抽弃牌域仍按自身能力准入。目标合法性在付款前检查。值执行期间不调用旧攻击或死亡命令；旧投影只解码已提交结果，构造伤害与攻击历史，并写入最终标量、阵容、生命周期和终局。

完成读取增加攻击次数、零费用攻击开始、伤害命中对、受伤集合、上一张攻击和死亡阶段，保持原键的编码及缺席／显式零项。通用编码仍使用具体容器的值枚举器，避免给生产路径增加接口装箱。技能计数不再将攻击当作技能。

每个读取器创建一个独立的旧根副本，供未迁移但不变的公式与临时工作对象使用；原有历史初值的隔离副本仍保留。它们属于每读取器初始化成本，不是逐叶投影，不进入冻结候选。根副本中的可变临时对象不能在多个 worker 间共享。

最后一击须保留原版时序：`IsEnding` 成立后，卡牌移入弃牌堆的命令被拒绝，末击卡暂留出牌区；结束标记由完整动作之后的 `CheckWinCondition` 锁定。已结束状态禁止再次开始动作，撤销和恢复同时还原目标、牌堆、生命、阵容与终局。

## 性能口径与后续

本批没有进行整场原输入 A/B，也没有调整 Beam、额度、排序、药水政策或 DOP。附带洗牌探针使用进程默认分层 JIT，旧路径线程 CPU 从 234.43 降至 51.31 微秒／叶，新路径含准入从 82.69 降至 16.94 微秒／叶，阶段间编译变化明显，因此不据此计算新增加速倍数。完整样本保存在 JSON。新路径含准入的分配约 6,128–6,161 B／叶；这是该洗牌夹具的成本，不是新攻击场景或生产 Beam 的存活量。
