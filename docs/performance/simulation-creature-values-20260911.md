# 生物值与完整估值读取（2026-09-11）

[性能目录](README.md) · [前置可增长工作区](simulation-growable-state-20260911.md)

这批迁移基础生命／格挡算术及完成状态的生物读取，为紧凑伤害执行提供共同基础。生产引擎持有同一纯值算术，生产搜索仍执行原命令、Hook 与生命周期。没有新增完整搜索加速结论，伤害命令、Power 数量、死亡回调和完整紧凑跨回合尚未迁移。

## 所有权与行为

- `CreatureVitals` 保留旧 `SimCreatureState` 的小数截断、数值上限、过量伤害和治疗／最大生命规则。原影子保留 Creature 身份、显示值与 `DamageResult` 外壳；标量运算只有一个实现。
- `CreatureValueSlots` 只持有布局偏移，HP／MaxHp／Block／Present 通过所属程序的同一 `ReversibleValueState` 写入、冻结、恢复和撤销。零生命与移出阵容是两个状态，不在标量扣血时执行死亡。
- `CompletedStateReadView` 提供生物值、有序活动敌人和明确可空的终局时点。完整快照的血量分布、耐久、集火、威胁与原键共用原公式；怪物 AI 和沙漏计数的指纹必须按分支阵容编码。根敌人／焦点缓存只在敌人不变时允许复用。
- 未迁移的 Power、AI、宠物、历史和 Hook 公式仍须在准入闭包内不变且不能依赖已变数值。当前读取测试只注入明确列出的标量／阵容／终局变化，不模拟死亡回调；测试通道没有进入生产 Beam。

## 验证

[独立值合同](../../tools/CompactCreatureChecks/README.md)通过九个手写边界向量、治疗／最大生命限幅、64 槽跨页、嵌套撤销及八工作区重复恢复。冻结后兄弟写入不能改变父状态或保留候选。

`COMPACT-CREATURE-VALUES-NATIVE`（`CORPSE_SLUGS_NORMAL`，SILENT，种子 COMBATSOLVER，120 秒上限）最终 `f79411f25e10403cab705060cd22d350` Passed，23.64 秒：

- 三敌 16 种读取状态，覆盖 HP／MaxHp／Block、零生命仍在阵容、部分／全部离场、Defeat／Victory、恢复根、缓存旁路及保留排序。每种状态比较 `SimulationSnapshot` 全部公开属性，只有已释放的 Simulator 引用不参与；包含原状态键和完整评估，不只比较聚合 HP。
- 12 个原生非致命伤害样例，分别作用于敌人和玩家，含零值、小数、全挡、破防、穿透格挡；每次比较完整 `MoveStateSnapshot` 与原生结果。这里验证的是生产共用算术，不能称为紧凑攻击程序验证。

既有 `COMPACT-SHUFFLE-POWER-NATIVE` 最终 `310ff556730f4086affc538afc587915` Passed，5.68 秒：24 个分支、全属性／历史／九流 RNG、撤销、8 worker 与 T1→T2 原生链保持一致。回合边界仍使用旧引擎。测试实例在两请求结束后显式停止。

初次构建因新测试误用输出路径属性失败，随后修正。v1／v2 (`8fa39bc58dde4d058e47b645aec332da`／`eca9707350cc4bfa80c2ff6917ea1396`) 在离场样例的 StateKey 失败：原 AI 指纹按活动 roster 编码，读取器漏传该阵容。修正共同入口，亦同步沙漏计数的阵容读取。v3 (`6591a0719c1848c796a22b9e47eb6353`) 已完成所有语义断言，在 JSON 写出时因 `block`／`Block` 参数重名失败；最终改用 initialBlock／finalBlock，并加入部分离场组合。独立工具第一次构建的 tuple 命名推断错误已修正，不作为通过证据。

## 完整原输入对照

两轮均完成，两场各自 88 项逻辑字段及完整动作、逐回合结果、Forecast 一致。A 为 `3ce18ed` 保存产物，B 为最终本批产物；两端均在独立进程预热原机甲／亡灵两场，再各测一次，VeryHigh、DOP8、NoGC 16 GB，无预算覆盖、无增量验证。首轮 A–B1 后消除读取参数的闭包捕获、共用原 checked 累加，并内联值读取；最终按 B2–A 反向对照。两个候选不混算均值，单组结果不用于宣称小幅提速。
