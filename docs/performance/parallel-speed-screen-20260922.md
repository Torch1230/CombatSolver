# 极高8/16路提速筛查与稳定请求判重（2026-09-22）

[性能目录](README.md) · [结构化证据](parallel-speed-screen-20260922.json)

**相对当前基线 `35b6a8fe`，本轮没有达到完整计算速度额外改善20%，也没有证明显著决策质量改善。** 保留的是一项通用的判重正确性修复；扩大并行等待方式的原型已经撤回。此前内存优化的收益不计入本轮。

## 发现与修改

已有固定lane调度器能够并行执行动作、药水、回合结束、必经的首层选牌回放、StandPat探针及部分保路元数据。Tail在动作派发后即可启动；普通原版卡牌及合格Power已有克隆锁旁路。同父Fork仍写入COW共享标记、历史及模型重映射状态，不能直接移除保护。动态选择配额和候选提交仍要求原序执行。

新的线程采样定位到 `OrderedMutationAdmissionClaim.GetHashCode` 递归进入候选及父节点图。实际问题位于[已应用请求集合](../../src/Search/CombatBeamSolver.BeamRetentionPolicy.OrderedMutation.cs)：默认record哈希还包含随后会改变的调度字段，同一对象入集合后可能无法再次被识别。

上游已经按 `OrderedMutationAdmissionClaimKey` 合并理由并唯一化请求。现在集合直接保存这个不可变标识，四个应用入口共用 `ApplyOrderedMutationAdmissionClaimOnce`，首次出现才执行原来的义务更新。标识保留root、initial/derived lease、parent lineage、父状态、来源和option/子状态；没有减少预算、改评分或按场景特判。新增合同直接调用生产入口，覆盖首次应用、原对象及父节点变化、同标识别名，以及不同子状态、父状态和来源的独立义务。

该修复避免递归哈希并保证一次性应用，但不是搜索质量大幅提升的证明。键集合每项保存更多值字段；没有新增跨请求缓存或修改模拟器所有权。整体内存变化以实测为准。

## 研究中撤回的候选

- **推迟worker统计合并：** 临时探针在DOP16的两个完整请求中分别记录Merge约83.0/104.9ms，占带探针墙钟约0.74%/0.80%；线程启动约7.7/18.7ms。收益空间不足，不实施。诊断耗时包含调度及测量影响，不是精确CPU占比。
- **Slim等待事件：** 用带短暂自旋的等待替换每微任务的内核等待，四对完整请求路线/质量相同，但配对平均耗时增加0.634%，撤回生产修改。

## 最终完整请求对照

Linux、.NET SDK9.0.120、Ryzen 7 7840H（8物理/16逻辑核）。24个既定输入覆盖五角色、精英/首领/普通遭遇、留出及新增Act2种子、弃牌/药水哨兵。每输入两个独立进程，按输入交替A/B与B/A；12对DOP8、12对DOP16，两边实际最大并发均达到配置值。

使用默认极高Beam135、分支72/42/54，设置MaxExpandedNodes=10,000、请求预算60,000ms，完整Coordinator、portfolio、Smart药水、16GB NoGC，进程上限120秒。**这不是默认500,000节点的完整极高预算。** 组合、药水审计和既有补搜全部计入请求工作量；10,000也不是请求总展开上限。测量不与构建、其他测试或采样器并行。

## 复现

源码基线为`35b6a8fe`，候选为本报告同提交的生产修改；分别用`dotnet build CombatSolver.csproj -c Release -p:CopyModOnBuild=false`生成独立DLL。离线宿主通过`OFFLINE_HARNESS_COMBATSOLVER_DLL`选择版本。所有输入路径、内容哈希、逐次命令及指标见JSON。

```bash
OFFLINE_HARNESS_COMBATSOLVER_DLL=<绝对DLL路径> \
  dotnet tools/OfflineSearchHarness/bin/Release/net9.0/OfflineSearchHarness.dll \
  --request <请求包装.json> --out <独立输出目录> \
  --profile VeryHigh --nodes 10000 --dop 8 --budget-ms 60000 \
  --search-mode Coordinator --use-portfolio \
  --enable-no-gc-region --no-gc-region-budget-gigabytes 16
```

另一组DOP改为16。请求包装格式为`{"scenarioId":"标识","characterId":"角色","generatedScenarioPath":"夹具绝对路径"}`。定位探针使用`--measure-phases`；EventPipe线程采样另跑，含JIT、等待和GC，不能代替无插桩A/B。原始请求和结果保存在`.local/parallel-speed/`；提交的JSON保留可审核摘要与原生请求结果。
