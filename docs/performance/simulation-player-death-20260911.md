# 玩家死亡清理与施伤者分支存活状态

迁移灼伤回合末时发现并修复两个旧模拟路径问题。

玩家死亡进入 `HandlePlayerDeath` 后，现在先通过 `ICombatPredictionEffectSink.CompletePlayerDeath` 调用领域层已有的 Power 退休／清理及死亡阶段记录，再处理球与宠物。原入口只处理后两项；已有死亡清扫只遍历敌人，导致玩家 Power 留在预测状态。原生的清理发生在 `AfterDeath` 之后，球与宠物之前。

两个伤害入口现在都从 `State.GetCreature(dealer)` 读取施伤者死亡状态，避免将 live 身份的当前生命带入冻结分支。受击者原本已使用分支状态。变化只修正结算及所有权，不修改搜索预算或排序规则。

- 只补清理后的 `1b1a06a2afe24fe1b305c7f6a23176e2` 首次完整对照一致，但原生死亡后的冻结根重放失败：预测 HP 应为零，实际仍为一。定位到施伤者 live 死亡读取。
- 最终 `9215d87712ed4b01befaae18c76ee62b` Passed，23.45 秒。完整状态、三个 Power 移除、根与兄弟隔离、原生死亡后再次重放一致。列表及单目标伤害入口同时覆盖“live 存活／分支死亡”和反向状态；已死亡分支不得追加伤害或历史。模拟失败只在显式安全检查点锁定为 Defeat。
