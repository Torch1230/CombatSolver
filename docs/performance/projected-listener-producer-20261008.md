## 机制与回退

1. 镜像视图未缓存时，仅在原缓存资格通过、字段读取已审计、登记卡牌至少256张且尚未构造完整快照时尝试投影。256沿用原大牌组容量路径的规模门槛。
2. 按原玩家顺序先物化球，再按手牌、抽牌、弃牌、消耗和打出堆物化卡牌；已移出状态的卡牌沿原规则略过。仅省略既有镜像参与位图为0的接收者。
3. 完成惰性牌堆物化后，复用原Power前缀映射及活动过滤。新增Power无法证明原插入锚点时，回退原完整构造。
4. 拼接原跑局前缀并消费现有类型布局。模型属于当前分支；布局只含不可变Type/位图，普通失效继续清空派生视图。
5. `HookListeners`、`RunHookListeners` 和原生遍历仍返回完整序列。显式核对模式比较参与者引用与原序，随后使用完整源继续执行原facade空操作审计。

当前原生证明锁定0.111.0：MVID `8a76776c-0ce1-4d4f-90bd-8cce653dad8e`，DLL SHA256 `2b40d2df538db1ceb5fa48d958c80ab730ada1e07db88a870aff01a661768b9f`。`CardModel.HasBeenRemovedFromState`、`Affliction`、`Enchantment` getter实际是字段读取；自有`PredictedCard.Preview`同时检查补丁资格。游戏模块不同、相关getter有Harmony补丁、基Hook/原生关键字Hook补丁或不透明CardModifier成员均保留完整构造。外部/动态模型保守保留全部参与位，不以程序集身份作为无回调证明。

这是镜像分派的派生表示优化。回复来源证书、胜利见证、Smart资格、成长、遗物、资源追回和保命目标继续由原实现处理。新增搜索剪枝规则为0；现有剪枝计数逐次保存在JSON。字段准入开销没有单独微测，其成本计入完整请求。
