# 搜索热路径分配：2026-09-25

## 范围与方法

基线是 `upstream/main` 的 `d231e9e5`；首轮候选只修改五处搜索和预测热路径。先用 Regent 首领、VeryHigh、DOP8 的 EventPipe 分配栈定位调用点，再在独立进程中交错运行基线与候选 DLL。对照使用离线宿主的 `Coordinator`、宽度组合、Smart 用药、生产预算和 Server GC。每个配置按 ABBA 顺序运行，保留所有样本。原始数据在本工作区 `.local/perf-20260925/`；离线宿主口径见 [使用说明](../OFFLINE_SEARCH_HARNESS.md)。

分配栈显示，循环准入的有序 LINQ 链、攻击历史指纹中的单人字典排序，以及几处方法入口闭包，在每次调用时产生临时对象。候选在原比较键和输入顺序上直接选最小项；单人攻击历史直接写唯一条目，多人仍按 `NetId` 排序；无免费出牌次数时先返回，预测状态工厂改用无捕获委托。没有改预算、候选过滤、评分、状态键内容或最终政策。

## 未采用的实验

- 自旋式 lane 交接在 Regent / VeryHigh / DOP8 的交错实验中，虽然个别墙钟样本较短，CPU 中位数增加约 6%～19%，且出现双方都有的长尾离群值；已从源码撤回。
- 将 Server GC 的 Gen0 大小设为 64 或 256 MiB，单次 Regent 搜索未减少工作量，墙钟约 20～22 s，GC 总暂停高于默认样本；没有改玩家配置或生产 GC 策略。

后续若要证明玩家可感知的收益，应在负载稳定的正常可见 Steam 会话中单独测量；本报告不将离线数据当作可见性能结论。
