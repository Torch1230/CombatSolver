# 完整回合层之间回收临时对象（2026-09-22）

## 结果与取舍

本轮独立基线是当前提交 `d373bdee`，已包含上一轮搜索间回收。以下收益全部是此基线之上的增量，
不重复计入历史优化。主实验采用固定的24个完整请求、默认16 GB NoGC配置，所有样本都纳入统计。

逐场计算期RSS峰值平均 **下降53.71%**，采样托管占用峰值平均 **下降60.26%**；
完整请求耗时平均 **增加3.08%**。主要内存指标超过本轮额外20%的目标。

这是用更多GC和少量请求时间换取计算期内存下降的取舍。评分、候选保留规则、节点/Beam/时间配置都未改变，
累计分配基本持平；收益来自更及时回收已不可达对象。该机制不依赖角色、卡牌、遭遇或测试种子。

## 调研与实现

前期分配采样显示，可低风险修改的单项分配热点占比不足以支持完整请求20%的收益；
共享可变模拟器需要重写所有权，范围过大。组合/能力开局搜索虽然成本高，但确实提供更好的路线，不能直接删去。
因此沿既有Runtime回收完成链，在更早的通用生命周期边界寻找可回收空间。

同一求解器会依次搜索多个战斗回合层。上一层已完成并行任务、剪枝和frontier提交后，
许多被淘汰分支产生的临时对象仍留在NoGC堆里。新入口在下一完整回合层开始前尝试回收：

1. Search只调用注入的信号；Runtime仍唯一拥有GC模式、Gate、取消、回退与重开逻辑。
2. 复用既有256 MiB分配门槛、非压缩回收和相同NoGC配置预算；低分配、普通GC、所有权争用时跳过。
3. frontier、候选顺序与搜索缓存保持。严格增量校验跳过新入口；GC耗时仍计入请求，并将暂停记入工作节流器。
4. 两种边界独立退避：搜索间无收益保持scope级抑制；层间无收益只抑制当前solver，下一solver重新获得机会。
   optional回收只记录本次收益，不消耗或重置mandatory内存压力恢复的无进展终止额度。

生产变更只涉及 `SearchGcPolicy.cs`、`SearchMemoryPressureSignal.cs`、`CombatBeamSolver.Phases.cs`。
没有新增用户设置或另一套GC状态机。

初版把两种边界的退避合并，dev05出现RSS **+19.89%**：一次无收益的搜索间收集使后续所有层间机会消失。
最终改为独立生命周期状态，dev05重新对照RSS **−61.34%**、耗时 **+1.93%**、完整搜索结果相等。
旧原型数据单独保留并从最终汇总排除；随后24根主实验全部重跑最终二进制，没有只重跑有利场景。

## GC成本与边界

24个请求中，Gen2次数合计 246→866，
搜索指标累计GC暂停 3694.86→2761.61 ms，
最大单次观察暂停 230.32→157.32 ms。
候选层间检查点386次，搜索间检查点47次；
两臂未发现收集超时、区域丢失或重开失败。
求解器累计计时 446.869→459.253秒
（+2.77%）；单场请求时间最大增加11.04%。
暂停分布受场景影响，不承诺每个请求的最大暂停下降。
显式检查点墙钟累计16.646→28.386秒；回收更频繁，这组数据中总暂停反而下降，
但等待收集及区域重开的总耗时增加。因此请求变慢与暂停总量下降并不矛盾。

日志中的显式检查点、CLR Gen2计数和GC暂停时间是不同指标，不能互相替代。
GC发生在仍在计算的请求中，不是完成后清理；没有据此声称累计分配减少或游戏帧率提高。

## 复现与限制

原始数据位于本机 `.local/layer-memory/{corpus,extra,regression-pilot,normal-repeat,contracts-final,native-multisolver,native-strict}`。
[结构化证据](turn-layer-reclaim-20260922.json)保留逐场数据、等价核对、命令、输入、运行标识和可复现脚本。
请求wrapper只含scenarioId、characterId与generatedScenarioPath；切换环境变量中的DLL即可对照同一请求。

```bash
OFFLINE_HARNESS_COMBATSOLVER_DLL=/absolute/path/CombatSolver.dll \
  dotnet tools/OfflineSearchHarness/bin/Release/net9.0/OfflineSearchHarness.dll \
  --request /absolute/path/request.json --out /absolute/path/results \
  --profile High --beam 90 --nodes 6000 --dop 1 --budget-ms 60000 \
  --search-mode Coordinator --use-portfolio \
  --enable-no-gc-region --no-gc-region-budget-gigabytes 16
```

主要验收结论适用于已测默认大NoGC区域的完整请求集合。每根主样本每臂一次，单场小幅计时/峰值差异不作统计显著性承诺；
另有修复后的独立dev05重复对照和普通GC反向顺序复测。软时间预算可能被GC跨过，原有补充搜索也可能越过请求软预算，
不能承诺所有短墙钟截断下路线恒等。普通GC与小区域另列，不承诺20%收益。
没有测Windows、可见Steam帧时间、完整Mod栈或自动打完整场战斗，也没有发布或推送。
