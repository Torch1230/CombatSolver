# 紧凑生成卡牌：小刀实例与有序牌堆

基于 `1d2f108` 的索引缓冲区，本批把卡牌定义与实例拆开：根卡和生成模板是不可变定义；新增实例的定义编号、捕获 X、六个有序牌堆均属于可撤销工作区。初始根实例的定义不会变化，直接使用固定索引；新增实例从值行读取定义。生成会先填手牌，超过十张的部分按原顺序进入弃牌堆。

编译器新增 `CLOAK_AND_DAGGER` 和 `SHIV`，总计 28 种精确卡牌。生成模板从根闭包捕获，小刀使用当前模板的攻击与消耗语义；尚未准入 `BLADE_OF_INK`／`Inky` 或其他生成器。洗牌比较从实例映射到定义，仍使用捕获的原版比较结果和相同 Shuffle RNG。Sly 嵌套帧上限保持显式准入边界，卡牌实例与牌堆不再固定为 64 张。

## 读取和验证边界

完成读取器独占以实例编号／定义编号索引的生成模型池，首次需要某组合时物化，后续候选恢复复用。活动实例列表与当前值绑定，缓存模型不进入冻结候选；根不可变卡牌旁路逐牌导入。小刀出牌次数进入 `CardHistoryReadValues` 的可选字段，由原指纹编码器覆盖玩家当前计数；普通生产读取仍沿用原值。

事件投影只记录生成、加入牌堆和生成完成历史，不重放生成 Hook 或卡牌 OnPlay。身份对照按根实例与本根之后的生成顺序建立；原生比较使用生成历史中的同一顺序，不能只按卡名匹配。整根准入同时检查新增卡入场／生成 Hook，未表示的回调明确拒绝。

纯值测试一次生成 300 个实例，比较满手溢出的完整次序、定义、超过字节范围的事件编号、攻击、消耗、后续洗牌、整体撤销和八工作区重新生成。缓冲区额外覆盖截短／清零、较高索引树复用与恢复。原生夹具覆盖普通／升级生成、两种手牌容量、生成小刀的后续攻击／消耗／洗牌与敌人死亡，比较全部快照、原键、历史来源、九条 RNG 与缓存开关。

完整原输入、墨刃附魔、其他生成闭包、紧凑回合推进和生产接入／完整 A/B 仍未完成。

## 迭代中定位的问题

- `artifact-v3` 原生请求 `5d9dc710a5a043bf8f739c662dff4a21` 在首次投影失败：已绑定 Owner 的模板又传给设置 Owner 的创建入口。读取器改为克隆完整模板、保留其 Owner；未改变值执行器的生成语义。
- `artifact-v4` 请求 `3faad127654247ab91e29033e0fdc0d2` 通过首次状态对照后，历史来源不一致；`artifact-v5` 的诊断请求 `1554943161d648fcaeb7d69d96c7a1c1` 将差异定位为生成／生成完成事件多带了一层 OnPlay。旧引擎对该卡仅推断格挡，生成发生在后续补偿阶段；投影在对应精确边界退出方法来源作用域。
- `artifact-v6` 编译发现 nullable TraceScope 的调用错误，未产生可运行 DLL；启动入口随后在缺少产物的预检中退出。改为已有的条件释放形式继续构建。

上述失败不作为语义通过证据；最终原生与成本结果另列。
