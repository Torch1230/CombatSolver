# 交错分配的紧凑索引缓冲区

基于 `5e2f43f`。原事件记录要求独占工作区尾部；生成卡牌或其他动态状态一旦插入槽位，后续事件就无法追加。本批新增 `ReversibleValueBuffer`，事件改从缓冲区索引读取。它是继续迁移生成卡的基础，本批尚未生成或执行新实例。

## 所有权与表示

缓冲区布局只保存四个头部槽的位置，长度、树根、层级、尾叶与全部索引／数据都在同一个 `ReversibleValueState`。64 值叶与 32 路索引按需追加，已有数据不搬移；尾叶支持连续写入，读取按索引定位，其他领域块可以穿插分配。检查点、冻结和恢复沿用值工作区，候选不引用任何 lane 游标或外部可变集合。

事件由一个值扩为两个值，完整保留有符号 32 位卡牌实例、目标及数值，另存种类、标记和自动执行位；避免原字节编号在大量生成卡时别名化。事件数量取缓冲区逻辑长度，读取不依赖工作区尾部。代价是事件数据增大及索引访问，不能将该能力本身计为提速。

## 验证

`CompactGrowthChecks` 的三个独立列表执行 800 步固定种子交错追加、写入、嵌套撤销和不同候选恢复；八工作区逆序恢复后独立增长。三个缓冲区跨 64、2048、65536 附近的叶与索引层级边界，逐项比较；事件往返覆盖负数、255／256／65536、int 极值及全部标记位。原八组工作区合同继续通过，512 次真实值程序在事件之间追加领域数据，冻结中途后续执行与直接执行逐槽一致。

原生验证及局部成本使用相同既有生存者／Sly／洗牌／选择链和固定 JIT 设置。A 为上一产物，B 为本次索引缓冲区；各进程内部四轮按正反顺序测旧回放与三种紧凑读取，包含准入、工作区、冻结与完整原键估值。它不是完整原输入搜索 A/B。

## 结果与取舍

| 含准入链路 | A：原连续事件 | B：索引缓冲区 |
| --- | ---: | ---: |
| CPU／叶 | 20.536 µs | 21.263 µs |
| 分配／叶 | 6005.07 B | 6101.69 B |

本组 B 的 CPU 增加 **3.54%**，分配增加 **1.61%**；旧回放对照自身 CPU 减少 2.26%，跨进程漂移不能忽略。B 内完整局部链路约为旧回放 **2.90×**，分配为旧回放 **20.94%**。为生成状态的交错分配保留此能力，明确记录额外成本，不作全场性能结论；卡牌、牌堆与帧的固定上限尚未迁移。

- A 成本请求 `2321744580d545658aa1abec3536982c` Passed，28.088 秒；B `70f16b4d11984d1c98d46718324c2034` Passed，28.071 秒。两个请求都通过 24 分支完整状态／原键／历史／九 RNG、八工作区与原生两回合；回合推进仍是旧引擎。
