# 自身弃牌续执行正式接入与整搜对照（2026-09-14）

用户原始请求：“那可以试试接入正式的 然后测试全场收益”。本批在 `476ef77` 上接入原型已验证的投掷匕首、杂技、早有准备自身弃牌暂停点，保持原搜索预算、候选顺序、动态选择额度及完整动作。旧[原型报告](choice-continuation-prototype-20260914.md)是历史单卡实验；本报告单独记录正式接入和完整搜索。

## 实现与边界

- Engine 保存明确的 CardPlay、trace、历史后缀及抽牌前洗牌计数，分叉时通过一个 PredictionForkContext 重映射。过去的稳定历史共享，活动 CardPlay、伤害结果和抽牌配对独立。原路径与续执行共用唯一出牌结算尾部。
- Prediction 检查点独占暂停种子、执行帧、死亡集合和 Fork 锁。Search 只在同父节点、同完整原动作的选择链/frontier内持有；初探读取原 pending spec 后释放自己的引用，所有首层生产者和唯一原序消费者排空才释放检查点。
- 普通 Fork 继续拒绝暂停种子。只允许三张无附魔/污染的原版牌手动打出一次、单层执行、空显式选择及可复制历史，拒绝全部事务和不透明外部 StateStore，包括外部模型状态的内部包装。未命中时完整回放。
- 续执行产生后续挂起选择时，先退出所有子作用域再从原父完整回放。逻辑转换和选择额度各扣一次；额外物理 Fork 显式计入 `card_prefix_fallbacks`。比较器核对 `forks - round_prefix_captures - card_prefix_fallbacks == transitions`，未知指标仍默认参与相等检查。

## 整场测量设计

以 `476ef77` 为A，正式接入为B。初始计划按 A1 / B1 / B2 / A2 交错，组内先原蟹战再静默蟹战；最终修改后的顺序与保留样本见下文；全部为独占新进程，双方同样使用结果冻结后的完整动作导出。固定 VeryHigh / DOP16 / 16 GB NoGC设置（实际16,000,000,000字节）和300秒正式搜索上限，完整请求420秒在首个样本前确定；不使用增量验证计时。主机内核 VmHWM每250毫秒读取，峰值包含建局，不等于纯搜索存活堆或玩家可见帧时间。

原蟹战保持既有亡灵契约师牌组、种子、遗物/药水与完整预算，是不含三张目标牌的未命中哨兵。新增静默猎手同Boss牌组在原起始牌组外加杂技+、早有准备+、投掷匕首+各两张，无额外遗物/药水，保留起始遗物；用于直接测量命中效果。输入、解析配装、开局、政策、完整动作与路线分别严格对账；时间上限或质量差异不得得到同工作量提速结论。

首个整场启动在搜索前因本任务增量合同实例仍持有主机预约而失败；停止该自有实例后按原ABBA顺序开始，排队失败保留为非测量记录，不计作样本。

中间版B1完成后，发现选择链包装使用捕获局部函数，即使未命中也可能创建闭包。最终改为static显式参数迭代器，空检查点直接返回原枚举。B1两场保留作中间数据，B2/crab因源码已经更新主动终止、不计测量；保留A1基线，再做最终F1/F2/A2。最终搜索和严格增量请求 `c37f7aea45c942d2be284d67c920dd99` / `91e987fc05804e28a75099bf546ae5f7` Passed，最终Release 10.90秒、0警告0错误及双端结构门禁通过。

初始静默起始牌组加六张目标牌的完整搜索在两版中都只找到死亡路线，因此另固定无起始牌组的八张弃牌联动牌组，保持同Boss与预算，独立执行ABBA并验证完整部署；初始失败局面仍完整保留。

## 结论与边界

正式接入已验证三张牌的自身弃牌暂停/恢复、并行所有权及旧路径回退，完整搜索保持预算、质量与动作；弃牌获胜场景观察到约3.4%耗时、8.6%分配和5.8%进程峰值的下降，明显小于单卡原型。未命中哨兵的GC暂停不利变化需要保留，不能声称普遍加速。
