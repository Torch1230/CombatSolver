# 可增长紧凑状态与事件记录（2026-09-11）

[性能目录](README.md) · [全部样本与验证](simulation-growable-state-20260911.json) · [独立合同](../../tools/CompactGrowthChecks/README.md)

**保留为后续执行迁移所需的能力，不计为生产提速。** 固定事件容量已经无法承载长路线。本次把逻辑槽位长度纳入分支所有权，让追加、撤销、冻结和恢复处理不同长度的状态；事件记录按需增长。生成卡牌的逐实例代次、Power 数量、伤害、死亡、完整回合和生产 Beam 尚未迁移。

## 所有权与撤销

`ReversibleValueState` 区分逻辑长度和工作区容量。追加返回当前分支内的槽位索引；检查点保存当时长度，撤销清除新后缀，后续分支复用索引时读到零。冻结候选只复制实际使用范围的页表，共享私有不可变值页；物理余量属于 lane，不能逃入候选。

只对最近检查点之前已存在的槽位记录旧值，新槽位由长度回退删除。嵌套检查点仍记录其建立前已有的新槽位。`Append` 将新增一个值与初始化合并，事件带不再预留固定 256 个以上的槽位。写密度诊断明确把新增零槽也计入创建后的槽位集合，不再只从旧值日志推断。

恢复在任何写入前拒绝外根和活动事务，允许同根不同长度的候选。容量足够时复用恢复不分配；更长候选需要扩容。缩短时清除尾部值与页缓存，部分尾页重新捕获位图，避免旧候选的数据复现。卡牌数和嵌套帧数的既有闭包上限仍存在；这不是通用效果支持声明。

## 成本与取舍

独立工具链接 `3ce18ed` 与候选源码，固定相同程序和结构负载；各版 ABBA，每进程每模式四个样本，关闭分层编译。所有版本的 34 叶和逐槽合同均通过。

| 最终安全数组实现对固定容量版 | CPU 变化 | 分配变化 |
| --- | ---: | ---: |
| 34 叶展开并冻结 | +26.60% | +2.08% |
| 为 34 个候选新建工作区 | −17.85% | −28.69% |
| 复用工作区恢复 | −6.80% | 两版均零分配 |

固定长度的合成历史负载并非全面变快：最终短历史若干项约 −7% 至 +6%，8,192 槽历史的三种写密度约 +10% 至 +13%，分配不变。全部样本保留，不能只报告恢复收益。

开发过程中，首版展开约 +26.65%，仅省略新增槽日志的第二版约 +32.59%。合并追加与初始化后选择上表实现。另一版尝试在逻辑范围检查后移除重复容量检查，展开仍约 +31.63%，没有支持保留的收益，已撤回该访问方式。

实际完整估值链另外使用相同 `DOTNET_TieredCompilation=0`、相同 24 个选牌分支和每批初始化条件，执行 A→B，每版四组内部交错样本：

| 每叶线程 CPU／分配 | 固定容量 A | 可增长 B |
| --- | ---: | ---: |
| 已有读取器、执行／冻结／完整估值 | 19.002 μs／4,381 B | 20.144 μs／4,349 B |
| 含每批准入和工作区创建 | 20.769 μs／5,777 B | 21.942 μs／5,846 B |
| 同请求内旧对象回放 | 69.490 μs／29,859 B | 66.144 μs／29,859 B |

新增能力的含准入链路约慢 **5.65%**、分配约增 **1.19%**；同期旧回放对照自身快约 4.81%，说明单组跨进程对照仍有漂移。B 内含准入链路约为旧对象回放的 **3.01×**，分配约为其 **19.58%**。这是同一封闭原型的比较，不能解释为生产完整搜索已经三倍加速，也不能与历史不同条件的倍率相乘。

最终功能请求最初使用默认分层编译，不能把其中时间直接与历史关闭分层编译的 3.31× 比较。上表来自另行固定相同设置的两个产物；前面的功能结果只作为语义证据。
