本轮实现并验证了一个 Power 附着效果归一化缓存，最终没有保留。最小合同与相关原版差分通过，但没有建立稳定提速证据，分配量略增；交错测量又遇到桌面环境变化及一次冷启动预热超时。因此不能把原始均值中约 11% 的下降解释为优化收益。

## 实现与所有权

原型在 SimCardPile 增加随 Fork 复制的单调修改版本，牌堆变更或通过所属卡牌 MutablePreview 写入时递增。不透明附着模型令版本不可用，沿原全扫描路径处理。SimulatedCombatState 保存上一次无正数 VitalSpark / Galvanic / Smoggy 来源、且完整扫描完成后的所有牌堆版本之和；总和只作本分支内的变化检测，checked 溢出明确失败，不参与状态键。

每次仍读取当前 Power。第一次处理、生成牌首次入场、卡牌写入、能力获得及移除后的清理走原逻辑；来源存在时始终全扫描。没有删除原结算调用点，SwordSage 仍单独执行。卡牌和原归一化代码分别见 [SimCardPile](../../src/Engine/Common/SimCardPile.cs)、[PowerLifecycle](../../src/Search/SimulatedCombatState.PowerLifecycle.cs)；以上版本字段与新增测试均已从生产源码撤回，原型补丁保存在本地实验目录。

## 取舍与后续

撤回该候选及专用测试，保留原生产路径；停止扩大归一化机制族。没有完成一组环境稳定的八次对照，因而不宣称精确加速或退化幅度，也没有足够理由继续承担新失效状态的复杂度。所有实验实例均停止，源码、补丁、构建与原始结果保存在 `.local/simulation-refactor-20260910/`，不进入源码提交。

由于没有保留行为变更，不追加 DOP1/DOP2、增量搜索、整场原生部署或可见性能回归。P4 继续做类型所有权取舍，P5 另测共同前缀 CPU；后续完整诊断改为先运行机甲场景以预热公共执行路径，保持各请求 120 秒上限。这项测量流程调整不追溯改变本轮已中断的顺序。
