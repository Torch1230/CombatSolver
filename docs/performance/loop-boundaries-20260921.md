## 结论和口径

首批这 19 根的当次样本两侧均获胜，战损、最终 HP、药水、结束回合、胜负和边界指标一致，未发现胜负翻转或本次测量内的质量下降。18 根完整路线 JSON 逐字段相同，1 根不同；不能称为全路线等价，也不保证不同机器负载仍在同一动作深度切层。新增四项原生测试全部 Passed，其中三项包含严格增量和完整部署，计划外重算为 0。

## 补充 DOP 边界

对路线变化根另测 DOP2。开启零损早停时，A 的展开/转移为 DOP1 166/431、DOP2 169/437；B 为 139/359、142/367。两侧各自的完整路线也随 DOP 改变，但质量与 Score 都不变；DOP2 父节点与动作最大实际并发均为 2。因为基线也有此现象，不能算作新回归，也不能说所有循环都具有 DOP 路线／工作量等价。工具正确地将路线差异返回为非零，显式质量和结构检查通过。

## 4096 上限反例：ABBA 与设计含义

7200 HP 的 Letter Opener 根需要 4320 次出牌。原 ABBA 四份日志均为节点份额切层，没有时间份额切层；这些样本两侧选择 T2、战损 4、4321 个含 EndTurn 的动作。**T2 不是该输入在任意机器负载下的不变量**，也不是数学上无零损 T1 路线。该组完整路线相同，展开仍是 4675，转移却从 9375 增到 13471，多出的恰为未采用的 4096 次回放。

| 指标 | A1 / A2 | B1 / B2 | 均值变化 |
|---|---:|---:|---:|
| 求解 wallSeconds | 4.8917 / 4.8684 | 5.4202 / 5.4404 | +11.3% |
| Search 累计分配，字节 | 516595384 / 516249192 | 593748160 / 593114416 | +14.9% |
| 采样活对象峰值，字节 | 149967192 / 150210736 | 140708648 / 103726640 | -18.6% |
| 工作集峰值，字节 | 385912832 / 386433024 | 373583872 / 368959488 | -3.9% |

首对观察发现代价后，另取完整 ABBA 复核，不把首对重复计入均值。额外探测使用真实模拟并释放临时快照，有限上限保护了终止性，却不保证探测能交付结果。峰值受 GC 与 100 ms 采样影响，不能将其下降理解为没有额外计算和分配。没有可见 Steam 性能结论。

这些百分比是该组可比较样本的观测值，**不是性能退化的上下界**。负载增加会影响双方切层和后续工作量，既可能放大差异，也可能截掉后续搜索而缩小观测差异。审计者报告的 B2 T3／时间切层是有效的可复现性提醒，但其原始产物未在本工作树，以下不冒称独立复现了那次 T3。

## F1/F2/F3 追加修正与验证

**F1 已修正测试和诊断。** `letter-replay-cap` 去掉固定 `CombatEndedTurn=2` 断言，保留胜负、战损、药水检查；不改成同样缺少普适保证的 ≤3。完整路线、回合和其他质量差异仍保留：无时间截断时，它们依然属于可比较差异。

- 新增 `TurnLayerTimeBudgetStops`、`TurnLayerNodeBudgetStops`，两者之和等于原 `TurnLayerBudgetStops`。当两项份额同时耗尽时，与原日志一致归入 time。字段贯穿结果、归零、worker 汇总、原生指标及确定性比较，不改变任何切层判断。
- `Evaluate` 宿主原已通过诊断钩子设置 `timeBoundaryObserved`；缺陷是 runner 没有输出理由／区分状态，且夹具硬断言回合。新 runner 优先读结构化计数，旧 DLL 从已 flush 的日志读取 reason；同时核对计数之和与日志，不能把缺失证据默认为零。
- 出现局部或全局时间边界，样本标为 `TimeLimited`，比较标为 `Inconclusive`、退出码 2；保留原始路线差异和所有 fixtureCheckFailures，不混入有效性能均值。正常可比较差异／断言失败／宿主失败退出码 1，等价为 0。诊断计数互相矛盾仍算失败，不能借“负载”掩盖。
- 8 项 Python 回归检查覆盖审计描述的 ABBA T3 分类、节点切层下真实差异、旧日志兼容、新计数一致性、全局超时及失败优先级。
- 新 DLL 的普通预算 cap＋finisher 哨兵 A/B 均 Equivalent，cap 为 time=0/node=1；旧 DLL 的日志回退与新计数对齐。另以 2000 ms 预算主动触发两侧各 3 次时间切层：两侧均未完成击杀，观察到 26 HP 损失且路线不同；工具保留失败观察并正确返回 Inconclusive/2。这是时间边界分类验证，不是性能基准，也不是审计者 T3 的复现。

**F2 不作为安全拒绝条件直接采纳。** `(remaining / damage + 2) * period` 包含保守余量，且历史实测伤害不是未来伤害上界。估算超过额度不能推出实际不能完成；在回放中按上一周期判断也不能证明成长／隐藏触发之后不会加速。

新增[估算余量反例](../../coverage/unattended/generic-loop-replay-estimate-margin.json)：6835 HP 的 Letter Opener 根，常规 6 次出牌后剩 6825 HP，每 3 动作造成 5 伤害。估算为 `(6825/5+2)*3=4101`，但实际只需 `1365*3=4095` 次额外回放，低于 4096。离线实测 **6 展开／4107 转移、4095 回放、1 次回放胜利、零损 T1**，无任何切层。即使恒定伤害，粗暴按该估算拒绝也会跳过本可成功的这次探测；不能将“可能由更深的普通搜索补回”当作已经证明质量不降。本轮保留现有准入，7200 HP 的无效探测代价仍未修复，不把新增遥测说成性能优化。

**F3 只限定范围，不虚构请求级保证。** suite 和命令显式固定 `Evaluate`；配置 `Coordinator` 会在运行前被拒绝，4096 检查明确是单 solver。请求级 N×4096 风险未由本测试消除，仍需要独立的协调器预算设计与验证。

本次 Release 构建 0 warning／0 error；没有修改游戏结算或搜索政策，因此没有重跑原四项原生部署。当前验证为 8 项分类合同、目标＋哨兵 A/B、主动时间切层及估算反例，详见[追加证据](loop-budget-audit-20260921-evidence.json)。

## 重跑

基线 DLL 必须具备上一轮共享的固定夹具注入入口；不能直接拿未适配的旧发行 DLL 比较。`--out` 必须不存在，进程串行运行，差异／失败保留并返回非零，不能自动解释为退化。`--abba --cases letter-replay-cap` 用于复核反例。

```bash
python3 tools/OfflineSearchHarness/run_loop_boundaries.py \
  --baseline-dll .local/loop-comparison/baseline/CombatSolver.dll \
  --candidate-dll .godot/mono/temp/bin/Release/CombatSolver.dll \
  --out .local/loop-boundaries-rerun
```

脚本对全部样本的根和完整路线作比较，同时检查显式质量条件；不会自动批准不同路线。时间截断输出 Inconclusive／退出 2，不能作为一次可比较的质量或性能验收。原始首批日志位于 `.local/loop-boundaries/`，追加日志位于 `.local/loop-budget-audit/`；长期保留紧凑 evidence JSON。耗尽反例不再硬断言 T2；4 HP 战损等检查仍只是本测试目标，不意味着无界最优解或重负载下必然完成。
