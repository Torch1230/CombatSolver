# 精神过载与毁灭的紧凑执行

本阶段新增精神过载的能量、抽牌、施加能力及后续阵营开始毁灭结算；毁灭达到生命阈值时，在玩家阵营结束后或敌方阵营结束前直接死亡。该域由 Prediction/Compact 按精确原生类型和完整根闭包准入，当前卡牌编译器共 31 种类型。仍只支持既有主要生物、单个机械骑士回合图，没有因此准入奥斯提、其他遗物、药水或原始亡灵完整输入。

## 权威语义与所有权

- `CardEffectProgram.GainEnergy` 在同一撤销工作区先增加能量（含封顶），之后执行抽牌及能力指令。抽牌中的洗牌选择冻结当前能量、指令位置及未施加的能力；恢复不能重复资源或消费人工制品。
- `CompactRoundLayout` 保存玩家阵营开始的一次性标记。原生在起手／Tools 首个实际选择开放前运行阵营开始 Hook，没有选择时在起手完成后运行；挂起与恢复都保留该时点。回合开始的毁灭施加者集合由值事件记账、每个阵营开始清空，读取器单向导入原状态键所属字段。
- 毁灭直接杀死符合阈值的所属方生物，保留格挡，没有伤害／攻击历史；死亡阶段、能力退休、阵容与安全点终局一起记录。根闭包拒绝宠物、复活及未表示的死亡观察者，并审计 `AfterDiedToDoom`、能量增益修改 Hook。
- 读取器只导入已提交事件，不执行能量、能力或死亡 Hook；原 Snapshot、状态键、估值和续用文本继续使用同一编码。仅当根有精神过载卡牌／能力时准备其新实例模板；既有毁灭按原实例捕获，不给原机甲输入增加不可能生成的模板。

## 原生差分发现的旧引擎修正

1. 精神过载原先由推断抽牌镜像加事后效果规格处理，导致洗牌选择中尚未获得能量。失败 `aae3e36f3a014248903b757378f76576` 在首个挂起状态键暴露该问题。现在使用唯一精确 OnPlay 镜像：获得能量 → 抽牌 → 施加能力；删除原规格的重复资源／能力入口。原生选择观察器直接核对能量已到账、能力和人工制品尚未改变。此修正会改变此前错误中间态，不能描述成与旧错误实现逐位相等的优化。
2. 原版新建玩家负面能力均设置 `SkipNextDurationTick`，包括计数能力；旧引擎只给三个持续减益设置。失败 `e287b85aff7c44429083c1484a5c96a7` 的完整快照和键已一致，但逐能力完整元数据不同。通用施加入口现按新实例实际 Debuff 类型设置标记，叠加不刷新。原键／续用仍只编码实际影响持续递减的三类标记，未把无语义计数标记加入状态等价关系。

## 已取得的证据

- `COMPACT-NEUROSURGE-NATIVE`：两种升级、两次出牌和两次完整回合，5 分支／4 原生动作。最终能量 3、施加后峰值能量 8、毁灭 13；完整牌堆实例顺序、卡牌指纹、能力元数据、来源历史、九条 RNG、原键、缓存开关估值及完整续用一致。
- `COMPACT-NEUROSURGE-CHOICES`：增加根精神过载、人工制品、洗牌和 Tools 选择；5 个省略选择边界、4 原生动作、5 分支、1 个原生资源时点观察通过。毁灭最终 3，证明两次出牌与第一轮阵营开始分别消费三次人工制品。两组均覆盖逆序读取、八工作区独立恢复及实机推进后的冻结根隔离。
- `COMPACT-DOOM-PLAYER`／`COMPACT-DOOM-ENEMY`：两种阵营与生命阈值、错误阶段无效、正确阶段 Kill/Death 顺序、格挡保留、能力退休及终局锁定；原生分别调用所属 Hook。原生观察停在死亡清理后的安全点前，不声称整场原生胜负部署。
- `COMPACT-NEUROSURGE-SEARCH`：相同语义根，固定 250 节点；旧／紧凑 DOP1、紧凑 DOP2 的完整政策结果相等，实际并发 2，挂起候选非零。取消／注入异常后排空并复用同一根，未迁移药水明确拒绝，实机不变。
- `COMPACT-ROUND-NATIVE`：公共回合回归通过，三种根、20 分支／7 原生动作、8 个省略选择边界，完整状态／历史／原键／估值／RNG、逆序和八工作区及实机后根隔离均一致。
- `NeurosurgeChecks` 及整个 `CompactCreatureChecks` 通过：能量封顶、抽牌前资源、选择后人工制品、阵营开始只执行一次、双方毁灭相位、终局前时间／AI、撤销和八工作区。

原生运行的版本、runId、时长与完成检查保存在[结构化证据](simulation-necro-resources-20260911.json)。v6 原生通过后，v7 仅提取测试建局 helper 并增加搜索场景；没有再次执行同源的已通过原生请求。一次搜索请求因传入空 card-id 在建局前失败，修正为明确空列表后正常运行，不属于模拟偏差。

## 重跑方式与范围

先构建独立产物 `dotnet build CombatSolver.csproj -c Release -p:CopyModOnBuild=false -o .local/compact-necro-resources/artifact`，将根 manifest 复制到该产物目录；退出仍持有旧 DLL 的独立 headless 进程。Linux 使用 `tools/run-unattended-test.sh`，Windows 使用对应 PowerShell 脚本，场景 ID 如上；基础参数为 SILENT、MECHA_KNIGHT_ELITE、空 Cards 列表、敌人 300 HP、Instant、120 秒总超时。测试在内部建立精确根，搜索使用固定 250 节点，不启动 Runtime NoGC。

CoverageCatalog 的 `--verify-effective` 通过，精神过载从推断加领域补偿转为精确引擎镜像。生成目录版本同步到现有 manifest 0.34.6，原生方法原始 IL 指纹随当前 Linux 游戏程序集重新生成；这些指纹更新不是对全部效果重新取得原生差分的声明。

最终 Release 编译 11.38 秒，零警告／错误；Linux 结构门禁通过 92 个 Search 文件，PowerShell 同步维护但未执行。受影响文档 311 个本地链接有效。

本阶段无新增性能比较。原始亡灵完整输入、动态效果闭包与两个原始输入的预热交错正常 NoGC 验收仍未完成。已有机甲性能结论仍以[运行时对照](simulation-runtime-backend-20260911.md)为准。未运行 Steam、安装、发布或远端操作。
