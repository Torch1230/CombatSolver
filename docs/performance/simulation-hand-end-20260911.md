# 紧凑灼伤与手牌末尾阶段

`ResumableDiscardProgram.HandEnd` 现在执行封闭的手牌末尾阶段：先消耗不带手牌末尾效果的虚无牌，再按已准入的入场顺序处理灼伤。灼伤不可打出，造成可格挡、无属性修正的自身伤害；它不付款，不增加出牌、攻击完成或主动弃牌次数。致死移除玩家 Power 并记录永久死亡，但玩家保留在阵容；待失败与安全检查点的 Defeat 分开保存。牌堆、事件、Power 退休和终局均可撤销、冻结与恢复。

编译器增加精确 `Burn` 类型，限定原始不可打出费用、无附魔及原生伤害属性，共三十种卡牌类型。手牌末尾需独立整根准入，新增钩子审计覆盖自动出牌后阶段、侧回合末之前、虚无触发与刷新前回调。已准入标志是冻结候选的不可变配置；仅准入出牌的根不能调用该阶段。阶段本身最多十张牌，无选择或未表示回调。

`CompletedStateReadView` 增加累计玩家失血，原 Snapshot 继续使用同一评分公式；状态牌抽取计数通过原指纹字段导入。灼伤来源使用 `OnTurnEndInHand` 方法作用域，保留无属性修正／可格挡属性，不伪造为 OnPlay 或攻击完成。读取器、旧模型投影只消费事件，不重新执行效果。

## 原生调度边界

原生 `DoTurnEndCards` 并行启动各牌入场，再串行完成效果。三张灼伤的致死基线暴露了动画模式的差别：

- Instant 基线 `670bcad427274860a8e84c5025828446` Failed：原生三张灼伤已经进入出牌区，旧顺序模拟只进入一张，另外两张仍在手牌。格挡和非致死根一致。
- 同产物 Normal 基线 `1309cfa88cdf407693e19ff7e061ec88` Passed：带延迟的入场在死亡后被拒绝，两张灼伤仍留在手牌。

阶段接口因此显式接收入场顺序。Testing 在主线程捕获本次 Normal／Instant 参数，worker 只消费这个值；旧模拟同一手牌阶段也接受显式批量入场参数供 oracle 对照。没有把其中一种顺序推广为所有动画与手牌效果的规则。

**生产调用目前仍使用原默认顺序；完整回合接入尚未完成。** 后续接入必须把实际部署模式及可观察回调纳入根能力合同，不能据此声称生产 Instant 致死牌堆差异已普遍修复，也不能将该阶段等同于完整回合结束、怪物行动或下一回合起手。

## 验证范围

`COMPACT-HAND-END-NATIVE` 每个模式使用三个原生根、六条预测分支：6 格挡完全挡住三张灼伤，1 格挡先通过逃脱计划抽入第四张灼伤，以及 1 HP 致死；每根另有先打防御的兄弟分支。力量、敏捷和人工制品保留作无属性伤害及死亡清理对照，虚无牌先于灼伤消耗。

验证逐字段状态、单独补充的五个有序牌堆（含出牌区）、完整 Power 字段／顺序、风险与来源历史、九条 RNG、全部 Snapshot 属性与原键、缓存开关、撤销及八工作区恢复。原生执行使用真实 `CombatManager.DoTurnEnd`，保留其动画调度；致死后再次从冻结根执行及读取。没有启动搜索，也没有增量验证。
