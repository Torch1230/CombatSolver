# 战斗选牌与印牌分支来源逐项盘点（2026-09-12）

以提交 `87c2b7f` 为生产基线，检查当前游戏0.111.0原始IL和仓库搜索/模拟路径。扫描1,284个模型、5,955个方法，包含异步/迭代器状态机和同模型辅助方法，读取失败0。选牌、自动出牌、生成/小刀/灵魂辅助入口与铸造共202个调用点，涉及193个模型；再沿PowerCmd.Apply关系补入20张间接触发牌，共213个模型逐项评估。

85个显式CardSelectCmd调用点与仓库既有目录完全一致：42张卡牌（含多人专用Tutor）、9瓶药水、29件遗物（其中24件只在拾取时选牌）、5种能力。另补充自动出牌、固定/随机生成和铸造放大器。中文名称来自本机游戏简中资源；表中保留类型名便于定位。

“全量”指上述明确入口及其能力授予关系，不等于枚举任意牌组中的全部互动。普通抽牌、回能、攻击目标数、所有第三方动态登记都可能放大搜索，不能用一份原版类型表穷尽。第三方CardChoiceMirrors/PotionChoiceMirrors和ICombatPredictionChoiceSink依其运行时登记与语义另审；未知语义不默认跳过。

## 结论与优先级

1. 优先研究赌博筹码、赌徒特酿、灰水、护驾！！！的任意子集，及隐秘匕首、准备、微光/光子切割、清淤/涅奥之怒的多选组合。大头候选是组合中间集合和重复评分，不能靠减少原来的保留代表获取速度。
2. 每回合/洗牌反复触发的烘焙手套、熵、必备工具、暴政、计策，以及抉择，抉择/倾泻等嵌套自动牌，应按实际累计触发次数排序。
3. 三选一生成的历史查询和所有通用选牌令牌计数可以迁移小优化；工具箱/选择悖论已经直接携带选项，不应改成查历史。
4. 君权自授等随机生成通常沿分支RNG产生确定结果，并非遍历整个卡池；小刀/灵魂增多则扩展后续出牌组合。优化重心是每次生成和每个分支的成本。

本轮表格是静态逐项判断，不是逐项提速证明。历史/令牌两个共用路径已完成[迁移及验证](choice-migration-20260912.md)，累计分配减少，但机甲耗时出现回退信号；本清单中的其他方案仍是待测建议。此前已部署Windows的87c2b7f未被本轮研究自动覆盖。

## 分支规模与现有保护

设N为当前合法候选数，k为实际选择数。单选最多N项，固定多选理论C(N,k)，任意张理论2^N；这些是去重/限额之前的规模，不是实际搜索节点数。多个选择或自动牌会让后续组合继续相乘。

现有BuildCombinations按语义键去重并限制每种张数的生成数量；BuildChoices保留每种张数代表，再做排序、固定多弃牌的多样性代表和少量持久身份补充。单张回手/回顶/生成等路由会把限额至少提高到候选数加空选，不能假设所有选择都严格受同一固定限额。已有隐式全选直接生成一个选择。

赌博筹码的候选是手牌副本数组、来源是原手牌列表，不能因内容相等复用同一个引用计数。只在两个参数实际引用相同时才可合并计数。ChoiceCardKey(PredictedCard)已有缓存，不再为第二次读取额外添加字典。

计策的原生与模拟行为都是洗牌后选牌回手，不是弃牌预视。通用ResolvePileDiscardChoice/MaxBranches=1接口存在，但当前扫描未找到原版实际调用者；不把接口注释里的预视示例当作已存在原版卡牌。
