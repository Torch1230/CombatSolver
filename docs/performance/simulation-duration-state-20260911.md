# 持续减益的跳过递减状态

回合迁移时发现并修复了生产模拟中的两个相关问题：虚弱、易伤和脆弱的 `SkipNextDurationTick` 影响未来层数，但原状态键与续用文本没有记录；新施加的减益在不同入口使用 Power 字段或独立影子集合，导致首次施加的原生字段缺失、等价命令产生不同状态键，以及按类型入口被人工制品阻止后仍保留跳过项。

## 首个错误与修复

`POWER-DURATION-KEYS-NATIVE` 从原生新施加的三种 1 层减益捕获根，只在兄弟分支清除其中一个跳过标记。原生结束侧回合会先清除标记而保留层数，未带标记的兄弟在相同结算后失去该 Power。基线 `5535647e98f94d76889437630ee42a88` Failed：三个兄弟的未来不同，状态键与 ExactContinuationState 却全部相同。中毒同名字段不影响持续层数，其分支保持等价，作为不应拆分状态的对照。

`POWER-DURATION-APPLICATION-NATIVE` 随后检查普通、怪物和按类型三个入口。应用基线 `0ea7b37d671b42d2b3d01cddfb3ed224` Failed：第一次原生施加虚弱后，实机标记 True，预测 False；续用文本准确指出缺少 `/skip`。三个入口的状态键不一致，人工制品阻止时按类型入口还留下了额外状态。此前单独键修复产物 `7fa908c04ab249d586e7b18881c47d91` 虽通过捕获根测试，不能证明应用入口完整，因此继续修正表示。

`PowerLifecycleSupport.UsesNativeDurationSkip` 明确当前原生消费该字段的三种类型。新建玩家持续减益时，`SimulatedCombatState.ApplyPreparedPower` 将标记写入独占 Power；叠加不刷新，移除后的新实例重新设置。两个兼容入口对这三类不再写独立集合，因此不会产生双重跳过或被阻止后的孤立项。其他旧阶段补偿保持原有处理，此项没有扩大其语义范围。

状态键与 `ContinuationStamp.AppendPowers` 共用 `SemanticallyRelevantSkipNextDurationTick`。只有有效标记为真时增加标记；无待跳过及无关 Power 保持原编码。中毒不因无意义字段而多分支。`SolvedRouteCache` 的现有键已经包含求解器模块版本、完整原生状态及续用文本，因此新旧二进制的路线缓存隔离；本次无需再增加缓存版本或清空玩家数据。
