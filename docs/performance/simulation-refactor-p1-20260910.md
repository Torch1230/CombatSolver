# P1：复用率、归一化与 Power 类型成本

[执行计划](simulation-refactor-plan-20260910.md) · [完整计数与命令](simulation-refactor-p1-20260910.json) · [原 CPU/分配基线](simulation-profile-20260910.md)

基于 `a6bc386 / 0.34.6`，临时插桩后分别运行两场正常 VeryHigh / DOP8 / NoGC16GB 完整路线搜索，无短搜、预算覆盖或增量验证。诊断结束已恢复全部生产源码；本阶段尚未交付性能优化。

## 决策

1. **P2 的投影洗牌缓存不进入实现。** 所测保守输入签名的父结果复用率只有 1.19% / 0.11%，8192 槽每线程缓存约 0.99% / 2.39%；构造签名耗时约为原投影计算的 55% / 58%。即使减少签名开销，这个命中率也不支持复杂缓存。此结论不排除其他快照组件，也不是任意更宽等价关系的理论上限。
2. **P3 优先验证一个归一化族的重复扫描。** 两场常规与 Power 污染归一化合计访问约 5.07 亿 / 4033 万张牌，没有卡牌 `MutablePreview` 访问，但有 750,469 / 78,862 次生成牌首次入场记账。不能直接跳过“没有 Power”的整段；先评估保留首次入场、牌堆/牌状态变更和 Power 变化的分支内失效边界。
3. **P4 优先关注实际克隆数据，不能共享全部动态变量。** 亡灵契约师最高的两个非空变量类型为 PlatingPower 与 WitheringPresencePower，各约 169 万次 Fork 克隆，合计约 2.41 GB。后者的 CardsLeft 在每次出牌时修改，并且是多实例能力，不能当作显示常量；前者的 Decrement 在施加时写入、回合开始时读取。完整迁移需要逐实例读写与重映射合同。

签名包含排序前按 Discard → Draw → Hand 组合的 Original 身份哈希、有序卡牌语义指纹、CardValue 的 double 位值和完整 Shuffle RNG 状态。缓存是单个完整请求内、每线程有界直接映射表，没有保存模拟器或卡牌对象，也没有用无界全局命中率代替可实施缓存。

JSON 的 `identity_changes` 与 `card_value_changes` 比较的是有序输入向量，牌的位置变化也会令它们递增，不能解释为同样次数的卡牌数值写入。

原版 CardModel 比较器先比较模型 ID，再比较升级数；同键不同实例的排列不能随意忽略。这里的身份/有序签名比结果等价更严格，且仍是哈希观察；零输出冲突只说明所测请求没有观察到冲突，不构成通用正确性证明。输入签名没有参与生产搜索判断。

输入构造、投影与查询使用 Stopwatch，仅用于判断诊断方案本身的成本级别；是多线程经过时间之和，包含抢占和 GC，不是新的 CPU 百分比或可见 FPS。由完整有序输入变化引起的低命中，不能靠缓存容量扩大解决；已经失败的延迟估值、无序牌堆指纹及排序委托实验也没有因此重启。

## 克隆

ForkPower 累计记录约 2304 万 / 77 万次实际克隆；范围内分配分别 9.734 / 0.291 GB，包含模型克隆、context 登记与字段设置，不是存活堆或纯模型对象大小。两场类型明细及每 64 次抽样的 elapsed ticks 保存在 JSON，后者不能按类型解释为准确 CPU 时间。

PowerModel.DeepCloneFields 会克隆 DynamicVars 并重建内部数据；DynamicVarSet.Clone 创建字典、克隆变量并重新绑定 Owner。当前高成本对象不仅包含空变量容器，不能用统一共享替代。Plating 的 Decrement 经 AfterApplied 写入、AfterSideTurnStart 读取；WitheringPresence 的 CardsLeft 在 AfterCardPlayed 中递减及重置，DisplayAmount 也读取它。原生源码定向反编译证据保留在本地 native 子目录；本阶段没有改变这些语义或克隆链。
