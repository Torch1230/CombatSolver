# 增加预测卡牌引用与集合状态辅助接口

审阅状态：设计草稿，尚未实现，以下为拟定范围与验收条件。

模型状态接口可以保存自定义状态，但适配者仍需自行查找预测卡牌、在 Fork 时重映射集合元素，并保证两侧状态描述一致。遗漏映射会让子分支持有父分支对象；只按卡牌 ID 描述，又可能把同名的不同实例错误合并。

拟提供少量辅助入口，复用已有 `FindCard`、`PredictedCard.References`、`PredictionForkContext.RequireRemap` 和状态 writer：

- 将已捕获的实机卡牌身份解析为当前分支的 PredictedCard；零匹配或有歧义时明确失败，不回退读取 live，也不任选一张同名卡。
- 在同一次 Fork 的 context 内复制卡牌引用集合，保留空值、重复元素与实例差异；缺失必需映射时失败，不悄悄保留父引用。
- 为有序集合提供按顺序的状态描述；无序集合只有在调用方明确声明且具备稳定实例身份时才规范化。不能靠排序掩盖影响结算的顺序差异。
- 提供可编译的中性遗物／Modifier 示例，把根捕获、引用保存、Fork 和两侧状态描述连起来。

此改动不另建全局对象 ID 系统，不自动深拷贝任意对象图，也不扩展战斗中途获得／移除遗物的生命周期。首批仅覆盖已有预测对象体系中的卡牌引用。

验收计划：

- 同 ID 的两张牌、不同升级或实例状态不能混淆；原卡、Preview 与 COW 后 Preview 的解析保持一致。
- 父、子和兄弟分支中的引用均指向各自对象；修改子分支不改变其他分支。
- 缺失映射、空集合、重复引用、顺序交换及明确无序集合分别有合同检查。
- 走真实根捕获、完整模拟器 Fork 和最早续用边界，核对 live/predicted 状态；根捕获后的实机推进不能污染旧根。
- 检查空路径与集合描述的分配，不在指纹热路径引入逐元素字符串格式化或额外全表扫描。

当前没有本 PR 的构建或测试结果，不能复用其他 PR 的通过记录作为本项证据。它可独立于 PR 1 实现；需要阶段更新的示例再依赖 PR 1。
