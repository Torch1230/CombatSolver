# 增加已适配 OnPlay 补丁的精确登记

审阅状态：设计草稿，尚未实现，以下为拟定范围与验收条件。

当前根捕获会拒绝战斗相关的第三方 OnPlay 补丁，但没有入口表达“这组补丁已经有完整的预测实现”。仅按 Mod ID 放行无法保证安全：同一方法新增一个未知补丁，或已有补丁改变执行顺序，都可能让镜像再次偏离原生行为。

拟在现有补丁审计中增加精确适配声明，首批只覆盖当前审计可见的、根可达卡牌 OnPlay：

- 声明绑定目标 MethodInfo、具体补丁方法、补丁类别与所有者，以及对应的预测实现；不能只填写一个名称就获得放行。
- 核对实际生效的完整补丁组合及顺序约束，包括优先级和 before/after。逐个补丁分别有登记，不自动等于其组合已受支持。
- 为命中的完整组合选择唯一预测实现，避免原版镜像与补丁补偿重复执行；缺失实现或存在歧义时拒绝。
- 每次根捕获重新核对当前补丁集合，预测期间消费冻结的适配选择；补丁卸载、增加或组合变化使旧根及依赖其语义的缓存／续用结果失效，在采用或部署旧路线前拒绝过期结果。
- 保留未知补丁、无法确认的来源和项目明确拒绝的 Mod 边界，不由此解除其他订阅者、状态或方法检查。

不将登记解释为对整个 Mod 的兼容承诺。未纳入审计的异步状态机改写、战斗中后来才生成的卡牌以及其他原版方法，仍需独立扩展审计覆盖，不能因同一个 OnPlay 声明而自动放行。

验收计划：

- 无第三方补丁时行为保持不变；精确匹配的一组补丁执行对应镜像。
- 相同所有者下的另一个未知补丁、错误重载、错误类别、执行顺序变化均不能误放行。
- 多补丁组合冲突、补丁卸载／重装、跨根变化及旧路线缓存失效分别验证。
- 用中性测试卡牌和补丁进行原生／预测严格差分，覆盖替换效果与前后缀组合，确认每个效果只结算一次。
- 补丁表读取限于主线程边界；搜索节点不反复扫描 Harmony 表，也不执行原生补丁代码。

当前没有本 PR 的实现或验证结果。该 PR 可独立于前两项开发；需要隐藏状态的预测实现继续依赖既有状态接口。接口命名与声明结构在实现前按现有 registry 和根失效机制进一步收敛。
