# 在选择分裂时检查战斗根支持

v85完整100场400次对照已完成并拒绝。随后10次真实单树实验通过，完整拟合器已接入并通过合成合同；新的完整候选尚未训练。以下原型阶段记录保留为历史范围，最新状态见末节。

## 有证据支持的问题

v85采用先拟合、再剪枝，五角色共80次低Hessian树提案全部缩成一个叶节点；各轮有充分根支持的乘积树桩虽然改善训练损失，均未胜过整棵普通树。结果80轮都选回Hessian3树，遗物乘积分裂仍为0。这说明目前备选方案未解决实际树生长中的支持约束，不是实战收益或数据量因果结论。

## 原型实现

`root_histogram.py`在考察每一个分裂时，分别统计左右子节点中每个战斗根的Hessian。只有两边均满足至少3根、根曲率参与度至少3，才参与二次增益比较。因而最优但支持不足的分裂会被排除，其他有效分裂仍有机会被选中，不需要选中后再整棵退回。

每次最多显式提供256列训练观察，每列使用32个原始float32顺序统计量作为边界；乘积列另外保留严格负值/非正值的两个零边界。分箱矩阵按列连续、每观察每候选列一个字节，复用边界。节点最多深4，所有叶值仍由真实偏好图的当前梯度、Hessian、原L2=.001和学习率.1计算，无新增手写卡牌/遗物价值。特征索引保持原矩阵索引，未来可沿用乘积编译，但完整拟合器尚未接线。

左右曲率分别正向/反向累加，避免用总量相减时让稀有右分支丢失精度；向量化参与度先缩放再计算，避免平方溢出或下溢。生成树后用既有逐行剪枝实现核对，要求没有任何分裂被收回；不一致时失败。矩阵缺失值、非法来源或曲率、整个角色支持不足，以及超时均显式失败。

这些约束仍有边界：根数不是统计独立样本数；有限分箱和有限列不能穷尽所有有效分裂；目前未测真实大图时间/内存，不能称为快速或实战更强。

## 已完成验证

六项合成合同通过，CPU0、0.116秒、峰值RSS约44.5MiB：向量化/逐根参与度跨尺度一致、排除稀有最强分裂后选择受支持分裂、float32零/次正规数边界、16轮条件反转、常量列及重复行不增加根支持、非法输入和超时。只有小型合成数组，最大单个数组8×20；实际条件反转为12行6根。

这次轻量合同在v85使用CPU12–15执行对照期间运行于CPU0，记录在证据中。未同时导出真实图、训练完整候选或启动另一场战斗。下一步须等v85管线终止且由所有者回收，再做有界真实单轮适用性检查；通过后才考虑保留完整模型，后者仍须30分钟内完成训练并完整跑100/400对照。

## 真实适用性实验与完整拟合接线

在v85完整对照及实际进程回收后，按事前固定协议串行完成五角色×两种字段集合，共10次单树拟合。总9.458秒、进程峰值RSS3.51GiB，退出码0；不是完整模型成本。每次都用相同48树前缀的真实训练梯度、显式根来源，所有分裂通过逐行支持核对、乘积编译后的预测逐值一致。

两种集合的全部10棵树均比原Hessian3首轮降低更多训练损失。DEFECT、IRONCLAD、NECROBINDER、REGENT两种集合均各采用1个乘积分裂；SILENT均0。扩展能力列使DEFECT/IRONCLAD训练损失进一步下降、NECROBINDER/REGENT相同、SILENT略差。树结构使用了原前缀未用的玩家能力，但这不证明实战收益，也不把分裂数当作已解决的交互种数。

`root_histogram_fit.py`复用现有完整训练/导出驱动：重新拟合48棵普通树，再做16轮更新；每轮比较Hessian3、原信号直方图、加入全部能力的直方图三种提案及零更新，按实际训练图损失严格改善选择。两份分箱缓存按角色建立一次、各轮复用；仍是一个完整模型，不按角色拼接开发集赢家，不增加玩家模式。保留树编译回原始字段，下一轮梯度来自实际保留预测。共同驱动默认仍采用原拟合器，显式新入口才启用本方法。

四项新增合成合同和共同驱动受影响的原六项合同通过。首次0.838秒、77.1MiB有9项通过，新增能力用例失败：使用6个均衡根时普通Hessian3树也可同样分裂，无法断言只选扩展提案。用例改成3个均衡根以隔离低绝对曲率条件，单独重跑0.201秒、74.6MiB通过；算法和选择标准未因该失败修改，其余9项成功结果复用。既有10项未变动的直方图底层合同也复用。
