# 半小时预算下的评分替代研究（2026-09-27）

> 这是第一版记录。后续完整基线、终局见证缓存、有限探测及协调器对照见[第二版报告](outcome-valuation-v2-20260927.md)；总时间按两轮累计计算。

## 结论

在这台电脑上，**零训练的动作条件续搜可行，但逐节点普遍使用的成本过高**。
原型在 17 个局面中有 3 个降低战损（合计 8 HP）、1 个同战损提前一回合，其余实质相同；
搜索墙钟合计 68.0→108.3 秒，实际转移约翻倍。当前保持离线显式启用，没有更改生产评分。

建议后续将它用于少量关键剪枝边界，并复用已经找到的完整后续结果，逐步减少手工权重的决定权。
不能据这些样本宣称已取代所有卡牌/Power 估值，也不能承诺有限预算下质量不下降。

分支：`research/outcome-valuation-20260927`；起点：`5a47195d`。
机器：Ryzen 7 7840H，8 核 16 线程，约 58 GiB 内存；实测 DOP1，不用 GPU。
两批成功采集与比较共 **241.42 秒，训练 0 秒**。另外给无效建局调试、首次基线恢复、增量检查
和工具检查合计保守预留 90 秒，总计 **331.42 秒（约 5.5 分钟）**，低于用户的 1800 秒限制。
这是运行成本，开发/读代码时间不包含在采集和训练里。

## 哪些分数可以替换

当前至少有四类不同职责：卡牌/选牌的枚举排序、局面特征与基础分、中间 Beam 保留排名、终局目标排序。
`SolverWeights`、`StateEvaluation`、`StrategicEffectMirrors` 等确有手工启发式；但最终要优先什么
（存活、战损、药水、成长、资源追回）是用户目标，应保留明确的政策，不靠模型偷偷学习另一套目标。

对于中间局面，可用：

`Q̂(s, a) = 现有模拟器执行 a 后，短续搜找到的完整路线的质量向量`

质量向量使用胜负、保命资源、政策折算战损、成长、回合等现有终局顺序。
它回答“这个局面先做这个动作，已找到怎样的后续”，不回答“这张牌永远值多少分”。
执行动作和后续搜索仍可能遗漏更好的路；未完成分支没有有效的完整回报标签，不能自动当负样本。

这属于 rollout / 在线策略改进思路，不要求神经网络或离线数据集。
[Bertsekas 的课程材料](https://www.mit.edu/~dimitrib/RLCOURSECOMPLETE%202ndEDITION.pdf)
介绍了前瞻加基础策略模拟。理论中的策略改进条件不能直接套到这里：当前续搜是有限 Beam，
把共享预算分出去也可能损害原基线。只保证最终不劣于本次已经保留的半预算结果，
**不保证不劣于原来的全预算搜索**。

## 本轮实现

只改 `tools/OfflineSearchHarness` 并新增 `tools/OutcomeValuation`。
`--outcome-probes N` 在 Evaluate 中把一半额度分给普通搜索，随后对观察到的首动作分别续搜。
所有 solver 共享实际工作量账本；不增加节点和软时间配置上限，且分别记录每次实际成本。
最终使用生产终局比较器，清零旧 Score 尾键。普通 Runtime / Coordinator 不注入这个实验。

为控制实现与验证范围，本轮只探索首动作，后续 Beam 仍消费原手写启发式；它是结果估值的可运行原型，
不是完整 MCTS，也不是全部评分自动化。已有生产能力牌固定前缀后验与这条思路相近，
但本实验覆盖已生成的各种首张牌和选牌选项，未接入生产能力前缀编排。

动作池最多保留 128 项，按完整动作键均匀取至多 8 项，不按手写分挑选；
仍受原搜索的动作枚举、合法性与转置准入限制，不能称为穷举全部合法首动作。
药水、结束回合动作、根准备选择暂不支持额外探针。单个原子工作可能超出软时间；
节点超额、时间截断、覆盖不足单独输出。本轮未观察到节点超额或时间截断。

## 固定配置与结果

12 根筛选组：10 个已知机制族、新 RNG 种子和统一压力，外加 2 个随机构筑。
再冻结运行 5 根五角色随机精英战，未调整参数。相较筛选组，这 5 根采用不同牌组与遭遇；
它们不是大规模统计验收，17 根也不能证明各种机制均能泛化。

两臂均为 Evaluate、DOP1、beam24、最多 12000 展开、30 秒软时间、禁用药水、零损早停；
实验后续 beam≤8、最多 8 个探针。每根采用相邻独立进程，交替两臂次序。

| 组 | 实质更好 / 相同 / 更差 | 搜索墙钟总和 | 实际展开 | 实际转移 |
|---|---|---|---|---|
| 12 根筛选 | 3 / 9 / 0 | 30.98→64.67 s | 16913→58907 | 82300→307442 |
| 5 根留出 | 1 / 4 / 0 | 37.00→43.68 s | 27323→32614 | 153283→184256 |

4 项实质改进中：

| 局面 ID | 基线 → 实验 |
|---|---|
| `focus_investment` | 战损 1→0，回合 5→6；按低战损优先判为更好 |
| 筛选 `random-regent` | 战损 22→18，回合相同 |
| 留出 `random-silent` | 战损 52→49，回合相同 |
| `draw_before_spend` | 战损均为 3，回合 10→9 |

没有胜负翻转；`target_order` 两臂均未存活，不能称为该局面已经解决。
这批实验累计做了 108 次首动作后续探针。两臂相同的是**配置上限**，不是实际模拟工作量。
耗时来自每根每臂一次离线运行，仅说明当前开销量级，不作稳定提速/可见帧率结论。
带增量验证的检查数据不进入这张成本表。

动作条件估值示例：`attack_or_block` 同一个根，固定先打不同原始卡牌 ID：

| 首动作 | 续搜找到的完整路线战损 |
|---|---|
| `BASH` | 20 |
| `DEFEND_IRONCLAD` | 30 |
| `POMMEL_STRIKE` | 20 |
| `SHRUG_IT_OFF` | 25 |

## 为什么不直接训练一个小模型

瓶颈主要是可靠标签与覆盖，不是拟合矩阵的时间。只拟合原启发式输出会复制原有偏差；
只记录当前 Beam 的赢家会遗漏被剪分支；同一战斗中的大量相邻节点不能算大量独立样本。
仓库已有 28 维残差实验，在历史留出测试中出现过胜转败，见
[既有上下文排序报告](contextual-ordering-20260922.md)。这不是本轮重新测试的结果。

| 方法 | 采集/训练负担 | 本项目的取舍 |
|---|---|---|
| 小型线性模型、岭回归、浅树 | 拟合便宜，标签仍要模拟 | 适合以后压缩已验证结果；本轮没训练，不保证泛化 |
| 动作条件 rollout | 零离线训练，计算转移到当前决策 | 本轮已运行，有少量收益和明显额外开销 |
| MCTS / 嵌套 Monte Carlo | 可零训练 | 深层组合、稀疏胜利奖励和昂贵模拟可能需要很多在线样本，本轮未实现 |
| 局部穷举 / 动态规划 | 无训练 | 适合可控的小手牌/单回合子问题；无法直接覆盖所有跨回合效果 |
| 已完成路线的反向结果缓存 | 无训练，主要复用已做工作 | 后续优先方向；必须用精确状态和完整政策标签，不能把“当前最好见证”当剪枝下界 |

[Cazenave 的 Nested Monte-Carlo Search 原论文](https://www.lamsade.dauphine.fr/~cazenave/papers/nested.pdf)
是无神经网络搜索的另一参考；上述本项目成本判断是推断，未声称已做该算法对照。

## 后续优先级

1. 用已经完成的路线沿前缀回传结果，缓存可行后续见证；先减少重复续搜成本。
2. 仅对实际剪枝截线附近、估值不确定的少量候选付费探测，既有队列保留探索机会。
3. 把终局政策、精确状态等价与启发式排序继续分开。探针失败表示未知，不制造安全剪枝证明。
4. 在生产 Coordinator 的同请求预算下对照，再做最终候选的原生完整部署；当前未完成这两项。

这比在半小时内训练全卡牌通用价值网络更符合现有模拟器和预算，但本轮仍只是探索证据。

## 验证与调试记录

- 生产 Mod Release 构建、离线宿主 Release 构建：均 0 警告、0 错误。
- Bash 结构门禁：`REFACTOR_BOUNDARIES_OK search_files=209`。
- Python 3 项合同：过期批次不启动进程、超时杀停及失败保留、留出生成覆盖，全部通过。
- 一个另建的含选牌短搜根开启 `--verify-incremental`，9 次求解共 455 展开、4282 转移、1443 选牌分支，
  完成零损胜利；这是增量回放一致性检查，不是原生 actual/simulated 或整场部署验收。
- 首次批次误用了不存在的药水枚举名 `Never`，19 个已记录进程在建局前失败（约 18.77 秒），
  改为 `Disabled`。随后修正读取 `result.json` 的字段位置，并复用已完成的首个基线，没有重跑它。
  失败材料保留，不进入质量分母；最终 runner 连续两次失败会终止并保留原因。
- 最后补齐了输出的请求级循环回放计数；本轮所有相关计数均为 0，此更改只影响诊断记账。
- 无可出牌动作的独立根检查通过：0 个探针、仅运行基线；采集器在离开首动作层时关闭，避免无可采动作时持续复制后续候选池。
- 未运行可见 Steam、完整生产协调器 A/B 或原生自动部署；未修改正式评分、版本或发布包。
- 已按仓库要求复制同源码的 DLL、manifest、MemoryCleaner 与两份许可到本地 Mod 目录；研究入口只在离线宿主中，不会启用到游戏。
