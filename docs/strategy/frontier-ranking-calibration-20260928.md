# 队列次序试验与跨回合评分校准线索

上一轮已观察到REGENT开发反例的获胜续局进入新颖性队列，却直到时间上限仍未展开。本轮先尝试让学习分取得直接调度机会，随后查看真实待展开队列中的相对名次，并审计既有训练图的跨回合约束。v77的292根补采及后续完整训练/100场评测协议继续冻结，没有加入该开发反例的标签。

## 已撤回的轮换原型

原型在学习模式的一个有界OPEN上建立两个指向同一Entry的索引，交替按原新颖性次序和按模型分数次序取出。原准入、容量、最差项淘汰和请求预算保持；淘汰、取出及Clear同时删除两个索引，不保留过期模拟图。旧算法保持单索引，没有新增玩家模式或卡牌/遗物效用。

五项轮换合同与3,000次混合操作参考对照通过，原七项队列合同、12,000次新颖性对照及现有预算合同也通过；构建与两端230文件门禁通过。初次纯检查因项目尚无NuGet资产文件失败，恢复本地无第三方包项目后成功，失败日志保留。

但在已知REGENT反例上，目标状态仍未取出，完整失败路线和终局与v76相同，观察未触顶。关闭诊断的旧算法哨兵保持路线、终局及全部剪枝计数，586展开、4,118转移、1,252选择分支。该局部试验没有达到其预期作用，因此**原型源码已撤回，未部署，也未作为完整质量候选进入100场评测**。这不能推导它在其他场景全部无益或整体更差。可复现实验差异保存在 `.local/objective-search/v79/alternating-frontier.patch`，基于 `c18f64ef`；原始失败和成功记录均保留。

## 保留的诊断改进

`BfwsBoundedOpen.RankedValues` 只读取队列已有的值和优先级。正常停止时，显式观察器对同一批待展开状态计算原队列名次，以及仅交换比较键次序后的模型分名次。新字段为零起点索引；不重算模型分、不调用新颖性判定、不改变真实队列。关闭观察时立即返回；停止后的诊断副本只在同步方法内存在，原finally继续释放所有队列状态。

恢复原队列后，REGENT反例仍为原完整失败路线。在这一份未触顶诊断中，目标状态的记录如下：

| 项目 | 观测值 |
| --- | ---: |
| 模型分 | 5.299659498758458 |
| 新颖性等级 | 2 |
| 待展开状态数 | 1,951 |
| 原队列名次（从1起） | 496 |
| 仅按模型分优先的名次（从1起） | 496 |

因此在这个实际队列截面中，仅交换新颖性和模型分的优先顺序并不能抬高目标名次。它不是整个搜索过程的反事实重放，也不证明前面495个状态均无可行胜利。该请求有时间边界、诊断工作量不同，不能据此给出正常搜索提速或内存收益。

最终诊断构建及两端门禁通过；队列只读视图新增两项合同通过，修改导出副本不会改变真实顺序或所有权。代表旧算法哨兵的完整路线、质量、剪枝及586/4118/1252工作量保持，无时间边界。最终主Mod部署按规定精确覆盖五个文件，学习模型继续关闭。

## 原训练图的覆盖

读取冻结v76的实际float32观察矩阵和偏好边，按边两端的 `battle/turn` 判断是否跨回合，没有重建终局政策或重训模型：

| 角色 | 全部偏好对 | 跨回合偏好对 | 跨回合边的权重和 |
| --- | ---: | ---: | ---: |
| DEFECT | 94,184 | 700 | 1.318 |
| IRONCLAD | 95,141 | 866 | 0.778 |
| NECROBINDER | 71,667 | 689 | 1.209 |
| REGENT | 70,793 | 544 | 1.286 |
| SILENT | 75,854 | 671 | 1.119 |
| 合计 | 407,639 | 3,470 | 5.710 |

跨回合边占0.85%；每根总权重1、292根总权重292，跨回合边占总权重1.95%。这些边并非不存在。五个模型头的线性 `battle/turn` 系数均为零，但残差树仍可使用该特征，不能将零线性系数解释为模型完全忽略回合。

这是训练覆盖的诊断，不是独立验证准确率。局部成对排序是否足以校准同一搜索队列中的不同回合状态，是下一步待验证的假设；不能仅凭比例断言增加跨回合边必然更强。后续若试验，只能使用原训练根的真实完成见证，共用现有终局比较器、根身份和权重约束，保留独立开发与最终测试边界。
