# 统一自动搜索（2026-09-27）

玩家只保留一个自动搜索入口，不再组合「多宽度路线精炼」与「多策略路线搜索」两个开关。性能预设、并行度、战损/成长/药水目标保持。旧 JSON 字段仍可读写，以兼容存档和历史测试，但不决定游戏内使用哪套搜索。

## 实现

- 保留有界新颖性探索、普通 Beam 基线和不同宽度/保留策略的精炼，共用同一主搜索轮次的实际工作账本及时间余量。普通 Beam 的中间手写评分仍在；这次降低对单一评分的依赖，不声称消除了启发式。
- 复用已经完成的真实终局见证：每根/政策/轮次最多 2048 次回调、128 个动作，只复制首动作和终局标量。首个保路池另复制最多 128 个合法首动作，不启用完整路径诊断，不持有模拟器或节点，不跨战斗训练。
- 能力搜索原有成员的份额优先交给尚无终局见证的可打能力前缀；有覆盖时沿用原能力承诺策略。未知不等于差，不用卡牌/遭遇白名单挑选，也不把见证当作可采纳剪枝界。
- 取消自动路径的能力专用节点/时间预留，替换原有「能力前缀 × 多种搜索变体」追加。主组合完成后，有余量才按已知/未知交替、牌和目标分散安排最多四次窄 Beam 首步后验。追加节点至多为此前主组合实际用量，且不能超过配置的本轮总额。完整结果依照既有终局政策选优。
- 目标达标、潜在治疗、成长/遗物目标、强制用药、取消和玩家接管沿用原政策。默认普通基线保留，不启用旧再分配或学习型门控。路线缓存与问题包记录 `UseAutomaticSearch`。

这里统一的是主搜索轮次预算。时间仍是软截止；原有药水审计按剩余请求时间执行，无胜利时的救命升级仍可增大节点帽。不能声称所有药水层/救命重搜都受严格全请求节点上限约束。旧模式只保留于内部历史消融；没有新增玩家模式。

## 本机有限对照

Ryzen 7 7840H、58 GiB RAM，普通 .NET 离线宿主；DOP1、Beam24、12,000 节点、30 秒软时间、Disabled 药水、零战损达标早停。旧对照同时开启多宽度与生产新颖性，包含独立能力前缀；其实际工作允许超出主搜索配置。

五根均获胜，四根战损相同、一根少损 1 HP；Regent 在完整终局排序中退步一回合。合计耗时下降约 67%，主要来自亡灵契约师不再反复追加能力前缀；一个小根略慢。因此不承诺每场更快/更好，也不称为同工作量提速或可见帧率改善。

初稿只收紧预算并在最后追加首步后验，亡灵契约师战损退到 52；能力槽总选已知前缀的中间版退到 57。最终让未知能力前缀取得原能力槽份额，恢复到 38，没有增加额度。失败/中间版全部保留并计入时间。最终三个受能力槽修改影响的根单独复测；无能力或先达标的两根复用未受影响结果。所有五对根状态与目录指纹一致。

这是五个已经检查过的根上的开发验证，最终修订沿用此前取得的对照结果；不是新的独立留出，也不是 ABBA。新颖性和部分旧能力成员触及软时间边界，计时与分配可能影响结果。可复算数据见 [逐根证据](automatic-search-20260927-evidence.json)。
