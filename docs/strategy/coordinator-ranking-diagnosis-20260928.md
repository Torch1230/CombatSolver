# 完整协调器的获胜前缀丢失诊断

v72中稳定丢失胜利的开发配置为`v72-validation-05-ironclad-the_insatiable_boss`。旧算法获胜、累计战损92；v71模型失败、累计战损39。v73特征索引优化保留了同样结果。本轮冻结v73引擎及v71权重，定位质量失误，不将这个开发反例加入训练或打开最终测试。

## 观察工具

离线宿主允许`--observe-ordering N`用于完整Coordinator，要求DOP1、手动药水Disabled，仍保持最多100,000条记录的硬上限。既有`SolverId`与`BoundaryId`分别区分搜索成员和保路边界，不将多个成员合并成一次排序。

追加`--observe-ordering-states-only`时，必须同时提供显式状态列表和记录额度。只为包含目标状态的保路池复制详细候选；仍记录这些池中的竞争者及目标状态的生成、准入、最终保留和展开事件。观察器只接收既有脱离值，不修改接受规则。`ordering-observation-summary.json`记录每个SolverId的写入数量及是否触顶，触顶不能当作完整覆盖。

先各取4,000条探索记录，覆盖首个保路成员到第六回合附近，两个流都触顶，因此不能单独据此评价其他成员。再从旧算法42步获胜路线提取前六步的实际状态键，以10,000条上限进行定向观察。旧算法实际写1,525条、模型2,060条，均未触顶。

## 已确认的失误

第一回合的出牌顺序不同只是表面差异：旧算法获胜路线的前五步在模型首个保路成员中仍被保留。首次观察到该完整前缀落选，是第二回合第六步，动作是`MIND_BLAST`，紧接`FORGOTTEN_RITUAL`。

| 进入目标池的模型成员 | 原始名次（从1起） | 全局保留 | 最终保留/展开 |
| --- | ---: | --- | --- |
| Beam45 | 92 | 否 | 否 |
| Beam30 | 69 | 否 | 否 |
| Beam68 | 99 | 否 | 否 |
| 另一个Beam45 | 25 | 否 | 否 |

最后一项的原始名次不能单独判断准入：完整协调器包含不同排序区段的成员，实际SelectedIndex和最终事件才是证据。目标状态在模型记录中有7次生成/准入、4次进入保路池；四个池都未最终保留。按相同完整状态键额外查找了两种动作前缀别名，均未找到模型的PruneFinal或Expanded事件。旧算法同一状态在四个保路成员中均保留并实际展开，原始名次分别8、9、8、4。

目标状态的模型评分在四次保路中同为5.23602908453212；它有6能量、3张手牌、投影HP62，既有完整获胜后缀。这个观测足以证明当前预测排序排除了一个可获胜的延续，不能证明其他被保留候选全部无解，也不能据此给某张牌手工加分。诊断中的旧战略特征只作解释材料，不作为新训练标签。

## 对诊断干扰的检查

旧算法和模型的探索、定向观察请求均成功，完整路线、终局及全部非时序剪枝/工作量与对应未观察请求一致，且均无时间边界。定向观察的7.64/8.23秒仅为诊断成本，不作为正常性能数据。四份诊断与两份对应正常请求的live/continuation两种完整根戳均一致；v73正常对照已核对实际原生装备，观察不改建局。

最终宿主构建成功，41项缓存/自动搜索/观察入口合同通过，覆盖Coordinator的串行与药水约束、记录上限、缺失状态列表及精确状态池匹配。主程序集没有变化，复用v73已完成的五文件部署，不重复部署或开启游戏。

## 对下一轮训练的约束

现在有可定位的中间排序错误，下一步应在训练侧收集跨回合的实际竞争池，并为保留/淘汰的可比较状态取得真实后缀见证。不能只增加根数或同一路线的重复观察，也不能将全部未选中候选标成死亡。目前的首回合补查无法覆盖本例第二回合的错误；需要明确扩大监督位置，而非在此开发样本上回填标签后再宣称测试改善。

当前模型仍未达到替换要求。完整原始流在`.local/objective-search/v74/`；[结构化证据](coordinator-ranking-diagnosis-20260928-evidence.json)保留目标状态全部事件、原始名次、身份、终局、冻结摘要和诊断对照。
