# 共用偏好图的 CPU 树训练器

本轮增加可选 XGBoost CPU 离线训练器，保留游戏中的 C# 模型格式与推理实现。固定 376 个有效训练根，完整导出加五角色拟合约 63 秒，原训练器约 203 秒；新模型仍丢失一场旧胜局，并漏掉另一场胜局的成长奖励，未达到替换门槛。正常游戏保持旧算法，最终测试未打开。

## 数据与算法边界

沿用资源观察实验重新采集的 408 个固定训练场景，其中 376 个有可用比较。统一抽样为 141,734 行，实际参与偏好图的 108,191 行构成 250,229 对比较。训练与 15 场开发、五场最终测试按原生遭遇及近似牌组隔离；不加入开发战斗轨迹。本实验只预先声明一个完整候选，没有按开发结果挑选角色头或调整参数。

`PrepareTraining` 现在是 C# 内置拟合与外部导出的共同入口：完整校验、同池去重、等根总权重、每根配对上限、固定抽样顺序、参与行压缩、跨根特征支持度均由这一处裁定。`FitLinearFoundation` 共用原来的连续线性基础项。外部宿主只导出二进制 float32 稠密矩阵、精确偏好边、基础分和摘要，缺失列保留原有的零语义。Python 不解析游戏终局政策，不把稀疏省略项当成未知数值。

XGBoost 3.4.1 CPU 使用 64 棵深度 6 的直方图残差树、32 桶、学习率 0.1、L2=0.001、四线程、固定种子、无行列抽样；参数在查看开发结果前冻结。目标仍为原根权重下的成对逻辑损失。每条边的真实 Hessian 为 `h * [[1,-1],[-1,1]]`，训练使用对角上界 `2hI`；其差为半正定矩阵 `h * [[1,1],[1,1]]`。这是处理行间耦合的优化近似，不把这些样本声称为独立行监督。[官方自定义目标说明](https://xgboost.readthedocs.io/en/stable/tutorials/advanced_custom_obj.html)列出限制与对角上界的用法；此处配对形式由本项目推导和数值验证。标准树学习器对零边际收益上下文分裂的处理与原训练器不同，不能保证两者学习相同交互。

可选依赖固定于 `requirements-xgboost.txt`，只安装在私有 Linux Python 环境。[官方 CPU 安装入口](https://xgboost.readthedocs.io/en/stable/install.html)提供 CPU 包；Mod 不分发或运行 Python/XGBoost。导出模型继续由原 `OutcomeModelFile` 校验 schema9/游戏 MVID，并在 C# 内压缩未使用列。

## 数值与结构验证

- 103 项 C# 契约通过，包括导出偏好边顺序/权重、显式零矩阵、线性基础与原拟合一致、坏数据及覆盖已有证据拒绝。
- 固定 20 个真实新格式根，重构前后完整/线性模型分别逐字节相同。完整模型摘要为 `e97cba8f110a21ff5de0a0fe6ee9025270e8e8d2590a7ac123925b34c0f663ab`；线性为 `105ec90967767883d82c073d7f8413ee91686a02c3224db5c8791e6755944850`。
- 原训练与导出的 42 个总量/逐角色字段相同，包括根顺序、抽样行、参与行、配对类别与数量。
- 五项 Python 检查通过：有限差分梯度、Hessian 上界、极端边际、树拟合方向、模型转换和非有限观察拒绝。缺少可选依赖的普通环境明确跳过这五项，不影响其他工具测试。
- XGBoost 使用严格 `<` 分裂，C# 使用 `<=`。将 float32 阈值替换成其 **double 前驱**，保持所有有限 float32 观察的分支选择；实际 C# 核对 26 个零、次正规数、端点和阈值相邻观察，预测完全一致。
- 对完整训练观察，转换后 double 推理与 XGBoost float32 累计的最大绝对差约 `8.14e-6`，250,229 对训练比较没有符号翻转。另取固定 1,280 个实际观察，C# 与转换参考实现预测完全一致；不声称 XGBoost 与 C# 的全部数值逐位相同。
- Release 主程序集和宿主构建、两端结构门禁通过（221 个 Search 文件）。首次构建的自动复制受沙箱目录权限限制；禁用自动复制后构建成功，再精确部署已验证的五个 Mod 文件。没有启动可见 Steam。
