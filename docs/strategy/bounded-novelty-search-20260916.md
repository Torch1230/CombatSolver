# 有界新颖性与 Beam 组合（2026-09-16，未发布）

## 交付方案

性能页的「多策略路线搜索（实验）」开关默认关闭。开启后先用一段有限预算探索结构不同的路线，再把剩余请求时间和主搜索节点交回现有 Beam 搜索；完整候选按既有终局政策选优。无需训练数据、模型推理或新增运行时依赖。

选择依据是同一总预算下的战斗结果、完整请求成本及实际部署。它会改变中间保路，不能承诺所有战斗都优于原搜索；详细样本与限制见下文。完整结果预计损失至少 8 HP 时，关闭状态下显示一次可永久隐藏的开启引导；7 HP 及以下和功能已开启时不显示。

基线为上游 `7f806de` / 0.39.0，包含已合并的多宽度精炼与此前分配优化。本轮冻结游戏 0.111.0、RitsuLib 0.6.2；早期旧版本研究数字不作为当前收益。没有提升版本、发包或启动可见 Steam。

## 算法与所有权

1. `CombatBeamSolver.NoveltySearch.cs` 复用当前动作准入、模拟展开、回合标注和最终排序。新颖性在候选生成时记录；它只决定探索顺序与剪枝，不是状态相等关系。
2. 特征包括原评分的结构量、能量/HP/格挡分桶、各牌区的卡牌身份/升级/有限重数、前三张抽牌身份与 Power 身份/层数。分区为敌方剩余 HP 的十点区间和已用药数。它不是完整战斗描述，不宣称剪掉的状态等价。
3. `BfwsPackedNovelty` 将值类型事实分配整数 ID，单事实和事实对打包为 `ulong`。同分区且已完整记录的父节点中，未变化的旧事实对不再查询；容量触顶后保守停止复用。参考字符串实现留在独立测试项目。
4. `BfwsBoundedOpen` 按新颖性、现有评分、稳定序号排序，最多保留 2,048 项。满时立即移除最差项，不保留含模拟图的墓碑。父节点的全部后继归属确定后，按快照身份释放被剪项；正常结束、取消和异常均清理待搜图。
5. 默认宽度 2、熟悉后代配额 M=0，元组历史最多 1,000,000 项，最多 128 个动作、32 个后续回合。队列上限不包含正在展开的父批次，元组数量也不是整个请求的字节硬上限。
6. `NoveltyPortfolioBudget` 在普通战斗最多分配一半时间、章节首领最多四分之一时间给探索，且最多 5 秒、2,500 个节点和总节点的四分之一。少于 2 秒或 1,000 节点的请求直接走 Beam。探索与 Beam（含多宽度成员）共享主搜索节点上限，按实际消耗扣减；所有阶段共用请求时间截止点。Smart 药水审计沿用上游每层节点上限和剩余请求时间，不把原有各审计层的节点预算改成全请求硬上限。
7. 两种搜索保留独立队列与转置，只共享已完成结果。提前结束复用可接受战损、成长目标、药水政策及接管规则；不把中间高分当成完整胜利。调用者取消及模拟异常继续向外传播，只有已定义的无法满足强制用药边界可以交回 Beam。

`Phases` 提供生产内存预约、Runtime 回收信号、进度和接管边界；搜索层不操作 GC 模式或读取 live 可变值。开关在请求捕获、设置往返、中英 UI、路线缓存身份和问题包有效政策中贯通。`NoveltyPortfolio` 遥测描述主搜索组合，最终 Smart 审计可能选出另一份结果；最终质量和成本以 `SolverResult` 及 `total_*` 为准。

## 实验与取舍

| 方向 | 实际结果与决定 |
| --- | --- |
| 紧凑编码与父差量 | 12,000 个生成状态与字符串参考逐项比较新颖性、表项/事实/分区数、容量边界和直方图；三个游戏根的动作、工作量和最终结果一致。保留。 |
| 有限熟悉后代 M | 小图中原严格剪枝无胜利，M=4/16 能到达战损 6 的胜利；复杂根中会消耗更多队列和预算，未稳定优于 M=0。保留纯共享配额机制及合同，交付参数为 M=0。 |
| 有界队列替换 | 旧实验遇到 2,048 队列即停，复杂根常无完整结果；移除最差项后仍可继续探索并在两个精英根取得更低战损。保留。 |
| 单独使用新颖性搜索 | 多个复杂根缺少完整胜利，不能代替当前 Beam。交付共享总预算组合。 |
| 短前置探索 | 同进程热样本 1.25/2.5 秒可捕获改进，但独立进程铁甲精英 2.5 秒只探索 484 节点，错过改进；5 秒配额能捕获战损 37。最终全部对照使用独立进程。 |
| 检查点重放/回溯 | 当前主要代价仍为模拟分配与展开；有界队列已限制保留图，未取得额外重放能抵偿成本的证据，本轮不加入。 |

熟悉后代配额采用同一最近新颖祖先下共享 M 次准入，兄弟和后续熟悉节点共同消耗，并非每条路径或每个父节点重新给 M 次。来源为 [Polynomial-Time Exploration for Planning with Width-Based Algorithms](https://nirlipo.github.io/publication/lipovetzky-2017-polynomial/poly-bfws-icaps-17.pdf)。本实现使用领域特征、生产准入与额外队列界限，不把论文的形式化保证直接套用到本游戏。

原型的字符串/packed/delta、有限熟悉后代及探索份额选项保存在[历史实验补丁](bounded-novelty-search-prototype-20260916.patch)，基于 `7f806de`；它不参与当前生产编译，最终接口已收敛为类型化选项。

## 验证口径

- [冻结方案](bounded-novelty-search-plan-20260916.json) 包含 14 个开发/哨兵根和 5 个在选参数前生成、未参与选型的新根；[固定输入](../../coverage/novelty-search) 与 [复跑说明](../../tools/BfwsResearchChecks/README.md) 一并提交。
- 全部质量/成本样本使用完整 Smart 协调器、正常 Release、同一 10 秒与节点预算、DOP1、NoGC 关闭、保留成长/遗物与目标战损早停。A 为关闭开关，B 为开启；每份样本单独进程，逐根交替 AB/BA，核对五份输入/原生开局 JSON。
- 不比较热启动探索批次的耗时。累计分配不等于存活堆，Linux `VmHWM` 包括游戏初始化；限时工作量不同也不称为同工作量加速。超时和失败样本保留，不当成通过。
- 无头原生部署使用冻结的首份完整结果、Instant/0 秒，记录战损、药水、结束回调和计划外重算；根不变合同同时核对完整 live 与 shadow 状态。

## 结论与适用限制

交付的是本轮候选中有实际质量或成本收益、能完整部署的可选组合。它没有稳定优于原搜索的逐场保证，默认保持关闭。没有使用训练、卡牌/遭遇专用分支或扩大原主搜索预算来获得收益；旧药水审计的每层节点规则保持原样。

本轮没有可见 Steam、FPS、肉眼动画、可听音频或 Windows 游戏性能验证；两个结构门禁不等于这些测试。完整原始产物保留在本机证据目录，提交的[结构化摘要](bounded-novelty-search-20260916.json)包含每份样本、runId、配置、工作量、反例与失败；复跑使用固定输入。
