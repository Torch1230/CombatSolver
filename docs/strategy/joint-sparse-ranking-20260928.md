# 联合稀疏线性排序研究

联合拟合改善了固定留出集的排序损失，完整模型每个角色仅32–59个非零系数，但实际搜索仍两场退化，没有达到替换旧算法的要求。新增训练器只作为离线研究工具保留；游戏与夜间任务默认不变，最终测试继续封存。

## 方法与职责

原线性基础最多128次贪心坐标更新，可能反复使用少量列。本轮直接联合学习现有观察列，使用C#导出的同一偏好图、根权重和特征支持度；不以旧基础分为标签，也不重新定义胜负、战损或卡牌效用。

`sparse_fit.py` 对偏好对构造稀疏差值，按训练侧根归一权重计算列RMS（下限1），根内不变的列不参与拟合。目标为加权平均配对逻辑损失，加L1及L2正则。将系数写成两个非负向量之差，用有界L-BFGS-B联合优化；L1产生的精确零直接沿用原C#列裁剪，不另设经验截断阈值。还原原始单位后写入已有 `LinearWeights`，原schema、游戏身份和零残差树保留，不新增运行格式或Python运行依赖。

固定最多256次迭代，输出实际停止原因和KKT残差；达到固定上限可作为明确标注的未收敛研究候选，不宣称全局最优。所有角色合用一个时限；完整模型预算仍计入C#导出，停止、损坏输入或其他优化失败不发布完整模型。

## 验证与唯一完整候选

六项新Python合同通过：解析梯度、具有解析最优解的排序问题、L1精确零、根内不变列、重复对不增加根权重、原单位预测以及停止/坏输入/重复输出目录拒绝。两端结构门禁通过222个Search文件，架构地图与相关skill同步离线所有权。主Mod和离线宿主源码未变，复用v48成功构建、原生合同及五文件部署，不重复构建或复制。

唯一选中配置在494根图上拟合9.83秒（外层10.26秒），加历史导出59.80秒，完整成本70.07秒。拟合峰值RSS1,190,400,000字节，约1.109GiB；五头非零系数为32、40、58、59、47，KKT残差约1.17e-6–3.61e-6。1,280条实际观察的Python/C#预测零差异。

两场退化，没有改善，未进入剩余十场或最终测试。搜索峰值RSS约291–353MiB，全部观察到时间边界；更少系数和较短单次墙钟不能证明同质量提速。完整本轮研究180.73秒，用户的最终目标仍未完成。

本轮结果说明联合拟合和适当稀疏化能改善离线排序，却仍不能弥补实际搜索中的胜局丢失。后续需要继续检查状态分布、监督质量与非线性条件关系，不能仅继续降低同一留出损失或增加随机行数。
