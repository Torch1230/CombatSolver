# 状态键漏掉整场历史计数（2026-09-19）

分支 `fix/gold-axe-state-key`，基线上游 `0e6cc2d`（0.41.0）。全部数字来自离线宿主（不启动游戏），High 90/50000、Coordinator、Smart、DOP 1、`fixedSearchBudget`，两个宿主并行。

## 问题

`CalculatedVarSpecRegistry` 里六张牌的动态变量读的是**整场**历史计数（`CombatManager.Instance.History` 的实况部分 + `simulator.History` 的模拟部分）：

| 牌 | 读的计数 |
|---|---|
| 金斧 `GOLD_AXE` | 已完成出牌数（全体） |
| 电流相生 `VOLTAIC` | 玩家闪电球充能次数 |
| 扯碎 `TEAR_ASUNDER` | 玩家受到的未格挡伤害事件数 |
| 亡魂牵引 `PULL_FROM_BELOW` | 玩家打出的虚无牌数 |
| 谋杀 `MURDER` | 玩家抽牌数 |
| 超质量体 `SUPERMASSIVE` | 玩家生成牌数 |

`BuildStateKey` / `SimulatedCombatState.AppendFingerprint` 覆盖牌堆、能力、RNG 与逐回合计数，不含这些整场总数。于是两条只差这些总数、其余逐项相同的分支哈希相同，`RankBest` 的精确去重只留一条，留下的那条之后这些牌的伤害/数值算错。转移影子实验（`exp/shadow-transition-trace`）在 50 根语料的 1390 万次转移里抓到 6 对"同键不同输出"，全部是金斧（19 次对 18 次完成出牌）。

## 修法

新增 `CombatHistoryCounterKey`：根牌组（`root.PlayerCardIds`，手牌 + 抽牌堆 + 弃牌堆）含上述任一张时，`BuildStateKey` 遍历一次模拟历史，把六个计数追加进键；根之前的实况历史整场恒定，不进键。不含这些牌的战斗，键逐位不变。战斗中途才生成读者牌，以及根捕获时读者牌已经在消耗堆、之后被回收的情况，都不会命中这项根牌组条件，仍是已知缺口。

## 验证

三组语料，基线为上游 0.41.0 DLL，比较用 `compare_results.py`（排除耗时/内存字段）：

| 语料 | 根数 | 含读者牌的根（按生成场景 loadout 查） | 实际不一致的根 | 其余根 |
|---|---:|---|---|---|
| EQ（1 瓶药） | 10 | `NECROBINDER-ELITE-00`（亡魂牵引） | 同左 1 根 | 9 根 983 字段一致 |
| FULL（2 瓶药） | 40 | `NECROBINDER-ELITE-00`（亡魂牵引）、`SILENT-BOSS-01`、`SILENT-ELITE-03`（谋杀）、`SILENT-BOSS-03`（金斧 + 谋杀） | 同左 4 根 | 36 根一致 |
| GA（EQ 规格 + 无色牌固定含一张金斧） | 10 | 全部 | 全部 10 根 | — |

不一致的根恰好就是含读者牌的根，一个不多一个不少。这些根上键变细的效果：

| 根 | 基线 战损/用药/胜 | 修复 战损/用药/胜 |
|---|---|---|
| EQ-NECROBINDER-ELITE-00 | 8 / 1 / 胜 | 8 / 1 / 胜（路线变，结果同） |
| FULL-NECROBINDER-ELITE-00 | 8 / 1 / 胜 | 8 / 1 / 胜 |
| FULL-SILENT-BOSS-01 | 53 / 0 / 胜 | 53 / 0 / 胜 |
| FULL-SILENT-BOSS-03 | 70 / 0 / 负 | 70 / 0 / 负 |
| FULL-SILENT-ELITE-03 | 48 / 0 / 胜 | **29** / 2 / 胜 |
| GA-DEFECT-ELITE-00 | 9 / 0 / 胜 | **8** / 0 / 胜 |
| GA 其余 9 根 | — | 路线有变，战损/用药/胜负全部相同 |

15 根含读者牌的根：2 根战损下降，0 根上升，0 根胜负翻转；展开量比 0.997–1.000。路线普遍变化是搜索的混沌性（去重集合变一点就换路线），不是收益本身。

## 试过的另一种做法：无条件追加

顾问指出条件式修法有缺口：读者牌可能战斗中途才出现（随机无色生成能生成金斧），那时只差计数的分支已经合并，事后补键救不回来。于是试了无条件追加（每个键都遍历一次模拟历史）：

| 语料 | 路线变化 | 战损 更好/更差/相同 | 胜负翻转 | 展开比 |
|---|---|---|---|---:|
| EQ 10 | 9/10 | 2 / 2 / 6 | 1 根胜→负（路线未结算） | 0.988 |
| GA 10 | 10/10 | 1 / 0 / 9 | 0 | 1.000 |
| FULL 40 | 37/40 | 4 / 12 / 24 | 3 根胜→负、1 根负→胜 | 0.983 |

键变细波及了 46/50 根，胜负翻转 3 负 1 正、战损"更差"多于"更好"（合计差被两根未结算路线的大数拉负，不能当收益）。样本太小不能下"更差"的结论，但也没有任何收益证据；每个键多一次历史遍历的墙钟代价在这批里没有受控测量。在没有增量计数器（历史追加时同步维护、键构建零遍历）之前，不值得为一个罕见缺口付这份扰动。**因此 PR 采用条件式修法，缺口写进开发笔记**；增量计数器 + 无条件追加留作后续，届时要单独做同工作量质量对照。
