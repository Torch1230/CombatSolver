# 零训练估值第二版：终局见证调度（2026-09-27）

## 结论

已实现“保留完整基线 + 复用已完成终局的估值 + 少量条件续搜”，不训练模型，也没有增加手写卡牌权重。
22 个 Evaluate 根中，4 根降低战损、2 根同战损更早结束，其余 16 根实质相同，无胜负翻转。
但这些收益不能直接等同于完整生产搜索的收益；完整协调器的对照结果见下文。
实验继续通过离线入口显式启用，正常游戏不启用这套调度。

这里的“估值”是模拟器找到的可行后续结果。后续 Beam 仍使用原启发式，因此没有消除所有手写评分，
也没有证明最优解或通用泛化。缓存只保存当前冻结根的首动作与结果标量，不保存可直接执行的完整路线，
不会跨战斗迁移一张全局卡牌分数表。

分支：`research/outcome-valuation-20260927`。机器仍为 Ryzen 7 7840H、8 核 16 线程、约 58 GiB，DOP1，无 GPU。
本轮与[第一版](outcome-valuation-20260927.md)共用用户的半小时采集/训练预算。

## 实现与边界

1. 原搜索先取得完整配置的节点/软时间额度，保存其返回结果。`SearchCompletedOutcomeObserver` 在已经完成胜利的串行边界复制首动作与终局标量，先检查容量，不持有节点/模拟器，也不填充节点动作缓存。默认不注入。
2. `RootOutcomeCache` 每次根请求新建，最多接收 2048 次回调、128 个动作。回调可能重复观察同一终局，次数不代表独立样本数。动作键保留物理牌、目标、状态、选择及次序，去掉显示文案；政策不一致显式失败。
3. 至多安排 4 个首动作探测，先覆盖不同牌/目标组，再覆盖组内物理牌与选择。已知动作按终局政策排序，并与未知动作交替；分组只用于调度，不能当作状态等价。已有好见证的动作仍可再搜，差或未知见证均不作为质量上界。该轮调度在基线结束后冻结。
4. 每个探测使用 beam≤8。追加展开至多等于基线实际展开，同时所有 solver 累计不超过原配置节点帽；剩余墙钟按整个请求扣除。达到明确启用的战损目标时复用原组合早停条件。基线用尽额度则不追加。
5. 只有完整、存活、无预测风险且快照无语义边界的胜利参与替换，沿用原终局政策并清零旧 Score 尾键。第二版允许搜索触及 NodeLimit 后已经找到的完整胜利；未完成快照、部分接管、内存截断、时间截断等不由此放宽。

首动作池仍来自已有外层 Prune 输入，最多 128 项，无法找回更早未生成或未准入的分支。
额外探测暂不支持药水、EndTurn、直接结束回合的牌，以及带根准备选择的局面。
终局旁听拿到的是搜索内的候选摘要，仅用于安排探测；最终选择必须重新使用正式结果的终局摘要。

`CombatSearchCoordinator.Solve` 增加显式测试账本注入点，默认仍每请求新建账本。
离线 `--selective-outcome-probes --outcome-probes 4` 支持完整协调器基线，且要求 `Disabled` 药水政策，
避免用单个 Beam 后续绕过智能药水审计。正常 Runtime 没有注入缓存或探测策略。
所有 `Total*` 指标涵盖基线及探针，其他单 solver 指标仍属于所选结果。

保留的是**本次运行中**全额度基线的结果；旁听开销仍可能影响时间截断下的遍历，
不能据此保证比另一次独立运行永不降级。原协调器的专用成员本身可能超过节点或软时间配置，
实验按实际总量扣账、用尽后不追加，并明确记录基线超额；不会伪装成严格的整请求预算合规。

## 固定对照

两臂节点配置 12000、软时间 30000 ms、beam24、DOP1、禁用药水、零战损早停。
实验追加至多 4 个 beam8 探针；每根相邻独立进程、交替两臂次序，使用生产质量比较器。
17 个旧根作为回归集；另外先冻结五角色随机精英的新种子 `-v2-confirmation`，随后不再调参。
重复使用同一机制族不能证明新机制泛化。

## 完整协调器

两臂都使用 `Coordinator --use-portfolio`，禁用药水。3 个目标/哨兵加同一批 5 个新种子，
**8 根全部实质相同，没有新增战损或回合改善**。

| Coordinator 组 | 更好 / 相同 / 更差 | 搜索墙钟合计（基线→实验） | 展开 | 转移 |
|---|---|---|---|---|
| 3 个目标/哨兵 | 0 / 3 / 0 | 32.82→34.35 s | 27396→28898 | 210953→216889 |
| 5 个新种子 | 0 / 5 / 0 | 175.37→176.37 s | 191539→193103 | 1089422→1097995 |

其中 4 根的完整基线已超过 12000 节点，1 根达到早停目标，另外 3 根实际追加共 12 个探针，均未改善。
新种子 `random-defect` 与 `random-necrobinder` 的协调器已经超过追加探测的 30 秒时间配置；
后者两臂最终均为 TimeLimit，单进程分别约 112.80/112.20 秒，均在固定 120 秒硬超时内。
普通 Coordinator 宿主的 `timeBoundaryObserved` 不完整覆盖子搜索/追加时钟，不能用其 false 推断没有时间边界；
证据同时保存最终 `resultBoundary` 和实验观察值。时间截断也使两臂实际展开可以不同。

原三个根的协调器基线战损分别已为 12、0、13，而单棵搜索基线为 20、1、22。
新种子 `random-silent` 的完整协调器是 34，单棵搜索探测曾找到 33，但协调器已经耗尽追加节点额度。
所以结论是：**末尾追加探测尚无收益证据，而且经常已经无预算可用**，并非证明这类结果估值永远无用。

若继续，应把见证调度放进协调器已有成员的预算分配中，而不是再叠加一轮完整搜索。
这需要单独验证预算重分配的损失；当前保留可复现实验和旁听基础设施，不默认替换生产评分。

## 失败试验与修正

第一轮只优先探测缺少好见证的动作，并跳过已有相当见证的动作。三个目标/哨兵均没有新增收益。
这把“找过一条好路”误当成“无需再探索”，还让未知但较差的动作消耗额度，已经撤回。
改成好见证与未知交替、保留所有动作的探测资格后，`focus_investment` 一次探测就找到零损路线。

随后 `random-regent` 的首探针在 544 展开内已找到战损 18 的完整胜利，原型却因搜索 NodeLimit 拒收。
核对 `CombatBeamSolver.Phases` 后确认，搜索停止原因与所选快照的边界是两回事。
第二版检查两者并分别输出，不扩大预算，也不把尚未完成的分支改标为胜利。
两个中间试验各为 3 根，耗时 34.99 与 34.04 秒，均保留在总账和证据中，不计入最终质量样本。
