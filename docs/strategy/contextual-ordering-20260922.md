# 上下文排序实验：设计、反例与当前边界（2026-09-22）

分支 `feat/contextual-search-ordering-20260922`，冻结基线 `2a4b1a45`。用户要求自行构造多类战斗，改善排序与高压搜索质量，不能靠大幅提高速度/内存成本换收益。本记录是进行中的证据，不是优化已完成或模型批准上线的结论。

## 实现边界

正常 Runtime 不注入模型，保留现有评分。离线宿主可以明确加载一个 28 维线性残差；特征只读取已有节点快照，栈上计算、无每节点数组持久化。修正以 HP 评分单位表达，实验首版上限 ±2 HP；终局、状态等价、转置支配及战斗语义不消费它。调用方搜索前验证 schema、特征顺序、有限系数、范围、Mod/Game 的 MVID；超出特征包络时该节点回退原分数。错误模型直接拒绝，不掩盖配置错误。

**这不构成质量保证。** 范围内的微小排序变化也能改变后续保留节点；同序比较器也不是 MonoBeam 完整算法，更不证明固定时间下比旧搜索更好。预测值不是可采纳下界。

## 自生成语料与测量

`tools/ContextualOrdering/generate.py` 生成 105 根：10 种机制 × 低/高压力 × train/validation/test，以及 5 角色 × Monster/Elite/Boss × 3 划分的随机构筑。涉及攻防取舍、卖血换资源、力量、消耗/压缩、毒、持续防御、先抽后花、球、集中与多目标。相关压力变体不跨划分；这是种子留存，不能声称机制族完全隔离。没有玩家问题包、没有伪造最优解。

第一次 v1 的 20 根有 4 次建局失败：旧作卡名不存在，以及最大生命未同步导致压力被原生截断。改用有效原版牌、同时注入最大/当前生命与敌方力量，独立生成 v2；旧失败保留，不并入成功样本。

v2 训练划分固定 beam24、20000 展开上限、60 秒预算、DOP1、Smart、正常零损停止。baseline/base/band 复用既有排序，不改宽度；105 次进程全部成功，101 次无时间切层，4 次 TimeLimited。一个 Silent 随机构筑达到约 35 万转移但受时间边界影响；不能拿它证明固定节点收益。Defect 普通遭遇基线 20000 展开/119281 转移，未碰时间边界。必须同时报告展开与转移。

这些是发现问题的观察，曾与诊断采集、构建重叠；**耗时不可作为最终 ABBA 性能结论**。

| 训练根 | baseline 战损 | base 或 band 战损 | 说明 |
|---|---:|---:|---|
| 多目标，低压力 | 23 | base 17、band 18 | 非能力牌的差距 |
| 资源投资，高压力 | 12 | band 9 | 同宽度、同预算 |
| 力量铺垫，高压力 | 失败 | base/band 13，胜利 | 排序影响胜负 |
| 消耗资源，高压力 | 17，胜利 | base 10；band 失败 | 不能全局切换 |
| 毒，高压力 | 2 | base 8 | 换排序退化 |
| Silent 随机 Boss | 17 | base 27、band 48 | 泛化反例 |

这里战损只是便于阅读；接受与否调用实际 `CombatSearchCoordinator.IsBetterPotionPolicyResult`，保留复活、成长、战略资源与药水政策。报告另列把末位 Score 置零后的比较，避免把旧启发式尾数当作实质收益。

## 标签与首个失败模型

20 个定向训练根 × 3 排序、每次最多导出 2500 个真实保路候选。仅用同根完整动作前缀匹配到的完整获胜/死亡路线作为后续见证，不把无后续的被剪节点标成负样本。全部 60 对见证通过根戳、预算与政策一致检查。

最初 206 对包含旧 Score 尾键差异；排除后只剩 **94 对、13 个根**，数据远少于“导出数万节点”表面上看到的数量。标签是已观察到的较好后续，仍不表示较差见证的分支没有未发现的更好后续。

纯 Python 岭正则逻辑排序损失，按根均衡，优化过程不运行搜索；系数从零残差开始，拟合包含相同截断函数。首模型训练代理 loss 2.35533→2.34005，正确排序仍为 39/94。随后跑 20 个真实训练根：

- 实质政策：6 好、4 差、10 同；含原末位评分：7 好、4 差、9 同。
- 多目标战损 23→17；力量高压从失败→13 HP 胜利；资源高压 12→11；集中高压 7→5。
- 消耗高压从 17 HP 胜利→失败；抽牌高压 5→9 HP；另两根相同战损但结束回合推迟。
- **候选被拒绝，没有上线。** 未动 validation/test，未把训练集收益写成泛化质量收益。

进一步单特征筛选以训练内部 leave-family-out 的代理损失比较，不称为真实战斗敏感度扫描。代理前两名 hand / reachable_hand 复搜 20 根后，实质政策分别为 4 好/3 差/13 同、3 好/4 差/13 同，仍拒绝。hand 同样使消耗高压由胜转败。不能用代理排名改善替代真实战斗质量；后续转向定位较好见证前缀第一次被丢掉的保路环节。

## 已完成验证与未完成项

- 模型能力 DLL Release 构建 0 警告/错误，宿主同样通过。
- 514 组真实/边界特征的 Python/C# 对齐，加上版本、系数、范围、截断和终局旁路：14921 断言通过。
- 默认未注入模型时，消耗高压与多目标两根的完整路线、根戳和全部非时序 pruneCounters 与冻结基线相同。

## 复现入口

```bash
python3 tools/ContextualOrdering/generate.py --out .local/contextual-ordering/repro-corpus
dotnet build CombatSolver.csproj -c Release -p:CopyModOnBuild=false
dotnet build tools/OfflineSearchHarness/OfflineSearchHarness.csproj -c Release
```

冻结基线 DLL 后，variant JSON 明确提供 `name,dll,harness,arguments`。旧 DLL 需搭配兼容的旧宿主，新宿主引用实验 profile 成员，不能假设可以加载旧 DLL。所有工具拒绝覆盖已有输出目录。完整参数见 [工具说明](../../tools/ContextualOrdering/README.md)。

本机证据在 `.local/contextual-ordering/`：`screen-v2`、`observed-v2`、`pairs-v2`、`fit-v1`、`fit-v1-train`、`fit-v1-comparison-fixed`、`default-sentinels`、`feature-contract-result.json`。大日志和模型产物不提交源码；重跑必须从精确生成输入及冻结 DLL 开始，不能用当前版本冒充旧基线。

## 首次已观察到的排除位置

追加三个根的 GlobalRetention / RetentionPoolFinal 诊断，6 次均无时间切层，根与原始发现相同。力量高压较好见证的第 3 个动作后被排到 rawRank=34（从零计），未进入24席，没有同状态别名留下；此时并没有开能力，实际上是防御→剑柄打击→耸肩无视，说明问题不能缩成“能力牌权重不足”。消耗高压的第8个动作（进入第3回合）rawRank=85，被外层Prune排除，也无同状态别名。这个状态实际16 HP、3能量、5手牌，结束当前回合的威胁投影为−1 HP，分数已经承受−1e12死亡罚分；它仍有可赢的完整后续见证。多目标在当前有限采集窗口内未找到可确证排除点，继续记未知，不能推断没有误剪。

这是具体后续研究入口，不是已证明可以取消所有死亡惩罚。真实死亡与尚能出牌时的致死意图应区别考察，修改前需要构建反向哨兵并按同预算复搜。
