# 按战斗回合分层的训练权重

回合等权改善了前期排序，却损害后期及整体留出表现。候选没有达到预先规定的整体门槛，未运行新的外部战斗或完整494根重拟合；生产和夜间默认不变，最终测试继续封存。

## 实现与不变量

原394根训练图中，后期状态占较高根归一权重。本轮新增显式离线输入 `pairWeighting=turns`：仍先按共享C#政策比较、去重、确定性抽样并限制每根最多4096对，再按每对较晚端点的实际回合分层。每个有偏好的回合等权，回合内各对等权，每个实际战斗根的总权重仍为1。不增加具体卡牌分、不改变终局标签、特征支持度、采样行或端点；默认 `pairs` 保持原值。

宿主仅解析配置，原始正整数回合在抽样前校验；共享 `PrepareTraining` 独占权重计算，内置和Python训练器共用其导出。缺失、非有限、非整数、非正或超整数范围的回合不能被抽样隐藏；列消融移除必要回合时明确失败。模型格式、观察格式、推理和玩家界面均不变。审计仍用全部原始偏好及原来的根均值，额外回合分项只用于诊断，不随训练权重切换。

## 验证

Release主Mod构建16.65秒，最终宿主2.60秒，无警告或错误；146项C#合同通过。新合同覆盖不同回合/根大小、跨回合归属、重复池、4096对上限、未采样非法回合、列排除、内置基础项、二进制导出及审计分项总量。首次新增导出检查误把未经过宿主行抽样的顺序作为预期，失败后修正测试为同一个既有行抽样入口；生产逻辑没有为通过测试而改变。

20个固定实际根的默认完整模型及线性模型与冻结v48程序逐字节相同。Bash/PowerShell结构门禁各通过222个Search文件；架构地图、工具说明和相关skill同步所有权。相同最终源码五文件部署完成，无可见Steam测试；这是训练权重改动，不涉及游戏结算，复用既有原生语义证据。

实际394根导出逐头核对：151,675条抽样行、112,573条参与行、245,159对的端点、顺序、类别、列和观察矩阵均与原图相同。每根每回合质量按旧图的已验证根边界直接核对，最大误差约4.36e-15。仅权重及据此拟合的参数变化。

## 固定留出结果

同一394根训练、100根完整家族留出，仍用L1=.01、L2=.001。基础、尺度、词表仅在训练侧构造。只允许一个全角色候选，以原有角色→家族→根等权、全部回合损失决定是否进入实战，不按回合或角色挑选模型。

五角色导出44.79秒、拟合进程7.01秒，完整候选成本51.80秒；拟合峰值RSS935,165,952字节，约0.87GiB。各头优化器均报告收敛，KKT残差约1.58e-6–2.53e-6；全研究64.67秒。整体损失变差，停止在内部开发；没有用改善的首回合分项覆盖预定验收标准。未执行新模型的外部推理/战斗验收，未证明同质量提速。

结果进一步表明，当前模型对前期决策的排序弱于后期；让所有回合等权只能转移误差，尚不足以解决长期规划。原始日志、冻结程序及脚本位于 `.local/objective-search/v52/`，[结构化证据](turn-balanced-ranking-20260928-evidence.json)保留全部结果。
