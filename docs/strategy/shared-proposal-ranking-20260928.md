# 开局候选共用所选排序器

学习分支将快照中的旧评分置零，但开局补充候选仍有19处直接按该字段排序。现在这些现有排序位置与新颖性队列共用`CandidateRankScore`：传统分支继续返回原分数，学习分支使用已有的上下文模型及其有界缓存。筛选条件、主启发式键、去重、配额、终局政策和预算均保持原有职责。

这解决了模型接入的一致性问题；五场开发对照没有改善最终决策，模型仍不能替换默认旧算法。不能把它说成已移除全部手写启发式。

固定使用此前v62完整模型，没有重训、按角色拼头或根据新结果换模型。修正前采用v65冻结引擎，修正后采用v67；每对复用同一请求、装备、种子及两个完整根戳，Beam24、节点12000、30秒、DOP1、自动组合搜索。比较同时保留同配置旧算法及v48历史门槛。

五场修正前后动作路线和最终质量全部一致；相对旧算法四场主要质量持平，一场从胜利退化为失败（`unseen-necrobinder-kaiser_crab_boss`，旧策略胜/64，学习策略负/66）。另外两场双方均失败，残敌血量略差；不能把失败局的主质量持平解释为整个终态完全相同。旧策略哨兵在新源码上仍胜/64，完整根和动作路线与修正前完全一致。
