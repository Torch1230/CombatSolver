# 小规模成对结果学习与场景隔离

本轮完成了训练与实现，但**候选被开发回归拒绝，不能替代生产手写评分**。不新增玩家模式，自动入口继续使用原实现。基线为 `5f36c4ed`，含已合并的上游 `8915a7c0`。数字与输入指纹见[结构化证据](pairwise-outcome-ranking-20260927-evidence.json)。

## 先修正测试口径

旧 `ContextualOrdering/generate.py` 的三个 split 共用场景模板，只改变种子、抽牌顺序与血量。其 `test` 名称不能证明跨场景泛化；已反复观察的根更只能作为开发回归。此前报告中相应“独立/留出”的表述仅说明未直接拟合那些根，**不满足本轮用户要求的场景隔离**。

新增 `tools/OutcomeValuation/dataset.py`，在训练或开启评估前检查：

- 同模板家族、同遭遇家族不得跨训练/评估；敌人 weak/normal 变种仍属同家族。
- 忽略种子、血量、牌序、升级和遗物计数，比较实际牌组多重集；同角色相似度达到0.85即拒绝。这是保守防重叠门槛，不是统计独立性的证明。
- 随机场景必须提供原生解析后的完整装备记录，核对种子、角色和指定遭遇，不能只凭生成器配置或新种子称为新场景。
- 保存输入、模型及划分指纹。同一根的全部搜索轨迹仍属于同一组，不逐行随机拆分。

实际检查拒绝了旧 `attack_or_block` 划分。另用 `prepare_holdout.py` 按原生目录顺序确定五个未见遭遇，覆盖五角色，生成不同牌组/遗物组合；同角色牌组与训练集最高多重集 Jaccard 为 **0.4286**。建局后冻结为 `.local/objective-search/v21/sealed-holdout/`。这五根**尚未运行基线或候选搜索**，因此没有测试胜率可汇报。候选已在开发回归失败，暂不消耗独立测试；未来若用这些结果调参，它们必须转为开发数据，另留最终测试。

## 本轮改变了什么

上一版预测胜利后缀的绝对 HP 成本。对失败的 `attack_or_block` 做单搜裁剪观察发现：旧搜索胜利前缀在第6个动作、边界12被新方法丢弃，没有留下同状态代表；模型给它和保留替代的后续损失预测相同，总预测主要被当前已损失的2 HP区分。这是具体裁剪证据，不能据此声称找到了所有失败原因。

本轮改为学习**同一真实裁剪池中两个有完整结局见证的状态如何排序**：

1. 沿完整、存活、无风险胜利回传生产终局政策结果；清零旧 `Score` 尾键。战后回血、首领折算、成长和复活政策使用调用方已有的权威结果。
2. 每个根最多8192个观察状态、256个裁剪组，每组均匀记录至多32个候选，每态至多8个组。重复组不重复计算同一对；没有结局的候选保持未知。
3. 由 `SolverInterimResultOrdering` 决定优劣。只有完整政策相等时，才用实际后续动作数打破平局；不把动作数量手工折算成 HP。
4. 每根总权重相等，至多2048条输入行和4096对比较。48棵、深度4的梯度提升树优化成对 logistic 损失，固定随机种子；学习率0.1、正则0.001是优化参数，不是卡牌效用表。模型 schema 升至4，旧 schema3 文件拒绝加载。

方法依据是 [Burges 的成对排序与树提升综述](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/)。实现是树模型上的成对 logistic 优化，没有实现 LambdaMART 的 NDCG 权重，不能冒称完整 LambdaMART。关于旧策略采样与新策略访问状态分布不同的问题，参考 [DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)；本轮没有实现 DAgger。

角色、遗物状态/计数、分支费用与牌序继续来自原始上下文，没有新增按卡 ID 的效用分。最终路线政策和状态等价不使用学习分。模型仍只是实验性中途排序器，部分其他搜索机制仍使用旧启发式元数据；这不是“已彻底移除手写评分”。

## 训练成本与内存

同一 Ryzen 7 7840H、约58.6 GiB内存电脑，DOP1，无 GPU：

| 项目 | 实测 |
|---|---:|
| 配置的采集+拟合时限 | 900秒 |
| 实际采集+拟合 | 359.160秒 |
| 拟合本身 | 4.008秒 |
| 训练根 / 有标签状态 / 比较对 | 43 / 8391 / 15050 |
| 无标签的训练根 | 7 |
| 原始特征 / 树实际使用特征 | 3675 / 230 |
| 原始模型文件 | 190778字节 |
| 采集进程峰值 RSS / 拟合进程峰值 RSS | 532.6 / 373.5 MiB |

8391条状态高度相关，不能当成8391个独立战斗。15050对中有1399对仅靠后续动作数区分，其余13651对的终局记录不同；没有因无解或超时伪造失败标签。模型仍受已知胜利覆盖范围限制。

推理加载时压缩树所用列，用复用的 double/float 数组接收特征，避免为每态建立完整结果字典；预测缓存最多4096项。仍须扫描上下文和创建部分字段名，条目限制也不是固定字节上限。训练二进制在该表示优化前冻结；数值投影、缺失列、常量树和压缩往返另有合同检查。模型固定，不在线重训。

## 开发回归结果

这三根是已知开发反例，**不是独立测试**。两臂独立进程、Coordinator、DOP1、Disabled药水、beam24、12000节点配置和30秒软预算。正常运行不开裁剪观察，数字含建局/JIT；自动协调器与替代搜索实际工作量不同，不能称为等工作量提速；例如 Silent 基线实际展开13297节点，12000配置不是该完整请求的严格总帽。

| 开发根 | 旧搜索结果 → 新模型结果 | 秒 | 峰值 RSS MiB |
|---|---|---:|---:|
| attack_or_block | 胜利，损17 HP → 未获胜 | 5.309 → 5.696 | 253.2 → 322.3 |
| focus_investment | 胜利，损2 HP → 胜利，损9 HP | 5.558 → 6.562 | 259.6 → 331.7 |
| random-silent-monster | 胜利，损29 HP → 未获胜 | 12.685 → 12.086 | 330.8 → 384.7 |

总墙钟23.552→24.345秒，约慢3.4%，且质量退化、内存增加。个别根快一点不能算有效提速。新目标更贴近最终政策，但这些结果证明**更合理的训练目标并不自动产生更好的搜索器**；不默认启用、不用测试集挑一个好看的子集。

## 验证与复现

- Release 主项目与离线宿主构建成功；Bash/PowerShell结构门禁通过。
- `--check-outcome-ranking`：22项断言，覆盖终局政策优先、根隔离、重复对、非法标签、模型版本、压缩与学习方向。
- 五角色笔尖计数8夹具：45项状态所有权与稀疏/数值特征等价检查。这是机制合同，不是泛化样本。
- `python3 tools/OutcomeValuation/test_dataset.py`：2个测试方法，覆盖同模板、换种子/血量/牌序、相似牌组、weak变种及缺少实际装备记录的拒绝。
- 没有运行可见 Steam、原生完整部署验收或独立集搜索，不声称真实可见性能收益。

采集/拟合入口为 `tools/OutcomeValuation/train.py`，`--seconds` 在60至1800之间；可带 `--evaluation-manifest` 在任何采集进程启动前检查划分。当前训练产物位于 `.local/objective-search/v21/training/`，回归位于 `validation/`，后者保留旧文件名但语义是开发回归。不要拿 schema3 的旧行/模型混入本轮训练。

下一步的证据缺口是新策略实际访问状态的有界后续标签和跨场景覆盖，不是购买 GPU。可先在训练侧采样少量发生分歧的状态，给候选分配相等的小额续搜预算；只比较完整结果，未知保持未知。该方案尚未实现，也不保证仅靠当前43根就能学会所有卡牌、角色与遗物组合。
