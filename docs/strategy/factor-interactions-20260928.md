# 学习卡牌与局面的二阶交互

五角色交互模型已训练并接入原生 C# 推理，实际预测一致，但五场独立开发中两场退化、零改善，因此未替换默认算法，也未打开最终测试。训练误差明显下降不足以证明更强；本轮仍未达到用户要求的决策质量或同质提速目标。

## 方法和固定输入

此前树模型需要通过分裂表达上下文变化。本轮尝试二阶因子分解：每个观察字段学习一个低维向量，两字段之间的作用由向量内积决定，避免为每一对卡牌、遗物和局面字段单独建立参数。该形式及其稀疏计算方法来自 [Rendle 的原始论文](https://jame-zhang.github.io/assets/algo/Factorization-Machines-Rendle2010.pdf)；[作者项目页](https://www.libfm.org/)提供背景。实现自行使用 NumPy/SciPy 编写，不复制或依赖 libFM 代码。

固定学习得到的线性基础 `linear(x)`，新增：

```text
score(x) = linear(x)
         + 0.5 * sum_k[(sum_i V[i,k] * x[i])² - sum_i(V[i,k] * x[i])²]
```

减掉平方项后，只保留不同特征之间的二阶交互。根内恒定遗物也可以与变化的资源、卡牌字段产生条件效应。这里表达的是学习能力，不表示所有遗物效应已经得到充分监督。

训练前冻结协议 `.local/objective-search/v45/protocol.json`。复用 v43 原导出的 376 个根、141,734 个抽样行、108,191 个参与行和 250,229 对 C# 权威偏好，保留相同线性基础及跨根特征支持度。没有为本轮新增开发/最终标签，也没有改终局政策。

参数固定为秩8、根权重归一后的平均配对逻辑损失、L2=.001；L-BFGS-B 最多128次迭代，seed0，初始标准差.01。用偏好边端点权重计算 RMS，尺度下限1，避免放大稀有二值字段；归一化折回导出系数。完全未观察列保持零。五个头都达到迭代上限，**未收敛**；协议允许固定迭代结束，其他失败拒绝发布候选。

## 实现边界

`SearchOutcomeValueModel.Interactions.cs` 只校验和计算有限秩因子。与树/线性共用紧凑特征列、float32 观察和请求缓存，因子使用 double。加载和导出都复制矩阵；全零因子归一为缺省项；线性导出同时去掉树残差和交互。新文档 schema10，明确兼容无因子的9，带因子的9拒绝，避免旧程序忽略新字段。原始观察仍为8，无需因模型形式变化重新采集。

推理遍历紧凑特征，只对非零观察执行秩维乘加，复杂度为 `O(F + nnz*K)`，使用两个最多16维的栈数组。秩8时这两个数组共128字节；此数不包含模型、特征捕获、缓存或整个搜索内存。五头 JSON 为3,458,394字节；各角色实际使用2,749–3,331列，比稀疏线性模型需要更多上下文，不能只由数值公式推断整体更快。

`ranking_data.py` 共用外部训练的图读取、哈希校验与逻辑损失。`factor_fit.py` 提供可重跑入口，仅需 NumPy/SciPy；XGBoost 后端也改用相同读取器。完整导出与所有角色拟合共用至多1,200秒的研究预算，不能每个角色重开计时。停止、超时、损坏输入不发布完整模型。正式脚本通过合同和冻结实样本预测核对，没有为了重构重复整批训练。
