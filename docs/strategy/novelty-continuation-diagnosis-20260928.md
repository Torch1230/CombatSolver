# 学习估值与新颖性队列的续局诊断

v76完整开发评测新增失利 `v72-validation-16-regent-knights_elite`：旧算法两次获胜、战损65，模型两次失败、战损75。与之前没有时间边界的铁甲战士反例不同，本例双方都触及时间边界。本轮只定位搜索中断位置；开发场景及诊断观察不进入训练，v77的292训练根补采与训练协议保持冻结。

## 诊断入口

离线宿主新增显式 `--replay-selected-states`，要求有界路径观察、DOP1、Disabled手动药水且禁训练采集。搜索结束后逐段重放最多96步选中路线，输出各前缀/状态身份，并检查根的完整Continuation不变。根准备选择明确拒绝。结果仍使用不持有祖先节点的 `SelectedSearchPlan`；诊断不增加生产结果对模拟状态的持有。

搜索观察器新增新颖性入队、淘汰、取出及停止时待展开四种事件。只有显式关注的状态才复制值；记录实际已经算出的新颖性等级、入队分数和队列长度，不为日志再次计算新颖性或模型分。队列顺序、容量、探索规则、模型和预算均保持原实现。字段空时不加入原观察JSON。

第一次尝试从结果直接遍历祖先的宿主草案构建失败，因为结果有意使用脱离搜索图的 `SelectedSearchPlan`；失败构建和未启动搜索的宿主调用日志均保留。最终采用单独、限长的诊断重放，没有扩大结果所有权。

## 实际发现

最初各4,000条普通观察均触顶，只覆盖旧获胜路线前三个动作。新增重放导出23步路线的24个状态，前三个与先前真实搜索观察一致；随后按全部24个状态定向观察。完整定向事件量旧算法1,337、新模型1,213，均未触及30,000条上限。第二回合入口也在双方真实生成事件中找到，与重放的状态身份完全一致。

该状态位于第五步：第一回合 `CRASH_LANDING`、`STARDUST`、`BLACK_HOLE`、`SOLAR_STRIKE` 后结束回合。不能把第三步在普通Beam中落选直接归为失利原因：双方的六个普通保路成员都不保留这条完整前缀，而双方的新颖性成员都实际展开了第三、四步。

| 第二回合入口 | 旧算法 | v76模型 |
| --- | ---: | ---: |
| 真实生成／转置准入／回合注释 | 均有 | 均有 |
| 入队时新颖性等级（上限2） | 1 | 2 |
| 入队时队列长度 | 19 | 33 |
| 后续实际取出与展开 | 有 | 无 |
| 取出／停止时队列长度 | 275 | 1,969 |
| 搜索结束时该状态 | 已继续并获胜 | 仍在队列，停止原因为时间上限 |

模型确实把这个具有获胜延续的状态放进队列，没有因容量或新颖性门槛删除它，但本次预算内未再展开。新颖性等级取决于搜索已经访问的事实，因而同一物理状态在不同排序形成的搜索历史下可以得到不同等级。这里证明了真实队列中的等待，不证明模型分数是所有退化的唯一原因，也没有测出仅按模型分排队时该状态的名次。

## 验证范围

- 最终主Mod和显式引用它的宿主构建成功；主Mod有离线NuGet漏洞源NU1900警告，宿主零警告。两端结构门禁均通过230个Search文件。
- 新入口及缓存合同50项通过，包括显式诊断准入以及缺失观察额度、非串行、药水或训练采集组合的拒绝。
- 选中路线重放保持原23步路线及完整终局，24状态齐全、根不变；只允许一条普通观察事件时也能独立导出所有重放状态。未声称根准备选择或超过96步路线已受支持。
- 最终两份定向搜索保持原完整路线、终局、原生装备及双完整根戳。双方都触及时间边界，工作量与正常请求不同，因此这些运行不作为性能数据，也不声称固定工作量等价。
- 关闭诊断的单个固定工作量哨兵 `v72-validation-00-defect-shrinker_beetle_weak` 与原v76候选的路线、终局、剪枝计数完全相同：513展开、3,703转移、1,037选择分支、2回合，无时间边界。它验证观察关闭后的代表路径，不替代模型的100场质量评测。
