# 夜间训练：有效监督与拟合吞吐（2026-09-27）

本轮改动提高离线拟合吞吐，没有改变模型结构或游戏内推理。92 根训练后的线性及残差模型在开发筛选中仍有两场退化，未达到替换旧算法的要求，最终测试保持封存。

## 数据量与有效信号

92 根采集已见到 449 种卡牌、128 种遗物，覆盖当前允许的 35 个角色/章节/战斗类型组合。它们只是出现次数，并不表示模型已经学会所有卡牌和遗物效果：174 种卡、54 种遗物只出现在一到两个根中；第三章首领的许多随机牌组只有失败续局。

原监督进程按完整结局 JSON 的差异粗筛偏好，将敌人剩余 HP 不同的两条死亡路线也计成有信号。C# 拟合器一直正确地把两条失败续局视为平局，所以未生成错误训练标签，但 Python 的根选择占用了训练名额、夸大了有效覆盖。现在先将所有失败归为同一签名；继承旧任务时重新计算资格，原始失败观察仍完整保留。

首批 45 根的 36,568 条拟合输入，实际只有 37 根、22,569 行参与采样后的偏好。拟合器仍先验证全部输入，再只为被偏好对引用的行建立列/梯度/直方图；根支持统计、采样和偏好权重保持原规则。

## 固定顺序的并行拟合

直方图按特征独立计算，最多四个 worker，各自写互不重叠的统计槽。每列仍按原行顺序求和；所有 worker 完成后，按原列/分箱顺序串行选择分裂，保留平局语义。小节点保持串行，共用临时数组在每个递归节点结束统计后才能复用。并发度由离线宿主注入，搜索内的模型推理继续保持 DOP1。

线性和完整模型都与初始产物完全一致。测试时后台研究任务仍运行，因此这些数字只描述本机这次离线拟合，不能外推游戏提速或稳定的普遍倍率。新增两次拟合实验分别消耗 61.06/29.19 秒进程墙钟；它们是额外研究成本，不覆盖已有采集/拟合账本。

监督进程可分别冻结搜索引擎和训练引擎：`--fit-harness` 与 `--fit-mod` 只替换拟合程序，采集、验证和原生基线仍使用原搜索程序集。加载器继续验证模型 schema 和游戏 MVID。新阶段继承原数据、失败轮次及成本，不因升级拟合器重新声明免费训练预算。

## 质量与验证

92 根旧串行拟合用时 348.30 秒、RSS 3.82 GiB。其线性和树模型都在 THE_KIN_BOSS、KAISER_CRAB_BOSS 开发根退化，其余三个筛选根未取得政策改进；没有扩大到全部开发集，也没有打开最终测试。数量增长尚未解决质量问题。

Release 主项目/宿主通过，50 项 C# 合同包含：无偏好行仍严格验证、压缩后的模型不变、串行/四路统计产物完全一致；6 项 Python 合同包含：纯死亡池不冒充偏好、替换拟合器不改变搜索引擎、真实子进程在截止时间被回收。Bash/PowerShell 两端结构门禁通过（221 个 Search 文件）。此次没有更改游戏搜索行为，不重复运行整场搜索或可见 Steam；研究模型仍未启用。
