# 压缩训练行的战斗根来源

来源实现已通过C#构建、251项排序合同、两端231文件结构检查及真实导出核对，尚未用于新模型。来源核对和剪枝原型各六项Python合同通过。v84固定100场400次性能对照及其Hessian审计正常结束并回收后，才串行启动本轮构建与导出。不能把这些准备工作称为决策或性能改进。

## 为什么需要显式来源

现有导出知道每个角色头来自哪些输入根，却未记录压缩后的每条观察属于哪个根。一个根可能包含互不连接的候选池；相同状态数值甚至相同观察对象也可能出现在不同输入根。因此不能按矩阵行数、特征相等或偏好图连通分量推测根身份。

现有Hessian3门槛能保证至少三个输入根贡献，但它比直接计数保守：少数遗物在多个根出现，曲率仍可能不足。先补齐来源，后续才能研究直接按根约束叶节点；它不是放宽监督、保证稀少交互已学会或提升实战的证明。输入根数量也不等于统计独立样本数，仍依赖原生身份、家族和近牌组隔离审计。

## 实现边界

`PrepareRanking`把每行对应的原输入根编号与原行一起保留，再用同一个参与行索引压缩。偏好边、随机数流、行序、标签、归一化和特征筛选不变，新增编号不进入观察特征或推理模型。该信息增加训练期整数存储，不增加游戏特征采集。

离线输入文件显式设置`exportRowRoots: true`时，完成结果、路线模仿和联合导出在原文件旁生成`row-roots.json`及每头的`.roots.i32`。二进制每行一个小端int32，保存整个输入列表中的根编号；无偏好根被压缩移除后允许编号有空缺。附属清单绑定原始导出清单的SHA256，每头再绑定编号文件的长度、摘要、来源根范围与参与根数。默认不生成附属文件，旧训练器和既有冻结导出不变。

Python `root_provenance.read_assignments`显式要求这些文件，核对清单、范围、长度、摘要、边两端同根、每个参与行有边及每根边权重总和1。缺失或不一致立即失败，不猜测或自动降级。它不重建战斗标签，也不读取开发/封存测试结果。

## 根参与度剪枝原型

`root_support.py`先按来源根累加每个叶节点的Hessian，记作`h_r`，再计算参与度`(sum h_r)^2 / sum(h_r^2)`。该比值不随所有曲率的共同缩放改变，且不超过有正Hessian贡献的根数。它描述曲率分布的集中程度，不是统计独立样本数、净梯度支持数或战斗收益估计。

原型仍要求至少3个不同根，参与度也至少为3。一个根占绝大多数曲率时，即使有少量其他根也无法通过。恰好3根需要均衡贡献；因此它仍可能挡住部分稀少交互，不保证解决全部覆盖问题。在原根总权重1及精确算术下，每根总Hessian不超过1，旧Hessian3门槛蕴含参与度至少3；新约束保留根分布要求，去掉对曲率绝对大小的同一限制。数值临界值采用小的浮点余量，并另外检查整数根数。

原型检查普通导入树：若一个子分支支持不足，就把该分裂收回父节点，并按当前真实训练梯度、Hessian、原L2=.001和学习率.1重算父叶。父节点也不满足要求时继续向上收缩；整棵树无足够根支持时显式返回无候选。支持足够的原叶值保持。后续训练必须使用剪枝后的预测逐轮重算梯度，不能训练完原树后只在导出时修改并沿用旧预测。

6项新增合成合同通过，CPU0，进程0.207秒、峰值RSS约74.4MiB。覆盖尺度不变性、单根占据大部分曲率、重复行、低曲率的均衡支持、父叶Newton重算、坏输入和条件反转。在仅12行、每类上下文3个根的反转例中，原Hessian3树保持零预测；16轮逐树拟合/剪枝使用新预测继续更新后，所有合成偏好方向正确，保留叶均通过根参与度检查。这不是实际卡牌/遗物数据，也没有形成新的完整模型或实战结论。
