# 保留跨回合纠正监督的联合训练

v75已能取得跨回合真实续局，但每场至多六条查询若直接混进数百条原样本，可能在抽样时全部丢失。本轮将查询作为原物理训练根内的独立采集来源，保留其有效偏好边，并平衡两种来源的权重。没有添加卡牌、角色或遗物的手工价值。

## 训练边界

联合输入可增加与原根顺序对齐的 `correctionInputs` 数组，以及显式 `balanceCorrectionSources: true`。每项为 `outcome-correction-rows.json` 或明确的缺失项null；重复路径、超过六行、错误标签以及原训练/补查的任一完整原生根戳不同均拒绝。空查询文件合法，不构造虚假胜负。

原有结果见证与获胜路线模仿继续使用各自的抽样器，每根每目标512行。本轮查询不占用这两个行额度，使用第三套独立池编号；不能按特征向量相同拼成状态，也不能让不相同采集的池号相撞。所有结果比较仍由C#权威政策生成，Python训练器只消费导出的数值矩阵和偏好图。

显式平衡时，每根保留全部实际补查偏好（六行最多15对），余下的4096对总额度供原联合监督使用。原监督保留自己的随机数流，因此某根增加查询不会扰动后续根的原边抽样流；达到上限时，当前根最多让出15条原边。两来源都有有效边时各占该根的一半权重；只有一种来源有信号时，它占全部权重。整根权重始终为1，特征支持度仍只计算一次物理根。两条失败见证没有偏好，不能占走训练权重。

这是一个明确的离线采样/权重假设，半数权重不表示教师置信度或最优值。未知分支仍未知，完整失败后缀不能证明活前缀不可获胜。没有补查输入时默认训练行为保持；关闭来源平衡也保留普通逐对等权入口供研究对照，没有增加玩家模式。

## 正式候选协议

完整补采继续使用已冻结的v75引擎和v71预测器，不因本轮训练实现更新而重启。待292根有限采集结束后，将其有效补查与原292根联合数据整合；失败采集明确列出，原根保留原有监督。旧100根内部验证已参与v71训练，本轮不能再次用作独立验证。

只计划一个完整来源平衡候选，沿用v71的64棵树、深度6、最小叶Hessian3。完整导出加五角色拟合及所依赖v71的135.88秒训练成本，共用1800秒外层期限；本轮数据采集另行计费，不更改用户的单次完整训练上限。不按角色挑选不同候选头。

数值对齐后，仍使用固定100个开发场景、每算法两次、共400次ABBA/BAAB完整搜索，任何质量退化都不导致提前停止统计。报告完整终局与核心质量、丢失/新增胜利、稳定性、同质量耗时和内存；不会由训练损失自动启用模型。55个最终配置保持封存。

冻结协议与可执行本地研究脚本在 `.local/objective-search/v76/full-protocol.json` 和 `train_and_evaluate.py`。启动前修正了脚本的期限传参：拟合器接受的上限为1200秒，因此取它与完整模型剩余预算的较小值；没有使用拟合或开发结果修改参数。详见[结构化证据](source-balanced-corrections-20260928-evidence.json)。

## 完整补采与正式拟合

292个原训练根、35个遭遇家族的有限补采正常退出，0失败；其中10个根复用已核对的先导数据，没有增加新的物理场景。总共取得1,595条终局标签，其中1,305条有获胜后缀、1,027条从原先未知变成有获胜后缀；这些是分支证据数，不能算作模型胜率。查询按回合分布为350/532/531/182条（第1～4回合），25个根没有查询。累计采集进程4,943.07秒，续局教师计时536.20秒；整个采集进程的峰值RSS均值704.16MiB、最大1497.71MiB，包含搜索、续局与导出，不能当作普通推理内存。

完整联合导出保留586条实际纠偏排序对，共193,392行参与排序、407,639条偏好边。按角色分别为120/126/107/108/125条纠偏边。拟合仍为每角色64棵树、深度6、最小叶Hessian3，没有按角色挑选不同版本。

本轮导出117.27秒、拟合20.03秒；加入所依赖v71的135.88秒后，完整训练成本273.18秒，低于1800秒上限。导出峰值RSS4.04GiB、拟合峰值2.23GiB，最终模型1,139,294字节（约1.09MiB）。Python导出文档与C#在1,280行预测上的最大绝对差为0；XGBoost自身float32累加与文档double累加的训练边符号有2条差异，保留在原始训练指标中，不称为所有训练边逐位等价。

模型实际使用的特征数按角色为92/93/96/90/86。只有REGENT线性基础使用一条直接遗物状态特征，五个头均没有遗物树分裂；遗物通过资源和Power产生的间接影响仍可能进入其他特征，但目前不能声称已经充分学会卡牌与遗物组合。

100场、400次配对开发搜索已完整结束，进程正常退出，0失败、0终局证据问题。55个最终配置尚未运行，模型继续关闭。正式模型与日志位于 `.local/objective-search/v76/full/`，配对记录位于同目录上级的 `evaluation/`。

按15个遭遇家族进行2,000次描述性重采样，核心改善比例区间约5.1%～19.4%，退化约8.0%～18.2%；它们不是玩家实际战斗总体的置信保证。100个配置已参与反复开发，不能称为封存最终测试。

结论：局部改进存在，但核心质量仍有13场退化、一场丢失胜利，同质量成本也未下降，不满足默认替换条件。原始汇总含逐场质量、成本、稳定性及全部回归条目，见 `evaluation/summary.json` 和 `cases.csv`。

## 补查位置覆盖审计

完整采集后只读取已保存的实际前缀元数据，按查询状态所在回合统计该回合已执行动作数；此前回合的动作不算入这一深度。1,595条查询分布如下：

| 当前回合已执行动作数 | 查询数 |
| --- | ---: |
| 0 | 1,119 |
| 1 | 128 |
| 2 | 210 |
| 3 | 130 |
| 4 | 8 |

70.16%的查询处于本回合尚未出牌的位置。第2～4回合共1,245条查询，其中1,119条（89.88%）当前回合动作数为0；只有6条达到2次，均在第2回合。因此跨回合标签数量不能代替回合内决策深度的覆盖。该统计不包含未被观察的竞争池，也不能单独证明模型退化的原因。

源码的 `ObserveCorrectionBoundary` 在第一次取得某回合的合格竞争后就把该回合加入完成集合，后续深度不再有机会入选。后续选样改进应在原六查询/六秒教师额度内解除这一顺序偏差，并保持真实最终保留/淘汰身份、完整前缀及物理根权重。还需核对采集器的普通观察池上限，避免新的深度抽样又被早期观察占满。本轮尚未修改该采样策略，冻结v76评估继续完成。

配对进程结束后已对267个非空纠偏根运行原C#权威排序审计，其中247根实际提供586条偏好；25个空查询根仍保留在原292根分母中。v71正确/错误/平局为359/159/68，v76为502/37/47，按根平均符合度（平局计半）67.81%→90.45%，对数损失0.6165→0.3956。72条胜负偏好中正确44→61、错误22→7。模型学到了大部分新增监督，但这些行已用于v76训练，不能把90.45%当作独立测试准确率。

31条偏好两端的完整观察字典相同，说明当前表示无法区分这部分已观察终局差异；其余平局也不都能归因于相同特征。这一诊断与深度覆盖审计支持继续改进监督覆盖，尚不能将所有开发退化归于某一个原因。元数据审计在 `.local/objective-search/v76/correction-depth-audit.json`，原生排序诊断和汇总为 `correction-audit-v71.json`、`correction-audit-v76.json`、`correction-ranking-summary.json`。后续[深度分层采样](depth-stratified-corrections-20260928.md)单独验证，不回写本轮冻结候选。

已完成与验证源码一致的本地五文件部署；本轮仅改变显式离线训练，默认仍使用旧自动算法，不发布或启动游戏。
