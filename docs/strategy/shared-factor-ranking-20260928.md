# 跨角色共享交互模型

同一批训练与内部留出场景下，共享模型的留出排序指标略有改善；独立开发仍两场退化、一场改善，没有达到替换旧算法的要求。默认算法不变，最终测试未打开。

## 固定协议

沿用v46的276个训练根、100个内部留出根和9个完整留出遭遇家族，不重新挑选划分。模板、原生遭遇和同角色近似牌组的分离证据复用输入未变的审计。线性基础、特征支持度、归一化及交互项都只用训练侧拟合。

改为一个跨五角色共享的模型，现有 `character/<ID>`、遗物、资源与状态观察提供可学习的条件信息。不是拼接五套已拟合权重，也不从完整376根的基础项泄漏内部留出信息。模型容器、C#推理、训练器及原始观察格式均沿用现有实现，无需新增玩家模式。

仍比较线性及L2=.0001/.001/.01/.1/1的秩8因子，最多128次迭代。采用前轮相同的角色→遭遇家族→根等权配对损失，选一个配置。预先规定：只有选中共享配置的内部损失不差于上一轮已选分角色模型，才重新用完整376根拟合，并打开唯一候选的原定五场外部开发筛选。

共享训练改变了特征支持度和参数容量：一个128步线性基础及一套因子代替五套独立基础/因子；不能把全部差异只归因于参数共享。另检查了偏好抽样：276根未截断偏好总数175,348，单根最多2,406，小于C#的4,096上限，因此保留相同偏好对及根权重。随机数流变化只改变对的排列顺序。参与行75,960、抽样行99,757和三类偏好数均与分角色导出一致。

## 监督质量的后续线索

另检查了既有外部开发VANTOM基线的未验证原因：其选中终局快照确实带有 `SEEKER_STRIKE.CardPlay / UnresolvedPlayerChoice`，不是被淘汰分支的全局提示。`CardChoiceSupport.BuildSeekerSpec` 在构造可枚举选项时无条件记录该风险；当前动作选择流程随后可以执行、暂停和恢复指定选择。原游戏同版本方法经只读反编译确认使用伤害结算后的抽牌堆、相同随机源洗牌、取候选并选一张入手。

这提示可能存在已经解析选择仍被标风险的问题，进而令相关见证被训练收集器排除。但尚未完成原生状态/RNG/选择续接对照，本轮没有删除标记、放宽验收或将VANTOM判为可信胜局。下一轮应先用最小原生对照验证这个具体假设，而不是继续只增加同类训练行。
