# 同回合补充前缀的回合边界

夜间采集的一场储君战斗在补充防御搜索中失败：打出虚空形态会结束回合，下一回合的格挡被当成当前回合防御收益，该动作因此进入只支持同回合的固定前缀，触发显式拒绝。

防御及准备后续的生成器现在同时要求动作不结束回合、动作回合及结果回合均与前缀相同。正常候选展开和固定前缀的拒绝合同不变，不吞异常、不改卡牌语义。两个生成器还持有并释放全部已物化候选，包括不能用于前缀的候选；不保留被筛选掉的模拟器。

复现使用原root-000743请求、冻结的第15轮学习模型和原12秒/6,000节点预算，仅增加诊断输出。同原失败记录的完整根诊断、根描述及实际装备均一致。修复后11.18秒进程完成，搜索8.63秒，得到第三回合零损无风险胜利；正常路线中仍出现`VOID_FORM`且`EndsPlayerTurn=true`，`BIG_BANG+ULTIMATE_DEFEND`的合法补充防御前缀也执行成功。导出451条观察。目标复现经过防御生成器；准备生成器采用相同边界条件，未单独运行另一场战斗。

Release构建17.08秒、离线宿主3.01秒，均零警告/错误；Bash与PowerShell结构门禁均通过222个Search文件。证据为离线搜索合同，不是新的原生战斗语义验收、模型质量提升或提速结论。[结构化证据](same-turn-prefix-boundary-20260928-evidence.json)记录检查、日志摘要和程序身份，原始材料在`.local/objective-search/v57/`。夜间r7采集器保持原冻结版本，原失败不覆盖；新模型研究继续显式选择冻结评测程序。
