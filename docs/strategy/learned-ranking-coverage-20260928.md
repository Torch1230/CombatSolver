# 学习排序的实际特征覆盖与剩余手写估值

以下保留v85模型和v84开发记录的只读基线核对，末节新增已完成训练的v86静态审计。没有新增训练、搜索或最终测试，不将结构覆盖等同于决策质量。

## 模型实际上使用了什么

按C#导入时的常量分支收缩规则统计所有非零线性项和剩余树分裂。模型接收数千个候选字段，实际数值程序只使用每角色73–83列；不能把采集过某项信息当作模型已使用它。

| 角色标识 | 实际使用／已导出的玩家能力列 | 实际使用／已导出的遗物列 | 全部实际使用列 |
| --- | ---: | ---: | ---: |
| DEFECT | 1／41 | 0／106 | 83 |
| IRONCLAD | 3／36 | 0／104 | 74 |
| NECROBINDER | 0／37 | 0／85 | 82 |
| REGENT | 3／42 | 2／139 | 73 |
| SILENT | 4／41 | 0／122 | 75 |

分母仅指经过训练导出筛选的列，不是游戏全部卡牌、能力或遗物。REGENT使用的两项遗物字段是原有状态标识列；v85新增乘积的实际分裂数仍为0。没有直接使用某个身份列，也不意味着搜索完全不受该对象影响：通用牌堆/资源特征和后续真实模拟仍能反映部分效果。这份表不证明某张牌被错误估值，也不证明缺少特征是某场退化的原因。

原单树原型只从前缀已选信号、通用信号、遗物门控和乘积中选列，进一步漏掉大部分未被前缀选中的能力字段。它的五角色总候选列为145/151/150/152/148。为避免沿用这一限制，新增通用选列函数把所有已导出的`power/`原始观察加入，变为215/210/231/239/231列；没有列卡牌或能力名字、没有指定效用分数。容量统一设256，超过时明确失败，不悄悄截掉某角色或某能力。

当前v85全量对照完成并回收后，预先固定的真实单树适用性检查已经比较原列集合与加入全部能力列的集合，每角色各一棵、共10次单树拟合。两者共享同一48树前缀、训练图、根参与度和损失，没有用开发失败场景生成训练标签。此时仍不是完整新模型或实战验收。

## 尚未去掉的手写部分

学习路径主排序已调用学习模型，快照总分置0；`BuildObjectiveChoices`也绕过旧的手写卡牌选择分数。但状态快照仍计算保留手牌价值、未来资源价值、持续增益等估计，辅助保路和Pareto规则仍消费这些字段。因此当前实现尚未满足完整替换手写中途估值的要求。

例如未来资源字段仍含能量×16、抽牌/星星×8等人工系数；这类中途估值与明确的终局胜负、复活、战损及用户目标政策不是同一职责。后续必须在学习策略有完整质量证据后，逐步替换这些辅助入口并做相应路线验证，不能只改主排序便宣布完成，也不能以删除最终用户政策来冒充去掉启发式。

## 排除过早归因

v84的16场核心退化中，第一轮配对有2场双方都没有选牌分支；3场任一最终路线包含多卡选择，所有这些记录的选牌回放预算耗尽计数均为0。因而不能把全部退化归因于选牌组合枚举。没有多卡动作的最终路线也不能证明搜索没考察过该类动作；计数不能判断某个未保留组合是否能获胜。

下一步仍优先检查根约束下实际能学到哪些分裂，再决定完整训练方式；暂不据此改写选牌引擎，也不为某张开发失败卡设置例外。当前受控对照和运行时默认策略均未修改。

[结构化证据](learned-ranking-coverage-20260928-evidence.json)，本地只读审计入口为`.local/objective-search/v86-root-histogram/audit_model_coverage.py`。

该10次真实实验及后续完整拟合接线已完成，见[最新验证](root-supported-splits-20260928.md)。尚未完成新的模型实战验收，剩余手写入口仍未去除。
