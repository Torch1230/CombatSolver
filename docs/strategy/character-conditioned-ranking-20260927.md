# 角色条件估值试验（2026-09-27，未启用）

将同一批原始 170 个训练战斗按原生角色拆分，分别学习线性基础项及残差树；每次验证只按该战斗的原生角色选择对应参数，不按验证结果挑选不同头。目的是检验共享系数是否限制角色相关估值，并降低单次训练的特征维度；卡牌/遗物分数仍由完成见证的偏好学习，没有手填角色权重。

这是离线原型：五个参数头在验证前全部训练并记录 SHA，Python 验证宿主按冻结原生装备的 `characterId` 分派，实际调用的仍是普通模型文档。汇总 JSON 是实验清单，尚不是生产加载器可直接使用的模型格式。不会形成玩家需要选择的多个搜索模式。

## 数据与成本

五个角色分别使用 35/37/34/34/30 个实际训练根，每根最多 512 个观察。原始根、模型结构及训练默认超参数与前一轮共享模型相同；但每个角色的宿主各自从 `Random(0)` 开始抽样，所以具体观察行和配对顺序改变。不能把差异完全归因于角色条件化。下一次控制试验必须先固定全体根的实际抽样，再拆分拟合。

| 拟合方案 | 实际拟合进程墙钟 | 单进程峰值 RSS |
|---|---:|---:|
| 共享参数，170 根 | 313.83 秒 | 2,139,729,920 字节 |
| 五角色顺序拟合合计 | 77.35 秒 | 最大 398,098,432 字节 |

后台采集/拟合同时运行，这些数字只描述本机本轮训练成本，不能外推游戏搜索的提速。完整头合计占用比单个共享模型更多的文件空间；验证每场只载入该角色一个头。

## 独立开发结果

仍用原先固定的五场开发筛选、相同原生根、搜索配置及终局政策，未打开最终测试。

- 线性头：THE_KIN_BOSS、KAISER_CRAB_BOSS 退化，KNOWLEDGE_DEMON_BOSS 改善。
- 完整头：THE_KIN_BOSS、BYRDONIS_ELITE 保持原政策质量；KAISER_CRAB_BOSS 丢失旧胜局；KNOWLEDGE_DEMON_BOSS 从失败变为损 72 HP 的胜局；KNIGHTS_ELITE 双方失败。
- 与同批共享完整模型相比，四场政策情况相同，KNOWLEDGE_DEMON_BOSS 多损 4 HP（68→72）。因此不能宣称同等决策质量，也不能替换默认算法。

第一次实验分派错误地假定验证清单包含训练用 `character` 字段，在任何搜索启动前明确失败。修正为读取冻结的原生装备身份，失败与成本保留；没有通过解析场景名字或默认角色掩盖缺失数据。

角色条件化的训练成本更低，为后续更多根的训练提供了可验证的资源依据；质量仍需要继续改进。数据和完整比较见[结构化证据](character-conditioned-ranking-20260927-evidence.json)，原型位于私有 `.local/objective-search/v35/character-fit/`。夜间服务继续原配置，尚未接入这个原型。

## 固定全局抽样后的实现与对照

现已在 C# 宿主实现 `partition=character`：按原始全体输入顺序只抽样一次，再按已观察的原生角色分组拟合。新的 `CharacterSchema=1` 容器内嵌各角色普通模型文档，完整和线性产物各自是一个可由离线宿主直接加载的文件。搜索前按捕获根的原生角色选定预测器，搜索内不切换参数；所有头都验证模型 schema7、树/特征及游戏 MVID，缺失头、混合/歧义角色和坏头明确失败。旧格式与默认 shared 保持兼容，生产 Runtime 仍未启用研究模型。

同一批 170 根仍使用 74,219 行、99,019 对偏好、51,255 个有效比较状态，与共享控制模型一致。每根最多 1,801 对，未触发 4096 对的采样上限，因此偏好集合没有因分头随机流变化被截断；枚举/归并顺序可以不同。模型合同另外证明每个头等于直接拿统一抽样结果独立拟合，不会重新抽各角色的状态。

条件模型这次拟合 78.51 秒，进程墙钟 78.68 秒，峰值 RSS 1,217,908,736 字节（约 1.13 GiB）。这高于前一原型的单头独立进程峰值，因为本次一个进程持有所有已抽样根。完整文件 1,555,041 字节；各头共有 1,916 个特征槽，单次搜索最多用 480 个。原共享模型约 314 秒/1.99 GiB；这些仍是训练成本，不是游戏搜索提速。

训练根诊断在相同观察/偏好集合上，共享/角色条件完整模型平均每根排序正确率 84.32%/90.31%，log loss 0.379/0.288。这是拟合诊断，不是胜率或独立测试。外部五场固定开发结果：

- 条件线性模型：KAISER_CRAB_BOSS 从旧算法损 64 HP 改善为损 62 HP，同为第 9 回合获胜；THE_KIN_BOSS 则损 27 HP，相比基线多损 3 HP，成长奖励一致。其余三场政策情况持平。
- 条件完整模型：KAISER_CRAB_BOSS 仍丢失旧胜局，其余四场没有改善或退化。没有通过筛选，最终测试仍封存。

主 Mod/Search 实现保持冻结，实际验证使用新加载宿主与原基线的搜索程序集组合；每场核对原生装备和两个完整根状态戳。Release 宿主、75 项 C# 合同、7 项 Python 监督合同及两端结构门禁（221 个 Search 文件）通过。旧 45 根输入以新宿主重拟合，完整/线性模型均与原产物逐字节一致（额外约 29.88 秒）；同源码主 Mod 构建与本地部署沿用先前成功证据。
