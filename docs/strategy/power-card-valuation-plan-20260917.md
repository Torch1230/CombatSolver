# 能力牌逐卡估值与搜索优化计划

日期：2026-09-17
状态：六个卡池的104张单人能力牌已全部登记；静默猎手17张已接入第二版生产模型并复核，其余五个卡池为 `QuantifiedDraft` 逐卡草案，等待玩家复核后升级为 `Modeled`。公共承诺接口已重构为卡池无关，并加入无登记能力快速旁路。

## 1. 要解决的问题

当前求解器能精确模拟多数能力牌结算，但中间保路更容易看到“本回合防住”和“尽快击杀”的即时收益。需要先付出能量、星能或战损，之后才通过攻击、技能、消耗、抽牌或成长回本的能力牌，可能在回报出现前就被剪枝。玩家反馈中的谋划专家、领域、致死性、腐败等现象属于这类策略缺口。

本计划不把能力牌估值写进终局排序。终局仍以胜负、战损、药水、偷窃、卖血和既有边界排序为准；能力牌估值只用于保留有兑现可能的中间路线，以及后续独立的能力牌探索成员。这样能增加“先开能力再兑现”的搜索机会，但不会让一个能力分数压过真实战斗结果。

## 2. 硬边界

- 范围是原版单人五个角色卡池和无色卡池。
- 默认由用户逐卡给出自己的理解，再建立模型。用户明确授权某个范围由实现者先行量化时，可以建立 `QuantifiedDraft`，但必须完整记录实现者假设，并在用户复核前与 `Modeled` 区分。
- 卡名只采用当前游戏中文与英文官方本地化。没有从游戏资源或实机日志核对前，不在目录中自行翻译或预填名称。
- 未登记能力牌保持现有搜索行为，并明确标记为 `LegacyFallback`；空登记表是合法且必须通过测试的状态。
- 卡牌效果语义与搜索估值分离。结算、Power 生命周期、Fork 和跨回合状态仍由 Engine/Prediction 负责；本目录只把已确认语义量化为搜索信号。
- 新接口先作为内部边界。既有第三方 `StrategicEffectMirrors` 的公开适配合同保持不变，除非后续有独立设计和兼容方案。
- 第一阶段不接入最终选路，不调整 Beam、节点或时间预算，也不声称已经改善能力牌出牌顺序。

## 3. 第一阶段：逐卡建模

### 3.1 目录与职责

```text
src/Search/PowerCardValuation/
  PowerCardValuationContracts.cs       奖励、惩罚、时机和上下文值对象
  IPowerCardValuationModel.cs          每张卡统一估值接口与强类型基类
  PowerCardValuationRegistry.cs        精确卡类型登记、重复拒绝、未登记旁路
  PowerCardValuationModels.cs          六个卡池的唯一组合入口
  Cards/
    Ironclad/
    Silent/
    Defect/
    Regent/
    Necrobinder/
    Colorless/
docs/strategy/power-card-valuation/
  README.md                             状态定义、逐卡协作流程和索引
  <pool>.md                             各卡池逐卡规格与验证记录
```

每个角色单独登记，具体卡牌模型放在对应卡池目录；不得把全部公式继续堆进一个总表或 `CombatBeamSolver` 分片。

### 3.2 统一估值合同

模型输入由 `PowerCardValuationContext` 提供。每张卡通过 `PowerCardValuationRequirements` 声明自己真正需要的字段，使后续接入时只计算必要的牌组与未来触发特征。模型输出包含三部分：

1. 奖励向量：伤害、防伤、资源、牌访问、成长、控制。
2. 惩罚向量：启动成本、延迟兑现、触发稀缺、反协同、回合末失效损失。
3. 时机标签：应在攻击、技能、能力或消耗之前打出，以及是否只对本回合有效。

所有分量使用非负整数；净战略值为奖励合计减惩罚合计，可为负数，合计使用饱和算术。分量首先表达可解释的实际量，例如预计伤害、防伤、可用资源和牌价值；不能直接测量的成长或控制价值必须在逐卡规格中写明假设、上限和兑现窗口。惩罚不得重复扣除已经包含在奖励测算中的损失。

统一接口只解决“同一种语言描述各卡价值”，不假装所有能力牌能套用同一条公式。领域、致死性、腐败等机制可以各有模型，但必须返回同一结构化结果。

### 3.3 用户与实现者的逐卡流程

通常每次只处理用户点名并解释过的卡。用户明确授权实现者先做一个卡池时，以下内容改由实现者作为待复核假设记录，不把草案写成用户结论：

- 官方卡名与卡池；普通版和升级版是否改变模型。
- 核心收益是什么，靠哪些后续动作兑现。
- 理想出牌时机，以及晚打会损失什么。
- 愿意为启动承受多少能量、星能、当回合战损或机会成本。
- 哪些敌人、遗物、人工制品、Power、牌组形态会放大或压低价值。
- 一回合内收益、跨回合收益和战斗剩余回合的关系。
- 玩家认为求解器最常犯的具体错误，以及一条期望保留/拒绝的对照路线。

收到理解后，按以下顺序落地：

1. 从游戏本地化核对中英文官方名，并确认真实卡类型。
2. 审计卡牌、生成的 Power、触发 Hook、升级差异和跨回合状态，区分“模拟缺失”和“估值缺失”。
3. 把用户理解整理成该卡规格；有冲突或无法量化的部分明确记录，不擅自选择。
4. 在对应卡池目录实现独立模型，登记所需上下文和时机。
5. 增加公式级合同：零触发、高触发、资源不足、短战斗、长战斗、反协同和升级差异。
6. 在接入搜索后，增加一条应保留路线和一条不应盲目卖血的反例；实现者先行草案还要经过用户复核，通过后才把状态改为 `Modeled`。

### 3.4 单卡完成标准

一张卡只有同时满足以下条件才算完成：

- 用户理解已经原样或等价地记录在对应卡池文档；实现者先行草案已经由用户复核。
- 官方中英文名称、卡类型、升级差异已核对。
- 原版语义已确认；若模拟本身缺失，先修语义再谈估值。
- 奖励、惩罚、时机、上下文需求和上限有明确公式。
- 单卡合同和相关结构门禁通过。
- 接入搜索后，目标正例与反例均有可重跑证据。

## 4. 第二阶段：能力牌独立搜索分支

逐卡模型积累到能形成代表性样本后，再建立 `PowerCommitmentPortfolio`，而不是把分数直接加进所有 Beam 排名：

- 从当前可支付、已登记的能力牌生成承诺候选。
- 先按时机标签展开“能力优先”次序，再允许后续攻击、技能或消耗兑现。
- 独立成员使用共享请求预算和明确上限，不扩大总节点或时间预算。
- 保留承诺路线时同时检查启动代价与最低兑现证据，防止见能力就无脑卖血。
- 产出的完整路线仍交给既有终局比较；成员之间不拼接状态、不绕过转置和模拟错误。
- 多宽度精炼和多策略探索是调度参考，不复用其特征表来代替能力牌模型。

在此之前可以先把统一估值接入中间保路的一个独立通道，但必须默认不影响未登记卡牌，并由对照证明不会改变终局排序。

## 5. 验证与调参证据

### 5.1 第一阶段框架验证

- 独立 .NET 合同检查：饱和合计、负值拒绝、净值可为负、精确类型登记、重复登记拒绝、卡池分类和空登记表旁路。
- Release 编译。
- Windows 与 Linux 等价结构门禁。
- 无真实卡牌模型、无生产消费者时，不启动游戏来伪造行为收益。

### 5.2 单卡与搜索验证

- 公式测试先于游戏测试，覆盖边界值和用户给出的正反例。
- 最小无头场景只验证该卡首次错误决策；跨回合兑现时才升到两回合边界。
- 代表性玩家报告用于失败基线和最终证据，同根重复包不增加测试数量。
- 搜索质量至少比较：是否进入候选、能力出牌位置、预计与实际战损、回合数、用药和总工作量。
- 调参不得只看改善样本；必须保留“不该开能力”或“不该为能力卖过量战损”的哨兵。

## 6. 无头实例清理规定

Coding agent 启动无头游戏测试时，必须使用 `-CleanupInstanceOnExit`（PowerShell）或 `--cleanup-instance-on-exit`（Bash）。该模式让请求完成后退出游戏，释放主机租约和实例锁，再校验所有权并删除整个私有实例目录；成功、失败、取消和超时都走同一清理边界。禁止把仅停止进程或 `ExitOnComplete` 当作目录清理。

需要同一实例批量复用时，只能在批次内部保留；批次最后必须执行带清理开关的请求。性能分析明确要求保留现场时，不使用该开关，并在证据记录中说明实例路径与后续清理责任。

清理函数只接受归当前仓库与实例所有、没有主机租约、没有存活私有游戏且不含重解析点/符号链接的目录；所有权不确定时直接失败，不扩大删除范围。

- 已建立统一合同、强类型模型基类、精确类型登记表和六个卡池入口。
- 已建立不启动游戏的独立合同检查项目。
- 已从游戏版本 `0.111.0` 的六个原版 `CardPool` 和 PCK 本地化建立完整目录：`CardType.Power` 共111张，其中104张属于单人建模范围，7张 `MultiplayerOnly` 只保留资料并排除建模。修正了原目录把故障机器人 `WHITE_NOISE`（实为 `CardType.Skill`）计入能力牌导致的112/105。
- 静默猎手17张单人能力牌已按防御、中毒、小刀、牌流和直接伤害拆分实现并登记，状态为 `QuantifiedDraft`，并已由玩家逐卡复核、接入第二版生产模型；详细公式见[静默猎手首版量化规格](power-card-valuation/silent-quantification-20260917.md)和[第二版量化与路线保护方案](power-card-valuation/silent-v2-valuation-and-retention-plan-20260917.md)。
