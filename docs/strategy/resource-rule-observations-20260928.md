# 引擎资源规则量观察

本轮继续研究长期资源收益的表达，正常游戏仍不启用学习模型。上一轮具体卡牌身份列消融降低了训练成本，却未修复旧胜局丢失。本轮新增两个由引擎计算的机制量，并重新采集固定训练场景，完成了同样本消融。新增规则量没有改善本轮模型的独立开发质量，所有候选仍未达到替换门槛。

## 观察的含义与所有权

`SearchOutcomeContext` 增加：

- `resource/current-max-energy`：既有 `PersistentPowerSupport.GetModifiedMaxEnergy` 的结果。
- `resource/current-hand-draw`：既有 `PersistentPowerSupport.GetModifiedHandDraw` 的结果，基数使用原版 `CombatManager.baseHandDrawCount`。

两者读取当前分支/回合的规则与既有遗物补偿，不增加按卡牌、能力或遗物填写的效用系数。具体卡牌身份、Power 层数等原观察继续保留。它们不是保证下回合到账的资源；消失的能力、之后的回合事件、一次性延迟资源和未来动作仍由引擎结算。观察不调用资源消费入口，也不推进战斗。

稀疏推理只有引用相应字段时才查询，隐藏这些字段的控制模型不调用它们。查询职责仍属于 Prediction 的共用资源支持，Search 仅投影标量，没有另写一套卡牌效果规则。

之前看到的 COUNTDOWN、DANSE_MACABRE、DEMESNE 是开发路线差异的线索，不是本轮的卡牌评分表。原生定义中 DEMESNE 修改抽牌量与能量上限；DANSE_MACABRE 在达到费用条件的出牌前给予格挡，COUNTDOWN 在玩家回合开始施加原生 `DoomPower`。本轮的两个字段直接表达前一种机制，不能声称已经直接描述后两种全部延迟收益。开发轨迹没有加入拟合。

## 数据格式与重新采集

模型升为 schema9，原始观察升为 schema8，防止旧推理程序把不认识的新列当零。旧观察没有记录这两个量，不能从既有 Power 总数准确还原，所以当前宿主要求重新采集，明确拒绝任何 `featureUpgrade`。历史敌方总层数转换由原冻结程序/提交复现，当前代码移除失效的转换入口。Python 历史标签普查仍识别 6/7/8，只有检查标签的用途，不把旧行转换为当前训练行。

实验程序和原生依赖独立冻结；原生游戏 DLL 摘要与上一轮相同。保留原来 408 个训练场景，复制原生请求、规格与装备；每次新采集核对实际装备及原来的两个完整根状态戳，记录父观察及摘要。采集只运行旧算法，沿用 Beam16、6,000 节点、12 秒搜索预算；四路进程、每进程 70 秒硬上限，失败或超时保留隔离记录，不伪造标签。旧版随机生成服务继续使用其冻结程序，不能直接注入新 DLL 或混合版本行。

预先声明两个训练组：完整观察，以及显式排除 `resource/` 的控制组。两组使用相同的新观察、根顺序、512 行/根、角色条件拟合和全部偏好；核对根/行/偏好/参与行计数一致。每组的一次完整五角色拟合最多 1,200 秒，同时导出完整与线性产物，不按开发结果挑角色头。

训练、15 场开发及五场封存最终测试再次两两审计。评估会为新程序集建立对应旧算法基线，沿用固定五场筛选，有回退或未核实结果就不进入其余十场；最终测试继续封存。原始协议、输入摘要与进度在私有 `.local/objective-search/v42/`，实验截止时间为 2026-09-28 08:00 +08:00。

## 已完成验证

- 主 Mod/宿主 Release 构建分别 13.68/2.65 秒，96 项模型契约检查通过。删除了已失效的旧观察升级正例，改为缺失新量时明确拒绝；不把检查数量变化当质量变化。
- 30 项原生上下文检查通过，包含原生根资源查询对照、分支能力修改、完整 continuation 状态不变、不消费延迟能量/抽牌、父子隔离及只请求资源列的稀疏投影等价。夹具同时包含 PenNib 与 BagOfPreparation；短搜索完成 72 次展开、174 次转移，损 3 HP。
- 一份实际 schema8 模型被新宿主在读取训练行之前明确拒绝，没有产生审计产物。
- 7 项 Python 监督合同及两端结构门禁通过（221 个 Search 文件）。同源码五文件部署完成，没有启动可见 Steam。

## 采集、拟合与消融结果

408 场全部完成，376 场产生可用偏好；原始完成见证为 219,448 行。两组保持相同根顺序、141,734 个抽样行、108,191 个参与行和 250,229 对偏好。保留资源字段的五角色拟合为 202.88 秒、RSS 2.49 GiB；隐藏 `resource/` 的控制组为 225.92 秒、RSS 2.42 GiB。原始采集子进程耗时合计 6,205.13 秒，四路并行；该数值不是墙钟耗时，单次拟合时限覆盖全部角色。

两份线性产物实际 **逐字节相同**，摘要均为 `d71e6038617f35fb60c11fbe7167542cbf85f08e9d122b9ce90e49ed10489a47`；新增两列未成为线性项。冻结实验脚本按两个训练组分别运行了其五场筛选，结果相同。这是重复执行成本，不能算作两个独立模型的证据；后续同源实验应按模型身份复用此类验证。

保留资源的完整模型在 THE_KIN 仍损 24 HP，但漏掉旧算法的一次成长奖励；KAISER_CRAB 从旧胜局变为失败。线性模型保住前者的奖励，仍丢失后者，同时将 KNOWLEDGE_DEMON 从旧失败变为胜利、损 56 HP。

隐藏资源的完整模型通过全部五场初筛：THE_KIN 的奖励和 KAISER_CRAB 的旧胜局均保留。扩展开发中，BYGONE_EFFIGY 战损 27→29、DECIMILLIPEDE 战损 26→39，SLIMES 同为零损但结束回合 3→5；另外两场政策改善。VANTOM 的候选与基线都含原先的预测风险，继续记为未核实，不能认证质量。完整模型摘要为 `b326c1151a7bf1216c7ddd25744a9d1def48ed1648bd1226fb22f3aad106dca5`。

这是同一份新采样中的特征消融：增加可解释的机制量并不保证有限数据下的树更稳健。隐藏资源的模型能保住此前反复丢失的胜局，也表明不能单凭该反例断定原观察完全缺失必要信息。尚需区分样本覆盖、训练偏差与模型对特征组合的敏感性；没有证明数据量是唯一瓶颈，也不把原始行数视为独立战斗数量。

三份不同模型都未达到最终测试门槛，最终集保持封存。全部 30 次候选执行成本按原记录保留；不依据触及时间边界且路线不同的这些运行声称游戏搜索提速。资源查询实现保留用于研究采集，正常游戏仍不启用学习模型。
