# 纠偏查询的回合内深度抽样

本轮依据[完整补采位置审计](source-balanced-corrections-20260928.md)：1,595条查询中1,119条处于本回合尚未行动的位置，第2～4回合这一比例为89.88%。原采集器每回合只保留首次合格竞争，因此增加跨回合支持后，仍缺少回合内后续决策。已完成补采、完整训练与100场400次配对开发评测；核心13场改善、71场一致、16场退化，模型仍未达到替换条件。

## 实现

`SearchCorrectionSampler` 对最先观察到的三个合格回合各保留一对真实竞争：第一层在不同回合内动作深度之间做蓄水池抽样，第二层在选中深度的实际竞争之间抽样。两套局部伪随机流分开，重复浅层竞争不会增加该深度的入选权重；零动作位置仍可入选。种子来自冻结根状态，不使用或推进任何战斗RNG。该方法只平衡实际观察到的合格深度，不保证均匀覆盖所有战术、所有回合或未生成分支。

查询仍在最终保留及incumbent裁剪之后产生，保留与淘汰端必须同回合、同总动作数、同回合内动作数。现有风险、终局、未解决根准备及96步完整前缀限制继续有效。最多三对、六条查询，教师仍共用六秒软额度，每次至多1,500毫秒/1,000节点，不增加卡牌或遗物手写效用。

`SearchOutcomeValueModel.Corrections` 为这六条查询独立保存脱离节点的前缀、数值特征与完成见证，不占普通8,192状态/256观察池额度。替换样本后旧前缀不再由采集器持有；工厂同步执行，不保存节点、模拟器或闭包。每对使用自己的观察组，不继承普通采集的池成员关系。原观察与查询都通过同一终局政策更新已知最好见证，未知保持未知；来源平衡训练仍按一次物理根计权。

离线输出增加局部抽样种子、各回合的已见深度、逐深度竞争数、实际选择次数，以及查询被选中时普通观察池的占用。这些是覆盖与采集成本诊断，不能替代战斗对照。模型推理和默认旧算法不采用纠偏采集；冻结v76评估已先完成，才开始本轮构建和试采。

## 实际验证

- Mod和显式引用该DLL的离线宿主构建成功；Mod仅有离线NuGet漏洞源NU1900警告。213项排序/训练/采样合同通过，其中新增12项覆盖可复现性、浅层重复不改变深度选择、后续竞争替换、三回合容量、非法深度拒绝及导出元数据隔离。
- Bash和PowerShell结构门禁均通过230个Search文件。首次运行因仍检查旧的回合集合字段而失败；更新为新采样器的容量、数组及深度条件后通过，初始失败日志保留。
- 原生查询合同28项通过，六条查询分别位于第2/3/4回合，局部深度为1/0/2；完整与逐步回放的状态、历史、RNG及根不变检查通过。该开发诊断根的观察不进入训练，仍不声称覆盖专用强制结束回合或回合开始选牌场景。
- 预先固定的十个训练根全部完成，装备及两份完整原生根戳与原采集一致；八根各产生六条查询，两根没有合格查询。48条均取得已知终局标签并通过原生排序读入验证，每条只属于自己的一对查询池。
