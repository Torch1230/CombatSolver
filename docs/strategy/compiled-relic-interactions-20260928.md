# 可编译的遗物条件交互原型

当前完整模型中没有直接遗物树分裂。训练装备支持度不足是一个具体限制，训练算法还存在独立的表达障碍：当前锁定的[XGBoost 3.4.1分裂调度](https://github.com/dmlc/xgboost/blob/v3.4.1/src/tree/driver.h)拒绝即时增益不大于内部阈值的分裂，即使`gamma=0`。当同根不变的遗物条件使某个动作偏好反向、两类样本恰好抵消时，单列边际增益为零；单纯增加相同分布的数据不能保证贪心分裂学到这类交互。原内置拟合器曾显式允许平衡的零增益分裂，这一点不能认为更换外部后端后自动保留。

这是表达能力的反例，不是实际战斗退化的因果诊断。真实数据还可能有非零边际相关、间接效果、稀少支持、噪声见证及搜索分布差异。

## 离线原型

`tools/OutcomeValuation/context_gate_fit.py`显式运行新研究后端，默认`xgboost_fit.py`、采集器、游戏入口和冻结的v82协议均不变。沿用权威C#导出的原始观察、真实偏好图、根权重及线性基础项，不生成新标签或按ID指定卡牌／遗物效用。

先拟合48棵原深度6树。至多64个交互信号候选中，至多32个来自这个训练前缀实际使用的列；其余来自已有战斗、玩家、资源、宠物和牌堆／卡牌类型聚合的原始数值字段。这一部分允许加入前缀未使用的观测，避免纯条件信号由于零边际增益而永远没有机会进入。候选数上限和特征类别是明确的研究约束，不代表覆盖全部交互。

将原生`relic/<ID>/present`二值列与信号列相乘，根据当前训练梯度和同一Hessian对角上界筛选至多64项。逐项临时计算，不物化完整笛卡尔积；排序只读训练数据。恒为0／1的遗物列跳过，非二值／非有限输入拒绝。筛选分数是拟合代理，不能称作特征重要性、独立根支持度或战斗收益。

最后16棵树使用包含这些乘积的矩阵，深度上限4。乘积分裂在导出时编译成“遗物不存在则取零值对应分支，否则比较原数值列”。因此最终仍是64棵原格式树，最大深度不超过8，输入只含原始列；游戏不计算乘积，不增加模型格式或训练库依赖。更长判断路径与可能复制的子树会增加部分推理／文件成本，尚未测量实际搜索代价。

原Hessian门槛3和根支持筛选不放宽，因此该原型不会自动解决稀少遗物监督问题。48+16结构同时改变了后16棵树的深度与候选特征；实际对照必须将其作为整体候选，不把结果全部归因于某一个变化。

## 逐轮叶节点门槛诊断

新增只读工具`context_product_audit.py`，重放已保存的48棵前缀与后续16轮预测，从同一训练图重算每轮Hessian。它不训练新模型、不改权重或标签，不读取开发或最终测试场景。真实数据审计须等当前配对评测进程结束并回收后串行执行，外部硬限时180秒。

对有限乘积列z，任意数值阈值都使其中一个子节点仅含严格正值或仅含严格负值。由于行Hessian非负，正值与负值Hessian总和的较大者，是该子节点在根及任意后代处的上界。如果加上保守数值余量仍小于叶门槛3，该列本轮不可能分裂；未被排除仅说明通过这一必要条件，不证明有增益、足够独立根或会被选中。零值行的总量不能填补这个非零子节点的证据缺口。

数值计算遵循锁定版本的[自定义梯度入口](https://github.com/dmlc/xgboost/blob/v3.4.1/src/c_api/c_api.cc)与[梯度类型定义](https://github.com/dmlc/xgboost/blob/v3.4.1/include/xgboost/base.h)：先转float32，再按float64累加，临界值保守地不归为不可能。首轮显式使用前缀预测，避免把XGBoost的`iteration_range=(0,0)`误当成零棵树。

6项小型合同最终通过，进程0.210秒、峰值RSS约74.3MiB，限定CPU0。其中枚举所有后代子集和阈值验证必要上界，并将保存后逐轮重放的Hessian与96行合成训练中实际记录的16轮Hessian逐值比较。新增重放合同先发现NumPy计数不能直接写JSON，修正标量转换后重跑受影响的六项。它们不是实战结论。真实292根审计在评测进程正常结束并回收后完成，默认拟合器与v84冻结协议不变。
