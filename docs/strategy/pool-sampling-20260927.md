# 保留比较关系的训练抽样（2026-09-27，离线研究）

目标仍是替换手写中途估值后，在独立战斗中取得更好决策或相同质量下明显更快。增加偏好对、降低训练内存或训练准确率上升都不能单独满足这个目标。当前正式搜索未启用研究模型。

## 问题与单因素实验

缩减每根观察行数可以纳入更多独立战斗，但逐行抽样会让一个同池比较只剩一边，削弱有效监督。本实验固定上一轮的 170 个实际根、原始见证文件、512 行/根上限、模型结构、根权重及开发筛选，只把行抽样改为按已观察到的比较组抽样。

宿主先验证所有原始见证，再按固定随机序打乱组。只有至少两个不同已观察状态的组参与抽样；加入一个组时保留其全部已观察成员。跨组重复状态只存一次，不能为了增加比较重复行。不读取标签优劣或特征数值来选组，也不为未知/被剪掉的状态造标签。组无法放入剩余名额时跳过；若一个完整组本身超过该策略分到的总行额度，则明确报错。保留的状态仍携带其真实组关系，原来跨组共享的状态可能连带形成其他有效比较。

旧输入及 `sampling: "rows"` 保持旧抽样。仅显式训练 JSON 中 `sampling: "pools"` 开启这个实验，未知值拒绝。它不是玩家搜索模式，没有修改运行时排序、终局政策或训练标签比较器。

| 同一批 170 根 | 保留行 | 有效偏好对（每根最多 4096） |
|---|---:|---:|
| 随机行 | 74,219 | 99,019 |
| 比较组 | 72,482 | 170,154 |

组抽样少保留约 2.3% 的行，多保留约 71.8% 的有效比较，170 根都有比较信号。这是训练输入效率，尚不是决策质量结论。全部原始观察仍保留，最终测试保持封存。

## 检查与证据边界

Release 离线宿主与 64 项 C# 排序/训练合同通过。新增合同覆盖完整双边比较、跨组共享而不重复状态、冻结输入确定性、把所有标签优劣反转后抽样不变、过小组预算拒绝和未知采样值拒绝。Mod 搜索代码未改动，沿用已有同源码构建与本机部署，不重复整场原生差分或可见 Steam。

拟合 341.91 秒，进程墙钟 342.10 秒，峰值 RSS 2,196,332,544 字节（约 2.05 GiB）。实际参与偏好的是 57,879 行；模型结构与默认参数不变。线性和完整模型的五场开发筛选都在 THE_KIN_BOSS、KAISER_CRAB_BOSS 退化，没有超过基线的场景；相比上一轮逐行抽样，也失去其 KNOWLEDGE_DEMON_BOSS 改善。因此不提升为夜间默认抽样。详见[结构化证据](pool-sampling-20260927-evidence.json)。实验目录为私有 `.local/objective-search/v35/pool-fit/`，模型由冻结程序生成，训练和验证使用独立进程。后台 `overnight-current` 继续原来的逐行抽样，不因输入效率改善就自动改用新方案。

## 方法参考与适用范围

[RankNet/LambdaRank/LambdaMART 原作者综述](https://www.microsoft.com/en-us/research/publication/from-ranknet-to-lambdarank-to-lambdamart-an-overview/)讨论同一查询下的相对排序学习。本项目把一次真实搜索比较池视为可比较组；这里的组抽样是针对本项目有界观察的工程实验，不声称论文证明了它在本游戏中的收益。

[DAgger 原论文](https://proceedings.mlr.press/v15/ross11a.html)指出序贯决策的后续输入分布依赖先前动作。由此推断，本项目除了增加随机开局，还需要观察模型自身搜索到的状态；现有夜间采集以部分模型引导轨迹和有界纠正补充这类数据。但当前有限搜索提供的是可行后续见证，不是最优专家，不能套用论文结论宣称已解决泛化。

## 高难训练根的教师重搜

另从训练集选择五个角色各两个原先由旧算法采集、只有失败见证的第三章首领根；按原索引顺序取样，不读取开发/最终测试结果。只把教师搜索从 Beam16/6000 节点/12 秒增到 Beam24/12000 节点/30 秒，保持原角色、原生装备、全部根状态戳与无药政策一致。十场都没有新增成功见证或有效偏好，其中一场的选中结果还带预测风险并明确记录。

这不证明这些牌组不可获胜，也不能证明扩大预算永远无效；本次结果不足以支持将较昂贵的自动重搜加入夜间采集。原始输入与两次观察分别保留，不把同一根重试算作新独立场景，不把失败、风险或未完成后续伪装成成功标签。墙钟及子进程成本另记在上述证据中。
