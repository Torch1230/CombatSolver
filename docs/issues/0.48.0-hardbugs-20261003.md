## 保留的首因

`a71a97865d11427882a8c6ff49bd4665`：佩尔军团持有已完成CardPlay引用导致Fork失败，已经修复并验证。该包此前第一次精巧谋划后少一张消耗牌；9手牌、14抽牌、两次不同实例、Sly及相关遗物的原生完整合同通过，仍未复现这个首差。环境有Sts2CardAdvisor与DeckView；本地缺对应程序集，尚无证据证明其具体影响。保持严格身份和状态断言，整包保留。

`5f702a34efa84d2cb7ff9ee0d86257ac`：战斗监听快照的ModSubscriber后缀失配。环境加载MultiEnchantmentMod与sts_2_punch_tea_master；[MultiEnchantment公开源码](https://github.com/1939323749/MultiEnchantmentMod/blob/main/MultiEnchantmentSupport.Ui.cs)在原监听序列后追加额外附魔，符合该失败机制。原包没有实际补丁表或额外附魔实例审计，具体来源仍未证明；未把它列为已修或已证实第三方首因，整包保留。

`96135b44`的录制选择Production(index2)，驱动日志却记录JOAT(index1)。修复已经验证原生接受边界，原包实际开页时间被重置的来源仍未证明。

## 正常失效与外部动作证据

- `5d4da455`、`c682c2db`的录制在搜索根之后包含人工出牌/结束回合；`513db8f7`使用锻造祝福，`2938e800`使用混沌特酿。旧根失效符合预期。
- 其余人工偏离包由审计`manual_divergence`及录制动作归类，完整ID保存在结构化记录。
- `4b6eb02b`录制Sequence2使用爆炸安瓿，部署路线没有该动作；`Origin=solver`表示动作发生在部署期间，不能证明它来自部署计划。随后套用失效前缀导致的计算失败已修。
- `60c40985`末步星尘后预测和实际敌HP均65，原结果`engine_risk=True`、`combat_ended_turn=-`；部分路线耗尽后继续搜索，未出现状态失配。
- `d8767426`报告硬错误和计划外重算计数均0；当前258条战斗日志无错误，导出发生在搜索期间。
