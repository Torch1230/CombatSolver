# 在线统计与管理后台

## 客户端更新提醒（0.35.3）

成功的 `POST /v1/heartbeat` 返回 HTTP 200 与 `{ "latestVersion": "0.35.3" }`。版本由管理后台“客户端更新提醒”维护，通过已鉴权、校验 Origin 的 `GET/POST /api/release` 读取或保存，持久化于 SQLite `release_settings`；传入 `null` 表示关闭提醒。只接受三段非负整数版本，发布包可下载后再更新此值，允许回撤误填版本。

客户端复用每 30 秒一次的现有心跳与 HTTPS 证书校验，按数字比较三个版本分量，仅在服务器版本较新时显示中英横幅；与其他提示并存，不改变战斗操作。网络失败或旧服务器 HTTP 204 保留最近一次有效确认，非法响应记录明确告警；有效的相同/较低版本或 null 清除提醒。后台 HTTP 结果只写入线程安全的纯值状态，由主线程刷新 UI。关闭在线统计会停止后续版本检查；该功能不向 Steam 请求版本，也不绕过统计开关增加匿名请求。

监控工作台源码已同步线上部署对应的 `5611856`（包含 `342f887`、`1e2ec40`），保留新版筛选、阅读时暂停刷新和服务启动恢复采样。工作台用法见 [监控工作台](ONLINE_WORKBENCH.md)。

## 玩家设置与统计口径

0.34.7 增加独立持久化的匿名跑局战绩和首次历史战绩快照，包含角色、进阶、版本、胜负及求解器参与情况；受同一在线统计开关控制。旧文中的内存清理指昵称和最近战斗详情，不包括新增战绩。完整口径、接口与保留规则见 [跑局战绩](RUN_STATISTICS.md)。

后台“跑局中”使用 0.33.6 新增的 inRun 字段，统计当前处于跑局内的玩家，包括地图、商店、事件、休息与战斗，排除主菜单。跑局内挂机仍计入；最近战斗缓存不参与此判断。旧客户端没有该字段，暂不计入跑局人数，数字悬停显示缺少状态的人数。在线总人数与累计时长保持原口径。

在线统计默认开启，可以在设置的“在线统计”区域随时关闭，选择自动保存。每 30 秒向作者的统计服务发送随机安装标识、平台昵称、当前角色、楼层、当前战斗敌人名称、已计算的预计累计战损和 Mod 版本；完整路线、卡组、存档、Steam ID 与聊天内容不在上报字段中。

预计战损来自已确认战斗结束的完整路线，0 损是有效结果。客户端在游戏进程内缓存最近一次完整结果的角色、楼层、敌人和战损，主菜单、非战斗或新战斗尚未算完时整组沿用，收到新结果后整组替换。后台列名为“最近已计算战斗”，悬停显示采集时间；首次完整结果前显示“等待首次计算”。心跳仍每 30 秒发送，真实战斗状态与缓存字段分开，缓存不会增加战斗中人数。

心跳在原字段之外增加 inCombat 和 battleUpdatedAt。服务端接受旧客户端，并在本次在线期间缓存其最近完整战斗；旧客户端只能保留实际发过的结果，新客户端可捕获两次心跳之间完成的结果。服务端缓存随离线或重启清除，客户端缓存随游戏进程退出清除，不新增磁盘战斗明细。

同一安装标识去重，90 秒未收到心跳即离线，昵称和战斗详情从内存清除。关闭统计会取消当前请求并停止后续上报，列表最迟 90 秒后移除该玩家。重装、复制本地配置、网络连接和关闭统计会影响统计人数，因此这里统计的是近期上报的安装实例，不能视作 Steam 官方实时人数。

累计在线时间按服务端相邻心跳时间差累加，间隔达到 90 秒即视为中断，该离线间隔不计入。随机安装标识、累计毫秒和最后心跳时间保存在 SQLite `durations` 表，跨次上线、断线及服务重启保留；不保存历史昵称、角色或战斗详情。计时从此功能部署后的首次心跳开始，旧数据没有个人时间记录，无法补算。正常计时精度受 30 秒心跳间隔影响。

人数图表按所选时间跨度与绘图区宽度自动合并采样，服务端使用固定时间桶计算平均值；原始一分钟记录保留，顶部区间峰值使用原始最大人数。采样中断会拆开时间桶并断开曲线。概览接口支持 `maxPoints=32..240`，返回聚合间隔和各点实际采样时间范围、样本数；存在断档时优先保留断档边界。悬停按横轴寻找最近点，整列高度都可触发提示和垂直虚线，提示注明平均在线人数及覆盖时间。

在线玩家排行榜按所有当前在线玩家的累计毫秒降序排列，同值按安装标识稳定排序；离线用户保留累计值但不展示。每页固定 30 人，只在请求当前页时返回对应记录。搜索在服务端覆盖全部在线玩家，保留全局名次；翻页不预取后续页，人数减少后越界页会回到最后有效页。`GET /api/overview` 仅返回全局人数与历史图表，`GET /api/players?page=1&q=...` 返回分页排名。

无头求解子进程、无人测试进程和多人跑局不上报。历史人数每分钟采样一次，SQLite 持久化保留 90 天，不保留历史玩家名单；累计时长独立于该人数采样表保存。服务停机期间没有人数采样，图表显示间断。

## 服务与后台

源码在 `tools/OnlinePresence/`，使用 Node.js 24、SQLite 和 Chart.js。管理页显示在线人数、战斗中人数、区间采样峰值、玩家状态表，以及 1 小时、24 小时、7 天、30 天折线；支持按昵称、角色、战斗筛选。

采集端提供 `POST /v1/heartbeat`、`POST /v1/runs` 和 `POST /v1/run-history`，严格接受既定字段和大小，按请求来源与安装标识限流，并限制连接数和在线记录总量。它不提供玩家列表或管理 API。客户端请求属于自行上报，接口不声称提供 Steam 身份认证或防伪在线人数。

管理端默认监听回环地址，也支持通过私有环境配置开放独立 HTTPS 端口，并需要独立管理密码。监听非回环地址时强制要求 TLS 和允许的公网 Host。登录限制尝试频率，使用 HttpOnly、SameSite 会话 cookie，HTTPS 下增加 Secure；写入请求按实际连接协议核对 Origin，拒绝未登记的 Host。玩家字段通过 textContent 渲染，页面不加载第三方 CDN。管理密码和 SSH 凭据不分发给 Mod 客户端。

昵称和战斗明细只在内存里，业务日志不打印心跳内容、来源 IP 或玩家昵称。服务器网络层能看到连接来源，管理员应使代理和网络日志策略与这里的明细保留口径一致。

## 私有部署配置

客户端构建可通过仓库外配置或被忽略的 `.local/presence.props` 提供 MSBuild 属性 `PresenceEndpoint`（HTTPS 根地址）和 `PresenceCertificateSha256`（服务证书 SHA-256）。构建时写入程序集元数据；没有配置的源码构建不启动网络上报。真实地址与指纹配置不提交到源码。

客户端同时验证证书名称、有效期和固定证书指纹，禁止重定向、明文传输和任意证书信任。无域名部署可使用带 IP SAN 的专用自签名证书。更新证书需要同步客户端信任配置；私钥始终仅保存在服务器。服务地址是客户端连接所必需的信息，不能靠不写文档实现隐藏。

服务环境变量为 `ADMIN_PASSWORD`、`TLS_KEY`、`TLS_CERT`，可覆盖 `COLLECTOR_PORT`、`ADMIN_PORT` 和 `DATABASE_PATH`。公网管理端额外配置 `ADMIN_BIND`、`ADMIN_TLS=true`、`ADMIN_PUBLIC_HOST`，复用专用服务证书；使用自签名证书时浏览器首次访问需要核对确认。密码至少 20 个字符，环境文件与私钥权限为 600；`presence.service` 是用户级 systemd 模板，使用独立工作目录、资源上限与重启策略。启用 linger 后可随服务器启动运行。

部署前执行 `npm ci --omit=dev --ignore-scripts`。服务端源码、package-lock 与前端资源可以版本管理；`private/`、`.env`、密钥、数据库和 node_modules 已被忽略。真实连接地址及本机管理访问凭据仅保留于维护者的 `.local/` 私有文件。

## 验证

服务端：在 `tools/OnlinePresence` 执行 `npm test`，覆盖额外字段拒绝、未知/零战损、鉴权、Origin、去重、超时离线、历史持久化和限流。

客户端：`ONLINE-PRESENCE-CONTRACT` 无人场景验证默认值、关闭持久化、战斗标量快照、真实 HTTPS 与错误指纹拒绝。该场景需要私有端点配置，仅发送空对象并要求服务器返回 400，不发送玩家心跳，也不产生虚假在线人数。普通无人场景不会连接统计服务。
