# CombatSolver 滚动重构路线

## 策略与搜索重构收尾（2026-09-28）

P0–P6 已按各自固定根和边界证据收口；P7 仅完成单项权重探针与免费生成药链，目标代表试验因哨兵退化撤回。P8 已有此前提交的局部归因和诊断工具，但未达到阶段退出标准。按用户本次要求，停止 P7/P8 的新增工作并收尾；实际迁移、验证范围及剩余限制见[实施总结](strategy-search-refactor-summary-20260928.md)。

## 策略重构 P5（已收口，2026-09-28）

`AdmittedJobScheduler` 统一从 `AdmittedParent` 选取准备、卡牌、挂起选择、药水和回合尾部作业；`IExpansionExecutor` 保留串行即时交付与并行固定 lane 的执行差异。#24/#37/#81/#89 加两个生成根，对 P4 同政策 DOP1 基线的完整动作、续用、终局、工作量及剪枝逐位一致；P8a 后加的工作归因字段不参与旧协议字段对照。GA-SILENT-BOSS-00 的 DOP8 对其自身基线 122 个非时序字段全同。DOP8 搜索耗时 24,053→24,091 ms、worker 分配 11,885,994,992→11,879,940,960 字节，仅作观测。无头实例已清理；Linux 门禁按用户要求未运行。

## 策略重构 P6（已达退出标准，2026-09-28）

复制、能力启动、跨回合能力和生成免费药链均由 `PlanCommitment` 表达；固定前缀续搜使用共享请求账本与前沿调度器，终局由原路线质量政策裁决。VeryHigh／180 秒／DOP8 同根同政策：#100 从 41 战损／2 药改善到 22／2，#101 从死亡路线变为胜利 58 战损／1 药。与旧玩家投影相比仍分别多损 18、13 HP；旧投影不能代替当前源码同根人工回放。已达标 #90 保持 0 战损、最终 49 HP，完整动作、质量、剪枝与工作量同旧结果；GA-SILENT-BOSS-00 DOP1 对 P5 基线逐位相同。#100／#101 对此前 P6 结果也逐位相同；跨回合能力计划类型迁移后 #100 再次逐位相同。计划地平线的上限合同已验证，但这些目标根没有命中续期，不把两包收益归因于续期。Linux 门禁按用户要求未运行。

## 策略重构 P7a（探针已实现，校准未完成）

建立单项 Beam 权重灵敏度入口：无人测试请求在 Testing 校验项目和倍率，Runtime 冻结到搜索 profile；语料运行器可选择固定根，专用对照器只允许该扰动造成政策差异。矩阵工具可复用一次基线汇总多个已采集扰动。#24 玩家根与 GA-SILENT-BOSS-00 在 `CurrentEnergy:0.8` 下均为质量不变；GA-SILENT-BOSS-00 在 `EnemyHp:0.8` 和 `PersistentBuffDelta:1.2` 下均保持 44 战损／0 药，但末位 score 低 1。P6 收口源码的 #100 在同根同预算的 `PersistentBuffDelta:1.5` 下由 22 升到 55 战损、仍用 2 药，故不改默认权重。阈值维度和其他根的校准仍待证据；P6 地平线尚缺实际触发样本。

## 策略重构 P7b（部分完成）

增加混沌药生成链的有界续搜，并从已选首张牌后的合法进攻跟进提名早期变体。#90 同根从 3 战损／2 瓶原有药改为 0 战损／仍为 2 瓶原有药，另用两瓶免费生成药，最终 HP 46→49；已达标生成根逐位不变。动态机会成本和其他生成链来源仍待实现。

## 策略重构 P7c（试验撤回）

提前预约每目标 Beam 代表让 #97 从 21 降到 9 战损，但同源码基底的已达标多敌 #81 从 8 升到 9 战损。源码已撤回，目标代表的准入／最终保留位置仍需分层证据；当前无 P7c 生产行为变化。

## 策略重构 P8a（此前局部实现，本次暂缓）

常驻会话在新超时请求上保存最后一份本请求监控快照，包含阶段、当前成员节点上限、展开和结束节点、前沿与最好路线；旧超时包无快照时标为证据不足。请求账本现按前沿续搜用途、主 Beam、宽度精炼和直接审计／侦察成员分解工作量。#81 的主搜、Smart 药水梯度和能力成员分项与请求总数一致；其他可选成员尚无本轮命中证据，13 个历史超时包主因尚未完成。

## 策略重构 P8c（此前局部实现，本次暂缓）

修正离线首个丢路查询的边界配对，多个子搜索的相同边界编号不再混写，并区分全局 Beam 与后续仲裁落选；仍需事先采集观察数据。玩家包直达查询、模型编号映射和离线 ABBA 尚未完成。

同根结果的动作首分歧现可直接从两份 headless 证据提取；#97 的较优实验路线从第 2 张能力牌就不同，目标代表机制只是促成该路线的候选解释，尚未证明目标选择本身是首因。工具还未把问题 ZIP 自动接到路径观察；首个实际剪枝阶段仍待采集。

## 策略重构 P8b（源码核对）

计划所举 #44／#66／#68 的组合、抽弃牌和结束回合前缀失败在现有源码中已有具体修复；本次不重做，也不扩大异常捕获。尚无新的组合冲突样本可验证 P8b 的更广目标。

本路线已完成并合并到 `main`；`0.14.0` 发版以 `main` 为准。

本重构按小范围滚动推进。每一轮只读取相关源码和夹具，先更新核验记录，再实现、验证和提交。未核验的外部审计建议不直接进入代码。

## 第一轮：失败语义与搜索请求边界

### 目标

- 任何未知模拟错误都不能表现为候选被正常淘汰。
- 一次搜索使用启动前捕获的固定策略，不受运行中设置变化影响。
- Search 不直接依赖 Runtime、UI、Testing 的静态所有者。
- 不改变 Beam、评分、候选顺序、RNG 或最终路线政策。

### P2 实施状态（2026-09-27）

0.47.1 热修已并入任务分支。`SearchBudgetLedger` 现持有外层请求时钟和 `SearchRequestWorkTotals`，外层补搜与主 Pass 的前缀补搜从账本读取剩余时间与节点；药水梯度的转移采样与协调器回收开销也由此账本统计。`SearchBudgetWindow` 开始接管双药补搜的时间／节点切片，原准入阈值、候选顺序和结果政策未改。`SearchPassContext` 已收口主搜索、补充审计、开局能力与夜魇补搜、宽度与新颖性组合及无胜利升级的冻结输入与轮次时钟；三个药水审计入口也共用该上下文，截止令牌继续由补充审计派生。`SearchPassResult` 显式交还每轮的路线、接管与达标状态，`SearchRequestPipeline` 持有请求级首轮、接管和升级的调度顺序。外层双药死亡路线补搜已抽为具体 Pass；其余外层补搜尚未全部迁入管线。修复了语料运行器的语法错误，并从热修后的源码重新采集四个可比较玩家根与两个生成根；六根在外层账本迁移后逐位一致，#81 的能力路线组合及两层 Smart 药水梯度在本次成员接线迁移后与基线逐位一致，双药候选派发已由 #17 原配置直接验证；`SearchPassResult` 已扩为质量、累计工作量与真实轮次终止合同。其余前缀预算读取尚待后续对照，证据见测试矩阵。

### P2 外层补搜 Pass 抽取（2026-09-27 续）

把外层 `Solve` 里剩余的补搜块全部抽为 `CombatSearchCoordinator.PostSearch.cs` 中的具体 Pass：`RunForcedPotionOpeningRescue`、`RunTurnBoundaryRescue`、`RunZeroCostOpeningRescue`、`RunMidCombatRefinement`、`RunTurnEndChoicePosterior`、`RunEarlierCopyDelayedDamage`，并把 `RunEarlyTurnExploration` 从散参数收敛为接收 `SearchPassContext`。均为纯移动：方法体、分支条件、派发顺序、诊断标签与预算读取时点不变。`CombatSearchCoordinator.cs` 约 3,032 → 2,596 行。本轮按用户要求不启动实例，只通过 Release 编译与 Windows 结构门禁；行为等价与剩余阶段验证见[待测清单](strategy-refactor-test-backlog-20260927.md)，尚未取得基线逐位对照证据。
