# Gemini 审计处理记录

本文记录 `AUDIT_REPORT.md` 建议的核实结果。审计原文保留，不直接改写。

## 已采用

- 响应式尺寸：覆盖层根据 Viewport 调整宽高，保留最大尺寸，低分辨率下缩小。
- 路线滚动：路线区加入纵向滚动容器，长目标名和多张卡牌换行后不再被固定区域裁切。
- 紧凑折叠：折叠后面板宽度收缩，不再保留完整宽度。
- 执行反馈：自动部署时，已完成动作变暗，当前动作以黄色高亮并显示执行序号。
- 反射缓存：怪物数值字段/属性首次解析后使用编译委托，后续模拟不再重复查找成员。
- 后台让步：保留较低线程优先级，将固定休眠改为按批次检查的 `Thread.Yield()`；进度 UI 继续限制为每 200 ms 最多更新一次。
- 回合启动错峰：自动搜索至少等待三个渲染帧，并等待游戏回合开始动作队列执行完成，再进入后台搜索。
- 轻量进度文本：搜索过程使用普通 `Label`，不再每次刷新解析进度 BBCode。
- 可量化诊断：结果日志记录后台线程分配字节、每次回放平均分配、三代 GC 次数、搜索区间内进程 GC 暂停与线程让步次数。
- 热路径减配：模拟状态中的可选字典/集合改为按需创建；状态剪枝、动作支配与 Top 队列改为原地收集和排序，减少 LINQ 中间对象。
- 双 64 位状态指纹：在用户明确接受极低碰撞概率后，用两个 `ulong` 替代搜索内部的长字符串状态键；跨回合方案续用仍比较完整状态文本。
- 搜索预算收紧：根据实机回放分配量将 Beam、节点、动作和选牌分支预算下调，优先减少完整回放次数。
- 仓库整理：源码按 Search、Prediction、Runtime、UI 分区，文档集中到 `docs/`；本机路径和构建产物不纳入 Git。

## 未采用

- 报告中的固定性能结论：不采用“提升 10 倍”“80–150 ms”等未经本项目实测的数据。后续只根据实机日志中的节点、回放和耗时判断效果。
- 性能报告最初没有分配或 GC 事件数据；`0.6.1` 新增遥测后的实机日志已确认，单次搜索可产生约 `1.7–2.0 GB` 工作线程分配，并在搜索窗口观察到约 `3.1–4.6 秒` 进程 GC 暂停。具体到单次暂停时长、对象数量，以及“80–150 ms”“10 MB”等目标仍未验证。
- 直接照搬示例 UI：不采用。示例依赖当前 `PlanAction` 不具备的卡牌类型与费用字段，且会改变现有击杀与选牌胶囊语义；这些功能应在数据模型补齐后单独实现。

## 仍待解决

- 最大性能瓶颈仍是每个分支从当前实战状态完整回放。安全的父节点增量展开需要 RandomForeseer 模拟器提供可靠深拷贝，不能用浅复制替代。
- 当前跨回合只复用最终选中的路线，不复用整棵搜索树。
- `gc0/gc1/gc2` 与 `gc_pause_ms` 是搜索时间窗口内的进程级观测，可能包含游戏其他线程触发的 GC；`worker_allocated_bytes` 才是求解工作线程自身分配。
