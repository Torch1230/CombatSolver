# 有界搜索恢复研究（v54/v55 原型已否决并撤回）

本记录区分已取得的剪枝证据和候选设计，不宣称搜索已修复。v54/v55紧凑值剪枝记录与同根正常重试原型均通过基础合同但没有改善Custom质量，已从生产、Testing入口及门禁撤回。保持上游可接受战损停止规则、Smart 药水政策与原请求节点/时间预算，不按卡牌或遭遇添加搜索例外。

v54 基础合同已通过 `5b7cd7d6882b40eda490bf166bed78e2`，还不是样本质量通过。原型将整条动作父链转换为增量指纹，由 run-owned 弱键缓存持有无节点引用的值；初始展开只记录状态键，避免新增长线二次复杂度。已消费完的剪枝归还活动容量，另有有限退休摘要避免重置游标；不再以32次独立常数截断多层分页。实际重试上限受原节点额度及每次至少一个实际计账展开约束，原时间截止仍有效。具体通过边界见测试矩阵。

v55只修正过度保护：原双侧配额仲裁保持quota leaders，恢复同精确药量替换只保护required与完整胜利。旧W/pass10的19/26个普通席全部属于quota leaders，v54因此人为0/0；v55用药层no_seats降为0。然而两层各12000个恢复展开主要花在重复根前缀，用药层只到cut17、16、15、14的第一页，仍未找到胜利。原配置总29994展开、112192转移，HP0/敌347/4洗牌；这否定了该调度在当前预算下的实际收益，不否定状态重建正确性。下一设计必须处理前缀工作成本，并单独量化任何检查点保留的对象图、账本和内存生命周期；不能直接把相同HP或历史expanded状态当成完整调度检查点。

## 为什么单个补回候选不够

当前模拟器能严格重放 Custom 的十九步已知胜利路线；这不等于搜索能够发现它。对历史 v37 完整记录的关键剪枝层按双半状态指纹索引后：

- 宽度135的输入364个节点，状态去重后355个；目标排名172（从0计）。
- 目标是该层第72个在已记录区间没有最终保留或实际展开同状态代表的落选状态，同药量内第67个。不能把这两个排名写成算法常数。
- 目标与原始普通截线、必保置换后的普通截线不属精确同分块。已有同分轮转没有在目标块取得普通席位，不是轮转顺序出错。
- 同一个粗选牌上下文有已展开代表，但完整状态、牌序和父路径不同，不能据此认为目标未来已经覆盖。
- 不动必保节点和药量计数，这个旧截面有19个零药普通席、26个一药普通席。分批置换存在容量；这不是三批即可获胜的证明。
- 后续至少还有五个完整剪枝层。只保存最近层的一张票会同时遗漏较早剪枝层和该层较后排名。

原日志在后续层截断，因此“未覆盖”只指已记录区间；以上不是当前源码的新搜索成绩，也不能以相同敌人 HP 代替完整状态。

## 候选机制的职责和限制

以下是v54/v55被否决原型的设计约束，保留用于解释实验，不是当前实现。候选方向曾是持久的剪枝游标与有界重放决策链，替代失败后的一次窄宽度重试，不实现中途模拟器恢复。

1. 只在失败、没有完整胜利且原预算仍有余量时进入恢复。已有胜利、玩家接管、时间/节点耗尽直接保持现有行为。Soul 当前已有胜利且20秒耗尽，不适用这个机制，需要另找质量或单位工作成本问题。
2. 只保存不可变动作/选择身份、状态键、准入标签和剪枝地址。显式限制总字节、剪枝记录、决策链边数和尝试数；不保存旧节点、模拟器、待处理事务或转置表。
3. 每次从同一个根正常搜索，重新建立转置、循环和有序操作账本。所有重复工作同样计入原剩余节点/时间，不能把恢复重放变成免费展开。
4. 重建之前的恢复决策链，在目标剪枝处按已有同药量普通席分批置换。完整必保集合、药量分布和 Beam 容量不变；后续独立通道与循环预算仍可拒绝候选。
5. 在旧剪枝层及有限的新增分歧层之间轮转，游标不被更深的新层重置。无席位、重建身份不符或存储淘汰须单独记录，不能冒充已经探索。
6. 只有通过最终仲裁并真的展开，才计为新增覆盖。恢复一段前缀不证明后缀仍能存活，更不证明整场质量改善。

现有 `ApplyFixedPrefix` 不能替代这条流程：它不接受结束回合或强制结束回合，也不会按正常阶段推进重建全部展开与调度账本。直接把它当通用续搜入口会改变预算和历史语义。

### 下一方向尚待实现：单路重建后从叶子继续

正式 `ReplayAction` 已能执行显式EndTurn、强制结束与完整选择，但只返回Snapshot。若保存纯值完整前缀并只重建这一条路径，必须共享正常动作节点物化、保留真实回合及完整父链，所有前缀父节点工作也计入原预算；不能把单条出边回放登记为该状态所有出边已展开的TT覆盖。跨回合还有额外障碍：`AnnotateTurnOutcomes` 根据真实同组保守路线计算卖血，把单一路线作为整个组会错误清零额外卖血。票据需携带并校验有界的回合政策证据，不能只存动作然后默认数值。原兄弟分支形成的循环/区域/顺序租约不是一条路径可以完整恢复的账本；应明确新的有界attempt和NoGC生命周期，不冒充精确恢复旧Beam。

## 验收

先验证保存对象不持有模拟图、必保/药量/容量不变、取消与累计预算；再用同配置目标短搜及不可退化哨兵判断质量。分别记录：新增候选实际展开数、重放前缀工作量、身份匹配失败、无普通席位、后续裁决拒绝、游标推进、票据/剪枝记录淘汰和全部请求工作量。只有最终候选再运行完整自动部署及固定工作量性能对照。

该方向借鉴 [Beam-Stack Search 原论文](https://cdn.aaai.org/ICAPS/2005/ICAPS05-010.pdf) 的记录剪枝范围和回溯思想；论文的完备性前提不能直接用于本项目的零费循环、非保守启发式与有限资源预算。因此仍称有界启发式恢复，不承诺有解必出或全局最优。
