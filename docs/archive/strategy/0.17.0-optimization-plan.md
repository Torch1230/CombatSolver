# CombatSolver 0.17.0 策略优化规格

> 状态：0.17.0 已发布（2026-08-29）
> 发布深度：最小发布；创意工坊上传与完整发布门禁不在本次范围。
> 原始需求：`0.17.0-raw-requirements.md`

## 1. 总目标

本批次不以“搜索能返回路线”为完成标准，而以路线质量和资源结算正确为目标：

1. 同一起点和动作下，实机与模拟的战斗状态一致。
2. 能获胜时优先获胜，事件目标不能被“安全停滞”替代。
3. 终局比较以整场累计战损为主，并正确计入最大生命、一次性复活和局外成长资源。
4. 中间保路必须保住成型无限、成长牌培养和资源斩杀路线，不能用扩大 Beam 掩盖政策缺失。
5. 每项改动建立未改代码基线、目标场景和不可退化场景；战损是质量基线，回合数不是。

## 3. 策略分层

### 3.1 先修语义

- S017-03、S017-04、S017-07 和 S017-08 中涉及数值变化、复活、卡牌执行次数与牌堆去向的部分先做 actual/simulated 严格差分。
- 蜥蜴尾巴消耗、局内成长累计和呼唤状态属于分支战斗状态；必须明确根捕获、Fork、状态键、跨回合续用和清理时点。
- 无限循环的“搜索边界”与“模拟报错”分开处理。合法循环可以被证明并压缩为胜利进度，未知或无进展循环继续显式终止。

### 3.2 再修终局排序

- 胜利与事件目标高于 stand-pat 和安全超时。
- 累计战损、最大生命损失、药水与一次性复活资源分别建模，不用当前 HP 一个数混算。
- 狂宴、狩猎、贪婪之手、时候未到、王国资产和禁忌魔典作为明确的终局资源收益参与比较。
- 同为胜利且生存结果相当时，优先更多长期成长；长期成长不能覆盖死亡或更高战损。

### 3.3 最后修中间保路

- 为已成型循环、即将成型循环、成长培养、资源斩杀和关键局外资源建立有上限的独立保路通道。
- 愤怒的即时伤害和扩牌副作用分开评价；牌组已经形成更小循环时降低继续扩牌的中间价值。
- 遗传算法、巨镰、黏糊防御即使当前数值低，也要保留本场可培养候选；复制、重放和灵魂之力附魔按预期额外成长次数提升保路价值。
- 不把具体 Boss 或单个日志包名称写进通用搜索政策。

## 4. 实施批次

### 批次 A：证据与现状审计

- 安全分诊 Queen 与 Aeonglass 两个问题包，定位首个错误或候选丢失层。
- 盘点现有药水反事实、事件胜负、战损、遗物标注、循环剪枝和成长特征。
- 为十余个中文名称确认原版类型 ID，避免把同名、旧译名或重复“狂宴”写成错误注册。

### 批次 B：正确性基础

- S017-03 蜥蜴尾巴累计战损与遗物标注。
- S017-04 无限循环报错根因。
- S017-07 呼唤完整语义。
- S017-08 复制、重放、附魔下的成长次数语义。

### 批次 C：终局资源政策

- S017-01 全局增益药水的开局使用规范。
- S017-02 人偶击杀目标。
- S017-06 最大生命损失成本。
- S017-08 局外成长、回血、斩杀与炼药收益。

### 批次 D：保路与无限质量

- S017-05 小循环无限与愤怒扩牌取舍。
- 成长培养、资源斩杀和开局用药候选的中间保路。
- 固定质量基线、相邻不可退化场景和完整自动部署。
