## 0.13.26：卡牌身份克隆、振翅眩晕与配对事务收口

- 偷窃草蜢的首次偏移来自卡牌身份而不是 RNG 克隆。模拟卡牌首次写入时沿用了原版“创建新卡”的克隆收尾，清空了 `DeckVersion`；已经打出的摧残因此被偷牌过滤器排除，三张候选缩成两张，同一 RNG 原始值从第 2 张变成第 1 张。卡牌状态克隆现在保留 `DeckVersion` 与移除标志，生成新卡/复制牌继续使用原版清空语义；两项身份同时进入卡牌指纹、跨回合状态和严格差分。
- 振翅此前只递减层数，没有在归零时按原版把偷窃草蜢当前行动替换成 `STUNNED`。现在归零会读取分支行动历史、消费同一 Monster AI RNG 并建立正确后继；连续攻击不会在 Power 已失效后重复安排眩晕。
- 外骨骼问题包的 `Cannot fork while paired card-play state is pending` 来自配对状态绑定在监听器生命周期：湮灭结算中移除监听器后，出牌后 Hook 不再枚举它，瞬时配对残留。配对完成现在绑定整次 `CardPlay`，无论监听器是否在结算中移除，动作完成边界都能清空；Fork 的 fail-fast 保持不变。
- 仪式兽的削弱增幅此前从真实怪物读取 `DebilitatePower`，看不到分支中新施加的层数。虚弱与易伤乘区现在读取分支 Power，并保留纸鹤、纸蛙原版规则。原版 `0.111.0` 全量反编译源码固定在本地 `.local/decompiled/sts2-v0.111.0` 作为语义参考，后续不再为单个类型反复局部反编译。
- `0.13.26` 最终严格差分：削弱增幅 `424b21ac5fed47459ccc51693ad306ae`、已打出牌参与偷牌 `95c5b6570a444004b4422a4cde5e2902`、振翅归零眩晕及后继 `fbc61230c114421e9b7f8753588c2bde`。用户开战存档整战：偷窃草蜢 `25c6621068c6498b9bf7fcdd86b462e6` 第 5 回合结束，外骨骼 `3dd661ab8f3b4657a228fb84a914fbad` 开启增量等价后第 5 回合结束，仪式兽 `7132508e4aa24d4f9865198529938e76` 第 9 回合结束；三场均为中档、Smart、Instant/0 秒且 `UnexpectedReplans=0`。

## 1. 项目目标

CombatSolver 只解决一场已经开始的单人战斗：读取当前战斗状态和可预测 RNG，在不修改游戏 RNG 的前提下，以时间和节点预算搜索较优行动路线，并允许玩家查看或自动执行当前回合方案。

当前不讨论整局路线、选事件、商店、地图和构筑。开发回归通过隔离的塔 2 `--headless` 进程执行原版规则，不另建自有 CLI。

设计优先级：

1. 路线能在原版战斗中执行。
2. 已知效果尽量与游戏结算一致。
3. 未镜像内容必须显式记录，不能用“高置信度”掩盖。
4. 搜索在后台运行，不阻塞游戏主线程。
5. 性能优化不得悄悄改变 RNG 或把近似搜索描述成穷举。

## 2. 当前功能基线

### 搜索

- 两阶段 Beam Search：默认中档短搜统一宽度 `18`，深化统一宽度 `45`；药水不再拥有独立配额。
- 普通搜索按可用逻辑处理器自适应选择 DOP1/2/4，新安装在至少 4 个逻辑处理器时默认 DOP4；设置可在 `1–16` 之间调整。候选仍由协调线程按原顺序提交，详细诊断与严格增量验证固定使用单线程。
- 默认中档短搜预算 `8 秒 / 2400` 节点；短结果存在未来掉血、用药或未确认胜利时，同一搜索会话继续使用总计最多 `120 秒 / 12000` 节点的深化预算。
- 回合内行动数不设上限。费用、星能、可出牌性、击杀、精确状态置换、通用有界周期调度、时间和节点预算共同构成终止条件。
- 不设固定回合数或洗牌次数上限；时间、节点、确认胜负、跨回合无进展窗口和有界周期探测共同构成搜索边界。周期证据不是无限性的数学证明。
- 每节点默认中档短搜最多保留 Top-14 出牌分支，深化最多 Top-24；深化同时扩大牌堆/手牌选项预算。
- 子节点保存生成时的模拟快照；后续展开、最终复核和路线标注复用快照。
- 最优路线会保存后续玩家回合的预测起点；真实状态逐项文本一致时直接复用剩余路线，状态不一致则重算。点击“重新计算”始终从当前实机状态发起新搜索。
- 相同状态下的等价重复卡牌只模拟一次。
- 每次 Beam 剪枝除评分最高路线外，还保留一条当前威胁下预计剩余生命最高的防御路线，使回合结束时的最低可达到战损基线不会被输出评分提前挤掉。
- 深化搜索额外保留成长、资源、控制和帕累托路线，并对非即时效果执行一次缓存的结束回合探测；不按具体牌名特化毒伤或蛇咬。
- 同一搜索会话复用“父状态 + 动作”的模拟转移。完全相同状态继续由置换表剪除；控制形状在最多 `8` 个动作内重现时，以动作相位和一致转移建立通用周期证据。无即时进展的族按节点档位获得有限动作租约，并对各相位的非周期出口做最多 `8` 动作、`2` 次回合转换的收益探测；伤害、逐敌人耐久、回复、资源、持久成长、控制、牌库净化或特殊目标进展会阻止无进展淘汰。生产实现不包含按卡牌、Power、遗物或敌人名称放宽预算的分支。该机制不限制普通回合行动数，也不承诺找到所有长周期或晚兑现组合。
- UI 在滚动框中展示本次搜索得到的全部回合；完整路线同时写入日志。

### 选牌

- 支持从手牌、抽牌堆和弃牌堆选择已有牌，以及移动、弃置、消耗、升级等已列入支持表的选择。

- 每回合显示预计掉血、剩余费用、击杀和战斗结束。
- 本局扣血以无边框文字显示在“推荐路线”标题右端；常态界面不再显示主动卖血摘要。“状态详情”移到“方案就绪”状态行右端，详情内容仅在展开时占用高度。
- 覆盖层可拖动并按 Viewport 约束位置；标题栏去掉副标题，状态描述卡始终存在。路线窗口固定为三条未换行回合的高度，当前回合换行时优先完整显示当前回合。
- 顶部状态卡只保留一行 `14px` 原生粗体信息；底部只保留紧凑按钮行，战损栏与下分隔线之间不留伸缩空白。
- 自动部署时已完成动作变暗，当前动作以黄色高亮并显示执行序号。
- UI 的颜色、间距、圆角、字号和按钮样式集中为设计 Token；文字统一使用游戏当前语言字体，标题/指标/正文/辅助文字采用 `15/14/13/12px` 四级字号，不再出现难读的 `11px`，标题、回合标签、卡牌名和关键结果使用原生粗体。回合行拆成固定“回合 / 行动 / 结果”三列，单行按 `28px` 胶囊加上下各 `8px` 收束为 `44px`，三列内容统一垂直居中。行动胶囊按攻击、技能、能力、负面牌和药水使用克制的类型色。完整怪物名、胶囊内选牌和整颗击杀高亮沿用既定规则。
- 展开面板不再使用固定最小高度，按当前可见内容收紧；路线、状态详情或内部最小尺寸变化后执行两次延迟布局，先完成胶囊与底栏换行，再按新最小高度收紧底边，避免面板偶发多出一段空白。结果栏紧贴下分隔线，按钮区在分隔线下留 `8px`、面板底部保留 `12px`。
- 标题栏在“收起”左侧提供“设置”按钮。设置页可持久化三类全自动暂停、详细诊断日志、快搜/深搜时间、统一 Beam 宽度、节点上限、单节点出牌分支、牌堆/手牌选择分支、No-GC 预算（默认 `8 GB`）和 UI 位置；文件为 `user://combat_solver_settings.json`。性能预设为低、中、高、极高和自定义，复杂预算项带悬停说明。详细诊断默认关闭，只在下一轮新搜索中启用高频分支日志。数值框留空时不保存覆盖值，以灰色占位文字显示代码默认值；无效输入保持红色并阻止离开设置页。拖动只在松开时保存坐标，分辨率变化后仍按 Viewport 约束。
- 设置页提供“一键导出问题包”：按游戏问题包口径在后台收集最近 `8 MB` 日志、截图、当前档案和版本信息，并追加当前战斗完整续用状态、可读摘要、当前路线与求解器设置；ZIP 写入桌面 `CombatSolver-BugReports` 并打开所在目录，不自动上传。
- 面板拖动统一使用 Viewport 绝对鼠标坐标，避免标题栏局部坐标随面板移动而形成反馈漂移；移动帧只更新并约束现有矩形，完整响应式重排和位置持久化均在松手时执行。
- “收起”只隐藏方案摘要、路线和详情，保留重新计算、执行本回合、全自动三个操作按钮；紧凑状态隐藏“战斗结束时暂停”开关。
- 回合开始的强制选牌不再停在动态边界等待玩家。必备工具、暴政、熵和烘焙手套会进入 Beam 选牌分支，弃牌、耗尽或随机变换结果进入牌堆、RNG、状态指纹与跨回合续用校验；自动部署把同一组选牌保持到新回合结算完成，路线行显示选择来源与牌名。目录内效果若发起计划外战斗选牌会明确失败并停止自动执行，不再用运行时猜测掩盖搜索缺口。
- 战斗结束、胜利结算、放弃或退出时自动隐藏并取消后台任务。
- 后台模拟中的动态费用等预测变量可能触发从原卡牌克隆过来的 `CombatStateTracker` 事件。求解作用域会抑制这类伪状态通知，避免工作线程启动真实手牌 UI 刷新；正常游戏线程上的战斗状态通知不受影响。

## 3. 当前评分语义

最终路线不再只按线性 `Score` 选取，而是依次比较：玩家存活、确认胜利、整场预计掉血、药水数量、累计主动卖血、敌方剩余生命和行动数量。动态重搜或未支持边界不能冒充确认胜利。普通药水路线若能取得无药路线做不到的确认胜利可直接进入比较；否则仍须相对最佳无药路线每瓶至少省下 `9 HP`。龙涎香不适用胜利直通：无论药水模式如何，都必须相对最佳无药路线最终多保住至少 `ceil(最大生命 × 40%)`，同时使用的其他药水成本继续叠加。

Beam 中间排序与最终选择分离。稳健预设把 `1 HP` 约视为 `3` 点即时伤害，用于避免长线保血路线在到达终点前被即时输出挤掉；能力牌铺垫奖金只在当前回合内帮助展开，结束回合后清零，后续价值必须由模拟出来的 Power、牌序和伤害证明。未用能量不再单独扣分。普通出牌与药水共同竞争统一 Beam，快搜/深化默认宽度为 `24/60`；剪枝仍强制保留最佳无药、无药防御、无药进攻、无药策略、战术启动和具体药水身份代表，因此药水不会抹掉最终收益比较所需的无药反事实基线。

默认中档使用 `8` 秒短检查点和 `120` 秒总预算。短结果仍会新增战损、使用药水或没有确认胜利时，同一搜索会话继续深化；长预算是上限，搜索空间提前耗尽会立即返回。

扣血与主动卖血按整场战斗累计，不会在新回合归零。对同一个回合起始状态，搜索器先比较所有已经完整结算该回合、且没有停在动态或未支持边界的候选，以其中最低可达到战损为基线；某条路线超过该基线的实际掉血才算主动卖血。这样既包含少出防御，也包含放弃击杀、虚弱等其他可用减伤手段。直接击杀且未掉血不计卖血，根本防不住的伤害也不计卖血。主动卖血阈值为普通 `5`、精英 `10`、Boss `15`；阈值是整场战斗硬预算，搜索每完成一个回合就剪掉累计超额路线。

重要规则：战斗已经结束后，能力牌不再获得未来回合收益。`0.5.8` 曾因此错误选择第三回合先打能力牌再斩杀，而不是第二回合直接斩杀；`0.5.9` 已修正。

## 4. 代码结构

- `src/Search/`：搜索循环、计划与快照、选牌、模拟状态、预算和后台步调。
- `src/Prediction/`：怪物意图、牌与 Power 补偿、怪物行动效果和覆盖分类。
- `src/Engine/`：内置并独立命名的最小战斗模拟核心；只保留状态、牌堆、RNG、分叉、历史和战斗 Mirror，不含 RF 的入口、补丁、UI、设置、遥测与局外功能。
- `src/Runtime/`：Mod 入口、异步生命周期、状态文本、自动部署与结构化日志。
- `src/Testing/`：原版游戏进程中的一次性无人测试协议、场景执行器与进度隔离补丁。
- `src/UI/`：Godot 覆盖层 UI。
- `docs/`：持续开发笔记与外部审计材料。
- `tools/run-unattended-test.ps1`：直接启动使用独立用户目录、关闭 Steam 的 `--headless` 游戏进程，并等待同一 `runId` 的结构化结果；检测到玩家进程时拒绝启动。
- `tools/CoverageCatalog/` 与 `coverage/`：稳定编号的战斗钩子目录、分类和完整性检查。
- `local.props.example`：本机依赖路径配置示例；真实 `local.props` 不进入版本控制。
