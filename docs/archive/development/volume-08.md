# CombatSolver 开发笔记历史卷 08

## 0.14.0：求解器职责边界重构

### CombatBeamSolver 阶段边界

- Beam 快照新增存活牌堆的重放潜力：按卡牌额外执行次数与基础牌值计算并封顶，只参与中间保路，不进入战斗状态键、续用文本或终局胜负排序。获得更多重放的路线归入成长通道，修复未掘宝石把后续灵体变为三次结算后仍被即时伤害路线淘汰的问题。
- 猫头鹰法官问题包固定根在原 High 规模下从“仅死亡路线”改为主动打出未掘宝石并于第 8 回合获胜；实际执行后第 2-8 回合全部精确复用，零计划外重算。低预设的增量/完整前缀核对也找到第 10 回合胜利；双小啃兽长线保持第 5 回合、两次洗牌、0 药、0 战损。
- `CombatBeamSolver` 从约 4,133 行单文件拆为 `Entry/Models/Phases/Expansion/Retention/Terminal/StateEvaluation` 七个同类型 partial 文件；随后增加 `BeamRetentionPolicy` 与 `FinalPlanOrdering` 两个具体策略边界。预算/进度仍留在 `Solve`，不在纯移动批次假装完成 run-local context。
- 结构门禁固定分片文件集，并在所有 Beam 文件继续检查宽泛异常与 live 根回读。固定机甲第 5 回合、完整动作序列、4624 展开、33432 转移、17735 选牌分支及各剪枝计数精确不变；本轮 `11.35 s / 3.55 GB / 0 ms GC / 17.2 ms 最大帧`，零非预期重算。Defect 球与 Synchronize 严格差分通过。
- 单次搜索的计数器、性能指标、帧节流、转置表及 stand-pat/威胁/coverage/路由缓存进入具体 `SearchRunContext`；不可变根配置仍由 solver 持有。本批不复用 scratch 或集合。相同机甲为 `11.52 s / 3.55 GB / 0 ms GC / 17.4 ms`，路线和计数不变。
- Beam 状态去重、分数排序、多样性通道、药水配额和 Pareto 保留进入具体 `BeamRetentionPolicy`；模拟器仍由 solver 拥有，政策只通过窄 stand-pat 委托取一次延迟伤害评估。终局候选由只读 `SearchFeatures` 投影后交给 `FinalPlanOrdering`，胜负、药水、偷窃、卖血和边界排序不再留在 `Solve`。固定机甲最终仍为第 5 回合、同动作序列，`4624/33432/17735` 展开/转移/选牌分支和各项剪枝计数精确不变；本轮 `11.51 s / 3.55 GB / 0 ms GC / 18.8 ms 最大帧`，零非预期重算。

### 剩余编排与单一事实源

- 无人值守入口按 `ProtocolHost → ScenarioBuilder → Executor → Assertions → Writer` 建立具体边界；协议字段、stage 名、Passed/Held/Failed 语义和既有战斗夹具不变。同一 headless 进程中的成功、故意失败、失败后恢复、Held 释放、严格球/药水差分和实际自动部署均通过。
- 控制器在结果交给 UI 前一次性生成只读 `SolverOverlaySnapshot`。Overlay、回合行和动作胶囊不再读取 `SolverResult`、`PlanAction`、`PlanCardChoice` 或 `ModelDb`；钢笔尖两动作首回合击杀验证了路线文本、遗物标注、部署状态和速度恢复。人工布局检查仍按原测试项保留。
- 两类 `MethodMirrorRegistry` 统一输出 `MethodMirrorRegistryDescriptor`，CoverageCatalog 不再反射 registry 私有字段推断支持状态。切换前后全量目录均为 3035 项，所有 verify 门禁和生成文件保持不变；钢笔尖严格增量搜索与真实部署通过。
- 双小啃兽长线原失败定位为怪物从活动 roster 移除时过早删除 AI/静态参数，而同一敌方行动尾部仍需读取这些根数据。AI 状态现在跟随已知怪物与分支生命周期保留，不增加默认值或 live 回读；`REFACTOR-FINAL-NIBBITS-549` 第 5 回合结束、跨两次洗牌、0 药、0 战损并逐回合精确复用，`UnexpectedReplans=0`。

## 1. 项目目标

CombatSolver 只解决一场已经开始的单人战斗：读取当前战斗状态和可预测 RNG，在不修改游戏 RNG 的前提下，以时间和节点预算搜索较优行动路线，并允许玩家查看或自动执行当前回合方案。

当前不讨论整局路线、选事件、商店、地图和构筑。开发回归通过隔离的塔 2 `--headless` 进程执行原版规则，不另建自有 CLI。

设计优先级：

1. 路线能在原版战斗中执行。
2. 已知效果尽量与游戏结算一致。
3. 未镜像内容必须显式记录，不能用“高置信度”掩盖。
4. 搜索在后台运行，不阻塞游戏主线程。
5. 性能优化不得悄悄改变 RNG 或把近似搜索描述成穷举。
