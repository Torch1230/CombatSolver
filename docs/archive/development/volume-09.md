# CombatSolver 开发笔记历史卷 09

## 2. 当前功能基线

### 搜索

- 两阶段 Beam Search：默认中档短搜统一宽度 `18`，深化统一宽度 `45`；药水不再拥有独立配额。
- 普通搜索按可用逻辑处理器自适应选择 DOP1/2/4，新安装在至少 4 个逻辑处理器时默认 DOP4；设置可在 `1–16` 之间调整。候选仍由协调线程按原顺序提交，详细诊断与严格增量验证固定使用单线程。
- 默认中档短搜预算 `8 秒 / 2400` 节点；短结果存在未来掉血、用药或未确认胜利时，同一搜索会话继续使用总计最多 `120 秒 / 12000` 节点的深化预算。
- 回合内行动数不设上限。费用、星能、可出牌性、击杀、精确状态置换、通用有界周期调度、时间和节点预算共同构成终止条件。
- 不设固定回合数或洗牌次数上限；时间、节点、确认胜负、跨回合无进展窗口和有界周期探测共同构成搜索边界。周期证据不是无限性的数学证明。
- 每节点默认中档短搜最多保留 Top-14 出牌分支，深化最多 Top-24；深化同时扩大牌堆/手牌选项预算。
- 子节点保存生成时的模拟快照；后续展开、最终复核和路线标注复用快照。
- 最优路线会保存后续玩家回合的预测起点；真实状态逐项文本一致时直接复用剩余路线，状态不一致则重算。点击“重新计算”始终从当前实机状态发起新搜索。
- 相同状态下的等价重复卡牌只模拟一次。
- 每次 Beam 剪枝除评分最高路线外，还保留一条当前威胁下预计剩余生命最高的防御路线，使回合结束时的最低可达到战损基线不会被输出评分提前挤掉。
- 深化搜索额外保留成长、资源、控制和帕累托路线，并对非即时效果执行一次缓存的结束回合探测；不按具体牌名特化毒伤或蛇咬。
- 同一搜索会话复用“父状态 + 动作”的模拟转移。完全相同状态继续由置换表剪除；控制形状在最多 `8` 个动作内重现时，以动作相位和一致转移建立通用周期证据。无即时进展的族按节点档位获得有限动作租约，并对各相位的非周期出口做最多 `8` 动作、`2` 次回合转换的收益探测；伤害、逐敌人耐久、回复、资源、持久成长、控制、牌库净化或特殊目标进展会阻止无进展淘汰。生产实现不包含按卡牌、Power、遗物或敌人名称放宽预算的分支。该机制不限制普通回合行动数，也不承诺找到所有长周期或晚兑现组合。
- UI 在滚动框中展示本次搜索得到的全部回合；完整路线同时写入日志。

### 选牌

- 支持从手牌、抽牌堆和弃牌堆选择已有牌，以及移动、弃置、消耗、升级等已列入支持表的选择。
- 正在结算的头槌等卡牌不会提前进入自己的弃牌堆候选。
- 富足、发现、类星体和飞溅的生成三选一已进入搜索分支；部署器可直接驱动原生“选择一张牌”界面。药水、回合开始选择和嵌套自动出牌使用同一计划令牌，不等待玩家干预。
- 现有牌选择统一由 `CardChoiceSpec` 描述；必备工具等回合开始选择、普通出牌选择、生成选项和嵌套自动出牌共用计划令牌与部署选择器。
- 当前选牌不是全部穷举：单卡捞取枚举所有不同结果；默认中档多牌组合的牌堆选择最多保留 `6/12` 个启发式优先分支，手牌选择最多保留 `8/16` 个。
- 这个限制会提高速度，但可能漏掉面板价值较低、后续联动较强的候选，属于明确的精度取舍。

### 战斗状态与效果

- 已知牌序、能量、星能、手牌和各牌堆状态。
- 玩家与怪物的生命、格挡、力量、敏捷、虚弱、易伤、中毒、脆弱等核心状态。
- 怪物意图、逐段攻击伤害和一批常见怪物 Buff / Debuff。
- 武装的单牌升级与升级后全手牌升级。
- 噬尸蛞蝓的饥饿死亡联动：同伴死亡后获得力量，并立即将当前意图替换为带原行动后继的 `STUNNED`；最后一只死亡能确定结束战斗。
- 愤怒、战斗专注、绯红披风和上勾拳的基础 Mirror 缺口由求解器补偿。绯红披风在每个玩家回合开始触发自伤与格挡；自伤数值只在再次打出该牌时增加，不会随回合数自动增长。
- 瀑布巨兽的常规行动已补偿蒸汽积累、虚弱、治疗、压力炮成长、蓄爆与爆炸；`0.13.29` 补齐提前击杀后的阵容保留、无限最大/当前生命、强制行动和普通 Power 死亡清理。
- 缩小、人工制品的负数减益抵挡、缠结、昏眩和无实体已补齐完整确定性生命周期；卡牌附魔随新牌进入和 Power 移除同步，昏眩的回合内首张牌限制进入搜索状态指纹。

- 确定性 `OnPlay` 不再依赖宽松 IL 猜测：常见攻击/格挡/抽牌由严格 `EffectRecipe` 证明完整后执行，Power、资源、生成和永久牌面修改由参数化规格表补全；未知游戏调用、条件效果或模型写入不会被伪装成精确支持。

## 3. 当前评分语义

最终路线不再只按线性 `Score` 选取，而是依次比较：玩家存活、确认胜利、整场预计掉血、药水数量、累计主动卖血、敌方剩余生命和行动数量。动态重搜或未支持边界不能冒充确认胜利。普通药水路线若能取得无药路线做不到的确认胜利可直接进入比较；否则仍须相对最佳无药路线每瓶至少省下 `9 HP`。龙涎香不适用胜利直通：无论药水模式如何，都必须相对最佳无药路线最终多保住至少 `ceil(最大生命 × 40%)`，同时使用的其他药水成本继续叠加。

Beam 中间排序与最终选择分离。稳健预设把 `1 HP` 约视为 `3` 点即时伤害，用于避免长线保血路线在到达终点前被即时输出挤掉；能力牌铺垫奖金只在当前回合内帮助展开，结束回合后清零，后续价值必须由模拟出来的 Power、牌序和伤害证明。未用能量不再单独扣分。普通出牌与药水共同竞争统一 Beam，快搜/深化默认宽度为 `24/60`；剪枝仍强制保留最佳无药、无药防御、无药进攻、无药策略、战术启动和具体药水身份代表，因此药水不会抹掉最终收益比较所需的无药反事实基线。

默认中档使用 `8` 秒短检查点和 `120` 秒总预算。短结果仍会新增战损、使用药水或没有确认胜利时，同一搜索会话继续深化；长预算是上限，搜索空间提前耗尽会立即返回。

扣血与主动卖血按整场战斗累计，不会在新回合归零。对同一个回合起始状态，搜索器先比较所有已经完整结算该回合、且没有停在动态或未支持边界的候选，以其中最低可达到战损为基线；某条路线超过该基线的实际掉血才算主动卖血。这样既包含少出防御，也包含放弃击杀、虚弱等其他可用减伤手段。直接击杀且未掉血不计卖血，根本防不住的伤害也不计卖血。主动卖血阈值为普通 `5`、精英 `10`、Boss `15`；阈值是整场战斗硬预算，搜索每完成一个回合就剪掉累计超额路线。

重要规则：战斗已经结束后，能力牌不再获得未来回合收益。`0.5.8` 曾因此错误选择第三回合先打能力牌再斩杀，而不是第二回合直接斩杀；`0.5.9` 已修正。

## 4. 代码结构

- `src/Search/`：搜索循环、计划与快照、选牌、模拟状态、预算和后台步调。
- `src/Prediction/`：怪物意图、牌与 Power 补偿、怪物行动效果和覆盖分类。
- `src/Engine/`：内置并独立命名的最小战斗模拟核心；只保留状态、牌堆、RNG、分叉、历史和战斗 Mirror，不含 RF 的入口、补丁、UI、设置、遥测与局外功能。
- `src/Runtime/`：Mod 入口、异步生命周期、状态文本、自动部署与结构化日志。
- `src/Testing/`：原版游戏进程中的一次性无人测试协议、场景执行器与进度隔离补丁。
- `src/UI/`：Godot 覆盖层 UI。
- `docs/`：持续开发笔记与外部审计材料。
- `tools/testing/run-unattended-test.ps1`：直接启动使用独立用户目录、关闭 Steam 的 `--headless` 游戏进程，并等待同一 `runId` 的结构化结果；检测到玩家进程时拒绝启动。
- `tools/inspection/CoverageCatalog/` 与 `coverage/`：稳定编号的战斗钩子目录、分类和完整性检查。
- `local.props.example`：本机依赖路径配置示例；真实 `local.props` 不进入版本控制。

## 5. 性能现状

已完成：

- 搜索节点复用模拟快照。
- 节点去重与等价卡牌判断使用双 `ulong` 状态指纹，避免为每个状态创建长字符串；跨回合续用仍使用完整状态文本，不依赖指纹。
- 跨回合复用已选路线：逐项比较生命、格挡、费用、各牌堆、Power、怪物意图与相关 RNG 计数，不做哈希；完全一致时下一回合为 `0` 个新展开节点。
- 后台线程使用较低调度优先级；每 `16` 次回放检查一次连续工作时间，超过 `4 ms` 时调用 `Thread.Yield()`；搜索进度改用普通 `Label` 并限制为每 `200 ms` 最多刷新一次。
- 自动搜索至少延迟三个渲染帧，并等待游戏的回合开始动作队列执行完成，避免与发牌、状态结算的峰值直接重叠。
- 模拟状态中未使用的 Power/回合资源/怪物专项集合按需创建；状态剪枝、动作支配与 Top 队列避免构造 LINQ 中间分组。
- 怪物模型的反射数值访问器按类型和成员缓存为编译委托。
- 最终候选、战损、击杀和战斗结束标注不再重复完整回放。
- 合并等价重复卡牌与重复选牌组合。
- 选牌使用独立局部分支预算。
- 日志记录 `expanded`、`replays`、`snapshot_reuses`、`duplicate_cards_pruned`、`choice_branches`、后台线程分配量、每次回放平均分配、GC 次数、搜索区间 GC 暂停和线程让步次数。GC 次数与暂停是进程级区间数据，不能单独归因给求解线程。
- `0.7.6` 的真实跑局快照路线质量回归需要 `2542` 次完整回放、约 `5.99 GB` 工作线程分配和 `22.4 s`；结果正确但性能不合格。扩大 Beam 不是 GC 解决方案，下一阶段仍需 RF 提供可靠的模拟器分叉/深拷贝，或由本模组实现可分叉模拟内核。
- `0.8.0` 已在本地 RF fork 中加入完整模拟状态分叉 API：根状态只构造一次，每个搜索候选从父节点复制 RNG、牌堆、逐牌状态、Orb、生物、历史、RF StateStore 以及求解器自有 Power/遗物状态，再只执行当前动作。搜索节点改为父链保存单个动作，不再为每个分支复制整条动作列表。长线固定快照的 `2541` 个分叉逐一与旧完整前缀回放比较，状态文本、指纹、边界、风险和 RNG 全部一致；实机仍为第 `6` 回合结束、`0` 战损、`0` 药损。三次干净进程性能中位数为 `605,129,120 B / 2.394 s / 505.6 ms GC 暂停 / gc2=0`，相对 `0.7.6` 的 `5.99 GB / 22.4 s / 10.42 s GC 暂停` 分别降低约 `89.9% / 89.3% / 95.1%`，通过 `0.9 GB / 5.6 s / 暂停降低 80%` 门槛。原始三次指标和计算口径见 `docs/archive/performance/RF_FORK_PERFORMANCE_RESULTS.md`。
- `0.9.0` 在 RF fork 上继续加入卡牌预览写时复制、StateStore 按键惰性复制、共享历史前缀、求解器私有集合写时复制、原生 Hook 监听器分支缓存和无序列化 RNG 克隆。短搜/深化预算改为 `3/20` 秒，深化使用 `24+8` Beam、扩大选牌预算、帕累托路线和通用延迟收益探测；短结果有战损、用药或未确认胜利才触发。回合内行动上限删除，完全相同的无进展状态负责循环终止。最终长线差分比较 `2540` 个实际转移全部一致；8 张零费小刀在同回合全部执行并击杀。

## 6. 已知限制

- 牌堆选牌为 Top-K 近似，不是穷举。
- 搜索不再因洗牌次数、空牌堆或固定回合数停止；极端无胜负循环最终由时间或节点预算终止。
- 多人牌、多人模式和局外效果仍不在本项目范围；游戏版本新增而目录尚未收录的行为必须重新审计。
- 部分动态怪物伤害仍为近似值。
- 当前 `0.111.0` 目录内单人战斗钩子已完成分类与证据闭环；游戏更新后的新增行为仍需重新生成目录和审计。
- 瀑布巨兽被提前击杀后的无限生命显示、蓄爆与爆炸自灭已加入模拟，并通过 `MONSTER-WATERFALL-001` 可见游戏场景验证；其普通行动中的动态伤害仍按现有近似策略标注。
- 状态键和等价卡牌键需要随着新实例状态的支持持续补充。
- 当前只支持单人战斗。

## 7. 未来构想：RitsuLib 路径预设

搜索预算和 UI 位置已经由模组自身 JSON 设置页实现。这里保留的未来项只指改变最终目标权重的“路线风格预设”；此功能尚未实现。

初步预设：

### 短期保血优先

- 提高近期生命与格挡权重。
- 降低主动卖血容忍度。
- 降低为了未来回合而提前打能力牌的收益。
- 适合普通战斗、低血量或只关心眼前一至两回合的情况。

### 长线能力优先

- 提高能力牌与持续状态在剩余已知回合内的价值。
- 允许在阈值内承受少量战损换取后续收益。
- 仍必须在终局清空未来收益，不能为了“已经不存在的后续回合”延迟斩杀。

### 均匀伤害优先

- 提高 AOE 和敌方总生命下降的权重。
- 降低对单个低血目标的过量伤害。
- 可能适用于需要同步压血或后续有群体斩杀的场景，但面对高威胁单体时未必合理。

### 减员优先

- 增加存活敌人数惩罚和提前击杀奖励。
- 优先消灭能行动、成长或造成高威胁的目标。
- 避免把伤害平均铺开却让所有敌人继续行动。

### 建议的配置结构

不要直接在运行时修改 `SolverWeights` 常量。更合适的结构是：

1. 定义不可变 `SolverProfile`，包含评分权重、卖血阈值、搜索预算、选牌预算和边界策略。
2. 通过 CombatSolver 自身的持久化设置保存 `PresetId`，并允许高级用户覆盖少量关键参数。
3. 每次发起搜索前在主线程捕获一份完整配置快照，后台线程只读取该快照。
4. 日志写入 `preset`、配置版本和所有覆盖项，保证结果可以复现。
5. UI 中显示当前预设，但不要让预设名称代替实际权重日志。

预设不是“难度档位”，而是不同优化目标。它们应共享同一套模拟规则，只改变评分、预算和剪枝偏好。

## 9. 原版规则验证与无人闭环

- 开发流程通过 `tools/testing/run-unattended-test.ps1` 直接启动塔 2 自带的 `--headless` 进程；它仍运行原版游戏程序集和动作队列，不是自建 CLI 或重写规则。
- 无人进程使用 `%LOCALAPPDATA%/CombatSolver/headless-runtime` 下的独立 `APPDATA/LOCALAPPDATA`，通过 `--force-steam=off` 避免 Steam 会话，并在隔离设置中显式允许 Mod 加载，绕过无界面的首次 Mod 警告确认。由于关闭 Steam 后游戏不扫描创意工坊，启动器只在 headless 生命周期内把当前游戏版本的 RitsuLib 投影到带所有权标记的本地临时目录，进程退出后删除；不会复制 RF 或其他创意工坊 Mod。脚本只复用 marker 明确记录的测试 PID；发现任何其他塔 2 进程时立即拒绝启动，不与玩家进程并发。
- 一次性请求先写入同目录临时文件，再原子发布为 `user://combat_solver_test_request.json`，避免游戏读取半写入或被占用的请求。Mod 建立 `shouldSave:false` 的单人跑局，进入指定遭遇，通过原版 `CreatureCmd`、`CardPileCmd` 和动作队列注入状态，再调用求解器全自动。
- 测试结果写入 `user://combat_solver_test_result.json`，必须以同一 `runId` 匹配；成功场景会清理跑局并回到主菜单，默认保留进程供下一场复用，只有最后一场显式要求时才退出。
- 无人测试期间跳过原版 `UpdateProgressAfterCombatWon`，避免把测试遭遇和击杀写入玩家进度。首轮验证在加入隔离前已经把一次毛绒伏地虫胜利写入当前 Modded Profile；这次历史修改无法在没有事前快照的情况下可靠回滚。
- 独立 headless 档案第一次进战斗时，原版“战斗基础”教学会创建缺少场景字段的无窗口节点并在 `NCombatRulesFtue.Start()` 空引用。无人请求活动期间将该纯 UI 教学的 `Create()` 直接返回空，与游戏自身的 `TestMode` 路径一致；普通玩家进程不受影响。

- 不对构建产物进行哈希验证；搜索内部允许使用双 64 位状态指纹。
