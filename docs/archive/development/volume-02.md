# CombatSolver 开发笔记历史卷 02

## 0.46.2：可选 ServerGC 启动配置（2026-09-24）

- 基于上游 `3d45d78f` 增加显式的 `server-generational` 进程 profile。启动器只设置游戏子进程环境；Mod 确认实际 ServerGC 后，在搜索快照中临时关闭 NoGC，保留已保存的选择。未知值或运行库未生效时明确报告，继续使用保存设置。界面同步显示中英状态并禁用冲突控件。感谢 [ltlly](https://github.com/ltlly) 提交的 [PR #132](https://github.com/Torch1230/CombatSolver/pull/132)。
- 无人入口按实际准备传入的运行库环境区分可复用进程，模式改变沿用已核验所有权的重启流程；PowerShell 测试并行度接受 1–16。指定证据目录时追加完整搜索结果与实际运行库状态，便于对账。
- 不更改 GC 生命周期、搜索算法、配置预算、药水政策或游戏运行库文件。最小合同与使用方式见[启动配置说明](../performance/server-gc-launch-profile-20260924.md)；贡献者在 Windows 原生宿主五场测得总耗时降低 28.2%，等权几何平均降低 18.8%，采样内存峰值几何平均降低 72.1%。总 CPU 增加 15.7%，两场较慢、静默多损失 1 HP；作为可选配置保留明确取舍，不声称普适 20% 或决策不退化，无可见帧时间结论。

## 0.46.2：策略侧栏展开方向（2026-09-24）

- 药水、成长、遗物策略侧栏原先只尝试放在主面板右侧，放不下时贴着主面板右缘向内展开，主面板靠右停放时会盖住路线列表。现在依次尝试右侧、左侧；两侧都放不下时贴到空间较大一侧的屏幕边缘，尽量减少遮挡。纵向位置与宽高规则不变。感谢 [s1f102500012](https://github.com/s1f102500012) 提交的 [PR #131](https://github.com/Torch1230/CombatSolver/pull/131)。

## 0.46.1：恢复在线连接配置（2026-09-24）

- 0.46.0 在独立发布 worktree 构建，该目录没有主仓库 `.local/` 中的私有连接配置。项目文件仅在配置存在时嵌入在线监控和战斗展示端点，因此正式 DLL 缺少两项连接元数据；监控客户端无法创建 HTTP 客户端，也就没有发送心跳。线上监控容器正常运行，故障位于发布构建来源。
- 发布构建现在显式接收私有配置目录并要求监控、展示两份配置齐全；构建完成和统一发布脚本启动外部上传前都检查 DLL 的连接元数据、HTTPS 地址及证书指纹格式。普通无私有配置的开发构建仍可继续，但不能作为发布包。配置内容不进入源码或日志。
- 0.46.0 标签与渠道内容保持冻结；0.46.1 用含正确连接元数据的构建恢复新心跳、战斗统计和合格录像上传。验证见 [测试矩阵](../../TEST_MATRIX.md)，玩家说明见 [0.46.1 更新日志](../../releases/0.46.1-RELEASE_NOTES.md)。

## 0.45.0：搜索读数过渡动画（2026-09-23）

- Windows 集成测试发现呼吸峰值合同把爬升时长重复计入相位，修正断言时刻；动画计算未变。
- 内存条的系统段、进程段、占用/可用数值和压力颜色不再在每次 `0.25 秒` 采样时直接跳到新值，而是按帧用时间常数 `0.18 秒` 的指数缓动逼近采样值；前台整理和后台清理期间进程段以 `1.4 秒` 周期呼吸提亮，文字颜色保持稳定。采样频率、状态判定与内存诊断日志仍按原始采样值，不受缓动影响。
- 搜索中的“已查阅 N 条世界线”与搜索进度条改由挂在覆盖层下的逐帧驱动节点向最新进度报告滚动。计数从本次搜索的起点开始、不倒退；总数变小（换了战斗）时直接跳到新值。摘要被其他展示路径改写后停止滚动，不覆盖别处的文本；搜索结束后的最终摘要仍直接显示精确总数。
- 覆盖层或内存条隐藏期间不推进动画，重新显示时从最新采样直接开始。
- “已用 X s”在两次进度报告之间按帧时间连续走表，最多领先最后一次报告 `1 秒`，避免停顿或被节流的搜索看起来仍在前进；报告时间回退（回合开始搜索不经 `ShowSearching` 直接报告）视为新请求并重新计时。有时间预算时搜索进度条目标取“走表时间 / 预算”与已报告比例的较大值，仍以 `0.95` 封顶，因此进度条在报告之间持续缓慢前进。
- 搜索进度条的 `Step` 设为 `0`。Godot `Range` 默认按 `0.01` 取整，在 0–1 比例上等于 1% 网格，宽面板上每格约 10 像素；实机截图中缓动后的进度条仍按格跳动即由此造成。
- 执行路线时的动作胶囊高亮改为逐帧过渡：变为当前动作时从增亮色回落到当前色，完成后淡到已完成色，停留超过 `0.45 秒`（慢速出牌、选牌界面、长动画）后开始 `1.2 秒` 周期呼吸。所有时长由实测的相邻“新当前动作”间隔决定：过渡时间常数取 `min(0.08 秒, 间隔 × 0.2)`，不足半帧直接切换；间隔短于 `0.3 秒` 不做增亮闪烁；“瞬间”速度下下一步总在呼吸延迟前到达。只有完成度变化的调用（最后一步、结束回合）不计入节奏，避免把收尾误判成瞬间执行。行复用时颜色直接复位，不淡出上一轮部署。目标颜色仍同步设定，只有显示值被缓动。
- 问题包上传进度条向最新百分比缓动，字节计数成批到达时不再成段跳变；状态文字仍按整百分比刷新，完成或失败时照旧立即隐藏。

## 未发布：能力驱动的 Power 施加不再继承外层卡牌来源（2026-09-22）

- 问题包 `c4e28f3b`（0.43.2）里同一场战斗的预测与实机分叉：`POISON_POWER` 预测 11／实机 5、
  `UNSETTLING_LAMP` 预测 1／实机 0、敌方血量 7／13。
- 根因是「Power 的来源」这半条语义没跟上：实机 `CorrosiveWavePower.AfterCardDrawn` 调的是
  `PowerCmd.Apply<PoisonPower>(…, cardSource: null)`，来源是能力本身；预测侧那条镜像走的是不带来源的
  `ApplyPower`，而它正处在**卡牌执行作用域**里（后空翻抽到的牌），于是这层毒被记成「那张牌直接施加的减益」：
  既被算到那张牌头上，又触发了只认卡牌直接施加的不安油灯。
- 同一类错误在镜像层还有一批，逐条对着反编译源码核对后一起修正（原版都显式传 `cardSource: null`）：
  腐蚀波、吸取（Suck）、破甲钻（HandDrill）、军械库（Arsenal）、手里剑（Shuriken）、激怒（Enrage）、
  湮灭（Oblivion）、撕裂（Rupture，含 `AfterDamageReceived` 那条）、温柔（Tender，两条）、生命火花（VitalSpark）、
  红头骨、定形黏土、ReaperForm／Underworld 的灾厄，共 16 处调用点改用
  `ApplyPowerFromSource(…, cardSource: null)`。
- 影响面同样是通用的：凡是按「卡牌直接施加」判定的遗物与增幅，都会被能力/遗物驱动的减益误触发；
  这是原版卡牌就能走到的组合，与第三方内容无关。新增严格差分夹具 `LAMP-POWER-SOURCED-DEBUFF`
  （腐蚀波 + 抽牌），改动后通过；证据与未覆盖范围见 [测试矩阵](../../TEST_MATRIX.md)。

## 未发布：状态键补整场历史计数（2026-09-19）

- `CalculatedVarSpecRegistry` 里有六张牌的动态变量读的是**整场**历史计数：金斧（已完成出牌数）、电流相生（闪电球充能数）、扯碎（受到的未格挡伤害次数）、亡魂牵引（虚无牌打出数）、谋杀（抽牌数）、超质量体（生成牌数）。`BuildStateKey` / `AppendFingerprint` 只含逐回合计数，不含这些整场总数，于是两条出牌次数不同、其余完全相同的分支会被 `RankBest` 精确去重合并，留下的那条后续这些牌的伤害算错。转移影子实验在 50 根离线语料里抓到 6 对同键不同输出，全部是金斧（19 次对 18 次完成出牌）。
- 修法：新增 `CombatHistoryCounterKey`，根牌组含上述任一张牌时，`BuildStateKey` 遍历一次模拟历史后追加六个计数（根之前的实况历史整场恒定，不计）；不含这些牌的战斗状态键逐位不变。
- 已知缺口：读者牌若战斗中途才生成，或根捕获时已在消耗堆、之后又被回收，根牌组条件不会命中，仍沿用旧键。试过无条件追加：键变细扰动了 46/50 根的路线（胜负 3 负 1 正），且每个键多一次历史遍历；这批没有受控墙钟测量，不声称具体耗时增幅。在没有增量计数器之前不采用无条件追加，见策略报告。
- 验证：见测试矩阵。
