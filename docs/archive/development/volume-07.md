# CombatSolver 开发笔记历史卷 07

## 0.20.0：在线问题包、首回合选牌与稳定性

- 合并 PR #6 的跨平台开发与无人测试入口。Windows 继续使用 PowerShell，Linux 新增对应的 Bash 构建、本地化、单项无人测试、完整矩阵、可见基准和结构门禁入口；两端按明确的进程身份与隔离数据目录管理无人游戏进程。
- 武装面对唯一未升级候选时，原版会直接选中并立即升级。原生选牌驱动现在保存请求发生时的卡牌语义身份，随后用该身份核销隐式选择，不再拿升级后的状态反查升级前计划。
- 无人建局不再调用按当前 UTC 秒重播种的调试接口；相同 run seed、楼层与遭遇会生成相同敌人组合。无人请求同时跟踪仍在运行的搜索、部署和原生选牌任务，后台失败不能在清理阶段之后把当前请求误报为通过。
- Windows 的临时 RitsuLib 投影先删除两个已知载荷，最后删除所有权标记；进程退出后的短暂文件占用会在有限时间内重试。删除载荷失败时标记仍保留，下一次启动器可以安全识别并继续清理。
- Windows 合并态回归覆盖武装隐式升级、同一 PID 的相同 seed 敌人组合、失败请求退出、成功请求复用、骇鳗活力攻击、毒气炸弹自爆死亡结算和琥珀灰额外回合中的情感芯片历史；对应 runId 与断言保存在 `docs/TEST_MATRIX.md`。Linux 结构门禁在当前 Windows Bash 环境因缺少 `rg` 未执行，保留贡献者原生 Linux 全矩阵证据，不写成本机复跑。
- 花园幽灵鳗问题包实际加载的是 `0.18.0`。旧版在首回合手牌页算出路线后立即确认烘焙手套选择，并在打完本回合后把下一回合的烘焙手套选择错误交给当前结束回合复核，最终以“计划选牌没有触发”中止。`0.19.0` 已包含两处生产修复：计划就绪后保持原生页面并等待玩家启动；实时结束回合复核只消费玩家回合结束与敌方回合选择。
- 新增首回合启动边界断言：必须先观察到原生页面、搜索开始和计划就绪，此时 `Selected=0`、玩家仍处于原生手牌选择页且出牌数为 `0`；无人测试随后才模拟玩家点击启动。基础场景 runId `a2a1fd688e71465d9458c5cbb1c743d4` 在第 2 回合结束，计划外重算 `0`。
- 严格增量校验的完整回放现在先重放同一组首回合准备选择，再重放出牌动作；旧校验从选择前根状态直接找已选择后的手牌，会把正确的烘焙手套分支误报为找不到手牌。花园幽灵鳗问题包的战前牌组、遗物与 RNG 在严格模式下完整自动执行到第 5 回合，runId `0451b77331a94c96ae507e2ccdb4603a`，首回合用户启动前未选牌、未出牌，结束回合复核开启且计划外重算 `0`。
- 求解器设置新增“上传问题包”按钮（位于“导出问题包”左侧），点击后提供可选的问题描述输入框。确认后复用现有导出流程打包，通过接收服务上传，后端字段保持不变。上传时会在玩家原文后追加本场结构化自动分类，覆盖更优世界线、手操或重算后战损上升、计划外重算、续接路线缺失、路线耗尽、搜索初始化/计算/回放/容量错误、第三方 Mod 不兼容、选牌异常、自动执行中止及全自动风险暂停；未出现的类别不会写入。
- 求解器设置新增“反馈联系QQ”文本项，仅需填写一次并持久化到本地设置；后续上传自动带上。QQ 只通过后端既有联系字段发送，不再重复写入 ZIP 的求解器设置。问题包环境信息只保留可执行文件名、用户数据目录名、程序集名称和版本，不再写入本机绝对路径。

- 所有需要玩家反馈的异常统一改为引导玩家在设置中点击“上传问题包”提交日志，不再提示先手动导出再另行提交。搜索初始化/计算失败、回合准备选牌失败、自动执行中止和过期结果会在错误正文中直接显示入口；计划外重算、续接路线缺失、路线耗尽、重算后战损上升、结束回合实机复核偏差和更优世界线会在反馈栏或对应暂停说明中显示入口。用户主动停止计算、按设置在预计死亡回合暂停等正常控制行为不提示报错上传。

## 0.19.0：重算、中止与选牌边界批次

- 本批次始于 `0.18.0` 发布后，最终发布为 `0.19.0`。原始反馈与逐项状态维护在 `docs/archive/issues/post-0.18.0-bug-batch.md`，实施顺序和验收口径维护在 `docs/archive/issues/post-0.18.0-fix-plan.md`。
- 当前范围只处理战斗语义、原生选牌与自动部署、跨回合续用和计划外重算。更优手操路线、能力牌估值和用药质量已按用户要求暂缓；已有问题包与战损上界继续保留，不写成已经改善。
- 计划选牌现在显式区分动作内、玩家回合结束、敌方回合和玩家回合开始四个时机。实时结束回合复核只消费本次结束回合与随后敌方回合的选择，不再提前要求下一回合必备工具、暴政等准备选择；环境组装师、花样百出、三卷轴怪和知识恶魔共享这一阶段边界。
- 选择悖论、烘焙手套、赌博筹码和工具盒会先显示原生首回合页面，再启动搜索并展示预计行动；求解器等待玩家点击执行或开启全自动后才确认计划选择。执行本回合进入下一回合时，会停在必备工具或暴政页面；此时再次执行或开启全自动会接管已有计划，不进行重复搜索。
- 环境组装师的条件行动按原版把自身计入存活队友。怪物攻击补齐完整的攻击前与攻击后生命周期，骇鳗的活力会在攻击前武装并在攻击后消费，不再于跨回合续用时错位。
- 原生大卡池页面只创建当前可见行的卡牌节点。部署器现在沿原版网格的滚动范围逐段移动并等待目标行分配，再通过真实节点确认；灵魂枢纽的 37 张牌池可正常选择底部的主宰。
- 实验体战利品、永世沙漏原生选择、养蜂人塞入笨拙、千足虫升级和三骑士最终回放在当前源码均越过旧失败点或完整自动结束。蔓生爬虫包记录到搜索期间实机药水栏被改写，但当前源码复跑零重算，暂列证据不足；骇鳗免费能力层数 `3/4` 差异也未在精确牌堆与增量回放中复现，不宣称已经修复。
- 骇鳗增量整包回归在无人测试 `360s` 上限内仍停留于首回合，未形成断言，记为超时而不是通过；同场完整自动执行与怪物攻击严格差分已经通过。
- 主宰会先完整结算易伤施加引起的 Power 层数监听，再读取目标当前易伤并获得力量；凶恶抽牌与地狱狂徒自动打出的攻击因此发生在加力之前。最小原生/预测严格差分通过，runId `ad8f66a8594d436dac6a1c5fafb0e313`。幽灵骑士死亡时移除恶咒的现有补偿也已纳入覆盖声明，三段施加、叠层与施加者死亡回归通过，runId `d53826f1d06a487fbca60ffb740892f7`。
- 无人复现器可直接从问题包回放状态恢复四个有序牌堆、升级、附魔、苦难与疯狂科学的枚举内部状态；自定义性能覆盖会按实际值断言，不再把自定义设置误判成中档。多尼斯异鸟和实验体的精确基线分别保持 `55` 与 `20`，对应玩家上界 `41` 与 `0`；两项只固化为暂缓的搜索质量差距。

- 本节记录 `0.17.2` 发布后的 29 项集中修复；全部问题已结案并进入 `0.18.0` 发布准备。

### 跨平台 No-GC 预算边界

- macOS ARM64 问题包中的两次首轮搜索都在进入 worker 后、建立求解器之前失败。默认 `6 GB` 总预算和 `1 GB` LOH 预算使 `GC.TryStartNoGCRegion` 抛出 `ArgumentOutOfRangeException(totalSize)`；同一战斗的手动全自动重试在相同调用点再次失败，战斗根本身已成功捕获。
- No-GC 启动现在明确区分成功、内存不足和当前 CLR 不支持该 SOH 区域大小三种结果。区域大小不受支持时，Runtime 使用现有 `SustainedLowLatency` 与 Beam 安全检查点回收继续搜索；参数错误、嵌套 No-GC 等其他异常仍然直接失败。首轮进入和检查点回收后的重建共用同一入口。
- Windows headless 以 `16 GB` 预算完成首轮求解并产出可执行动作，证明正常 No-GC 路径未退化；该平台实际接受了 `16 GB` 区域，因此不能替代 macOS ARM64 对拒绝分支的实机复测。
