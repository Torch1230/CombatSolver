# CombatSolver 0.18.0 发布后修复计划

## 原则

1. 当前只修 actual/simulated、原生选牌、部署时序和计划外重算；搜索质量由用户明确暂缓。
2. 旧版问题包先用当前源码运行；被 `0.18.0` 共享修复覆盖的项目直接登记证据，不重复修改。
3. 首回合准备选择先显示原生页面，求解器从该页面对应的待选状态计算并展示预计行动；只有用户点击执行或开启全自动后才确认选择。
4. 单步执行的边界位于本回合结束。下一回合的必备工具、暴政等页面必须保留给玩家；玩家从页面点击执行或全自动时，继续使用已有计划，不重新搜索。
5. 路线质量以整场战损为首要基线，回合数仅作次级信息。

## 批次 A：当前版本中止

- 修复实时结束回合风险复核对未来回合选牌的消费边界，覆盖暴政的消耗与必备工具的弃牌。
- 验证 Fabricator、花样百出、三卷轴怪和知识恶魔从同一战斗根继续全自动，原生页面正常出现、选牌由计划接管、自动执行不中止。
- 计划选择显式携带动作、玩家回合结束、敌方回合或玩家回合开始时机；每个运行阶段只消费自己的选择。

## 批次 B：旧版部署与回放失败

- 在当前源码复跑千足虫的升级选牌、永世沙漏的弃牌堆选择、实验体的满手生成牌与战利品回放、三骑士最终标注、知识恶魔长线回放。
- 计划卡牌身份必须按原生选择发生时的实际状态匹配。升级、降级、附魔、临时费用、保留、重放和关键词变化由同一身份规则处理，不写卡牌专用例外。
- 手牌已满时，生成、抽牌和后续动作只按原版真实进入的牌堆规划；搜索和部署共享最大手牌数与被阻塞动作结果。
- 原生大卡池网格只为可见行创建节点。部署选择底部卡牌时，沿原版滚动范围移动并等待目标行分配，再触发真实卡牌节点，不伪造网格选择。

## 批次 C：重算语义

- 分别定位产卵飞虫的伤害首差异、骇鳗的活力生命周期、养蜂人塞入笨拙后的牌堆与洗牌时序，以及三骑士虚无/升级变化。
- 每项先做目标严格差分，再做跨回合增量等价；完整自动战斗固定 `Instant / 0 秒`，计划外重算为零。
- 搜索期间实机状态被玩家或外部自动化改变时，登记根前后证据并按当前源码复现；没有复现出模拟偏差时不加入猜测性容错。

## 批次 D：能力牌与用药策略（暂缓）

- 以下内容保留为下一策略批次，不在本轮实现。
- 从女王、知识恶魔、实验体和构装体包抽取手操前后的首个动作差异，确认能力牌候选是未展开、被中间淘汰还是终局未选。
- 为持续能力建立有上限的通用铺垫代表，价值来自可实现的后续收益与生存窗口，不用简单固定加分抬高所有能力牌。
- 为每个可用药水及关键使用时机保留有限代表，允许两瓶药的组合路线独立存活；智能用药的边际审计只在候选路线已经形成后决定是否值得消耗。
- 审计“指定使用某瓶药”的设置入口。若加入，使用稳定药水身份约束合法候选，不把指定药水写成评分奖励，也不改变智能用药语义。

## 完成标准

- 25 项反馈全部登记；当前范围内的错误、自动中止、重算和选择边界标为 `已修复 / 当前源码已覆盖 / 当前行为正确 / 证据不足`，并给出直接证据。
- 当前版本中止包完成全自动部署；所有语义与续用修复具有目标差分，跨回合项目计划外重算为零。
- 暂缓的策略包只保留旧求解、当前求解和手操上界，不把它们写成已经改善。
- 更新 `docs/DEVELOPMENT_NOTES.md`、`docs/TEST_MATRIX.md` 和本计划；本批次不提升版本、不打包、不上传。
