# CombatSolver 0.18.0 集中修复计划

## 范围与原则

- 范围固定为 [原始问题批次](0.18.0-raw-bug-batch.md) 的 29 项。
- 全部 29 项均已完成结案，改动归入 `0.18.0`。
- 先从问题包找到最后正确检查点和第一个错误检查点，再按共享根因合并修复。相同表象不预设为相同原因。
- 语义和实机部署一致前不调 Beam；药水与更优路线只有在模拟、增量回放和续用正确后才进入搜索政策分析。
- 开发日志、测试矩阵和最终更新日志使用游戏 `0.111.0` 官方简中译名；原始问题清单保留玩家原话。

## 执行批次

### A. 证据盘点与根因矩阵

1. 安全解包到 `.local/issue-bundles/0.18.0-<issue-id>/raw/`，保留原 ZIP。
2. 为每包记录版本身份、session、回合、动作、首个异常、首个 `ContinuationStamp` 差异、路线和设置。
3. 将 29 项归并为确定的共享根因；没有错误文本或精确对应包的项目保持“证据不足”，不猜测。

### B. 直接失败与卡死

优先处理初始化失败、搜索动作回放失败、原生选牌计划外事件、长时间无结果、无法触发后续状态、部署找不到手牌/药水，以及全息影像后的异常。验收要求是目标入口不再失败，并为共享类型族补相邻回归。

### C. 续用、状态与最终回放

处理计划外重算、重算后战损上升、情感芯片额外球、知识恶魔/变牌相关状态、遗物标注与选中路线不一致。验收要求包括严格状态差分、必要的增量等价、完整自动部署和零非预期重算。

### D. 药水政策

处理满血再生药、格挡药水、易伤药水、保留药水、强制用药后战损上升和双药槽识别。先证明药水动作与效果语义正确，再分别检查候选展开、中间保路、无药反事实和终局排序；不按具体遭遇硬编码。

### E. 路线质量

处理历史课、女王更优解、灵动步法及无描述的感染棱柱包。用户手操路线只有在同一起点、牌序和 RNG 可比时才作为精确质量上界；否则记录为路线线索。

## 完成标准

- 29 项均有 `已修复 / 已由共享根因覆盖 / 当前行为正确 / 证据不足` 之一，且附直接证据。
- 每个源码修复都有目标回归；共享 helper 覆盖受影响类型族。
- 跨回合或部署改动完成至少一场 `Instant / 0 秒` 全自动战斗，并断言计划外重算为零。
- `docs/DEVELOPMENT_NOTES.md`、`docs/TEST_MATRIX.md` 和本计划同步最终状态。
- 发布工作以用户明确指令为界；本批次已收到发布准备指令。
