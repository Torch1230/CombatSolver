# 伤害来源死亡状态读取实机

## 报告与定位

代表报告 `794cc6676ffb49c0badc4c5bbabda86a` 声明 CombatSolver 0.35.1 / 游戏 0.111.0，亡灵契约师对实验体。搜索在 T5 / action_count=27 打出 ERADICATE 时报告“模拟抽牌同步递归达到 100 层”。

首个异常栈中的触发链为 Corrupted 自伤 → 玩家死亡处理 → 清理 Osty → NecroMasteryPower 的 HP 变化伤害 → 敌人死亡 → GremlinHorn 抽牌 → PagestormPower 重复抽牌。不能只凭递归异常提高上限或忽略失败移牌。

当前伤害入口的单体和多目标路径均直接读取 `dealer.IsDead`。dealer 是稳定实机身份，而其生命会随预测分支变化。预测玩家已死亡、实机仍存活时，该检查错误放行 NecroMastery 的伤害，引出死亡来源不应触发的敌人死亡/抽牌链。

游戏 0.111.0 的 CreatureCmd.Damage 在来源已死时返回无伤害结果，不进入逐目标结算。预测器既有约定将这类无操作结果省略为空列表；本次只纠正死亡判定的数据来源。

## 修复

两个入口改为 `State.GetCreature(dealer).IsDead`。仍保留无来源伤害、空目标、既有结果返回和异常边界。没有改伤害公式、死亡清理顺序或同步抽牌递归上限。

排查还发现原版在清理玩家宠物前移除死亡能力，而模拟器该阶段保留能力；其完整能力移除/AfterRemoved 语义需单独研究。本次不同时迁移该生命周期，避免用新的顺序变化掩盖已经明确的来源状态错误。

## 验证范围

`tools/DamageDealerChecks` 编译实际生产伤害入口和全部重载。旧代码在分支已死/实机存活时失败；修复后 101 项检查通过，包含反方向状态差异、分支复活、独立分支、禁止 live getter、无来源伤害和空目标。已死来源不进入逐目标效果和后续 Hook。

逐目标伤害及后续 Hook 为测试替身。该合同证明错误来源被入口拒绝，但原报告完整死亡/抽牌链、实际根捕获/Fork 和原生差分尚未回放；其余相同递归异常报告不批量标为已解决。
