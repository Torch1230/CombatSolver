# 盛碗虫群：父节点预约与并行调度

本轮基线为 `e956f5c`，生产修改只位于 Search 的内存预约算术与调用处；未改模拟语义、Beam、节点/选牌预算、DOP 或 No-GC 区域上限。详细样本见[机器可读证据](bowlbugs-wave-admission-20260912.json)。

## 原因与实现

旧实现把64 MiB写成父节点分配高水位的初值，之后只允许升高。乘1.5安全系数后，每个父节点永久至少预约96 MiB；1 GB设置对应本机约666.7 MB分配边界，使父节点窗口通常只能放1–6个。已有两次阶段采样各约1.2万批，按批平均的实际分配/预约量仅约0.66%。这会增加批次切换，并减少跨父节点的负载平衡空间；父节点数不能当成实际同时工作的lane数，单父节点仍可有多个作业。

新实现把冷估计与实测值分开：

- 尚无完整父节点观测时沿用每父节点96 MiB冷预约。
- 完整观测后，整次搜索的父节点实测最大值保持只升不降，乘1.5后按已准入父节点数预约；每批再额外保留96 MiB突发余量。
- 纯串行后备维持原来的 `1.5 × max(64 MiB, 实测高水位)`。并行余量放不下时允许回到该后备，不能仅因整批余量超过小区域而直接退出No-GC。
- 所有既有批次排空、原序提交、取消/错误清理和Runtime回收入口继续生效。当前预测不构成未知分配的硬上界。

## 定位与撤回实验

对旧版本进行199 Hz `cpu-clock:u` 采样，21,024个样本中18,788个栈明确属于搜索；回合模拟、快照、回放与Fork成本分散。CPU时间不能按线程累计后当成墙钟，也不能从阶段占比直接推算某个容器的收益。

Ritsu精确类型缓存的字典快照实验未证明稳定收益，已撤回。它的预热后A-B-B-A耗时为15.165、16.338、15.316、15.291秒；相关数字仅用于记录取舍。

GC事件跟踪来自该撤回候选：与40个回收检查点匹配的后台GC累计约14.971秒，检查点累计16.693秒，GC结束后的间隔累计0.577秒、平均14.4毫秒。该覆盖范围不等于整次请求；证据不支持把主要耗时归因于轮询完成后额外等待。

不额外叠加突发余量的诊断版本初步显著加速，但不作为交付实现。第一个保守版本将并行整批余量误用于串行后备，导致104 MiB人工压力合同明确失败；已修正并重新验证，未扩大测试压力区域。

完整动作/选择对象及89项质量、总工作量和语义剪枝字段一致：30,000展开、419,813转移/Fork、240,306选择，战损19、无药、第5回合终局。并行专属父/动作/选择计数单独列为调度指标：整批余量放不下时，一部分区域尾部工作改由原串行后备完成，因此这些计数下降，但总转移、总选择尝试和原序结果不变。源码核对与DOP1/DOP2完整结果合同共同覆盖这一区分，未把这些差异丢弃。

收益来自调度，不是减少总工作或分配；端点内存值不作为峰值内存结论。

## 边界与限制

- 原封不动的104 MiB压力合同已在盛碗虫群与独立亡灵场景通过，runId分别为 `b3d8c6d381ad4f6598012f815ffa56bd`、`779eb75069f74cf6a125d4bb9be6e752`。覆盖DOP1/DOP2完整结果、待命探针实际并发、取消、注入错误、排空及同根复用。
- 纯算术合同通过冷估计、实测预约、200 MiB突增、串行原下限、溢出/零容量及10,000组独立余量计算；另保留既有容量/倍增合同。这是算术突增覆盖，不伪装成200 MiB原生卡牌效果验证。
- 最终Linux Release构建0警告0错误（8.68秒），Linux结构门禁通过；Windows门禁规则同步，未在Windows执行该脚本。

全部性能数字为Linux无头、诊断恢复、首个主搜索。每个请求不超过120秒，不运行完整自动战斗。原归档缺少旧ModelId编码映射，ContinuationStamp匹配但native二进制不可比较；测试构建统一旁路源码身份检查并在首个主搜索返回，生产不包含这两个测试旁路。没有重跑原Windows完整Mod环境的186秒请求，不外推可见帧时间、FPS或所有战斗提速。
