# 原版卡牌克隆并行边界（2026-09-13）

本轮继续优化代码并行性，不重跑8/16核性能系列。实现位于 `Engine/Common` 的预测模型克隆入口；未改变搜索预算、评分、候选顺序或原版克隆语义。

## 发现与实现

`CloneModelForSimulation` 直接执行 MemberwiseClone、事件隔离、DeepCloneFields、AfterCloned，没有调用原版 MutableClone，因此不会触发其 BaseLib CloneSpireFields 后缀。过去预测入口仍对整个深克隆持有同一全局锁。

核对实际 BaseLib 3.4.7 与 Ritsu 0.5.20 后，只放行模拟隔离域中的普通原版卡牌：变量必须已物化、全部为原版类型，无附魔或灾厄；原生克隆阶段不能改写，变量克隆与元数据复制补丁必须严格匹配现有稀疏复制保护。源表只查询，目标由当前克隆独占。其他模型、变量、附着模型和未知补丁保持原锁，原版 MutableClone 的第三方字段保护不变。

补丁与类型证据属于线程当前最外层隔离域，跨域重新核对；不持有卡牌或分支值，不为判定路径物化共享源变量。求解期间改变 Harmony 补丁不在支持范围。未加载 BaseLib 时不支付这套核对成本。

## 失败记录与限制

首次要求真实锁的合同失败（`51ca61c0718a4fa39a36674f257d458c`），揭示旧无头环境实际没有加载 BaseLib。此前父节点预约等无头数据仍属于当时环境，不能用于声称本轮减少 BaseLib 锁竞争，也不能代表完整 Windows Mod 栈。

加入真实 BaseLib 后，中间合同 `d849066f25844c38b9d07a05927436f3` 在跨域补丁失效断言失败：继承方法的 ReflectedType 导致 Harmony 查找未命中。现改为声明类型的 MethodInfo，最终合同通过。没有删除失效断言。

本轮证明指定原版克隆路径不再等待该全局锁，未量化整场吞吐、CPU利用率或收益覆盖率。没有可见测试、Windows部署、版本提升或发布。
