# 重复牌优化的跨场景与整场验证（2026-09-29）

本轮以 `e6dc57ae` 为基线，继续[前一轮研究](duplicate-choice-pruning-20260929.md)。范围扩展到五角色的普通、精英、首领根，CPU 采样、JIT 汇编、硬件计数器和原生完整部署。普通出牌与组合的等价关系保持原样；本轮削减构造相同选择结果时的重复计算和临时对象。

## 保留的实现与安全性

1. **同次多选的令牌复用**：`BuildChoices` 按 `PredictedCard` 引用身份，在一次调用内复用不可变 `PlanCardToken`。只用于多张选择、多个保留组合；每次调用重新建立。相同牌名的不同实体不会共享缓存条目。来源序号、候选序号、状态键、标题及最终顺序保持。返回的选择列表各自独立，只有不可变令牌共享。
2. **结果容器的精确容量**：选中张数已知，令牌列表按该数分配，覆盖单选、多选及隐式全选，省去扩容与闲置槽位。
3. **直接定位尾部实体**：对于某个语义键，设选择了 N 次，当前位置是其中从零开始的第 j 次；原实现映射到候选中最后 N 张的第 j 张，等价于从候选末端数第 N−1−j 张。新实现按这个序号倒序定位，只有实际替换实体时才分配结果数组。空选择、数量不足、重复引用及多个键交错均沿用原结果。不删除任何额外实体代表、不改变两条补留上限或排序。

直接定位的选中序列扫描最坏为平方复杂度，因此仅用于选中数不超过16的集合；更大的选择保留原分组算法，避免把普通手牌收益推广成大牌堆回退。没有跨动作、Fork、搜索或战斗的模型缓存。Testing 保留冻结旧算法，逐引用和次序核对直接与回退两条路径。

## 测量过程与未采用实验

- 预先建立全部等价候选分组：每次通常很快达到两条补留上限，提前构建的组未被充分消费。重复牌微基准分配从84.816 MB增加至86.464 MB，耗时也更高，撤回。
- 只需祖先节点时省略路由签名：静默猎手交错样本未建立稳定时间收益，撤回。
- Fork监听表的数组专用重映射：君王两次约快2%，静默猎手没有收益，合计差异较小，未保留新分派路径。

以上失败试验与逐次结果一并保留在结构化证据中，不能只挑局部最快的一次作为结论。

## perf 的证据边界

环境为 Linux、AMD Ryzen 7 7840H、.NET 9.0.19。使用 `perf record -k 1 -e cycles:u --call-graph fp`、`.NET` JIT映射及 `perf inject --jit`，并用 `perf annotate` 检查重映射方法的机器指令。第一次协调器长采样有423827个样本、零丢样，但 `DOTNET_EnableEventLog=1` 带来了明显的事件记录开销，因此只用于探索，不引用它计算生产占比或速度。

去掉事件记录、关闭阶段测量后的独立采样为33593个样本、零丢样。在该样本中，快照路径的包含式占比约16.04%，选牌构造一个JIT版本约1.06%；包含式父子项相互重叠，且全进程包含建局、JIT、GC，不能相加或当作纯搜索墙钟占比。这也解释了为什么局部选牌提速难以变成普遍整场大幅提速。

最终受控测量另外采集 `cycles:u,instructions:u,branches:u,branch-misses:u`，保留计数器运行比例。它们统计宿主进程，包含建局/JIT，不伪称搜索独占计数。`perf annotate` 是采样落在指令上的分布；JIT内联、合并、硬件采样偏移及数据依赖使它不能提供每条C#语句精确、可相加的独立耗时。

## 可复现配置

广泛根使用 `coverage/corpora/novelty/{dev-*,holdout-*}.json` 的17份既有生成场景。每个请求只包装 `generatedScenarioPath`，不改变开局。探索轮High、Beam48、2000节点、DOP2、30秒软上限，按根ABBA，共68次；中途构建与部分测量重叠，且DOP2的lane学习导致少数前缀物理Fork计数同版本也波动，这轮用于路线与工作量核查，不作最终提速证据。

最终轮固定 `DOTNET_TieredCompilation=0`，DOP1，其余预算同上，17根各A/B；静默猎手与君王精英另以5000节点ABBA，两个针对性选牌根另以500节点/Beam24做ABBA。所有进程顺序执行，采集PMU，无增量差分、无NoGC、无软件阶段计时。选择相关夹具沿用 `coverage/fixtures/scenarios/choices/duplicate-choice-pruning-{dense,purity}-20260929.json`。

```bash

  --request <request.json> --out <out> --label <label> --profile High \
```

原生整场选择五个既有生成场景：`holdout-00-ironclad`、`holdout-01-silent`、`dev-02-defect-elite`、`holdout-03-regent`、`dev-04-necrobinder-elite`。只把生成配置的 `mode` 改成 `Deploy`，使用High/Beam48/2000节点/DOP2/15秒搜索软上限、Instant/0秒、请求120秒、`expectedUnexpectedReplansAtMost=0`，逐次清理工作树内的隔离实例。原生走完整协调器，不能与离线Evaluate混用时间或探索量。

首批完整部署没有导出实战终局HP；旧结果中的solverMetrics只是预测。为补齐测量，在无人测试的最终断言入口追加 `NativeOutcome:combatEnded=...:turn=...:hp=...:maxHp=...`，读取原生玩家当前值；基线和候选以相同记录器补采整场数据。这个测试输出不改变战斗、搜索、部署或终局比较。

## 推广判断

已有相同状态牌的出牌指纹去重和语义选牌去重适用于各卡牌，不只打击；本轮通用构造优化随选牌入口覆盖多种牌与效果。不过玩家眼中的同名牌，可能有不同的费用失效层、牌堆位置或后续实体关联，不能仅按牌名进一步合并。两条物理代表上限是既有策略，本轮没有为其提供全新完备性证明，也没有扩大它。

更有希望的后续对象是采样中成本较高的快照、Fork及重映射路径；本轮已实际试过重映射特化，收益不足而撤回。跨动作顺序、跨回合、不同目标或不同药水的等价剪枝，需要连同有序牌堆、RNG、历史和生命周期证明后续行为不变，目前的证据不足以安全开放。每条语句都可以检查，但优先减少高频路径的整块工作；逐句改写既不能保证收益，也容易把低占比局部收益误报成整场提速。
