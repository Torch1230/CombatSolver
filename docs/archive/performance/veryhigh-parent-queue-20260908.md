# 极高配置：有界父节点队列（2026-09-08）

[返回性能目录](../../performance/README.md) · [结构化证据](veryhigh-parent-queue-20260908.json)

本轮以 `5dedbae` 为基线继续优化死灵法师药水压力场景。最终保留并行父节点调度改动：正常配置的单样本耗时 45.660→39.915 秒，减少12.58%（1.144倍），独立进程峰值RSS增加9.49%。**没有达到用户提出的再快一倍目标。** 没有调整搜索预算、Beam、评分、剪枝配额、DOP或GC政策；仍只用极高预设做性能A/B，普通开发提交，不升版本或发布。

## 为什么药水场景昂贵

输入包含38张牌、20件遗物及弃牌重抽/生成无色牌两瓶药水，要求至少使用一瓶。弃哪些牌、重抽后的手牌和后续出牌顺序共同扩展状态空间；生成牌又增加选择层。十张手牌理论上就有1024个弃牌子集，实际代码有分支配额，不能把理论数当作实际枚举数。最终返回路线虽然只用无色药水，搜索仍会评估另一瓶的候选。

这组输入没有找到可提前结束的胜利路线，会继续原有深搜与窄搜恢复。正常配置累计46,239展开、636,428转移、431,140选择分支，约35.5GB累计分配。短搜阶段测量中，累计worker耗时为Fork约5.60秒、动作约19.67秒（其中直接药水执行约3.47秒）、快照约15.04秒、剪枝约1.90秒；这些是跨线程累计且含嵌套阶段，不能相加换算墙钟百分比。成本分散在状态复制、卡牌/回合结算与评分指纹，只优化药水调用不足以翻倍。

## 最终实现与所有权

旧实现每组最多DOP个父节点，coordinator自己模拟一个，再按序提交；即使其他lane空闲，也要等整组结束才能接下一组。现在在同一内存预约窗口中最多准入`2×DOP`个父节点，由最多DOP个固定后台lane消费；coordinator从完成队列接收结果，归并该worker指标后先派发窗口内下一任务，再提交已接收连续前缀。较慢的父节点不再阻止空闲lane处理后续已准入工作。

候选和父节点仍按原输入顺序提交，转置、剪枝与预算由coordinator独占。原始批次使用独立lease；所有已准入父节点都完整计入现有内存预约，窗口不是固定字节界。异常停止继续派发，补齐未派发计数，排空工作后才释放批次和根。额外父节点lane参加缓存清理及Dispose；自然单父节点仍沿用coordinator加空闲lane的动作/选择回放，不嵌套外层并发。详细诊断和增量模式继续DOP1。

职责仍在`ParallelExpansion`与`Phases`，没有新增战斗状态或改变药水结算。架构地图、性能skill和两端结构门禁同步说明队列、按序接收及额外lane的生命周期。

## 撤回的实验

- 仅卡牌预览监听失效时保留Power视图：短搜6.950→7.469秒，分配不降，撤回。
- 跳过只用于构造下一选择层的PendingChoice完整快照：在早期队列版本上6.116→5.883秒，额外收益约3.8%、分配仅少约26MB。扩大了回放/快照接口与验证面，收益不足，完全撤回。
- 早期队列固定短搜为6.950→6.116秒，10000/144368/101808工作量一致；最终队列另显式使用接收位图并在串行提交前补发任务，最终结论以正常配置表为准。冷启动预热11.832→11.040秒也不能混进正式倍率。
