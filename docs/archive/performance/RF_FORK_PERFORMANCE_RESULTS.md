# RandomForeseer fork 性能与正确性结果

## 0.9.0 最终结果

`0.9.0` 在原增量分叉基础上继续加入卡牌预览写时复制、StateStore 惰性复制、共享历史前缀、CombatSolver 集合写时复制、Hook 监听器缓存、直接 RNG 状态克隆和热路径集合压缩。回合内行动上限已删除；最终差分实际执行 `2540` 个增量转移并逐一与完整前缀回放一致。

用户在两轮最终独立进程样本通过后要求停止继续统计并定版：

| 次数 | 工作线程分配 | 搜索耗时 | GC 暂停 | Gen0 / Gen1 / Gen2 |
|---|---:|---:|---:|---:|
| 1 | `208,446,152 B` | `1,570.2 ms` | `225.8 ms` | `16 / 7 / 0` |
| 2 | `208,450,648 B` | `1,529.4 ms` | `211.5 ms` | `16 / 7 / 0` |
| 两轮中点 | `208,448,400 B` | `1,549.8 ms` | `218.7 ms` | `16 / 7 / 0` |

两轮均为第 `6` 回合结束、`0` 战损、`0` 药损，第 `2-6` 回合精确续用；工作线程分配约 `198.8 MiB`，低于项目 UI 使用的 `200 MiB` 门槛。相对 `0.8.0` 三轮中位数，分配降低约 `65.5%`、耗时降低约 `35.3%`、GC 暂停降低约 `56.7%`，保持 `Gen2=0`。

另有激进深化闭环：测试态把短搜压到 `1 s` 后，`24+8` Beam 深化展开 `1219` 节点、命中 `670` 次转移缓存，并在搜索空间耗尽时提前返回；总计 `3.824 s / 579,181,384 B`，将短搜有战损路线改善为第 `6` 回合 `0/0`。生产默认预算为短搜 `3 s`、触发后追加最多 `20 s`，不是每次固定等待满预算。

## 正确性差分

场景 `RF-FORK-DIFF-061`，run ID `f93228432f31403cab6d35c7c416b19a`。搜索生成的 `2541` 个子分支同时使用以下两条路径执行：

1. 父节点 `CombatPredictionSimulator.Fork()` 后只执行当前动作。
2. 从真实战斗根状态重新创建模拟器并完整回放动作前缀。

每个分支比较完整状态文本、双 `ulong` 指纹、搜索边界、预测风险、已处理死亡集合和 RNG 计数，全部一致。实机最终结果仍为第 `6` 回合结束、`0` 战损、`0` 药损，第 `2-6` 回合精确续用。

旧基线：`5,992,337,032 B / 22.4 s / 10,419.4 ms GC 暂停 / gc2=1`。

按中位数计算：

- 工作线程分配降低约 `89.9%`。
- 搜索耗时降低约 `89.3%`。
- GC 暂停降低约 `95.1%`。
- Gen2 从 `1` 次降为 `0` 次。

既定完成门槛为分配不高于 `0.9 GB`、耗时不高于 `5.6 s`、GC 暂停降低至少 `80%` 且 `gc2=0`，本次全部通过。`0.5 GB / 2 s` 是继续优化目标，不是本轮完成门槛。
