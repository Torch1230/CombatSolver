# 已准入父节点内的动作与选择作业（2026-09-08–09）

[性能目录](../../performance/README.md) · [结构化证据](admitted-expansion-jobs-20260908.json)

本轮在 `984fa59` 的现有搜索后端上实现固定父窗口内的作业调度。保留卡牌动作、药水/目标、选择准备、保证必经的首层回放、原序续接与 EndTurn 作业，共用一次 Solve 的固定后台 lane。VeryHigh 的搜索预算、候选配额、选择回放上限和接受顺序不变。没有版本提升、发包、推送或新后端。

## 最终交错对照

源码与构建在实验前冻结，预定顺序为 **A1 → B1 → C1 → C2 → B2 → A2**：A 是原版加诊断计时，B 是整条动作/选择链/药水作业，C 是最终保留的首层回放小批作业。每个条目启动独立 headless 进程，先用 10,000 节点短搜预热一次，再测一次相同短搜和一次正常配置搜索。各请求在首个结果停止，总期限 120 秒；VeryHigh、DOP8、NoGC 设置 16 GB、详细诊断关闭、增量回放关闭。设置使用十进制 GB，配置字节数为 16,000,000,000。

## 为什么这样拆

1. 首轮只拆卡牌和完整选择链时，药水仍绑在父节点尾部。诊断原型 v2 的尾部累计经过时间为 48.83 秒，其中药水 34.41 秒、EndTurn 14.41 秒。这些是线程段经过时间之和，不是墙钟占比。把药水/目标拆成独立作业后，单轮 wave 总跨度从 20.94 降至 18.69 秒。
2. 同一动作的后续分支会获得前面分支未用的额度，不能预先平均分配整条链的预算。对于 N≥2 个非空首层语义选择，若原语义最终额度 F 与回放额度 R 均≥N，原 `ceil(F/N), ceil(R/N)` 子租约即使耗尽，也至少给后续 N−1 个兄弟各留一个名额。递推保证每个兄弟第一次回放必经，因此可以先做这些回放，而不增加回放或选择数量。
3. `PrimaryChoiceReplayFrontier` 保存必经首层快照。所有生产作业完成后，一个续接作业按原序取快照、扣原逻辑额度、执行嵌套选择和实例补充；无效分支仍按原规则返还未用额度。额度不足、空选择或首层之前存在挂起选择时继续原完整链。不共享修改动态预算，不对 PendingChoice 中间态任意 Fork。
4. 每次只回放一个兄弟会产生 421,883 个很短的作业，试验中用核增加但时间收益不足。最终每份合并 `min(4, max(1, N/DOP))` 次、末份截短；正常场景成为 235,065 个首层回放作业，实际并发达到 8。N≥DOP 时仍至少保留 DOP 份作业，所有原物理回放仍执行。

最初整条动作版本还做过 A–B–B–A 对照，原版正常搜索 38.33→43.28 秒，漂移约 13%；没有把那一组均值作为定版收益。各轮原型、正式样本与 runId 均保留在结构化证据中；一次小批原型因漏复制 manifest 在启动前失败，补齐后才取得有效样本，失败启动不计行为通过。

## 所有权与顺序

- `ParallelExpansion` 保留 lane 生命周期、原始候选物化和串行提交；`AdmittedExpansion` 拥有已准入父节点的作业状态与完成邮箱；`PrimaryChoiceReplay` 拥有必经回放快照和唯一续接消费者。
- 外层最多预约 `2×DOP` 个父节点，内部同时运行最多 DOP 份作业；自然单父节点也使用同一组 lane。父节点高水位预约、动态收缩、纯串行退路及已提交边界的回收机制不变，内部不新准入父节点或设置 GC 检查点。这是数量界与观测预约，不是硬字节上限。
- 同父 Fork 的 COW seal 仍由独立窄 gate 保护，分支模拟在 gate 外运行。准备动作表后按父节点轮流派发，完成的选择优先续接。所有卡牌和药水结果按各自原索引归并，完成父节点只提交连续前缀。
- EndTurn 会发布父节点的 stand-pat 基线，必须等该父节点的卡牌、选择和药水全部完成。TT、dominance、fallback 与最终候选接纳仍由 coordinator 按原序执行。
- coordinator 归并 worker 指标后才能复用 lane。probe、首层快照、raw batch 分别移交唯一所有权；异常停止派发，等待全部在途 lane 完成，再释放未交出的结果和根。药水批次移交与卡牌一样先接纳、后移出，旧租约 Dispose 不触碰后来的租户。

`parallel_waves/work_items` 仍表示父 wave/parent；`parallel_action_*` 表示卡牌探测；`parallel_round_choice_*` 现在合计准备、首层回放、续接及完整链回退作业。它们和 `deferred_round_choice_*` 是物理调度诊断，不能作为搜索工作等价字段。`SEARCH_PARALLEL_WORK kind=PrimaryReplay` 的 count 是小批作业数，max_concurrency 是该类作业实际并发。日志还给出经过时间总量、对数桶 p50/p95 上界与最大值；Parent 包含排队，Wave 包含 Wait/Commit，不能相加。

## 正确性与验证边界

32 个探索及正式短搜/正常搜索样本均保持原版 **83 项非时序、非物理调度字段**一致，短搜 59 条、正常搜索 64 条预测 ACTION 逐行一致。固定短搜为 10,000 展开 / 144,368 转移 / 101,808 选择；正常搜索为 46,239 / 636,428 / 431,140。正常搜索仍只有死亡路线、投影战损 9，没有找到新胜利路线；ACTION 日志一致不等于逐分支原生状态差分。

最终构建 `build-primary-batched.log`：Release 零警告、零错误。最终 `SearchPolicySnapshot + ForkBoundaries` 合同 `d31a5136765943cda47a5200337310e5` Passed：固定节点 DOP1/DOP2 的完整动作、选择、评分、续用和工作/剪枝指标一致，DOP2 实际并发≥2；注入执行中取消及原始异常，确认回调排空、原 token/异常身份、部分工作只计一次，随后复用同一个根完成求解。首层额度合同覆盖饱和、无效、混合消耗和 512 次上限。

`ExpansionBatchChecks` 的 8 项检查通过，包含药水顺序移交、部分移交失败、清空与旧租约隔离；该部分源码此后未变。最终 Linux 结构门禁 `REFACTOR_BOUNDARIES_OK search_files=81`；Windows 门禁已同步规则，本轮未执行。

## 仍剩下的成本

C 两轮 wave 总跨度为 17.57 / 17.70 秒，正常搜索仍有 **18.51 / 19.02 秒在这段调度区之外**，包含初始化、阶段协调、保路、终局处理及相关等待。该差值不能全部归因于排序。每次回放、Fork 和快照的实际工作量没有减少；并行拆分提高了平均用核，但尚未充分利用 8 核，也没有实现成倍加速。进一步细分作业只能覆盖调度区里的剩余等待。
