# 等价重复的采样与准入优化（2026-09-29）

基线 `a765c8f1`（生产代码同 `79f8ff73`）。本轮落实[文献研究](equivalence-reduction-literature-20260929.md)中的“先量重复、提前省去不必要工作”，新增可复现的离线观测器，并将已有精确转置判定提前到战术分类之前。没有启用通用动作换序、修改状态等价关系或增加新的剪枝边。

## 采样发现

17份既有 `coverage/corpora/novelty/{dev-*,holdout-*}.json` 开局，High、Beam48、500节点、DOP1、Evaluate、30秒软上限。观察器只跟踪自然到达转置准入的动作序列，不另行强制执行交换次序，不改变准入结果。

累计36,524次候选分类、2,175次卡牌转置拒绝。观察到1,144组反向两步序列，其中366组状态指纹和六项转置成本标签相同。各求解器的20,000个两步索引上限均未触及。

这不是“所有换序中32%可安全剪枝”的统计：只覆盖搜索自然访问、无选牌/回合结束/遗物动作标注的两步卡牌动作；同起始状态按指纹分组，动作配对刻意忽略实体序号，每组只比较首先观察到的两个方向。指纹相同不是独立的完整状态证明，未被Beam保留的次序也不在样本里。样本用于定位机会，不能生成跨状态的换序白名单。

已确认两个实际限制：

- 多数已观察到的反向序列并未达到原指纹相等条件；不能为了提高命中率直接无序化牌堆或删除历史。
- `CanPlayCard` 虽然是可打出性查询，调用链仍包含Hook、未支持效果诊断和 `StateStore.Get` 的惰性物化。因此本轮没有将重复牌筛选随意移到全部合法性检查之前，也没有引入跨实体的可打出性缓存。

## 保留实现及安全论证

入口：`CombatBeamSolver.ExpansionPlan.ProcessExpandedCardCandidate`，串行与并行展开都通过这里按原顺序提交。

原路径先 `BuildCandidate` 扫描新增历史，检查路线特征，分类动作用途并通过 `with` 复制SearchNode，然后将原始child提交转置判定。被拒绝的普通候选用不到刚建立的分类对象。

新路径在原交叉回合无进展过滤之后，先识别两种例外：有序变异保留租约、延后准入的循环候选。它们继续构造候选并进入原路径。普通候选先执行原 `TryAcceptTransposition(child)`；拒绝时立即按原方式释放快照，通过时才构造战术候选。

不变量：

1. 转置输入仍是原始child，使用原状态指纹、用药数、药水战略成本、卖血、累计战损、动作数和评分；不读取新分类的Traits或ActionOptionFamily。
2. `BuildCandidate` 不执行战斗动作或修改child的转置标签；分类返回的是复制出的节点。租约/循环分类读取已有节点与账本，和战术分类无依赖。
3. 普通分支的转置调用次数、顺序、接收结果及诊断输入保持。特殊路径继续维持原来的转置旁路与延后处理，不用“见过状态”删除待完成的探测义务。
4. 快照释放仍由原串行/批次所有者完成，没有缓存可变模型或跨父共享模拟器。

因此这是利用已有等价证明避免多做战术分析，不是新增等价性假设。它省不了已经发生的Fork和动作结算；其收益上限应按被省略的分类计算，不能把整个转置拒绝率当作搜索提速比例。

## 离线观测器

新增 `tools/search/OfflineSearchHarness/EquivalenceProbe.cs`，仅显式设置环境变量时安装宿主内的Harmony观察补丁。生产Mod不包含该工具。它不改方法返回值，输出 `equivalence-probe.json`，只保留分离出的键、标量和有限例子，不保存节点或模型；每个求解器最多20,000个两步索引，超限计数并停止新增。

```bash
OFFLINE_HARNESS_EQUIVALENCE_PROBE=1 \
OFFLINE_HARNESS_COMBATSOLVER_DLL=<baseline-or-candidate.dll> \
DOTNET_TieredCompilation=0 \
dotnet .local/tool-build/OfflineSearchHarness/bin/Release/net9.0/OfflineSearchHarness.dll \
  --request coverage/fixtures/scenarios/choices/duplicate-choice-pruning-dense-20260929.json \
  --out <out> --label equivalence-probe --profile High \
  --beam 48 --nodes 500 --dop 1 --budget-ms 30000 --search-mode Evaluate
```

观测器使用锁、字符串与JSON，仅用于归因；开启时的时间和分配不用于性能结论。评测必须关闭它。它目前适合单次Evaluate小预算采样，不宣称覆盖所有动作排列或建立可复用安全证书。

本轮收益结论是：直接消除了确定无用的分类与分配，成本较低，但没有建立显著整搜提速。换序观测器为后续规则提供数据；它尚不能将366个指纹相同的样本转换为生产POR规则。更早避免Fork仍需完整效果条件和Beam代表存活证明，本轮没有以样本相同冒充该证明。
