## 结论与范围

本轮修复的是 NoGC 在一次内存压力/意外收集后退出、剩余搜索一直停留在普通 GC 的路径。保留现有回收完成确认和搜索提交边界，允许有界恢复；不更改玩家搜索预算、Beam、候选顺序、剪枝、评分、药水策略或默认 NoGC 配置。

实际女王根的固定工作量交错对照中，最终方案平均搜索耗时 **37.8816→34.5280秒（−8.853%）**，Gen0计数 **674→55（−91.840%）**，GC总暂停 **12.2317→6.0585秒（−50.468%）**。84项非时序/非调度结果字段、40步完整动作和其余结果文本一致。恢复后的内存预留有代价：采样峰值RSS **4.5382→5.2227GB（+15.083%）**，最大单次GC暂停均值 **1.7133→2.1653秒**，没有证明最坏暂停改善。

全部新增运行均为 Linux headless；没有启动可见 Steam，也没有 Windows 实机验证。上述比例只属于下述复现配置，不能外推成原Windows请求提速比例、FPS改善、完整战斗胜利或原始三层大预算请求已经在120秒内结束。

## 原Windows问题包的故障边界

原包 `CombatSolver-0.37.0-QUEEN_BOSS-bc494904718141aab26bf81fa1ab1a25.zip` 的本次搜索记录：

- 根为35张牌、2个Power、66个监听者；Beam512，100000节点，300000ms，DOP16，NoGC配置16GB。
- 搜索开始后46.588秒，第七次已确认后台回收完成时，物理占用29,291,520,000B，高于策略上限29,228,695,790B，因此没有再次申请NoGC，进入`system_headroom_insufficient`回退。
- 此时已展开60388节点，仍有37820个回合结束候选和1060个frontier节点；回收后的托管存活约5.042GB、堆9.535GB、碎片4.494GB、已提交27.547GB。这些不同口径不能互相替代。
- 45.657秒的帧样本记录累计GC暂停7.2511秒；236.888秒的样本为130.9225秒，展开数76609。约191秒窗口中增加了约123.67秒GC暂停，而节点只增加16221。

日志证明退出原因及后续暂停与慢搜重合，没有CLR触发栈，不能据此断言每一次后续收集的具体触发原因。回合结束候选仍参与整层注释、保路及下一回合展开，不能直接删去或提前剪枝来降低内存。

## 修复机制

`SearchGcPolicy.Recovery.cs` 属于 Runtime。Search只在`EnsureMemoryForNextCommit`已排空边界调用注入信号，仍按原序提交工作。

1. 意外退出后沿原路径结束/协调区域并确认后台Gen2完成。如果还没有在这份堆状态上尝试失败的预留，保存该完成index，允许下一个安全边界直接使用；不再为了等待第二次Gen2而让大批工作先进入普通GC。
2. 首次准入失败、或已经申请失败的预留，须等新的已完成Gen2再评估；普通观察至少间隔2秒。每scope最多3次真正预留尝试，后续尝试保留退避；新的退出事件不能清零次数或缩短退避。
3. 恢复预算至多为当前物理余量的一半，同时不超过用户配置。小于512MiB、或不足以容纳已知下一次不可分割工作时不尝试。恢复后的区域上限保留到本scope结束，避免下一次回收立即扩回原大预留。
4. 恢复使用`TryStartNoGCRegion(..., disallowFullBlockingGC: true)`，自身不调用强制GC，也不加入要求搜索退出的deferred完成链。已在途工作和已发出的回收仍须先排空。
5. 取消、退出NoGC、Dispose及新的scope代次会阻止旧探针复活。显式关闭、不支持的平台/尺寸、不可分割工作主动选择普通GC、收集确认超时均不自动恢复。

复用的是已确认回收的完成证据，不是共享可变战斗状态。只有恢复成功才清除系统压力回退的保守并行标记，原队列增减和内存预约规则不变。`fallback_latched=true`旧日志字段仍表示该检查点结束时处于普通GC；应结合后续`GC_NO_GC_RECOVERY`判断是否恢复。

本地游戏runtimeconfig声明.NET9.0.7。微软文档将`FullBlocking`定义为阻塞Gen2、`Background`定义为后台Gen2；采样代码也检查Generation字段。[GCKind定义](https://learn.microsoft.com/en-us/dotnet/api/system.gckind?view=net-9.0)。恢复API不允许为了预留而主动触发完整阻塞回收，但这并不是消除所有暂停的保证。[TryStartNoGCRegion](https://learn.microsoft.com/en-us/dotnet/api/system.gc.trystartnogcregion?view=net-9.0)。该版本SOH预留沿临时分配区扩展，因此全堆`FragmentedBytes`不构成下一轮SOH一定可复用的容量证明；新恢复预算不把它加到物理余量上。本轮没有修改旧常规区域重建的碎片估算路径。[.NET9.0.7 GC实现](https://github.com/dotnet/runtime/blob/v9.0.7/src/coreclr/gc/gc.cpp#L23959)。
