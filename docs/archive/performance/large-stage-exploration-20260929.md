这组实验单独只能说明有界搜索行为/质量改变，不能独自证明状态抽象在完整搜索中不安全。以下反例提供独立的语义证据。

## 相同牌堆多重集和RNG仍不足以保证洗牌相同

离线工具创建两张私有StrikeIronclad，分别设置持久 `BaseReplayCount=1` 和 `2`。原生 `CompareTo` 返回0，但完整选牌键不同。对 `[A,B]` 与 `[B,A]` 使用相同捕获RNG状态，直接调用游戏提供的 `StableShuffle`：

- 排序比较相等；两边多重集相等。
- 原生洗牌后的有序牌状态不同，一边是 `[replay2,replay1]`，另一边是 `[replay1,replay2]`。
- live状态戳前后一致。

因此，盲目忽略弃牌堆顺序会把未来抽牌不同的状态合并。名字中的StableShuffle不代表它会按完整战斗状态规范化所有牌。反例针对持久状态不同的牌；现有两张完全相同打击的动作代表剪枝不受影响。

后续若继续做顺序归一化，必须保存相同原生排序键内部的有序状态，并证明其余读取者（选牌、随机抽取、实体引用、钩子等）不可观察被移除的顺序；同时处理Beam代表保留与循环/有序变异义务。只验证两步末态相同，或只验证洗牌结果，均不满足这些条件。本轮没有把这份要求清单伪装成已实现的安全机制。
