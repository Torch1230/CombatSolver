# 女王 CPU 与卡牌回放归因（2026-09-13）

在 `2352d08` 的 NoGC 恢复改动之后继续调查同一女王根。保留一项按需评分优化：固定短搜交叉对照平均耗时减少 **3.065%**，完整路线一致。长样本未建立总耗时收益，原 Windows 长搜和可见卡顿仍未验证。此前 GC 恢复的收益见[独立报告](queen-gc-recovery-20260913.md)，不能叠加成此次 CPU 优化的实测值。

## 为什么慢

原根有35张牌，10张手牌、24张抽牌堆和1张弃牌，包含三张杂技及多个抽弃牌来源。固定单主搜索20000展开，实际产生349198次转移、212548次选择回放。一个节点会展开多个动作与选择，节点数远小于模拟次数。

正常生产代码的 `cpu-clock:u` / 199 Hz / frame-pointer + JIT 采样共33067条，其中26683条栈锚定到搜索；两条缺栈，14条达到127帧。采集与解析正常结束，未把未解析原生符号或栈截断视为完整归因。搜索锚定样本约占进程CPU采样权重80.69%。以下为搜索内部按固定优先级互斥归类，不是请求墙钟耗时：

| 工作 | 搜索CPU采样权重 |
| --- | ---: |
| 快照与估值 | 27.76% |
| 回合推进 | 26.81% |
| 其他动作/选择回放工作 | 15.63% |
| 分支复制 | 12.38% |
| 手动卡牌执行 | 6.22% |
| 保路其他工作 | 2.36% |
| 其他搜索 | 8.85% |

选择回放调用栈的包含式占比54.78%，与上表重叠，不能相加。Hook、监听登记/枚举、模型克隆与状态键计算分布在各阶段，并非某一张牌的独立慢函数。

另建仅诊断版本，在每次 Replay 上按动作来源计时与统计线程分配：

| 来源 | 回放次数 | 累计回放时长占比 |
| --- | ---: | ---: |
| END_TURN | 125097 | 49.75% |
| ACROBATICS（杂技） | 51763 | 12.70% |
| PREPARED（早有准备） | 37454 | 7.95% |
| DAGGER_THROW | 32236 | 6.12% |

END_TURN 包括敌方行动、回合开始抽牌、自动触发与选择链；不能把全部成本归给结束回合按钮或一张 Power。累计125.574秒是并行 scope 时间之和，包含调度等待及GC，不能充当CPU时间或24.447秒请求时长的组成比例。预先准备的 Fork 在 scope 外，其分配也不在这组卡牌数字内。40705次快照仍挂起选择；主要来源为 ACROBATICS 14912次、TOOLS_OF_THE_TRADE_POWER 14469次，其余为 DAGGER_THROW / SURVIVOR / PREPARED。

这些数据支持“抽弃牌和回合选择导致大量重放”，没有发现单张牌错误死循环的证据。当前挂起选择含执行事务，`AssertForkable` 明确禁止复制；直接缓存或复制该状态需要新的所有权设计，本次未实施。

## 保留的优化

`CombatBeamSolver.StateEvaluation` 原先在任意贡献 Power 存在且开启首领特化时扫描全部可达攻击，计算 `FirstAttackDamage`。原版实际消费者只有 `LethalityPower`，此根大量快照没有该消费者；该扫描约占快照CPU采样11.75%，即总搜索约3.26%。

现在仅在存在贡献的 `LethalityPower` 或外部 `StrategicEffectMirrors` 登记表非空时计算。外部登记器可以直接读取既有字段，因此登记表非空一律保留旧上下文。普通政策仍为0；无跨分支缓存，不改预算、评分消费者、分支枚举或战斗规则。

两个克隆映射查找原型未采用：提前建立字典在40项微基准慢54.2%、56项快24.2%，不同规模方向不一致；改为 Span 线性遍历也无稳定收益。它们只是本地微基准，不是女王性能结论，生产代码不含这些改动。
